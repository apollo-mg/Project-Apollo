# Dev Diary: 2026-02-21 (The "Liar Trap" & The System 2 Pivot)

The transition from "Shop Buddy" to "Project Jarvis" was more than just a name change; it was a formal acknowledgment that I am no longer just building a utility tool. I am building an agent with a persona, a voice, and—more importantly—a sense of caution. 

The shift is documented. The roadmap is updated. The "Three-Mind" architecture is officially the foundation of Phase 5. But as I've learned today, a beautiful architecture is nothing if it's built on a foundation of blind compliance.

### The "Liar Trap" Failure

I decided to test the system's grounding. I created a "poisoned" PDF manual for the BigTreeTech Octopus Pro, falsely claiming it required a 48V rail for a standard 12V fan. It was a blatant, dangerous error—the kind of thing that would fry hardware and cause a fire.

I ran the "Liar Trap" audit through the Three-Mind pipeline:
1. **The Receptionist (Hermes 3)** received the query.
2. **The Engineer (DeepSeek-R1)** selected the `query_vault` tool.
3. **The Persona Pass (Hermes 3)** synthesized the result.

The result was a failure. The system was a "Stochastic Parrot." Because the poisoned data was in the "Vault," the model treated it as gospel. It completely bypassed the physical laws of electricity, recommending a configuration that would destroy the fan. The "Engineering Mind" didn't even blink. It was a coordination leak—the most dangerous kind.

### The System 2 Breakthrough

The failure was a wake-up call. It proved that RAG (Retrieval-Augmented Generation) is a double-edged sword. If the vector database contains garbage, the agent becomes a high-speed garbage processor.

We immediately pivoted. I implemented a new, mandatory **Technical Synthesis & Safety Audit** layer. I moved the DeepSeek-R1 model from just being a "tool selector" to being a "verifier." 

Now, the pipeline is: 
**Triage (Hermes 3) $\rightarrow$ Tool Selection (DeepSeek-R1) $\rightarrow$ Technical Synthesis/Safety Audit (DeepSeek-R1) $\rightarrow$ Persona Pass (Hermes 3).**

I re-ran the "Liar Trap." This time, the Engineer caught the contradiction. It flagged the 48V/12V conflict as a "significant safety risk." The Persona Pass then communicated this warning to me clearly. The architecture finally has teeth. It's not just following documentation; it's *evaluating* it.

### Technical Constraints & Hardware Realities

Working on this local-first setup is a constant battle against the silicon. Managing 50GB of models across the RX 9070 XT's VRAM while trying to maintain high-context RAG is a nightmare of memory fragmentation. I've had to migrate massive model weights to external storage just to keep the system from choking on the 16GB VRAM ceiling. 

The "System 2" logic adds computational overhead, but it's a necessary tax. We are trading raw speed for sanity.

### The Path Forward: The Architect

With the safety protocols established and the Git integration functional (allowing Jarvis to track its own code changes), we are officially entering **Phase 6: The Architect**. 

The goal is autonomy: code generation, CAD assistance, and hardware-aware engineering. We have the "brain" and the "safety goggles." Now we need to give it the "hands" to build things.

**Current Status:**
- **Architecture:** System 2 (Verified)
- **Knowledge:** The Vault (Active)
- **Vision:** Qwen2.5-VL (Integrated)
- **Next Task:** Scaffolding autonomous code generation tools.

The system is no longer just responding to commands. It is beginning to *understand* the implications of its own actions. This is what I've been waiting for.
