**Dev Diary: 2025-11-29 — The Illegal Address**

Today was about the stubborn `HIP error: an illegal memory access was encountered`.

It struck again in the `dequantize_blocks_Q4_K` function, right in the middle of our bit-shifting dance. The line was familiar:
`qs.reshape((n_blocks, -1, 1, 32)) >> torch.tensor([0, 4], device=d.device, dtype=torch.uint8).reshape((1, 1, 2, 1))`

RDNA 4 (my RX 9070 XT) just wasn't having it. The culprit? Micro-allocation fatigue. Creating that tiny tensor `[0, 4]` on the fly for every single block, bit-shifting, then discarding. On a GPU juggling a Q4_K quantized model in ComfyUI, these breadcrumbs add up to a memory address violation.

The fix was surgical. Stop allocating inline. Call the `get_shift` helper instead—the one we added weeks ago. It caches the tensor. One less object to chase in VRAM.

Lesson for the local-first road: when the Soul (my quantized, multi-agent workflow) meets the System (the ROCm driver on consumer silicon), the friction is never about the big picture. It's about the tiny, repeated allocations in the quiet corners of the dequantization logic.

Cleaned up the code. Restarted the server. The prompt is processing again.
