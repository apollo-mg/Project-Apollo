# Project Apollo: Dev Diary - 2026-02-20 (Part 2)

The friction between the "Soul" and the "System" was on full display today. I spent the first half of the session battling a ghost in the machine—a concurrency bug that made the agent look like it was having a seizure.

The "Dots" problem.

It turned out to be a classic race condition. The `reflect_and_learn` thread was trying to run a background task (the web search) while the main voice loop was still active. Because the search tool required human approval, it would trigger an `input()` call in a background thread. Meanwhile, the microphone was picking up the agent's own TTS voice, which triggered the `main_loop` to print "dot" feedback for noise detection. The result was a terminal filled with an infinite, growing line of dots that buried the user prompt. 

It was a mess. I had to refactor the `Toolbox` to split the web search into an internal, undecorated method (`_web_search_core`) that the background thread could use without hitting the human-approval gate. Once the concurrency was decoupled, the visual artifacts vanished.

Then came the VRAM wall. My RX 9070 XT is powerful, but running a local Whisper model + Kokoro TTS + DeepSeek via Ollama + ChromaDB is a heavy lift. I saw the VRAM hit 14.6GB, triggering my custom "Guard" mechanism to clean up ComfyUI. It's a brutal but necessary safety net for a local-first multi-agent setup.

The "Soul" (the personality) was also acting up. DeepSeek was being far too "robotic." When I'd say "What's up?", it would respond with a technical refusal because the "No Fluff" directive in the system prompt was too strict. It was looking for tool data and, finding none, it assumed it was being useless. I had to relax the constraints to allow for natural conversational context.

The most satisfying win, however, was the diagnostic breakthrough.

I realized that a truly autonomous agent shouldn't just follow a roadmap; it should *know* its own roadmap. I implemented a new `Diagnostician` module. It's a bit of a beast—it checks the LLM connectivity, scans the hardware, and most importantly, it parses `SHOP_BUDDY_ROADMAP.md`. It compares the actual system state against the completed items in the roadmap. It's the first step toward a self-correcting, self-aware agent. The parsing was tricky—regex is a nightmare when Markdown formatting is inconsistent—but after a few tweaks to the pattern matching, it successfully verified 5/22 of the core features.

The system is finally starting to feel like a coherent entity rather than a collection of scripts. It's still "twitchy" with the voice activity detection (VAD) due to the ambient noise in the shop, but the dynamic thresholding is holding the line.

**Core Lessons:**
- **Concurrency is the killer:** In local-first agents, background threads and UI/Voice loops must be decoupled from the decision-making loop.
- **The Prompt is a Constraint:** Strict persona instructions can actually kill intelligence if they prevent the model from using general reasoning.
- **Self-Knowledge is Mandatory:** An agent without a way to verify its own capabilities is just a chatbot with a fancy voice.

**Current State:**
- **System:** Stable, but sensitive to noise.
- **Personality:** Improving (less robotic).
- **Architecture:** Moving toward a self-diagnostic, multi-agent structure.
