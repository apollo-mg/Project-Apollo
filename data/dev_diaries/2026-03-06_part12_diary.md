# Dev Diary: 2026-03-06 (Part 12)

## The VRAM Crisis and the "Sovereign" Pivot

Today was a brutal battle against the limits of the silicon. I spent most of the morning wrestling with the Qwen 3.5 9B-FP8 model, trying to force it into a vLLM environment that just wouldn't accept its architecture. 

The machine was throwing `KeyError` after `KeyError`. It turns out the model's structure is "unfused"—the weight matrices are separate for gate and up-projection, whereas the optimized ROCm kernels for the RX 9070 XT expect them to be fused into a single tensor. It's a classic case of the "Soul" (the model's complex, multi-modal architecture) being at odds with the "System" (the rigid, optimized math kernels of the GPU).

I tried everything: flattening the config, nuking the nested vision parameters, even attempting a "Sovereign Patch" to force the model to behave like a standard Qwen 2.5. None of it worked. The vLLM loader kept getting confused by the residual `text_config` objects.

Then, I hit the wall. The engine started JIT-compiling, and I realized I was playing a dangerous game with the VRAM. With the 0.85 utilization limit, I only had 600MB of "wiggle room" for the KV cache. The model was attempting to load 12GB of weights, and the memory manager was teetering on the edge of an OOM crash.

## The Breakthrough: RDNA 4 and the 198 TPS Reality

We pivoted. I realized we couldn't fix the 9B model's broken fusion, so I abandoned it. I downloaded a "Clean" model—`Qwen2.5-7B-Instruct-FP8` from Neural Magic. It was a calculated risk, but it was a "Sovereign" play.

The results were staggering. The vLLM engine recognized the structure instantly. The weights loaded in 7.4 seconds. And then, the true test: the continuous batching stress test.

I pushed the RX 9070 XT to the absolute limit, forcing 64 concurrent requests through the engine. The GPU didn't just survive; it thrived. It saturated the KV cache to 97.3% and delivered **198.5 tokens per second**. 

That's the number that matters. 198.5 TPS on a single consumer card using native FP8 is a massive win for the RDNA 4 architecture. We proved that the hardware can handle high-concurrency, high-throughput inference. We just need the right, "clean" models to feed it.

## Lessons from the Silicon

1.  **Quantization is not enough:** A model can be FP8, but if the weight-fusion isn't aligned with the ROCm kernels, the overhead is fatal. "Clean" quantization (like the Neural Magic sets) is mandatory for high-performance local AI.
2.  **The VRAM Math is Non-Negotiable:** We learned that a 16GB card is a "Two-Mind" system. We can run a 0.6B Gatekeeper resident in memory *and* a 7B engine, but the KV cache headroom is the deciding factor for batching.
3.  **NVIDIA vs. AMD:** The 4070 Super might have higher burst speeds, but the RX 9070 XT's higher memory bandwidth and larger VRAM buffer make it the superior choice for a "Sovereign" multi-agent system. It's the difference between a sprinter and a heavy-duty engine.
