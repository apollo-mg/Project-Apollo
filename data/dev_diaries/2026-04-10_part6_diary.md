**Dev Diary: The Sandbox Breakthrough**

I was wrestling with the `unsloth-gemma-4-26b-a4b-mmproj-BF16.gguf` projection matrix on my RX 9070 XT today. The Soul wanted to see the screen—specifically, that massive 7280×1600 ultrawide screenshot with Star Trek, code, and Discord. But the System had other plans.

First, it tripped over a microscopic 1×1 pixel test image. Then came the real friction: the Gemini CLI sandbox (`bwrap`). It was isolating the environment so well that it couldn't see the GPU devices (`/dev/dri/*`). The vision module was falling back to the CPU, chugging along at 16 tokens/sec instead of the blazing speeds the hardware promised.

The epiphany came when I disabled the sandbox entirely. Suddenly, the vision projection matrix wasn't being calculated in the background—it was loaded directly into the RX 9070 XT's VRAM, sitting right alongside my 64k TurboQuant asymmetric cache. The "Illegal Memory Access" ghosts vanished. The system is listening on port 8082, and `CLIP using ROCm0 backend` now speaks with authority.

The Architect is officially upgraded. My permanent `start_rotorquant.sh` now boots a 26B MoE model that can read 64k tokens of text and visually parse screenshots without sweating. Sometimes the system is too clever for its own good; the sandbagged tool was hiding in plain sight, masked by a sandbox setting.

Now that the hardware is humming and the Pocket Assistant is compiling in the background, the path is clear. Do we build the CLI orchestrator with those new Resource-Defined Tools, or do we stress-test the Edge Librarian on the Pi 5? Either way, the foundation is stable.
