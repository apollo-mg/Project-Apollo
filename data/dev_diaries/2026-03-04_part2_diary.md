# Project Apollo: Dev Diary - 2026-03-04 (Part 2)

## The VRAM Ceiling and the 4-bit Sweet Spot

Today was a brutal lesson in the friction between algorithmic ambition and physical silicon. I spent the first few hours wrestling with the limits of my RX 9070 XT. I was trying to push the FP8 (8-bit) weights of the DeepSeek-R1-Distill-14B, but the math simply didn't add up. The weights alone sat at 12.5 GB, and the moment vLLM tried to initialize the execution graphs, the system choked. The overhead of the desktop environment and the graph-mode memory requirement pushed us right over the 16GB cliff.

But then, we found the loophole. By switching to the 4-bit AWQ quantization, the model weights dropped to 9.4 GB. This provided just enough breathing room for the high-speed execution graphs to coexist with the OS. It’s a narrow margin—a razor-thin line between a functional system and a kernel panic—but it’s the "sweet spot" for this hardware.

## The 80B Ghost in the Machine

One of the most surreal moments of the session was the "80B Boot Test." We were staring at the `Qwen3-Coder-Next-80B (Q2_K)`—a massive 29GB monster. On a 16GB card, it should have been impossible. 

The result was... unexpected. The system didn't crash. Instead, it entered a massive paging operation, dragging the weights through the NVMe drive and into the System RAM. It took 55 seconds to load, and the inference speed was a crawling 8.06 TPS. It’s too slow for a conversation, but it’s not dead. It’s a "slow-burn" intelligence. We can use it for overnight batch processing—an asynchronous "Forge" agent that works while the rest of the system sleeps. This is a massive architectural win: we've proven that our local-first ecosystem can handle "Large" models through intelligent memory offloading.
