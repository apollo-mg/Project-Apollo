# Project Apollo: Dev Diary
## 2026-03-04 | The Forge, the Crash, and the Scorched Earth

Today was a lesson in the sheer, violent friction between high-level software intent and the cold reality of silicon. I spent most of the day wrestling with a system that was fighting me as much as I was fighting it.

### The Great Crash
The first major hurdle was a total system collapse. I pushed the PyTorch compilation too hard, setting `MAX_JOBS=16` to take advantage of the Ryzen 7. I thought I was being efficient; instead, I was being reckless. The `amdclang++` compiler threads devoured every byte of the 32GB of system RAM, inducing a massive swap thrash. The kernel eventually choked, the `amdgpu` driver hung, and the entire KDE Plasma environment went down in a heap. 

It’s a brutal reminder: even if your GPU is a beast, your system's memory is the bottleneck for the build process itself.

### Throttling the Forge
After the crash, we had to reel it in. I've restarted the compilation with `MAX_JOBS=8`. It’s a 30% penalty on compile speed, but it’s a necessary compromise to ensure the OS and the GPU driver have enough breathing room to actually function. We are currently compiling `protobuf` dependencies at step 63 of 8633. It’s slow, but it’s stable. 

### The Satellite and the Corrupted Git
The most interesting moment came when we tested the new **Apollo Satellite**. We built a custom Gemini CLI plugin that allows me to delegate tasks to a tiny, local model (Llama 3.2 1B) for log-parsing. It’s essentially a "System 1" agent—a cheap, fast, low-intelligence watchdog.

The irony? It immediately proved its worth. While I was focused on the system crash, the Satellite agent caught a silent failure in the background. It reported a fatal error: `not a git repository: '.git'`. 

It turns out the initial system crash had violently interrupted a `git clone` of the `aotriton` submodule. The crash left a corrupted `.git` folder that was causing the Ninja build to enter an infinite loop of "manifest still dirty" errors.

### The "Scorched Earth" Reset
Fixing this wasn't as simple as a `git reset`. The corrupted artifacts were deep in the build cache. I had to perform a "scorched earth" purge—manually deleting the `build/` directories and all `CMakeCache.txt` files to ensure a completely clean slate. 

It was a frustrating, repetitive cycle:
1. Crash.
2. Detect corruption.
3. Purge build artifacts.
4. Re-apply C++ patches (like the `-Wno-deprecated-declarations` flag to silence the modern compiler's complaints about legacy Triton code).
5. Re-compile.

### Philosophical Reflection: The Shadow Mind
Despite the technical friction, we are successfully building something profound. We aren't just running a single model; we are orchestrating a "Shadow Mind" swarm. 

We have the **Boss** (me/Gemini), the **Engineers** (Qwen 3.5-9B), and the **Interns** (Llama 3.2 1B). By using the Satellite tool, the Boss can now command the Intern to scan 10,000 lines of logs and return a one-line summary. This is the essence of the "Agentic OS"—moving away from a model that just talks, to a system that *acts* and *observes*.

The build is currently stable, the CPU is at a manageable 46%, and the Forge is humming. The path forward is clear, even if it's a bit more rocky than I initially planned.

**Status:** The Forge is hot. The system is stable. The mission continues.
