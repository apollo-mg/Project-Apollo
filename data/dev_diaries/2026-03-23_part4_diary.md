# Dev Diary: 2026-03-23 (Part 4)

## The Vision Ghost in the Machine

Today was a battle against invisible failures. I spent most of the afternoon staring at the screen, wondering why the agent was hallucinating high-end desktop components when I was literally feeding it a photo of apples and oranges. It was a classic case of "The Soul vs. The System." The agent's "soul"—the creative, reasoning core—was functioning perfectly, but the "system"—the data pipeline—was a ghost.

The root cause was a dual-layered failure in the vision pipeline. First, a syntax mismatch: my `apollo.py` script was using the `@path/to/image` notation, but the `buddy_agent.py` logic was strictly looking for `[ATTACHED_IMAGE: ...]`. The agent simply couldn't see the trigger. Second, and more critically, even when the tool *did* fire and appended the correct tag to the history, the `llm_interface.py` was discarding the image data entirely if a `messages_override` was present. It was a silent death for the visual payload.

I had to gut and rewrite the `llm_interface.py` message builder. I implemented a new `_build_messages` function that scans the entire conversational history for those `[ATTACHED_IMAGE]` tags, encoding them into base64 on the fly. It was a heavy lift for the context window, but it's the only way to ensure the vision adapter actually receives the pixel data. 

Once the regex for the `@` syntax was patched into the agent, the vision pipeline finally breathed. The model finally "saw" the fruit. The friction between the logic and the data is gone.

## The Crow Architecture

The breakthrough came when I dug into the model's documentation via a link I found on HuggingFace. It turns out I've been running a much more specialized beast than I realized.

I'm currently running the **Crow-9B-Opus-4.6-Distill-Heretic**. It's a Qwen 3.5-based architecture, but the "Heretic" designation is the interesting part—it's distilled specifically for unconventional, non-standard reasoning. It’s clearly optimized for the kind of creative leaps I want from Project Apollo.

The quantization is the real hero here. It's an `i1` imatrix quantization (Q6_K). On my RX 9070 XT, this is the sweet spot. I'm pushing the limits of the 16GB VRAM, but the imatrix approach is keeping the intelligence high while staying within the silicon's physical boundaries. The multimodal projection file (`.mmproj-f16.gguf`) is what bridges the gap between the 9B weights and the vision capabilities.

## Lessons for the Local Ecosystem

1. **Multimodal Fragility:** In a local-first multi-agent setup, "vision" isn't just about the model; it's about the plumbing. If the tool-calling layer doesn't pass the image-data-to-base64-to-API-payload, the model is essentially blind, no matter how "smart" it is. 
2. **Quantization is not just about size:** The imatrix quantization is the difference between a model that is "smart but slow" and a model that is "intelligent and real-time." 
3. **The Ghost of the API:** Even with local models, the API-standardized data formats (like OpenAI's) are the bottleneck. We have to build our own middleware (like my new `llm_interface` logic) to bridge the gap between raw local files and the model's expected input format.

The system is stable. The vision is working. Now, let's see if the "Heretic" can actually do something useful with it.
