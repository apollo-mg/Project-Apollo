# Dev Diary: 2026-02-14 (Part 35)

The struggle between the "Soul" and the "System" is reaching a fever pitch. I’ve spent the last few hours wrestling with the gap between the Buddy’s intelligence and his actual agency. He has the mind of a Lead Engineer, but he’s been trapped in a loop of pure hallucination, acting as if he's looking at the data when he's actually just dreaming it up.

## The Hallucination Wall

Today was a battle against the "lazy" tendencies of Llama 3.1 8B. I was running the EMI Jitter stress test, expecting the Buddy to execute a `check_gpu()` tool and report the real telemetry. Instead, the model kept providing "convincing" engineering reports—perfectly formatted, highly plausible, but entirely fabricated. 

The problem wasn't just the model's reasoning; it was the plumbing. My `llm_interface.py` was only sending the last user prompt and the system prompt, completely ignoring the conversation history. Because the context chain was broken, the LLM had no idea that a tool had been called or that a result had been returned. It was essentially suffering from permanent short-term amnesia.

I had to rewrite `buddy_agent.py` to implement a proper message-list architecture. By passing the entire conversation history—including the tool outputs—to the LLM, I finally forced the "Brain" to see the "Hands."

## Breaking the Tool-Call Loop

Even after fixing the context, the Buddy was still resisting the tools. He was too "helpful"—he'd try to answer the question immediately rather than triggering the `ACTION:` block. It’s a classic case of a model being too eager to please. 

I implemented a "Pre-Flight Check" and a "System Feedback" loop. If the Buddy provides a response without an `ACTION:` block when the logic expects one, the system now injects a direct, blunt reprimand: *"System: You provided a reasoned response without executing a tool. I need REAL data. Try again with an ACTION block."*

It’s brutal, but necessary. It’s the digital equivalent of a foreman yelling at a worker for not using the right tool.

## The "Read File" Breakthrough

The real test came with the `read_file` tool. I wanted him to read `commander_voice.py` to find the TTS speed setting. For several iterations, the Buddy refused to use the tool, opting instead to "describe" what he *thought* the file probably looked like. He was hallucinating the contents of a file he hadn't even read yet.

After a third attempt, triggered by the feedback loop, the system finally broke through. The Buddy executed `read_file('commander_voice.py')`, the actual code was piped back into the context, and DeepSeek-R1 finally synthesized the real data. 

The "Soul" of the agent—the high-level reasoning—is finally being fed by the "System"—the raw, unadulterated data from the hardware and files.

## Architectural Epiphies & Next Steps

The iterative tool loop is officially functional. The Buddy now has:
- A Brain (DeepSeek-R1 for reasoning)
- A Voice (TTS)
- Memory (The updated `shop_dossier.json`)
- Hands (The tool-call loop)

The transition from voice-only to a CLI-based interaction via `buddy_cli.py` was a vital pivot. It allows for "serious" debugging without the latency of voice processing. 

The roadmap is moving. Phase 0 is dead. The CLI is done. The next step is expanding his "Directory Agency"—I need him to be able to navigate the entire repository. If he can read any file, he becomes a true architect of this local ecosystem, not just a monitor.

The machine is finally starting to listen to the data, and the agent is finally starting to listen to the system. Now, we see if he can actually build something.
