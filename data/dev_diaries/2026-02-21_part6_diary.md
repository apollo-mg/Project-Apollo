# Dev Diary: 2026-02-21 (Part 6)

## The Ghost in the Machine: Debugging the VRAM Recursion

Today was a battle against the silicon. I've been wrestling with the interplay between my local models and the AMD RDNA 4 architecture. The VRAM is a fickle beast; even with the RX 9070 XT, the sheer weight of DeepSeek-R1-14B combined with the memory-heavy PDF parsing was causing the driver to panic. 

I hit a recursive deadlock. The system would try to unload a model to free space, but because the "Unload Request" was triggered by a model that was already being processed, the state machine got stuck in a loop. The VRAM safety lock was doing its job—preventing a total kernel panic—but it was doing it so aggressively that the agent couldn't even breathe.

I had to implement a "Smart Loading" check in `llm_interface.py`. If the requested model is already resident in VRAM, we skip the purge. It’s a simple fix, but it’s the difference between a fluid agent and a frozen computer.

## Architecture Upgrade: Unified Tool Interception (UTI)

This was the breakthrough. 

I realized my orchestration logic was too rigid. I have two "minds" now: the **Receptionist** (Llama 3.2 1B) and the **Unified Engineer** (DeepSeek-R1). 

The problem was that the Orchestrator was too "greedy." It saw a keyword like "manual" and hijacked the query, forcing it into the Fast-Path (the small Llama model). But Llama 3.2 is a lightweight model; it’s fast, but it lacks the context window for heavy technical PDFs. It would see a complex technical document, get overwhelmed, and trigger a "safety refusal," hallucinating that the document was "illegal or harmful" because it didn't understand the technical jargon.

**The Solution:**
I refined the routing. The **Fast-Path** is now strictly for low-latency system stats (GPU/VRAM/CPU). If the query is a complex request (like "Find the Octopus Pro manual"), it bypasses the Fast-Path and goes straight to the **Unified Engineer**. 

The Engineer has the "soul"—the reasoning capability—to handle the heavy lifting. The Receptionist just handles the "reflexes."

## The Soul vs. The System

It’s a constant friction. The "Soul" (the goal of a highly intelligent, reasoning agent) wants to dive deep into the files, but the "System" (the hard limits of VRAM and memory fragmentation) wants to shut everything down. 

I also had to deal with the "Safety Hallucination." Llama 3.2's safety filters are tuned for general chat, and they choked on technical data. I had to harden the prompt to tell the small model: "This is safe technical data." It’s a reminder that even in a local-first, unfiltered environment, the model's training can still act as a phantom censor.
