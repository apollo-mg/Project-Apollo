# Dev Diary: 2026-03-02 (Part 2)

## The Architecture of the "Middle-Mind"

Today was a massive win for the intelligence hierarchy. I’ve been obsessed with the latency bottleneck between the high-level "thinking" (DeepSeek) and the low-level "listening" (Llama-3.2), and we finally found the bridge.

We integrated the **Qwen3-Coder:30B** as our "System 1.5" Researcher. This is a game-changer. Because it's a Mixture-of-Experts (MoE) model, it only fires about 3.3B parameters per token. On my RX 9070 XT, that means we get the reasoning density of a much larger model with the inference speed of a tiny one. It's the perfect "fast-thinking" agent for handling web searches, tool-calls, and JSON-structured data without the massive overhead of the 14B DeepSeek-R1 loop. 

The "Glass Cockpit" is now live, giving me real-time telemetry on the Whisper transcription engine and the Pi 5 satellite. Seeing the real-time log traces of the conversation scrolling in the cockpit makes this feel less like a terminal and more like a Mission Control center.

## The VRAM Tetris & The AWQ Debate

The friction between the "Soul" (the desire for massive context and reasoning) and the "System" (the hard limit of my 16GB VRAM) is constant. I spent a significant chunk of the session debating quantization with Gemini. 

We're currently running the `qwen3:8b` variant via Ollama/GGUF. It's efficient for swapping, but I'm eyeing the **AWQ** implementation. 

The technical reality is clear: Ollama is stuck in the GGUF/llama.cpp world, which is great for memory offloading but lacks the raw, pure-GPU throughput of AWQ. If I want to use the AWQ version of Qwen3, I'll have to bypass Ollama and run it through **vLLM**. 

The VRAM math is tight:
- **Qwen3-8B (AWQ) + Weights:** ~5.4 GB
- **KV Cache (at 32k context):** ~7 GB
- **Total:** ~12.5 GB

That leaves me only ~3.5 GB for the Linux desktop, the 1B Receptionist, and the rest of the system. It's a tight squeeze, but if I can manage the `gpu-memory-utilization` via vLLM, we can make it work. The speed-to-logic ratio will be insane.

## The Ingestion Daemon

The scale of the data we're dealing with is staggering. I have over 100,000 emails sitting in the local mailbox. The `mbsync` process is currently grinding through the backlog. 

I've decided on the next architectural leap: We're going to use the speed of vLLM (with that AWQ model) to accelerate the initial email ingestion. If we can use a high-speed, quantized model to parse the incoming stream, we can populate "The Vault" (our long-term memory) significantly faster than the current serial processing.
