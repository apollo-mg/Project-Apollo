# Dev Diary: 2025-11-19
## Project: Apollo (Sovereign Engine) | The ZLUDA Struggle & The CPU Pivot

### The Friction: Soul vs. Silicon
Today was a grueling battle against the limitations of the ZLUDA translation layer. I am operating on an **AMD RX 9070 XT**, a beast of a card, but even with this raw power, the software bridge (ZLUDA) is stumbling over its own feet. The "Soul" of this project—the ability to generate expressive, human-like speech through XTTS—is being choked by the "System"—the fundamental inability of the current driver-layer to handle specific matrix multiplication (GEMM) kernels.

### The Technical Descent (The Error Loop)

The session was a descent into a series of cascading failures:

1.  **The DeepSpeed Collision:** Initially, the system crashed trying to use DeepSpeed. I realized the ZLUDA implementation is too fragile for the heavy-duty optimization DeepSpeed demands. **Action:** I ripped it out. The engine is now running in a "pure" mode, sacrificing some throughput for stability.
2.  **The `cublasSgemm` Wall:** Even without DeepSpeed, the model (GPT2) hit a hard wall. The ZLUDA implementation of `cublasSgemm` (Single-precision General Matrix Multiply) failed for certain tensor dimensions. The GPU was literally refusing to do the math.
3.  **The Precision Paradox:** I tried to bypass this by forcing **BFloat16** (Half Precision). I thought, *"The 9070 XT is built for this."* But the error just changed. It wasn't a failure of the math, but a failure of the *type*. The `LayerNorm` operations in the Transformer blocks were demanding `Float32`, but the rest of the model was `BFloat16`. The mismatch killed the process.

### The Architectural Epiphany: The CPU Pivot
I realized I was fighting a losing battle with the ZLUDA/ROCm translation layer. The ZLUDA implementation is too immature for the high-precision requirements of modern Transformer architectures. 

**The Pivot:** I made a radical decision to force the **XTTS model to run on the CPU**. 

It felt like a retreat, but it was a strategic maneuver. By moving the core model to the CPU, I bypassed the broken GPU kernels entirely. To prevent this from becoming a performance nightmare, I implemented **Dynamic Quantization (`qint8`)** on the CPU-based model. This allows the CPU to crunch the numbers faster, even if it lacks the massive parallel throughput of the GPU.

### The Result
The "Soul" has returned. The voice generation is working. The speed is acceptable. The system is stable.

### Final System State
* **Model:** XTTS v2.0.3 (running on CPU via `qint8` optimization).
* **Hardware:** AMD RX 9070 XT (handling the display/OS, but bypassed for inference).
* **Environment:** Linux-ready (preparing for a full migration to Ubuntu 22.04 LTS to unlock native ROCm).
* **Status:** **Operational.**
