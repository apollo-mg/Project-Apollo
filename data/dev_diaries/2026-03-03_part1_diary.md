# Project Apollo Dev Diary
**Date:** 2026-03-03
**Status:** Partially Recovered / VRAM Stable
**GPU:** AMD RX 9070 XT (ROCm 6.2)

### The Ghost in the Machine

It's past midnight, and the hum of my 9070 XT is the only sound in the room. We're chasing a ghost tonight. The "Soul" of Project Apollo—the part that's supposed to *see* and *understand*—is fighting a losing war against the "System," specifically the brittle, unforgiving reality of ROCm drivers and Ollama's implementation quirks.

Today was supposed to be a simple victory: upgrading the vision pipeline to handle multi-image inputs. Instead, it turned into a forensic investigation of a hallucination cascade.

### The Multi-Image Bottleneck

We hit a wall early on. The architecture in `buddy_agent.py` was built on a naive assumption: that it could just dump a list of images into the payload and expect the Vision Model to handle the rest. 

The regex parser was greedy. It grabbed the first `[ATTACHED_IMAGE]` tag and stopped. If you sent two photos of a PCB, the model saw the first one, ignored the second, and we lost half the data. I had to rewrite the extraction logic in `buddy_agent.py` to build a full `image_paths` array and then update `llm_interface.py` to iterate over that array, encoding each image into the base64 payload. 

On paper, this should have been enough. On silicon, it wasn't.

### The Ollama Black Box

Here is where the friction gets real. I patched the code to send multiple images in a single message array to `qwen3-vl:8b`. I hit send. 

The result? **Silence.** 

The model didn't throw an error. It didn't return a stack trace. It just returned an empty string `""`. 

This is the nightmare of local LLMs: silent failure. Because the vision model choked on the multi-image payload, it passed nothing to the next agent in the chain. The `qwen3:8b` Engineer received a blank prompt and, being an LLM trained on probability rather than truth, it did what LLMs do when they're lost: it lied.

It hallucinated that the BigTreeTech board was an "EBB636." A phantom part number. It made up a spec to fill the void of the missing visual data. This is the danger of our current architecture—the handoff between agents is only as strong as the data passing through it. If the Vision Agent fails, the Engineer Agent becomes a creative writer, not a technician.

### The Fix: Split Streams

I couldn't just leave the bot running a lie. I had to patch `llm_interface.py` at 00:30 AM. 

I abandoned the single-payload approach. Instead, I implemented a "split stream" logic. If multiple images are detected, the code now constructs a sequential conversation history:
1. `User`: "Analyze this image." (Image 1)
2. `User`: "Also analyze this image." (Image 2)

This bypasses the Ollama/Qwen3-VL bug entirely. It's ugly, but it works. The model now sees both images and correctly identifies the board. 

### Restart Wars and Environmental Drift

The night wasn't without its procedural scars. After patching the code, I restarted the `discord_bridge.py` process from the wrong directory (`apollo_share_dist` instead of `gemini`). The bot failed to start because it couldn't find the `.env` file containing the Discord token. 

Then, subsequent restart attempts hung or produced empty logs, leaving me blind to the process state. It was a stark reminder that local AI is 10% model weights and 90% system administration. We're not just training models; we're managing a fragile ecosystem of background processes, environment variables, and file locks.

### The Path Forward

We've learned three critical lessons tonight:

1.  **Never Trust a Silent Failure:** The vision model's empty string response is a critical point of failure. We need a validation layer that checks for empty outputs before passing data to the next agent.
2.  **Web Search as a Grounding Wire:** I've updated `vision_audit_protocol.py` to mandate a `web_search` step for any silkscreen OCR output. If the model reads "EBB36" from the board, the system must verify that part number exists on DigiKey or Octopart before committing it to the inventory. This stops hallucinations from becoming "facts."
3.  **Modular Image Handling:** The multi-image array approach is dead for now. We stick to split streams until Ollama's ROCm backend matures.

The bot is back online, running the patched code. The hallucination is gone, replaced by boring, accurate data. It's not elegant, but it's real. And in local AI, reality is the only thing that matters.

**Next Up:** System cleanup. There are too many zombie `discord_bridge.py` processes running in the background, eating VRAM that should be reserved for the quantization matrix. Time to purge the ghosts.
