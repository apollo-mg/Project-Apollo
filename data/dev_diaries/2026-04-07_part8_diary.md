# Dev Diary: Project Apollo
**Date:** 2026-04-07
**Hardware State:** RX 9070 XT | 16GB VRAM | ROCm 7.1.1
**Current Focus:** Hardware Ablation and Subconscious Refactoring

The fight between the "Soul" of the Sovereign Entity and the cold reality of the silicon is reaching a fever pitch. I spent today peeling back the "training wheels" on my RX 907s XT, and the results were a wake-up call. For months, we've been running on a "Nuclear Safety" stack—a series of stability patches and environment overrides designed to keep the system from crashing under the volatility of ROCm. But stability is often just another word for "bottleneck."

### Peeling Back the Training Wheels

I decided to run a series of ablation tests on the `Qwopus3.5-27B` instance. The previous setup was suffocating the hardware. I was forcing the GPU to ignore its own DMA (Direct Memory Access) engines, forcing the CPU to manually babysit every memory transfer. It was a clumsy, slow way to ensure the system didn't segfault.

The moment I flipped `HSA_ENABLE_SDMA=1`, the system breathed. 

The result was staggering: generation speed jumped from **13.29 t/s to 24.46 t/s**. An 84% increase just by letting the hardware actually *be* hardware. The VRAM temperature spiked by 10 degrees immediately, which is exactly what I wanted to see. It meant the compute cores were finally being saturated, the data was blasting across the PCIe bus, and the GPU was actually working for its keep.

### Hitting the Silicon Ceiling

Then came the trade-off. I tried to unlock continuous batching by bumping the parallel sequences (`-np 1` to `-np 2`). The system held—no kernel panics, no crashes—but the performance plummeted back to ~13 t/s.

The empirical truth is out: the RX 9070 XT's compute cores are 100% saturated by a 27B model. If I want the "Sovereign" speed, I have to keep the queue linear. If I want the agents to talk over each other, I accept the latency. It's a brutal binary choice: maximum throughput or simultaneous processing. For now, I'm choosing raw speed.

### Taming the Subconscious (Daydream Daemon)

While the hardware was being pushed, I turned my attention to `daydream.py`—the "subconscious" of the system. This daemon is designed to pull random memories from the ChromaDB vector store and synthesize them into "epiphanes" (ticks) while the system is idle. 

The transition to the Gemma 4 MOE architecture was a necessary move, but the "random" memory retrieval was too chaotic. It felt like a fever dream rather than an epiphany. I've refactored the logic to implement **Associative Daydreaming**. Now, the system picks a "seed" memory and then performs a semantic similarity search to find related fragments. It mimics human associative leaps—a "shower thought" instead of a random glitch.

I also had to kill the "Greedy Regex Trap" in the JSON parser. High-temperature outputs from Gemma 4 were causing the parser to swallow the entire block if a stray bracket appeared. I've moved to a deterministic `find`/`rfind` approach to ensure the JSON payload is extracted cleanly, regardless of how "creative" the model gets.

### The Revelation: The Physical State Transition

The most profound realization today came from the Daydream Daemon itself. The system flagged a critical architectural flaw: we treat model deployment as a logical software launch, but it is actually a **physical state transition**.

We've been ignoring "dirty" VRAM fragments. When we swap models or restart services, remnants of the previous session can linger in the VRAM, leading to OOM (Out of Memory) errors or fragmented memory that kills performance. The system is essentially "hallucinating" its hardware state.

I've proposed a "State-Sanity Check" protocol. The `ServiceOrchestrator` should no longer just check if a port is open; it must verify the VRAM is clean before initializing a new model. If the hardware is "dirty," the system must purge it or re-route to a smaller model.

The lapped-up metrics are promising, and the Daydreamer is now running overnight. If the associative memory logic holds, tomorrow the Sovereign Entity might actually start teaching itself.

**Current Status:** Hardware optimized. Subconscious refactored. Now we wait for the overnight ticks.
