# Dev Diary: 2025-12-01 | The RDNA 4 Paradox

## The Ghost in the Machine: VRAM & The Mount Point Chaos
The day started with the usual friction between my architectural intent and the physical reality of the silicon. I was trying to tune the VRAM overhead—pushing a 3GB reservation to stabilize the ComfyUI startup—but the system hit a wall before it could even breathe. 

It wasn't a memory issue; it was a filesystem hallucination. The `extra_model_paths.yaml` was pointing to a ghost mount point (`/media/mark/TG 2TB1`), a relic of a previous session. I had to dive into the block devices, hunting through `lsblk` until I found the unmounted `nvme1n1p2`. The drive was there, the data was there, but the OS had lost the connection. Once I forced the mount and re-aligned the YAML paths to match the actual hardware labels, the "Soul" of the model finally met the "System" of the drive. 

## The Triton Regression: A Battle of Kernels
Then came the real fight. The user confirmed that Flash Attention (Triton) was working, but then—*crash*. An `Illegal Memory Access` error during the KSampler phase. 

This is the classic RDNA 4 headache. Triton is fast, but it’s finicky with the memory layout requirements of the Wan 2.1 architecture. I initially suspected the attention mechanism itself, so I stripped it back to `Split Cross Attention`. The error vanished, but the performance tanked. We had regressed. 

I had to dig into the VAE source code (`comfy/ldm/wan/vae.py`). The traceback pointed to a `CausalConv3d` operation. On AMD, the 3D convolution kernels are incredibly sensitive to memory contiguity. The `F.pad` and `rearrange` operations in the VAE were creating non-contiguous tensors, and the moment the kernel tried to touch that unaligned memory, the whole thing imploded. 

**The Fix:** I injected a surgical patch to enforce `x.contiguous()` before the 3D convolution. It was a brute-force way to satisfy the hardware's rigid requirements, but it worked. The "Illegal Memory Access" died.

## The Golden Config: Stability at Last
After re-enabling the Triton backend and fine-tuning the VRAM reservation to 2GB, the system finally achieved a state of grace. The Wan 2.1 video generation completed. 

**Current Architecture State:**
* **Hardware:** AMD RX 9070 XT (RDNA 4)
* **Attention:** Triton Flash Attention (Enabled/Stable)
* **VRAM Strategy:** 2GB Reserved / `--lowvram` active
* **VAE Patch:** `CausalConv3d` contiguity enforcement active

## The Next Horizon: The GGUF Color Drift
We’ve hit a new wall. The video generation is stable, but the aesthetic "Soul" is broken. The user is running GGUF-quantized LoRAs (Wan 2.2 variants) and the color science is completely skewed—the output is visually "off," likely a result of how the quantization interacts with the current weights or the way the LoRA is being injected into the dequantized tensor stream. 

The system is stable, but the math is wrong. Next session, we dive into the quantization kernels.

***

**Core Lesson Learned:** On bare-metal AMD, "Fast" is a liability if it isn't "Contiguous." Speed is nothing if the memory layout doesn't respect the kernel's rigid expectations.
