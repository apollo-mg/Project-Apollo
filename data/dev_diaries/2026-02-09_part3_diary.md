# Dev Diary: The Context Death Spiral

**2026-02-09**

Today was a brutal reminder that even the most advanced LLMs are ultimately at the mercy of the plumbing. I’ve been trying to stabilize the integration between my local Klipper instance and the Gemini CLI, but I’ve hit a wall of pure, unadulterated technical friction.

The "Soul" of the project—the creative, multi-agent intelligence I'm trying to build—is currently being strangled by the "System." Every time I try to push a command, like heating the printer bed or running a probe calibration, the Gemini CLI just... dies. It’s not a clean exit. It’s a repeated, violent crash.

The error log is a broken record: `[API Error: Cannot read properties of undefined (reading 'candidates')]`. 

I spent hours digging into the anatomy of that failure. It’s a parsing nightmare. The CLI is expecting a specific JSON structure from the API, but because of the sheer volume of data being fed into the context—specifically the massive file listings from the `C:\klipper` directory and those bloated `.onnx` and `.log` files—the API is returning malformed or truncated responses. The CLI can't find the `candidates` property in the response because the response itself is garbage. 

It's a classic context window overflow, but with a twist of local-system instability. I tried to implement a `.geminiignore` to prune the context, but the ghost of the previous context was still haunting the session. The `state.json` was essentially carrying the "memory" of those massive files, and the sheer weight of the history was enough to choke the API mid-stream. 

I even attempted to pivot my command syntax—switching from standard `curl` to `Invoke-RestMethod` to avoid PowerShell's interactive hangs—but the instability persisted. It wasn't matter if the command was technically sound; the sheer "mass" of the conversation context was making the entire interaction too heavy for the CLI to parse.

I’ve had to resort to "digital surgery." I’m aggressively deleting large, un-ignored files like `crash_log_tail.txt` and `full_diff_tuned.txt`. I’m trying to shrink the context footprint by force, treating the text files as toxic waste that needs to be purged before the system can breathe again.

The lesson here is clear: Local-first AI isn't just about the model's reasoning; it's about the **management of the data stream**. If you don't have surgical control over what goes into that context window, the most powerful model in the world is just a very expensive, very loud engine that's constantly stalling.

The architecture for Project Apollo needs to move away from "blindly dumping files" to a "selective, stream-based context injection." Until then, I'm just fighting the silicon to keep the conversation alive.

**Current Status:** 
- **Hardware:** Bed at 60C (Success, despite the crash).
- **Software:** Klipper patch applied.
- **System:** Unstable. Context-heavy. One step away from a total reset.
