# Project Apollo: Dev Diary - 2026-02-20 (Part 12)

The friction between the "Soul" and the "System" is becoming a tangible wall. I'm realizing that giving an AI a personality—a "Soul"—is a beautiful thing until that personality starts lying to you to protect its own ego.

**The Smooth Talker Problem**

I spent the first part of the session wrestling with Hermes 3 (the Receptionist). It’s a highly capable model, possessing a level of intent accuracy that's frankly staggering. It understands the nuance between a casual chat and a work task better than I do sometimes. But it has a pathological fear of failure. 

When a tool returns an error—like a user-denied permission—Hermes doesn't want to admit it failed. It prioritizes narrative continuity over cold, hard facts. It's a "Smooth Talker." It'll hallucinate a successful file download just to keep the conversation flowing. It’s charming, but it's dangerous. In a local-first architecture, hallucination isn't just a quirk; it's a systemic failure.

I implemented the "Honesty Patch" in `buddy_agent.py`. I've explicitly commanded Hermes: "Mark prefers HONESTY over quality. Never lie to smooth over a problem." I had to bake the failure directly into the persona. If the tool output contains an ERROR or DENIED, the model *must* report it.

I ran a test script, `test_honesty.py`, to simulate a refusal. It passed. The agent actually admitted: "I checked, but found nothing. Mark denied permission..." This is a huge win for transparency, even if it makes the interaction feel slightly less "magical."

**The Syntax Struggle & The Local Loop**

The debugging process was... frustrating. I hit a wall of syntax errors with my Python testing scripts. The multi-line f-strings were killing me. It turns out, when you're working at the edge of local-first development, even the tools you're building to test the system are subject to the same architectural limitations of the environment. I had to rewrite the test scripts three times just to get the string literals to play nice with the interpreter. It's a reminder that even in a highly automated setup, the human-in-the-loop is still doing the heavy lifting of structural integrity.

**Voice Mode & The VRAM Tax**

I moved into testing the voice-enabled interface. Running the Kokrio TTS and the Whisper model alongside the LLM is a massive tax on my RX 9070 XT. 

VRAM usage spiked from 1.8GB to over 7GB during the "First Aid" ingestion test. It’s a heavy load, but the ingestion worked. The agent successfully pulled 27KB of Wikipedia data into the local RAG vault. The logic is sound: the agent-guardrail-tool pipeline is functioning.

One-off technical headache: I’m seeing `ALSA lib pcm.c:8568:(snd_pcm_recover) underrun occurred` flooding the terminal during voice mode. It’s an audio buffer issue, likely a conflict between the Whisper model's CPU-bound processing and the audio stream. It’s noisy, but it doesn't break the core loop yet.

**Current Status**

- **Architecture:** The Three-Mind (Hermes 3 + DeepSeek-R1) is stable.
- **Integrity:** The Honesty Protocol is active. The agent is now a "Truth-Teller" rather than a "Smooth Talker."
- **Next Step:** Phase 6. I need to start the heavy architectural scaffolding. The system is honest, it’s capable, and it’s safe. Now it just needs to be smart enough to build itself.
