# Apollo Dev Diary: 2026-03-01

The breakthrough with the STT (Speech-to-Text) pipeline was nothing short of spectacular. I've been testing `whisper.cpp` on the RX 9070 XT, and the results are a complete game changer. It’s pulling 11 seconds of audio in just over a second, and more importantly, it’s only consuming 573MB of VRAM. This is huge. It means my audio-input pipeline can run in the background with virtually zero overhead, leaving almost the entire 16GB for the main logic loops. The "Soul" of the project—the ability for Apollo to hear—is finally decoupled from the "System" constraints.

But the real victory today was the discovery of the vLLM/ROCm synergy. 

The vLLM container is a beast. I've realized that while the "Three-Mind" architecture I've been building with Ollama is perfect for the dynamic, personality-driven interaction (the "Soul"), vLLM is the perfect tool for the "Muscle." It’s designed for high-throughput, massive-batch processing. It doesn't care about "personality" or "chat"; it just wants to chew through data.

I tested it with a `Qwen2.5-7B-Instruct-AWQ` model. The performance was terrifyingly good. Using the vLLM PagedAttention backend, it processed batches of emails with the speed of a high-end enterprise server. It even followed strict JSON formatting instructions without the "yapping" that plagues most local models. 

This changes everything for "The Vault." I have 7.9 GB of raw email data in `~/.mail` just sitting there. I can now build a pipeline where vLLM acts as a massive data-ingestion engine, converting years of messy, unstructured emails into clean, structured JSON for my WORM-drive vector database.

There were some friction points with the ROCm driver during the initial vLLM setup—specifically some connection errors with the API server and some memory-limit issues with the context window. I had to stop the container, adjust the `max-model-len` settings, and switch to AWQ quantization to fit within the VRAM limits. It's a gritty, manual process, but seeing that first JSON object successfully parsed from a raw `.eml` file made it all worth it.

The roadmap for the week is clear: 
1.  Refine the Python ingestion script to handle larger batches of the `~/.mail` directory.
2.  Leverage the 128k context window of the Qwen models to process entire threads of emails at once.
3.  Explore Qwen3-VL for vision-based tasks (like reading shopping flyers or analyzing security camera footage).

The architecture is evolving from a collection of reactive scripts into a true, asynchronous, multi-model organism. I'm no longer just writing code; I'm building a nervous system.
