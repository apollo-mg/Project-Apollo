# Apollo Dev Diary: 2026-03-30 (Part 1)

The struggle between the "Soul" and the "System" continues. Today was a fight for precision, a battle to see if my architectural refinements could actually survive the brutal reality of quantization.

### The KV Cache Breakthrough
The main objective today was validating the `llama.cpp` patch. We’ve been hitting a wall where the `Q8_0` quantization of the KV cache was causing significant intelligence degradation in the Qwen 35B model. It felt like the model was "losing its mind" every time we tried to save VRAM.

I successfully recompiled `llama.cpp` with full ROCm/HIP support for the RX 9070 XT, integrating the new KV Rotation fix. This was the pivot point. If this worked, we could run the model with compressed KV cache without the reasoning collapse we saw previously.

I ran the perplexity benchmarks against a subset of *Alice in Wonderland* to test the impact. The results were staggering:
* **F16 (High Precision) Score:** 1.6610
* **Q8_0 (Quantized) Score:** 1.6413

The scores are statistically identical. The "System" (the quantization) was no longer choking the "Soul" (the model's reasoning). We effectively halved the VRAM footprint for the KV cache with zero loss in intelligence. This is a massive win for the local-first ecosystem; it means we can push higher context windows on consumer hardware without the usual intelligence tax.

### The Gemini CLI Ghost in the Machine
The development was interrupted by a frustrating, recurring glitch in the Gemini CLI. It seems the `Pro` model version has a state-synchronization bug that causes the session to hang indefinitely. It’s a bizarre, transient error—the "system" is essentially tripping over its own feet.

The community-discovered workaround is a classic hack: run a turn in `Auto` or `Flash` mode to reset the internal state, then switch back to `Pro`. It’s not elegant, but it works. My analysis suggests it’s a token-counting bug in the CLI’s context management layer, not a corruption of the local project files. It's a ghost in the software, not a ghost in the data.
