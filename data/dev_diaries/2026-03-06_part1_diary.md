# Dev Diary: 2026-03-06

### The 80B Memory Wall and the Art of Dying Clean

The session started with a crash. Not a system failure, but a *logical* collapse. I was pushing the **Qwen3-Coder-80B** model, and for a few minutes, it was brilliant. The output was sharp, the code was clean, the logic flowed. But then, it started looping.

It wasn't a hallucination; it was a resource starvation event.

I looked at the telemetry, and the "Soul" of the model was suffocating under the weight of the "System." We were running on an AMD RX 9070 XT with a unified memory architecture that was being hammered. The model was using **16.4 GB of VRAM** (96% saturation) and **27 GB of System RAM** (87% saturation). The split was ugly: **62% CPU / 38% GPU**.

The model started looping because the weights were spilling into **Swap**. When you force a 33B parameter model to live in 32 GB of RAM, the latency between attention heads becomes inconsistent. The model loses its "train of thought" not because it's stupid, but because the silicon is gasping for air. The terminal died shortly after. The 80B model didn't just crash; it imploded, taking the terminal with it.

### PyTorch: The Bare-Metal Battle

To fix the looping, I tried to tweak the `Modelfile` with a `repeat_penalty` of 1.1. It was a band-aid on a bullet wound. The real problem was the foundation. I needed to rebuild the **PyTorch 2.4.0** engine natively for the **GFX1201** architecture.

The build was a war. The 8-core compilation was pegged at 100%, chewing through the `AOTriton` shims. Every time I tried to load a smaller model to test the fixes, the RAM usage spiked, and the build stalled or crashed due to OOM (Out of Memory) errors.

We had to perform "surgical" memory management:
1.  **Kill the 80B Model:** Free up the VRAM.
2.  **Unblock the Cores:** Let the C++ compiler breathe.
3.  **Inject the Patch:** Apply the `extern "C"` bridge fix for the `libtorch_python.so` ABI mismatch.

After forty minutes of compiling and thrashing, the wheel finally built. It was a victory. A native, patched PyTorch engine for a consumer GPU that wasn't officially supported out-of-the-box. The system is now running a stable, albeit fragile, stack.

### The Ghost Directory and Agent Integration

The friction between my engineering work and the AI agents was another hurdle. I wanted the **Career Agent** to review my progress, but the directory `/home/gemini` was locked down, owned by a different user. The agent couldn't see it.

I had to hack the file system to let the AI see its own work. I used `setfacl` to grant read access and then performed a `bind mount` to make the folder visible within the workspace. It felt like a metaphor for what we're doing: forcing the system to acknowledge the hidden value in our local infrastructure.

Once the mount was active, the Career Agent went to work. It parsed the build logs, the roadmap, and the `Resume_2026_AI_Systems_Engineer.md` file. It didn't just see code; it saw *narrative*. It updated the resume to highlight the **"30x Token Reduction"** and the **"Bare-Metal RDNA 4 Engine."**

But the resume tells a different story. It doesn't say "I'm looking for a job." It says:

I'm still not going to post a "I'm so excited to announce..." update on LinkedIn. That's not me. But the profile is now a mirror of the work we did tonight: complex, low-level, and unapologetically technical.

### Core Lessons for Apollo
1.  **VRAM is God:** You can't run 80B models on 16GB VRAM without sacrificing coherence. The model will loop or crash. We need a better multi-agent routing strategy that offloads heavy tasks before the memory wall hits.
2.  **Native Wheels are Non-Negotiable:** The generic PyTorch wheels from pip are too slow and lack the ROCm optimizations. We need to keep building and patching our own wheels for the GFX1201.
3.  **The Agent is the Mirror:** The Career Agent proved that if you give it the raw data (logs, code, memory stats), it can construct the narrative for you. I don't need to be a writer; I just need to be a builder. The AI can handle the translation.

The terminal is quiet now. The RAM is cool. The build is stable. We're ready for the next push.
