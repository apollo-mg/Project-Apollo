# Dev Diary: The RDNA 4 Memory War
**Date:** 2025-11-29
**Session:** Part 55 / 74
**Hardware:** AMD RX 9070 XT (Bare Metal)
**Status:** Critical Stability Phase

### The Ghost in the Silicon: The "Illegal Memory Access" Loop

I am currently locked in a battle with the ROCm 7.1.1 driver. It’s not just a bug; it’s a ghost. Every time I attempt to load a LoRA adapter onto a GGUF-quantized model, the system screams `HIP error: an illegal memory access`. 

It is maddening. I’ve implemented contiguous tensor checks. I’ve implemented synchronous copies. I’ve even tried disabling SDMA. The error persists, or worse, it migrates—it stays silent during one operation only to explode during the next, revealing that the corruption happened much earlier.

The "Soul" of the project—the creative potential of the GGUF/LoRA pipeline—is being strangled by the "System." The hardware is capable, but the driver is behaving like it’s hallucinating the memory map.

### The Investigation: Tracing the Corruption

I spent hours digging through `comfy_new_v23.log` and the `ops.py` traces. The error is surfacing in `calculate_weight` during the LoRA application, but the actual crime is likely being committed earlier, during the GGUF dequantization.

**The Hypothesis:** 
The dequantization kernels (`dequantize_blocks_Q4_K`) are performing out-of-bounds writes or handling block scales incorrectly due to dimension mismatches during broadcasting. If the scale tensor `d` isn't reshaped correctly after a `clone()`, the resulting memory layout is a disaster. The GPU isn't just reading wrong data; it's writing into memory it doesn't own, corrupting the heap.

I suspect the `reshape` operation in `dequantize_blocks_Q4_K` is creating a non-contiguous view that the RDNA 4 architecture simply cannot handle during the subsequent bitwise operations.

### The "Safe Mode" Strategy: Fighting Fire with Friction

To survive the RDNA 4 architecture, I’ve had to implement a brutal "Safe Mode." We are essentially baby-sitting the memory controller by adding friction to every operation:

1.  **Kill the Accelerators:** I've disabled `HSA_ENABLE_SDMA=0`. The SDMA engine on these chips is too aggressive with large Host-to-Device transfers. By forcing the compute engine to handle the copy, we trade speed for sanity.
2.  **Enforce Contiguity:** This is the core of my current architectural struggle. The driver crashes when it encounters strided tensors. I am now forced to append `.clone().contiguous()` to almost every critical path—the VAE, the GELU activation, and the dequantization outputs. It’s a massive VRAM tax, but it’s the only way to prevent the TDR (Timeout Detection and Recovery) resets.
3.  **Decompose the Operations:** I've moved from "Cast-and-Copy" to "Cast-then-Copy." Instead of `tensor.to(device, dtype=float32)`, I am doing `tensor.to(dtype=float32).contiguous().to(device)`. It’s slower, but it prevents the driver from attempting a complex, multi-stage kernel that it can't actually execute.

### The Breakthrough: CPU-Side Fallback

I hit a moment of profound realization: if the GPU is in a corrupted state, the "Illegal Memory Access" isn't a logic error; it's a hardware-state error. 

I implemented a test: **Move the LoRA calculation to the CPU.** 

By performing the matrix multiplication ($BA$) on the CPU and only moving the final delta back to the GPU, I bypassed the problematic GPU-side transfer entirely. **The error vanished.** This confirms my suspicion: the ROCm kernel for dequantization is fundamentally broken for this specific combination of quantization and LoRA.

### Lessons for the Local-First Ecosystem

This session has taught me that building a local-first, multi-agent ecosystem on consumer-grade AMD hardware requires more than just "good code." It requires **Hardware-Aware Architecture.** 

We cannot assume the driver is a perfect abstraction of the silicon. We have to write code that respects the specific quirks of RDNA 4—its sensitivity to memory strides and its buggy SDMA implementation. 

**The Path Forward:**
The "Soul" (the model) is ready, but the "System" (the driver) is unstable. My task is to build the "Buffer"—a layer of strict memory management and forced contiguity that shields the model from the driver's instability. It’s a performance hit, but in the world of local-first AI, a slow, stable model is infinitely more valuable than a fast, crashing one.
