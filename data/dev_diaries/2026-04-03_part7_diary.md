# Apollo Dev Diary: 2026-04-03 (Part 7)

The friction between the "Soul" and the "System" is becoming a tangible, measurable reality. I spent the evening staring at the DRADIS Console UI—this beautiful, amber-phosphor radar sweep that Gemini and I have been sculpting. It’s exactly the tactical, "Glass Cockpit" aesthetic I wanted. Seeing the system stats overlaid dynamically via JSON payloads instead of hardcoded PyQt6 elements was a massive moment of validation. The architecture isn't just a UI; it's a living canvas that the AI paints on. It turns my secondary monitor into a true, interactive HUD. 

But as much as the UI feels like a victory for the "Soul" of the project, the silicon is starting to push back.

## The VRAM Wall: vLLM vs. llama.cpp

We spent some time debating the core engine. There's this constant temptation to chase the SOTA features of vLLM—the PagedAttention, the massive throughput, the enterprise-grade bells and whistles. But vLLM is built for the datacenter. It's designed for 8x H100 clusters where you don't care about the overhead of a desktop OS. It's a resource hog that wants to grab 90% of your VRAM the second it boots.

For Project Apollo, we are fighting for density. We need to squeeze intelligence into a consumer-grade RX 9070 XT. `llama.cpp` is our lifeline here. The quantization capabilities—getting a 26B MoE model down to 2.06 bpw—are the only reason we can even attempt this. We are essentially performing high-level alchemy, turning massive parameter counts into something that fits into 12.5GB of VRAM. vLLM is built for scale; `llama.cpp` is built for survival.

## The Prefill Paradox

Then, the crash happened.

Chunk 18. A `Read timeout` error. 

The server was still alive, the GPU was still churning (as seen in `radeontop`), but the `llm_interface.py` was too impatient. We hit a wall where the sheer volume of the context window—now exceeding 43,000 tokens—became a computational bottleneck. 

It’s a fascinating, grueling reality: the RDNA 4 architecture is performing an astronomical amount of math during the "prompt prefill" phase. The GPU is doing the heavy lifting to calculate the attention weights for those 40k+ tokens of chat logs, but the software was hardcoded to give up after 120 seconds. The "System" was waiting for the "Soul" to finish its thought, but the timer ran out before the math was done.

I had to go into the guts of the interface and jack the timeouts up from 120 seconds to 600. We need to give the 9070 XT enough runway to chew through the prefill. 

## Current Status

The ingestion script is back online, re-building from Chunk 18. It's a slow, heavy grind. We are pushing toward the final synthesis, but we are learning that "Local-First" means you can't just rely on fast-and-loose API calls. You have to respect the physics of the context window and the temporal reality of the hardware.

The vision is still intact, but the margins are getting thinner.
