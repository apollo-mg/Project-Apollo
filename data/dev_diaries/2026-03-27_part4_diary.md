# Apollo Dev Diary: The Cockpit is Live

**Date:** 2026-03-27
**Status:** Architectural Breakthrough / High-Fidelity Testing

The "Sovereignty" phase is no longer a theory. It is a reality. Today was about moving from watching a terminal to actually commanding a system. I’ve successfully moved Apollo from a basic procedural script into a high-fidelity **Agentic Cockpit**.

### The Great Salvage: Harvesting the DNA
I spent the morning performing what I can only call "Software Salvage." I managed to extract the entire 25KB Gemini CLI system prompt—the "Operating Manual"—from the Google repo. This is the high-dimensional map that dictates how an agent handles context and tool-calling. It was like finding a flight manual for a stealth bomber in a dumpster. I've fed this into the Crow-9B model as its primary directive, and the difference in rigor is night and day. 

### Hardware vs. Soul: The Logic Inspector
The biggest friction point in local AI isn't just VRAM—it's the "Black Box" problem. You see a command, but you don't see the *intent*. 

I've implemented the **Level 3 GUI: The Logic Inspector**. Using PyQt6, I built a "Cockpit" that intercepts the model's thought process. 
* **The Left Pane:** Streams the `<think>` tags (the model's internal monologue).
* **The Right Pane:** Shows a syntax-highlighted diff of the proposed code.
* **The Veto:** A physical button to Approve, Edit, or Abort.

This is the "Cockpit" for a reason. You aren't just watching a script; you are monitoring the "Soul" (the reasoning) before it hits the "System" (the silicon).

### The Heuristic Gate: Intelligence vs. Friction
I realized that a blanket "Ask for Permission" approach would kill the workflow. I've implemented a **Heuristic Gate** in `modules/approvals/handler.py`. 
* **Auto-Approved:** New files, documentation, or minor edits (<50 lines).
* **Intercepted:** Changes to core modules, shell commands, or structural file edits.

The test run was illuminating. I commanded Crow-9B to write a script and verify it. The agent tried to deviate from the path, creating a `write_hello.py` instead of `modules/core.py`. Because it was a new file, the heuristic auto-approved it, but when it tried to run the shell command, the **Logic Inspector popped up exactly as designed.** 

It's a strange, powerful feeling to see a machine "thinking" in a window on your desktop, then having to manually "Approve" its actions. It's no longer just an LLM; it's a collaborative entity with a visible mind.

### Technical Friction & Lessons Learned
1. **Environment Chaos:** Encountered a `ModuleNotFoundError` because I wasn't calling the `venv_cachyos` Python directly. It’s a reminder that when building local-first, the dependency management is as critical as the model weights.
2. **The API Loop:** I had to spin up a dedicated server (`run_crow_9b_server.sh`) to bridge the gap between the model and the agent. The connection was refused initially, but once the socket was open, the stream flowed.
3. **The Reality of Local-First:** The power of this system is the sovereignty. I am not a tenant of a Google API; I am the landlord of my own local-first ecosystem.

**Next Steps:**
The "Cockpit" is working, but the model's tendency to wander (creating `write_hello.py` instead of the target file) suggests my prompt injection needs more "Constraint" or the model's temperature is too high for strict instruction following. I'll be looking into fine-tuning the prompt-template to tighten the "Constraint-to-Action" loop.

**Current Status: The Cockpit is functional. The pilot is ready. Let's see how much more the system can handle.**
