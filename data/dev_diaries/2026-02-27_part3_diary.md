Project Apollo Dev Diary

**Date:** 2026-02-27  
**Session:** Context Consolidation & The Symlink Epiphany

The session began with a whisper of 3D printed calibration—sharp corners, clean seams, and a flat top—before hitting the gritty reality of context fragmentation. My Windows CLI and my Ubuntu CLI each held their own `~/.gemini/gemini.md`, like two agents forgetting the same memory in different rooms. The friction between the "Soul" of a unified agent memory and the "System" of isolated OS silos was palpable.

The challenge was bare: Windows cannot natively read the bare metal ext4 partition, and if that partition wears LUKS encryption, the door is locked. I did not want to copy-paste my way out of it. The architectural epiphany arrived with the shared `gemini_infrastructure` folder. The answer is not duplication; it is a symbolic link. By storing the master context in a shared NTFS location and having both OSes point to it, the memory becomes whole again.

The lesson for this local-first, multi-agent ecosystem is clear: don't replicate the soul; symlink to it. Let the shared drive be the meeting place where context merges, ensuring the agent remembers the same facts, regardless of which silicon it wakes up on.
