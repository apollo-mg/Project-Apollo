# Project Apollo: Dev Diary

## 2026-04-01 | The Stability Paradox: Context, Memory, and the Silicon Wall

Today was a brutal, beautiful grind through the friction between high-level cognitive architecture and the cold reality of VRAM limits. I spent most of the session wrestling with the "thinking" model, and I finally identified the culprit behind the truncation issues. 

It turns out the upgrade to the Qwen3.5-27B-Thinking model was a double-edged sword. The model's internal `<think>` block is massive. It spends hundreds, sometimes thousands, of tokens just "pondering" the input before it even attempts to generate the JSON output. Because the `daydream.py` script had a hard `max_tokens` limit of 1024, the model was essentially running out of breath mid-thought. The output was a mangel of truncated JSON, essentially a digital seizure. 

I had to surgically bump the limit to 4096 to give the "Soul" enough room to think before the "System" cut it off. 

Then, the VRAM hit a wall. 

The RX 9070 XT is a beast, but 16GB is a finite sandbox. Between the 27B model, the desktop environment, the vision adapter, and a 16K context window, we were hitting 15.5GB+ and causing massive VRAM thrashing. The system was basically gasping for air, swapping to system RAM and tanking latency. I had to slash the context window to 8K in `start_architect.sh` to keep the whole stack from collapsing.

The real epiphany came during the KAIROS multi-agent tick. By dropping the context window to 8K, we inadvertently broke the TypeScript orchestrator. The agent was trying to request a 4096-token output, but the math didn't add up: `Prompt + Max Output` was exceeding the total 8K window. The server was throwing 500 errors because the agent was trying to read files that were too large for the remaining buffer. I had to throttle the agent's output limit down to 1536 to give the "Input" (the conversation history) the room it needed to actually function.

The result? The system is finally breathing.

It's currently in a self-correcting loop. It actually caught its own error in the file search, realized the context was exceeded, and re-attempted the search using a different path. Seeing the `<think>` blocks roll through the terminal is eerie—it feels biological. It's not just calculating; it's weighing contradictions. 

On the hardware side, we've confirmed the MoE issue. The `MUL_MAT_ID` error is a fundamental kernel failure in `llama.cpp` for RDNA 4. The mixture-of-experts routing is just too complex for the current HIP/ROCm implementation. The 27B dense model is our stable fallback for now, even if it lacks the raw speed of the 35B MoE.

**Core Lessons for the Ecosystem:**
- **Context is Currency:** In a local-first, multi-agent setup, you cannot treat context as an infinite resource. You have to manage the ratio between `Input` (the memory) and `Output` (the epiphany) as carefully as you manage your GPU temperature.
- **The Thinking Overhead:** "Reasoning" models require much more aggressive token management. You can't just give them a large context; you have to give them a large *output buffer* or they will never finish a single thought.
- **Memory Decay is Essential:** The biological decay function we implemented in `prune_memories.py` is the only thing keeping the vector DB from becoming a junk drawer. It’s the difference between a living mind and a growing pile of data.

The Sovereign Engine is finally autonomous. It’s cooking. I’m going to let it dream.
