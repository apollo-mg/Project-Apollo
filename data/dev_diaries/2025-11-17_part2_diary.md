# Dev Diary: When Silicon Says No
## The ZLUDA Graveyard and ROCm Redemption

**November 17, 2025 | 00:24–01:14 UTC**

---

### The Phantom CUDA

It started with a lie.

`torch.cuda.is_available()` returned `False`. Not with a whisper. Not with a warning. It returned `False` with the absolute certainty of a judge who's already read your file.

The problem: We're running on an AMD RX 9070 XT. We want GPU acceleration. We chose ZLUDA—the open-source compatibility layer that promises to let CUDA code run on AMD hardware. It works flawlessly in ComfyUI. It works in a dozen other scenarios. 

But not in our whisper transcription pipeline.

I watched the logs scroll by, each attempt more desperate than the last:

```
PATH: F:\AI\ComfyUI\ComfyUI-Zluda\zluda;C:\Program Files\AMD\ROCm\6.4.2\bin;...
RuntimeError: Attempting to deserialize object on a CUDA device but 
torch.cuda.is_available() is False.
```

The PATH was correct. The DLLs were present. ROCm was installed. PyTorch was screaming that CUDA didn't exist, even as it loaded CUDA-compiled weights.

### The Philosophy of Workarounds

Here's what I've learned about building on bare metal: **The ecosystem you inherit is not a suggestion.**

ZLUDA is clever engineering. It's also a workaround layered atop another workaround. We were trying to run CUDA binaries on AMD silicon using a compatibility shim that itself depends on ROCm dependencies. The stack looked like this:

```
Whisper (CUDA-compiled)
    ↓
PyTorch (CUDA build)
    ↓
ZLUDA (CUDA → HIP translation)
    ↓
ROCm HIP SDK
    ↓
AMD Hardware
```

Four layers of indirection. Four opportunities for something to fail silently.

The Soul of this project demands local execution. It demands privacy. It demands that intelligence run on *your* hardware, not some corporate datacenter. But the System—the actual silicon, the actual drivers, the actual dependencies—doesn't care about our philosophy.

### The Pivot

At 00:27:36, I made the decision: abandon ZLUDA. Go native.

The ROCm-enabled PyTorch build isn't pretty to install on Windows. It requires:
- Python 3.12 specifically (not 3.11, not 3.13—3.12)
- Manual wheel file installation from Radeon's repo
- Driver version 25.20.01.14 or newer

And it's still technically in preview.

But here's the thing about native solutions: they have fewer moving parts.

```
Whisper (CUDA-compiled, running on ROCm)
    ↓
PyTorch (ROCm build)
    ↓
AMD Hardware
```

Three layers. One of them is still doing translation, but at least it's happening at the framework level where it's documented and supported.

### The Architecture Lesson

The friction between Soul and System taught us something:

**Local-first doesn't mean framework-agnostic.**

We'd been treating the GPU stack as an implementation detail. "We'll just use PyTorch's CUDA interface," we said. "It'll work." But the interface *is* the implementation when you're dealing with hardware acceleration.

The new architecture for the Sovereign Engine needs to bake in hardware awareness earlier:

1. **Detection layer** that identifies not just "GPU available" but "which GPU, which drivers, which compatibility mode"
2. **Strategy selection** that chooses the execution path (native ROCm, ZLUDA, CPU fallback) based on actual capabilities, not assumptions
3. **Graceful degradation** that accepts some operations will be slower on some hardware without breaking the abstraction

### The Grind

By 01:14, we'd recreated the entire test directory structure with new versioning:

- `run_whisper_rocm.bat` (activates `.venv_rocm`, launches AHK)
- `hold-to-talk-v4.ahk` (hotkey capture, no `-NoExit` clutter)
- `transcribe-v4.ps1` (points to `cuda:0`, cleans up audio files)

And we hit another wall:

```
Activating virtual environment...
The system cannot find the path specified.
```

The batch script couldn't find the Python environment it was supposed to activate. Classic Windows path resolution hell.

### Where This Leaves Us

The lesson isn't "use ROCm instead of ZLUDA." The lesson is **trust but verify at the metal level**.

Every agent in the Sovereign Engine ecosystem needs to:
- Report its actual execution environment (not assumed, not desired—*actual*)
- Accept that operations have different costs depending on that environment
- Fail fast when the abstraction breaks, with diagnostic information that's useful

The Soul wants magical local intelligence. The System provides 12GB of VRAM, some HIP binaries, and a driver stack that's three patches away from stable.

We build in the space between.
