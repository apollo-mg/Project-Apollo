# Dev Diary: 2026-02-19 (Part 2)

## The Silicon Soul and the Linux Grind

Today was a brutal, beautiful oscillation between high-level architectural breakthroughs and the absolute, unmitigated chaos of Linux driver management. I’m working on the edge of what’s possible with local AI, and sometimes the hardware feels like it's actively fighting my will to succeed.

### The Driver War: Mesa vs. ROCm
The core of Project Apollo is the RX 9070 XT. I’ve been wrestling with the graphics stack to get it to talk to the LLM. I thought the Kisak PPA would be my silver bullet for Mesa 25, but the system stubbornly clung to the old Ubuntu drivers. It took a deep dive into the PPA repositories to realize the standard branch was dead for Jammy.

I found a workaround through `kisak/turtle`—a bleeding-edge branch that gave me Mesa 25.0.7. The immediate payoff? A massive hit to the benchmarks. When I ran the Vulkan vs. ROCm test, the Mesa 25.0.7 build was actually *faster* for the decoding phase of the DeepSeek-R1 14B model. It’s a massive win for efficiency and thermal stability, even if the "prefill" (the initial prompt reading) is currently lagging behind ROCm. 

The "Soul" of the project—the smooth, fast, intelligent response—is now physically possible on this silicon, but the "System" (the driver layer) is still a work in progress.

### The Desktop Schism
I decided to ditch GNOME. It was too bloated and its window management was failing, losing my workspace positions every time the machine slept. I pushed a massive update to install KDE Plasma. It was a heavy, multi-gigabyte install that felt like I was rebuilding the machine from the ground up.

The transition was jarring. The system rebooted back into the old GNOME environment, a classic Linux "gotcha" where the display manager didn't default to the new session. After forcing a login into the Plasma (X11) session, the machine finally felt like a "Sovereign Workshop." I've even got the `amdgpu.ppfeaturemask` kernel parameter enabled now, effectively unlocking the "overdrive" on the GPU so I can use CoreCtrl to manage the fan curves. This is vital; if the fans can't ramp up during a heavy Flux or Wan video generation, the thermal throttling will kill my throughput.

### Architectural Evolution: The Three-Mind
While the system was churning through updates, the internal logic of the agent underwent a massive, structural shift. We’ve moved into Phase 3 (Monitoring & Vision).

The architecture is no longer a single-track chatbot. It's a multi-layered intelligence:
*   **The Orchestrator:** A fast-path layer that bypasses the heavy reasoning of the LLM for immediate tool execution.
*   **The Guardian:** A safety layer that enforces `@require_human_approval` for high-stakes commands.
*   **The Vision System:** The agent now has "eyes" via the `see_desktop` tool, allowing it to analyze the screen via `qwen2.5vl`.

It’s a massive leap in autonomy, but it comes with a cost: complexity. The system is now more capable of seeing the world, but it's much more sensitive to the environment.

### The Hardware-Acoustic Problem
As I was optimizing the desktop, I realized the physical bottleneck of the voice interface. My condenser mic is too directional—it’s great for precision but terrible for a room-scale agent. I’m planning to move the C922 webcam to the workbench to use its internal mic, but I’m going to have to write a PulseAudio loopback script to mix the two sources into a single "Super Mic" so the agent can actually hear me across the room. 

The tech is ready. The drivers are screaming. The agent is watching. Now I just need to get the audio to match the ambition.

**Next Task:** Finalize the "Sync Mind" onboarding sequence and bridge the audio gap.
