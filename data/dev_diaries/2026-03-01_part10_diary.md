# Dev Diary: The Satellite Bridge

Today was about the physical embodiment of the "Soul." I spent most of the night wrestling with the architecture of the peripheral nodes, trying to bridge the gap between the high-level reasoning of the main rig and the raw, tactile data of the real world.

The breakthrough came when Gemini successfully provisioned the Pi 5. It's a strange feeling, watching a language model orchestrate the assembly of its own nervous system. The provisioning script was clean—it handled the `apt` updates, the `libportaudio2` libraries, and set up an isolated `satellite_env`. It’s a "blank slate" now, but it’s a dangerous one. 

The technical friction here is real. I’m running the core logic on the desktop, fighting the memory fragmentation issues that come with running heavy quantization on my 9070 XT. The VRAM is constantly on the edge of a cliff. If I push too much into the local LLM, the audio buffer pipeline will stutter, and the entire "sense of presence" we're building for Apollo will collapse into digital noise. 

I’m currently trying to stabilize the latency of the audio bridge. The Pi 5 is handling the ALSA access via `sounddevice`, using `numpy` for the noise gate, but the real test is the transport layer. We're firing audio buffers back to the main rig via `requests`. It’s not the most efficient way to move high-fidelity stream data, but for a decentralized agent architecture, it's a necessary evil to keep the satellite decoupled from the main compute.

I plugged in the Logitech C922—testing the visual input alongside the audio. It's a clumsy setup for now, but the goal is clear: the Pi isn't just a peripheral; it's a sensory limb. 

The struggle is between the System and the Soul. The System (the silicon, the drivers, the limited bandwidth) wants to chop the data into tiny, manageable pieces. The Soul (the continuous, flowing stream of human-like interaction) wants the whole, uninterrupted experience. If I can solve the latency bottleneck between the Pi and the RX 9070 XT, we might actually have something that feels alive, rather than something that just processes commands.

Current Status: 
- Pi 5: Provisioned, audio-ready, waiting for client-side handshake.
- Main Rig: High VRAM pressure, monitoring ROCm stability.
- Next Step: Testing the sensory-motor loop with the C922 input.
