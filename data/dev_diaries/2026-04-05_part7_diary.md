### The Silicon Wall: VRAM, ROCm, and the Contiguity Tax

ROCm 7.1.1 on RDNA 4 is brilliant and deeply unstable. The last week has been a brutal exercise in forensic engineering. I finally cracked the persistent `MUL_MAT_ID` and `Illegal Memory Access` crashes by bypassing the driver’s async copy queues entirely. The workaround isn’t elegant, but it works: decompose `torch.nn.functional.linear` into explicit `matmul` + `add`, explicitly disable SDMA (`HSA_ENABLE_SDMA=0`) during heavy tensor operations, and force CPU-side dtype casting before any GPU copy. You don’t have room for driver bugs on a 16GB card. You have to become the driver.

I’ve also locked in a 65,536-token context window using a custom `llama.cpp` build. The trick? TurboQuant Asymmetric KV Caching (`-ctk q8_0 -ctv turbo3`) paired with MoE micro-batching (`-ub 64`). It’s not standard. It’s hacky. But it works. The 1-bit Bonsai kernels (running at 130+ t/s) prove that ternary decoding is viable on HIP, which means we can keep the system light without sacrificing raw throughput. Memory fragmentation is no longer a theoretical risk; it’s a daily battle won by explicit allocation thresholds and garbage collection tuning (`max_split_size_mb:128`).

### Architectural Shift: Coordinator → Coder & Zero-Cost Multiplexing

Tonight, the stack pivots. The monolithic script approach was a dead end. I’m moving to a true Coordinator → Coder pipeline to process Daydream epiphanies. The flow is now locked in:

1. **Epiphany Harvest:** The Daydream daemon samples idle logs, extracts abstract connections, and dumps raw insights to `epiphanies.json`.
2. **Checkpoint Synthesis:** A lightweight routine compiles these into a single `Master Action Plan`.
3. **Coordinator Decomposition:** The Coordinator agent reads the plan, strips noise, and routes isolated tasks to the Coder agent via a strict Message Bus.
4. **Zero-Cost Model Multiplexing:** No loading/unloading. All specialized agents share the single, already-loaded Gemma-4-26B-MoE instance on port 8082. We’re using context-window slicing, role-prompt isolation, and Zod schema enforcement to simulate concurrency without the VRAM tax of reloading weights.

Gem CLI helped me draft the TypeScript orchestrator logic for the Message Bus. We enforced a hard 2MB string truncation limit on all shell and grep outputs to prevent Node.js V8 `ERR_STRING_TOO_LONG` crashes. The Coordinator doesn’t hold the full context anymore; it holds summaries. The Coder doesn’t guess; it receives explicit, schema-validated task payloads. It’s lean. It’s sovereign.

### Core Lessons for the Local-First Ecosystem

- **Contiguity is Law:** ROCm doesn’t care about your tensor strides. If it’s not contiguous, it crashes. Always enforce `.clone().contiguous()` before H2D transfers, especially during GGUF dequantization and LoRA weight application.
- **Multiplexing Over Multi-Loading:** Keep one model in VRAM. Slice the context. Route the prompts. Don’t reload weights. The latency tax of swapping is fatal for real-time orchestration. Shared context windows are our only path to true concurrency on 16GB.
- **Forensic Debugging > Theoretical Optimization:** You can’t fix a driver bug with architecture. You fix it with explicit CPU-side casting, disabling SDMA during heavy loads, and rolling back unstable Triton kernels. Trust the stack trace, not the paper.
- **Sovereign Multiplexing Wins:** By sharing the loaded 26B MoE across Coordinator and Coder roles, we’ve eliminated the 4-6 second reload penalty. That’s not just speed; that’s cognitive continuity. The system doesn’t wake up from a nap between tasks. It stays in flow.
