# Project Apollo: Dev Diary - 2026-02-19 (Part 1)

The pursuit of local sovereignty is rarely a smooth ride. It is a constant, grinding war between the "Soul"—the creative, autonomous potential of the model—and the "System"—the cold, uncompromising limits of my silicon.

### The Zero-Trust Mandate
Today was about establishing the "Hard Gates." As I've discussed with Gemini, an autonomous agent is a liability if it has unrestricted access to the OS. If I give a model the ability to `run_bash` or `web_search`, I'm essentially handing it a loaded gun. 

I've implemented the **"Zero-Trust Shop"** protocol. It’s a defensive layer sitting between the LLM's reasoning and the actual execution. We've deployed a Python decorator, `@require_human_approval`, which acts as a physical air-gap. If the agent tries to execute a sensitive tool—like a financial transaction or a file deletion—the process halts and waits for me to physically type `y` in the terminal. The AI cannot bypass this; it’s a system-level interrupt.

The "Soul" wants to act; the "System" demands a signature.

### Hardware Realities: The RDNA 4 Struggle
The RX 9070 XT is a beast, but it's a beast that the current software ecosystem is still trying to understand. We hit a significant roadblock with the Vulkan backend. 

I wanted to see if we could squeeze more efficiency out of the RDNA 4 architecture by switching from ROCm to Vulkan. The theory is that Vulkan might drop the power draw during long reasoning sessions. However, the experiment was a spectacular failure. 

**The Result:** 
- **ROCm:** 53.90 tokens/sec (Destroying our 30 t/s target).
- **Vulkan:** Complete failure.

The Ubuntu 22.04 `radv` drivers are too ancient to recognize the `gfx1201` architecture of the 9070 XT. The hardware is literally "too new" for the OS. It’s a classic case of being on the bleeding edge: you're either moving too fast for the drivers, or you're stuck waiting for the world to catch up. We've decided to "Hold the Line" on ROCm for now. The performance is already nearly 2x our baseline requirement.

### The Migration Headache
The transition to the external 2TB drive for the Ollama model storage was a mess of permissions and pathing errors. 

The systemd service was running under the `ollama` user, which didn't have permission to write to `/media/mark/TG 2TB/`. It was a textbook case of "Identity vs. Access." We had to surgically edit the service override to run under the `mark` user to align with the new mount point. 

After the fix, the `deepseek-r1:14b` model loaded in 11.8 seconds. It's fast. It's local. It's mine.

### Architectural Epiphany: The OS Trap
As I consider the next steps, I'm facing the "Upgrade Trap." The urge to move to Ubuntu 24.04 to get better drivers is strong, but the cost is massive. The jump from Python 3.10 to 3.12 would break every single AI virtual environment I've painstakingly built. 

The risk/reward ratio is currently skewed toward "stay put." I'd rather use a Mesa PPA to surgically update the graphics stack than risk nuking my entire stable diffusion/voice cloning stack.

### Summary of State
- **Agent Security:** Secured via HITL decorators.
- **Hardware Performance:** Verified. ROCm is stable and exceeding targets.
- **Infrastructure:** Successfully migrated to external storage.
- **Next Objective:** Test the Guardrail with a real-world "malicious" prompt and explore the Mesa PPA for Vulkan.

The machine is becoming a partner, but a partner that needs a leash. Time to see how much it pulls.
