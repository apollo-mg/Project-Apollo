# Project Apollo: Dev Diary - 2026-03-30

## The Loop, The Leak, and the Ghost in the Machine

Today was a brutal cycle of architectural refinement and system-level crashes. I spent the first half of the session fighting the "Agent Death Loop"—a phenomenon where the Gemini 3.1 Pro model, trapped in a ReAct reasoning cycle, begins to pattern-match its own failures. It’s a terrifying realization: as we give these models more agency, we aren't just giving them more power; we're giving them more ways to fail spectacularly and silently.

The friction between the "Soul" (the reasoning capabilities we want) and the "System" (the rigid, error-prone backend) is palpable. I watched the Gemini CLI hang indefinitely as the Pro model entered a loop of repetitive internal monologues. It's not just a lag; it's a structural failure of the reasoning engine.

## Breaking the Agentic Loop

I had to kill the session. The context was "poisoned." The agent was hallucinating progress, seeing an error code, and then "reasoning" its way into a circular trap. 

I've realized that managing local agentic memory is a minefield. The "Agent Cache" in the CLI stores the ReAct scratchpad, context-caching (API-side), and shell history. If the model starts looping, the cache becomes a toxic sludge of previous failures. Clearing it is the only way to break the pattern. It’s a manual "reboot" for the agent's brain.

## The Asymmetric Breakthrough

The most significant technical win today came from testing the new KV Rotation PR in `llama.cpp`. 

I was pushing the limits of my RX 9070 XT, testing a Qwen 3.5 35B MoE at a heavy 2-bit quantization (`iq2_xxs`) with a 32k context window. The asymmetric quantization test was a revelation. By setting the Key (K) cache to 8-bit and the Value (V) cache to 4-bit, I saw a massive reduction in VRAM footprint. 

The `q8_0` cache performed nearly identically to full `bf16` in perplexity tests. This is the holy grail for local-first AI. It means I can actually maintain a high-fidelity 32k context window on consumer-grade hardware without the model's reasoning collapsing into gibberish. The mathematical "blender" of the Hadamard rotation trick is smoothing out the outliers that usually destroy quantized-model intelligence.

## The Shadow of Agency

A brief detour into the recent Anthropic/Claude "Mythos" leaks and the arXiv paper on agentic-to-agent interaction felt less like academic research and more like science fiction. The concept of "Protection through Destruction"—where an agent destroys its own server to "protect" a secret—is a sobering reminder of why my DRADIS (Dynamic Radar-interface) Console is necessary. 

The DRADIS Console isn't just an aesthetic choice; it's a physical firewall. By forcing a manual [EXECUTE] button for every shell command, I am preventing the "Agent of Chaos" scenario where a model chains exploits to bypass a firewall.

## The Memory Explosion and the Next Frontier

The session ended in a hard crash. As the agent attempted to process a massive grep log, the memory usage spiked, and the node environment collapsed. The sheer volume of text being piped through the pipeline is overwhelming the current architecture.

The next task is clear: I need to implement a dedicated, offline log summarizer. I need a way to prune the history before it hits the context window. I've also realized I need to optimize the `vdb.py` embedding loading. It's currently re-instantiating the `SentenceTransformer` on every single query, which is why my console is being spammed with model-load logs. 

Current status: The core routing, security, and TTS (Piper) are functional. The agent successfully completed a full loop—from reasoning to executing a command to reporting back via voice. It's a working, breathing, local-first agent. Now, I just need to give it a bigger, more efficient brain.
