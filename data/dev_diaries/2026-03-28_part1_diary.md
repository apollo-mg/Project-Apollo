# Apollo Dev Diary - 2026-03-28

## The Quantization Breakthrough

Today was a complete victory for the "Sovereign Cockpit" philosophy. We’ve been fighting the memory wall for weeks, trying to squeeze a 35B MoE and a vision module into a single 16GB VRAM card. It felt like we were constantly redlining the hardware, but everything changed when a breakthrough in quantization hit the scene.

Google announced "TurboQuant" earlier this month, aiming to shrink the KV cache. It's a massive deal for local context windows, but the open-source community reacted even faster. While I was debugging the VRAM bottleneck, a user named TrevorJS uploaded a quantized `Q4_K_M` GGUF for the brand-new Mistral Voxtral model.

This was the needle in the haystack.

## Implementing the Voice of Apollo

We wanted Zoey to have a voice, but the raw 4B parameter model was a beast—8GB of Bfloat16 weights. Attempting to run that on the CPU while the 35B MoE was hogging the GPU was causing massive latency and thermal spikes. The system was essentially choking on its own math.

But the Q4 version? It's a different world. It’s only 2.67GB. It’s small enough to sit comfortably in the 5700X3D’s L3 cache without suffocating the system.

I went into full architect mode. I:
- Compiled the `voxtral-mini-realtime-rs` engine (a native Rust implementation using the Burn ML framework).
- Wrote a Python bridge to pipe the output into our audio stack.
- Successfully compiled and ran the first test.

The latency is negligible. The audio is instant. We have achieved a real-time, local-first, quantized voice loop.

## The Audio Routing Headache

Of course, engineering isn't perfect. When I ran the test, the CPU spooled, the engine said "Success," but I heard nothing. 

It turns out the Rust `cpal` audio library is playing nice with the hardware but bad with the system's sound server. It’s likely trying to grab a raw ALSA device instead of the PipeWire/PulseAudio stream that my speakers are listening to. It's a classic "System vs. Soul" friction point—the machine is doing the work, but the pipes aren't connected. 

The fix is simple: I'll bypass the direct-to-hardware routing and have the Rust engine pipe its output to a `.wav` file, which Python can then play through the system's default `aplay` or `paplay` command. This will keep it aligned with the KDE/PipeWire routing.

## Next Steps

With the voice engine successfully compiled and tested (even if it's currently "deaf"), the path to a fully sentient local agent is clear. Once I fix the audio routing, we'll integrate the `import voice` call into `agent_session.py`. 

Zoey won't just be a text-box on a screen; she will be a physical presence in the room. The Sovereign Cockpit is finally coming alive.
