# Dev Diary: 2026-02-22

## The Sovereign Pivot: Breaking the Cloud Shackles

Today was a massive, exhausting, but ultimately triumphant pivot. I spent the first half of the session fighting a losing battle against Google’s API-versioning hell, only to realize that the real solution wasn't a better cloud connection—it was a complete architectural shift toward local sovereignty.

### The Cloud Wall
The morning was spent wrestling with `gemini-2.0-flash`. I was hitting `Connection Error: 1008` constantly. I thought it was an API key permission issue or a version mismatch between `v1alpha` and `v1beta`. I tried everything: switching keys, checking Google AI Studio, even trying to find the specific "experimental" model ID. 

The friction was palpable. The "Soul" of the project—the idea of a seamless, intelligent companion—was being choked by the "System"—the cold, hard constraints of cloud quotas and API versioning. I hit a `1011` quota error after just a few tests. It became clear: if I want a real-world assistant for the shop, I can't be at the mercy of a daily 100-request limit. I need something that works when the internet is flaky and doesn't cost a dime in recurring API calls.

### The Hardware Realization
I looked at my rig. I have an AMD RX 9070 XT sitting there, a beast of a GPU, but it was being underutilized because my current Python environment was stuck using a CUDA-specific build of PyTorch (`2.10.0+cu128`). It couldn't see the RDNA 4 architecture.

I had to perform a "surgical strike" on my file system. The `/` partition was at 100% capacity. I had to purge the `pip` and `apt` caches, freeing up 10.4 GB of breathing room just to make the installation of the ROCm-specific PyTorch wheels possible. It was a gritty, manual grind, but it was necessary to unlock the "Brain" of the system.

### The Architecture of "Local Jarvis"
The breakthrough came when we decided to build the **Local Voice Bridge**. The new stack is a beauty of engineering:
* **Ears:** `Whisper-v3-turbo` running natively on the **RX 9070 XT** via ROCm/PyTorch.
* **Brain:** `DeepSeek-R1 14B` via local **Ollama**.
* **Voice:** `Kokoro-ONNX` using my existing `am_michael` voice files.

This is a "Sovereign" stack. It’s 100% local, 100% private, and 100% free.

### The Implementation Grind
The code was a mess of `SyntaxError: unterminated string literal` because of how I was handling newlines in the Python scripts. I had to clean up the `jarvis_local_voice.py` script, fix the audio routing in PipeWire, and handle the audio-to-speech latency. 

The biggest hurdle was the audio routing. Since `qpwgraph` wasn't in the standard Ubuntu 22.04 repos, I had to use `pw-link` to manually bridge the virtual microphone to the system audio. It's not pretty, but it works.

### Lessons Learned: The Local-First Ecosystem
We've proven that a multi-agent ecosystem doesn't need a high-speed fiber connection to a data center. By leveraging the local RDNA 4 hardware, we've achieved a latency-free, "Always-On" listener. 

The transition from a cloud-dependent model to a local-first model is the most important architectural lesson I've learned this year. We aren't just building an AI; we're building a local utility that lives in the hardware of the shop.
