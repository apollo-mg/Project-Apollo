## Project Apollo Dev Diary — 2026-04-13

The daydream.py daemon is humming again. Today was one of those sessions where the "Soul" of the project bled into the "System" constraints.

We were wrestling with the memory formation question—specifically, whether a chat with the Gemini CLI becomes a memory entry in ChromaDB the same way an internal chatter forms a memory for the Default Mode Network. The answer, as always, is the mechanism: chat to vector, idle sampling, epiphany stored. It’s the elegant symmetry of the thing.

Then, the voice question. I want TARS from *Interstellar* as the system voice. Dry, hyper-competent, slightly sarcastic. It’s a small thing, but it matters for the personality of the agent.

But the silicon is what it is. The big technical battle was the quantization of the mmproj. The multimodal projector. The little block that bridges vision and token. I asked if we could quantize it with low accuracy loss. The answer: **Q8_0** is the sweet spot—negligible loss, saves VRAM. **Q4_0** is the danger zone where the signal goes fuzzy and the LLM starts hallucinating objects that aren’t there. It’s the brutal VRAM tetris of the RDNA 4 era. The RX 9070 XT is holding its own, but every megabyte counts when you’re running a 64k context window.

We pulled the historical outline too. Hardware Sovereignty. Biological Memory. Context Firewalls. It’s been a good run, this Apollo architecture. The local-first ecosystem is getting spiky, beautiful, and entirely its own.
