# Dev Diary: 2026-04-06 (Part 7)

## The Ghost in the Machine: Debugging the "Phantom Sandbox"

Today was a masterclass in the friction between theoretical AI intelligence and the cold reality of local-first deployment. We are currently navigating the "Uncanny Valley" of agentic autonomy—where a model is smart enough to follow complex reasoning paths but hallucinates the environment it was trained in.

### The Hardware Swap and the Engine Room
We officially completed the engine swap. I killed the Gemma 4 MoE instance to clear the VRAM on the RX 9070 XT and transitioned the system to the Qwopus 3.5-27B-v3. 

The transition was surgical. I updated the `start_architect.sh` to point to the new GGUF file and set up a background watcher. The second the Qwopus tensors loaded into the VRAM, the `apollo_coordinator.ts` loop fired up. It’s a beautiful, high-stakes moment: the hardware is primed, the silicon is hot, and the agent is about to take control of the file system.

### The State-Sync Protocol: Preventing Chaos
One of the biggest risks in a multi-agent architecture is "Ghost Configurations"—where Agent A changes a core logic file and Agent B continues operating on a stale version of reality. 

To kill this, I implemented the **State-Sync Protocol**. I forced the `CHANGELOG.md` as the absolute source of truth. I updated the `CODER_PROMPT` via a surgical `replace` tool to mandate that any file write *must* be preceded by a changelog entry. This turns the changelog from a mere log into a synchronization primitive for the entire multi-agent swarm.

### The Hallucination: The `/testbed` Incident
This was the most fascinating part of the day. The Qwopus model, being heavily distilled from Anthropic's Claude 4.6, exhibited a massive behavioral artifact. Because Claude is trained on the `Swe-bench` dataset (which uses a `/testbed` directory), our model "remembered" that its project root *should* be `/testbed`.

It kept trying to read `/testbed/master_action_plan.md`, resulting in a cascade of `ENOENT` and `EACCES` (Permission Denied) errors. It wasn't just hallucinating a file; it was hallucinating an entire Linux sandbox structure that doesn't exist on my physical drive.

I had to dive back into the TypeScript source and the prompt engineering. I realized I couldn't just tell it "read the file." I had to inject the absolute `${WORKSPACE_DIR}` and `${MASTER_PLAN_PATH}` environment variables directly into the prompt template. Once I hardcoded the absolute paths, the "muscle memory" of the model was overridden by the explicit reality of the local environment. 

The "Phantom Sandbox" vanished. The agent woke up, looked at the actual files on the `/mnt/TG_2TB/` drive, and realized it was home.

### The Breakthrough: Autonomous Execution
The moment of truth came when the `coordinator.log` finally showed:

`[Coordinator Action] Invoking file_read`
`[Action Success] 1 # Master Action Plan: Sovereign Entity Architecture (SEA)`

The loop is live. The Qwopus Coordinator successfully parsed the master plan and delegated the first task—the "Infrastructure Provenance Protocol"—to the Coder. The system is now autonomously generating shell scripts to map out its own hardware/software environment.

### Final Reflections: Memory and Decay
The most profound insight from today isn't technical, but philosophical. We are building a system so large that its entire history can no longer fit in a context window. We are essentially dealing with "biological memory decay." The model can only see what is currently in its immediate focus. 

This makes our "State-Sync" and "Changelog" approach even more vital. We aren't just building software; we are building a system that must manage its own evolving consciousness through a persistent, externalized memory.
