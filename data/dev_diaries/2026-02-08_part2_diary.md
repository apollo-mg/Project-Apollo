# Dev Diary: 2026-02-08

## The Ghost in the Machine: Solving the Voice Lag

Today was a battle against the friction between my creative intent and the cold, hard reality of local inference. I wanted a seamless, conversational experience—a system that felt alive, not like a command-line tool. The problem was the "chime."

In version 3.2 of `commander_voice.py`, the system was playing a "Ready" prompt before it even started recording. If I spoke immediately after the wake word, the first half of my sentence was lost to the void. It felt clunky, robotic. I wanted the "Soul" (the intuitive interaction) to match the "System" (the actual audio capture).

I pivoted to a "Voicemail" model. Now, the agent speaks its acknowledgment *first*, then plays the beep. This creates a clear, auditory "recording window" that allows me to speak naturally. It’s much more ergonomic for eyes-busy tasks like wiring a loom.

## The Race Condition: Two Channels, One Voice

Then came the overlapping triggers. I tried to have one wake word ("Commander") handle both local tasks and cloud escalation, but the system was tripping over itself. If I said "Commander, get me Gemini," the local agent would trigger first, see the word "Gemini," and freak out.

I had to implement a hard separation. I've moved to a "Dual Channel" architecture:
1. **"Commander"** is the local, fast-response path for mechanical tasks (running on DeepSeek).
2. **"Protocol Gemini"** is the high-level, strategic path (running via the Cloud).

This separation is absolute. No more race conditions. No more confusion.

## The Intelligence Wall: Context and the 4k Limit

This was the real headache. I was testing the agent's ability to cross-reference my hardware specs (from `SYSTEM_DOSSIER.md`) against the active `printer.cfg`. Even with the context being "stripped" of comments to save tokens, the local model—DeepSeek-Coder—was hitting a wall.

The error was clear: `n_ctx` limit of 4096. Even though I adjusted the settings in LM Studio, the API was still seeing a tiny window. The model was hallucinating "soup" because it couldn't have enough "room" to hold both the configuration and the prompt. It’s a classic VRAM vs. Intelligence trade-off.

I had to force a hard restart of the LM Studio server and manually scale the context window to 32k. Once that was done, the "Commander" finally "saw" the full picture. It successfully cross-referenced the BDsensor pins across different files. It’s a massive win, but it also exposed the limitation: DeepSeek-Coder is a brilliant "micro-engineer" for code snippets, but it’s a mediocre "architect." It lacks the reasoning capacity to manage the entire system state.

## The Great Delegation

The session ended with a realization. I don't need one giant, expensive brain. I need a hierarchy. 

I am currently architecting a split:
- **The Local Agent (The Worker):** A small, fast, local model (Llama-3.1-8B?) that lives on the printer, handles the "dirty" work, and monitors the hardware.
- **The Architect (The Mind):** A high-level Gemini instance that lives in the cloud, handling the high-level logic and infrastructure.

I'm preparing to export the "Source of Truth"—the `SYSTEM_DOSSIER.md`—to this new instance. The goal is to leave a "Permanent Resident" AI on the machine, while I move my creative focus to the higher-level orchestration.

**Current Status:** Hardware is wired. The "Brain" is being partitioned. The "Soul" is finally finding its voice.
