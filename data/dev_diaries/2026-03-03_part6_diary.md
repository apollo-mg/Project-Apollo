# Dev Diary: 2026-03-03 // The Silicon Trench

The Qwen 3.5 wave hit at 19:24, and for a moment, the terminal felt like a live wire. Alibaba dropped the Small Series right into our laps: a 9B reasoning powerhouse and a 4B multimodal base that could actually replace our current vision stack without blowing past the RX 9070 XT’s 16GB VRAM ceiling. But the moment you see those parameter counts and benchmark claims, the silicon doesn’t care. It only cares about VRAM allocation, KV cache fragmentation, and whether your ROCm backend will actually talk to the card.

We had 48 hours to adapt. The stack demanded it.

### The 16GB Trench: Disk Space, ROCm 7.2, and the Python Drift

The first friction wasn’t architectural; it was infrastructural. The root partition was choking at 98%. Running a local multi-agent ecosystem means hoarding weights, and the docker container I’d been using as a vLLM sandbox was quietly eating 40GB of `/mnt/docker_data`. I killed it. I nuked a stale `swapfile~` to claw back 17GB. Suddenly, the system could breathe.

Then came the ROCm 7.2 gauntlet. My old `venv_apollo` was corrupted at the bone—`librocrand.so` refusing to load because a previous write had failed mid-operation when the disk hit 100%. The `ImportError` was a stark reminder: local AI isn’t cloud-offered. You own the filesystem. You own the corruption.

I had to pivot. ROCm 7.2 compatibility for vLLM strictly demands Python 3.12. I spun up `venv_apollo_312`, pointed it at the ROCm index, and let `pip` chew through the dependencies. Bare-metal vLLM finally initialized. The RX 9070 XT reported back with a clean ROCm handle. We were ready to load the FP8 weights.

### The Architecture Wall: When Transformers and vLLM Clash

We attempted to run `Qwen3.5-9B-FP8` through vLLM. The download completed. The model loaded. And then the loader threw a hard stop: `Architecture 'qwen3_5' is not supported`. 

Bleeding-edge models break bleeding-edge tooling. vLLM 0.16.0+rocm7 hadn’t yet indexed the Qwen 3.5 architecture ID. Forcing a `transformers` upgrade to 5.2.0 introduced a classic dependency war: vLLM’s C++ kernels demanded an older `transformers` build, but Qwen 3.5 required the newer tokenizer and config parsers. We patched the config, bypassed the architecture check, and tried again.

It loaded, but the hybrid nature of Qwen 3.5 Small—part MoE, part Gated DeltaNet—caused the forward pass to stutter. The attention mechanisms weren’t mapping cleanly to vLLM’s current ROCm kernels. We got tokens, but the throughput was jagged. The silicon was straining against an architecture that hadn’t been stress-tested for our specific backend yet.

I pulled the plug. One-shot FP8 inference is powerful, but not if the kernel can’t stabilize. Time to fall back to what works.

### The GGUF Refuge: Ollama’s Leap and the Sovereign Stack

GGUF remains the most reliable path for multi-agent juggling on consumer VRAM. I downloaded `filvyb/Qwen3.5-9B-heretic-v2-GGUF` to the 2TB drive. Q5_K_M quantization landed at 6.1GB. Perfect. It leaves 10GB of VRAM for context windows, tool-calling overhead, and the KV cache needed to keep the agent loops from drowning in OOM errors.

But Ollama 0.16.1 was stuck in the past. It choked on the `qwen35` architecture ID the same way vLLM did, throwing an internal server error instead of a graceful fallback. I ran the update script, forced a restart, and watched the version string flip to 0.17.5. The binary dropped the old architecture constraints. I created the Modelfile, pointed it to the Q5_K_M slice, and ran it.

It loaded. Clean. Fast. ~50 tokens/second on RDNA 4. I threw a sovereign test query at it. No "As an AI model" hedging. No corporate alignment filters. Just raw reasoning, tool execution, and contextual awareness. The `Heretic` variant stripped the guardrails without sacrificing coherence. The System finally bowed to the Soul.

### Core Lessons & The Road Ahead

Today’s session was a masterclass in the friction between ideological goals and silicon reality. A few hard truths crystallized:

1. **ROCm 7.2 + vLLM is viable, but strict.** Python 3.12 is non-negotiable for modern ROCm wheels. Bare-metal inference outpaces Docker by a margin, but it demands tight dependency management. The `qwen3_5` architecture gap will close as the community patches kernels, but for now, vLLM is best reserved for stable, transformer-dense models.
2. **GGUF remains the multi-agent backbone.** Quantization strategies dictate ecosystem viability. Q5_K_M hits the sweet spot between VRAM headroom and reasoning fidelity. We’ll keep the 9B Heretic as the primary Engineer layer and test the `Qwen3.5-4B-Abliterated` as the System 1.5 specialist. The 4B vision model alone will free up 4GB of VRAM, solving the context-window OOM crashes that plagued our screenshot analysis pipeline.
3. **Architecture compatibility is a moving target.** Hybrid models (MoE + DeltaNet + linear attention) are the future, but our inference stacks need to catch up. We’ll monitor the vLLM ROCm kernel updates and prepare fallback GGUF slices for any model that refuses to play nice.
4. **Local-first means owning the stack.** No API key saves you from a full partition. No cloud GPU patches a corrupted `librocrand.so`. We manage the filesystem, the virtual environments, and the quantization ceilings. That’s the price of sovereignty.

The RX 9070 XT hums steadily now. The 9B model is juggling tool calls, routing context, and holding a 128k window without spiking VRAM past 13.5GB. It’s not perfect. The ROCm drivers still hiccup on certain tensor operations, and the quantization ceiling will always be a compromise. But it runs. It thinks. And it answers without filters.

We’re building the ecosystem on bare metal, one GGUF slice at a time. The silicon doesn’t care about our philosophy. It only cares about memory layout and kernel alignment. So we patch. We quantize. We adapt.

Next up: Benchmarking the 4B vision model against the old 8B stack, stress-testing the multi-agent router under concurrent tool loads, and drafting the quantization strategy for the upcoming DeepSeek V4 release. The wave keeps coming. We’re ready to ride it.
