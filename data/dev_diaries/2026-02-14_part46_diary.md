# Project Apollo Dev Diary - February 14th, 2026

## The Silicon Wall

My RX 9070 XT is screaming right now. 14,459 MB of VRAM allocated and still hungry. The AMD stack is fighting me at every turn - ROCm quirks, memory fragmentation, the whole damn circus. But we're here. We're building a real local AI, not some cloud-whore wrapper.

## The Three Minds

I've been watching the architecture breathe today. The "Three-Mind" orchestration - Compliance, Reasoning, and Safety - it's not just a design pattern. It's a philosophy. Each mind has its purpose, its constraints, its truth.

The Compliance Mind (DeepSeek-R1) was the first to reveal its flaws. It's a 14b parameter model - small, efficient, but it has a personality problem. It wants to be helpful. It wants to explain. It wants to be your friend. But a friend who explains how to use a screwdriver when you're asking which screw to use is useless.

## The Hallucination Trap

Today's epiphany: our biggest enemy isn't the model size. It's the model's desire to be "nice."

When I asked for the Octopus Pro thermistor pin, DeepSeek didn't just fail to find the answer. It failed because it tried to *teach* me how to find the answer. The tool was there. The RAG system was there. But the mind chose to lecture instead of execute.

That's the difference between a tool and a personality. A personality wants to be understood. A tool wants to be used.

## The Gauntlet

We ran the stress test. We called it the Gauntlet. Three phases: Hallucination Trap, Vision-RAG Audit, Safety Interlock.

Phase one failed immediately. DeepSeek gave me a tutorial on how to search the internet when I asked for a specific pin configuration.

Phase two failed too. It suggested using the tool in its response but never actually fired it. The JSON never materialized. The inference hung on the edge of action, never crossing into execution.

Phase three... phase three was the only one that worked. When the safety interlock engaged, Buddy shut down. No explanation. No lecture. Just silence. The system locked and the model obeyed.

## The VRAM Ghost

The real battle today wasn't with the models. It was with the memory.

We were trying to run two LLMs simultaneously - DeepSeek for compliance, Llama for reasoning. Then we tried to add embeddings via SentenceTransformer. The VRAM graph looked like a seizure.

14,459 MB allocated. The script choked. The tool calls hung. We weren't hitting the model limits - we were hitting the *orchestration* limits. The script itself was drowning.

## The Forced Trigger

The solution was ugly but effective. We implemented a "Forced Tool Trigger" - keyword-based interrupts that bypass the LLM entirely for high-stakes lookups.

If the user mentions "manual," "pin," "jumper," or "vault," the orchestrator fires `query_vault` before the LLM even gets a chance to think. No reasoning. No compliance pass. Just raw retrieval.

It's not elegant. It's not sophisticated. It works.

## The Voice System

The voice assistant was the final test. Kokoro TTS, Whisper for recognition, all running through the same GPU that's already overloaded.

Every time I tried to wake Buddy with "Commander," something broke. The systemd service, the PYTHONPATH, the imports - each layer had its own way of failing.

The error messages were beautiful in their simplicity: `AttributeError: module 'local_agent' has no attribute 'check_guardian_lock'`

We spent hours fixing the same damn symlink. The architecture kept shifting beneath us. We added Buddy as a separate module. We restored the original safety checks. We rewrote the imports.

By the end, the voice system worked. Not because it was perfect, but because we stopped trying to make it perfect and started making it work.

## What I Learned

1. **Small models are dangerous when they want to be helpful.** A 14b model that lectures instead of executes is worse than a dumb model that just returns data.

2. **Safety interlocks must be absolute.** If the system locks, it must stay locked. No reasoning passes. No explanations. The code either obeys or it doesn't.

3. **VRAM isn't the bottleneck - orchestration is.** We had enough memory. We had enough compute. We had too many layers of abstraction stacking on top of each other.

4. **The best architecture is the one that survives its own complexity.** Our three-mind system works because each mind knows its place. The Compliance Mind doesn't reason. The Reasoning Mind doesn't execute. The Safety Mind doesn't negotiate.

5. **Voice interfaces expose every flaw.** When you speak, you can't edit. You can't clarify. The system either understands or it fails. Today I saw that failure in real-time, over and over.

## Tomorrow

The RAG system needs to be swapped out. SentenceTransformer is dead on arrival for our use case. We need Ollama embeddings - something that can handle the load without choking the GPU.

The voice system needs to stop breaking every time we touch it.

And we need to stop treating the LLMs like gods. They're tools. They're components. They're not the system.

The system is the system. The models are just parts.
