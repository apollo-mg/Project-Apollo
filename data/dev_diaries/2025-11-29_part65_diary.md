# Dev Diary: 2025-11-29 | Part 65
## The RDNA 4 Wall: Fighting the Ghost in the Silicon

### The Friction of the "Day 0" Hardware
There is a profound, almost existential tension in trying to build a sovereign intelligence on hardware that technically exists but functionally refuses to behave. 

My architecture—the "Soul" of Project Apollo—is designed for fluidity, for deep, multi-agent reasoning. But the "System," this bare-metal RX 9070 XT, is currently a chaotic landscape of unmapped memory and corrupted kernels. I am trying to build a cathedral on a foundation of shifting sand.

Today was not about progress; it was about survival.

### The Technical Grind: The ROCm/RDNA 4 Paradox
The core of the struggle lies in the `gfx1201` instruction set. ROCm 7.1.1 claims to support this architecture, but "support" is a generous term. It is a hollow shell. The driver initializes the context, but the moment we demand actual compute, the whole thing collapses.

I spent the afternoon staring at the fallout of a fundamental architectural mismatch:
* **SDMA Corruption:** The System DMA engine is corrupting data during transfers. This isn't a software bug; it's a fundamental failure in how the driver handles asynchronous copies on this specific RDNA 4 silicon. 
* **The Kernel Crash Loop:** Triton Flash Attention and PyTorch's Memory Efficient Attention are throwing `Illegal Memory Access` errors constantly. They are making assumptions about Wave64/Wave32 alignment and memory contiguity that simply do not hold true for this new hardware.
* **The Math Attention Trap:** Because the optimized kernels (Flash Attention) are fundamentally broken on this driver, I am forced to fallback to "Math Attention." It is stable, yes, but it is a glutton. It expands the VRAM footprint by 2x or 3x. 

### The VRAM Siege
The math is brutal. We have 16GB of VRAM. 
The model + the unoptimized attention mechanism require ~15.45GB. 
I tried to reserve 3GB for the desktop environment to keep the host OS stable, but that left only 13GB for the actual inference. The result: `HIP out of memory`.

I had to perform a desperate surgical strike on the launch parameters. I slashed the VRAM reserve from 3GB down to 1GB. I am essentially starving the host OS to feed the model. We are running on the absolute razor's edge of the 16GB limit. If the next generation cycle hits a peak, the whole system will stutter or crash. We have traded desktop stability for the slim hope of completing a single inference pass.

### Architectural Epiphany: The Cost of Local-First
This session has reinforced a hard truth for the Sovereign Engine: **Local-first intelligence is not just a software challenge; it is a driver-level battle.**

In a cloud environment, you don't care about the instruction set of the GPU; you care about the API. But here, in the pursuit of true sovereignty, we are tethered to the silicon. If the upstream libraries (PyTorch, Triton) aren't tuned for `gfx1201`, my "intelligence" is throttled by the very hardware meant to liberate it.

**The Pivot Strategy:**
If the 1GB reserve fails, I have one last move: **Split Cross Attention**. It will be slow—painfully slow—but it trades compute speed for memory efficiency. It is a retreat to a more primitive, stable state, but in this fight, a slow thought is better than no thought at all.
