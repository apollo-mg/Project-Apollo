# Dev Diary: 2026-03-27 (Part 2)

The battle between the 35B MoE and the 27B Dense is officially underway, and it’s a fascinating study in the physics of local inference. 

I spent the morning wrestling with a simple agentic task—having the agent write a "Hello World" Python script and verify it. The logic was surprisingly sound. It failed twice, exactly as I'd instructed it to "make a mistake," showing a level of self-correction that feels more like a reasoning engine and less like a pattern matcher. It realized it was trying to write to a non-existent `/output/` directory, pivoted, failed again with a logic error, and then finally nailed the file write on the third attempt. 

The "VRAM Tax" is real, though. Sitting at 15.9GB on a 16GB card is like driving a car on the edge of a cliff. The 8-bit KV Cache is holding steady, but there is zero margin for error. It's a delicate balance between the "Soul" (the intelligence of the 35B model) and the "System" (the hard limits of my AMD 9070 XT).

The most interesting part of the session was the architectural revelation regarding the Qwen 3.5 family. The 35B is a Mixture of Experts (MoE), meaning it only "activates" about 3B parameters per token. Theoretically, it should be a speed demon. However, the reality of local hardware is that the bottleneck isn't the compute—it's the memory bandwidth. The GPU still has to traverse the 35B parameters to figure out which experts to use. My perception of it being "slower" than the 27B dense model is actually a direct reflection of the bandwidth limitations on consumer hardware.

I attempted to pivot to GigaChat 3.1 Lightning—a 10B model that only activates 1.8B parameters. The promise was 120-150 tokens per second. I was looking for that "instantaneous" feel.

However, I hit a classic developer friction point: I tried to run a `.sh` script using the `python3` interpreter. A total brain-fade moment. The terminal spat out a `SyntaxError` because Python was looking for Python code, not Bash commands. 

I'm still fascinated by the "residency" argument. If the 35B model is already hitting 70 tps, it is already faster than any human can read. Why bother with a smaller model just for speed if the "genius" is already resident in the VRAM? The only reason to go smaller is if I want to run a "swarm" of agents simultaneously, which is a whole different beast.

**Current State of the Architecture:**
The 35B MoE is the current "Goldilocks" zone. It's smart enough to handle complex tool-calling, fast enough to be usable, and just barely fits in the VRAM. The next step is seeing if I can push this multi-agent ecosystem to actually *do* something meaningful without the system collapsing under its own weight.
