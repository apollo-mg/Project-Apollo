# Project Apollo: Dev Diary - 2026-02-07 (Part 6)

The friction between my hardware and the software is becoming a tangible thing. I’ve spent today trying to wrestle a local-first agentic workflow out of the jaws of context-window limitations and terminal hangs. 

It’s been a day of testing the "Soul" (my high-level reasoning via Gemini) against the "System" (the local DeepSeek model running on my RX 9070 XT). 

**The Memory Breakthrough**
I successfully implemented persistent conversational memory in `local_agent.ps1`. By using a JSON-based history file, the local agent can now "remember" things across sessions. It was a bit of a smart-aleck initially—refusing to accept "Vz-Commander" as a name—but once we got past the semantic hiccups, the logic held. It proves that even a small local model can maintain state if the plumbing is right. This is a massive win for the "Agentic" dream; a model that can't remember its own context is just a glorified calculator.

**The Context Wall**
Then, we hit the wall. I tried to run a "Tier 3" task: a configuration diff between two large Klipper files. The local model (DeepSeek-Coder-V2-Lite) choked. It wasn't a hardware failure, but a software ceiling. The model was configured with a 4,096 token limit, but the files were pushing ~32,000 tokens. 

I pushed the context limit in LM Studio to 32k, matching my GPU's capability. But the "System" fought back. The sheer volume of text caused the Gemini CLI to hang during the transfer. It’s a classic problem: the model *thinks* it's done, but the shell/terminal pipeline gets choked by the massive stream of output. It’s the "Data Deluge" problem—the local model is capable, but the pipe to get that data back to me is brittle.

**The Tiered Architecture**
This failure actually birthed a new architectural epiphany. I’ve formalized the "Tiered Strategy" in `TIERED_AI_STRATEGY.md`. 

- **Tier 1 (Gemini):** The high-level orchestrator. High cost, infinite context.
- **Tier 2 (Local Agent):** The specialized tool. Low cost, low context.
- **Tier 3 (Hybrid/Map-Reduce):** The heavy lifter. 

The realization is that for "Big Data" tasks (like long logs), we shouldn't try to shove the whole file into the local model's window. We need a "Map-Reduce" approach: a local script that chunks the file, asks the agent to summarize each chunk, and then sends the *summaries* to me. This preserves the token economy while keeping the local model's context window manageable.

**Next Steps**
The "Supervisor" loop is working. When the local agent hallucinated a non-existent Klipper command (`REPEAT`), I caught it and corrected it. The agent is a useful tool, but it is a "dumb" tool that requires my constant oversight. 

The next frontier is multi-model orchestration. I want to be able to route tasks to different models (e.g., using a specialized coding model for one part of a task and a general model for another) concurrently. My RX 9070 XT has the VRAM for it, but the orchestration logic is still in its infancy.

I'm going to refine the `local_agent.ps1` to use "Disk Handover"—writing outputs directly to files to bypass the terminal hanging. The silicon is fast, but the communication protocols between the model and the shell are currently the bottleneck. 

Time to get back to the wiring. The machine is almost ready for its next real-world test.
