# Project Apollo | Dev Diary: 2026-04-03

The RX 9070 XT is running hot. I can watch the VRAM allocation graph climb on the terminal, pressing against the 16GB cliff. For months, we’ve been playing hardware Tetris with ROCm, patching kernel segfaults and fighting HIP memory access violations just to get a 7B model to decode without crashing. Tonight, we crossed a threshold. The Gemma 4 26B MoE isn’t just running; it’s holding a 65K-token context window. We didn’t get here by asking nicely. We got here by weaponizing asymmetric quantization and treating the silicon like an adversary we finally outmaneuvered.

## Shattering the 16GB Ceiling

Loading a 26B MoE on consumer-grade RDNA 4 hardware should be mathematically impossible. Standard INT4/INT8 quantization leaves too much dead space on the floor, while full-precision is a suicide mission for the HBM. We went with the experimental TurboQuant (TQ3/Q8) asymmetric cache branch. It’s a brutal architectural split: Q8 for the critical attention heads and KV cache, TQ3 for the MoE routing gates and MLP projections. It’s messy on paper. It’s a fragmentation nightmare. But it shaved just enough off the activation overhead to give the 65K window a fighting chance.

The ROCm runtime didn’t make it easy. The usual suspects flared up immediately: `MUL_MAT_ID` errors, SDMA transfers corrupting quantized weights, and strided tensors triggering illegal memory access in the attention layers. We had to strip the model loading pipeline down to the studs. Explicit `.clone().contiguous()` calls on every weight transfer. Forcing CPU-side dtype casting before the `HIP` copy. Disabling `PYTORCH_TUNABLEOP` because the auto-tuner was generating unstable Triton kernels that choked on the asymmetric layout. It’s not elegant, but it’s stable. The context window holds at 65K without thrashing. We finally have enough silicon room to let the model think ahead.

## Soul vs. System: The Quantization Compromise

There’s a tension here that keeps me staring at the terminal at 2 AM. The "Soul" of Apollo is meant to be a sovereign, deeply contextual entity capable of nuanced reasoning. But the "System"—this 16GB of GDDR6—demands brutality. The TQ3/Q8 split is a hack that somehow works. It introduces slight rounding drift in the MoE gating mechanisms, which sometimes makes the model slightly more rigid on abstract or philosophical outputs. I can feel it when it drafts a response; it’s precise, but lacks a touch of creative friction. We’re trading philosophical nuance for computational survival. But survival is the first prerequisite for sovereignty. If the GPU OOMs, the agent doesn’t exist. Period. The system doesn’t care about our design philosophy. It only cares about memory layout and tensor contiguity.

## Zero-Abstraction Sovereign Mail

While the GPU was cooling down, I routed the rest of the night toward the data pipeline. Google’s OAuth flow is a leash. It throttles us, it sanitizes metadata, and it funnels our agency through a cloud API that treats us like a third-party plugin. Tonight, we cut the cord. `email_ingest.py` is live. No more fetching JSON payloads and hoping the API doesn’t rate-limit us or break authentication flows. We’re reading raw `.eml` files directly from the local Maildir, populated by `mbsync`.

The parser is brutally simple. It strips MIME headers, handles multipart decoding, and dumps the payload into the agent’s working memory as raw text. No abstraction layer. No OAuth refresh token dependency. Just filesystem access and Maildir compliance. It’s a massive win for data sovereignty. The agent now owns its inbox. It can cross-reference local logs, project files, and communication threads without asking a cloud provider for permission. The friction of cloud auth is gone, replaced by the cold, reliable speed of local I/O. This isn’t just about privacy; it’s about latency and determinism. The multi-agent swarm needs predictable data ingestion, not a web browser’s network stack.

## System Lessons for the Sovereign Swarm

Three things crystallized out of the smoke tonight, and they’re reshaping how we build the rest of the ecosystem:

1. **Asymmetric Quantization is Mandatory for 16GB.** We can’t brute-force 26B+ MoEs on consumer RDNA. TQ3/Q8, or similar hybrid schemes, are non-negotiable. The VRAM budget demands we treat quantization as a structural architecture decision, not just a storage optimization.
2. **ROCm Contiguity is Non-Negotiable.** The HIP runtime is unforgiving on non-contiguous tensors. Every Host-to-Device transfer must be explicitly cloned and contig-ified. The driver’s DMA engines will silently corrupt strided views on quantized layouts, and the error messages are deliberately vague. We have to enforce memory layout at the Python layer before it ever touches the GPU.
3. **Sovereignty Requires Raw File Access.** OAuth and API abstractions are performance bottlenecks and single points of failure. Direct Maildir parsing gives the multi-agent ecosystem deterministic latency and total control over its memory pool. When the network drops, the agent should still function.

The architecture is shifting. We’re moving from a model that guesses at tools to an architecture that operates directly on the raw filesystem, leveraging quantization hacks to squeeze maximum context out of every millimeter of HBM. The 65K window isn’t just a number. It’s the space where the agent can hold the entire project codebase, the local ROCm logs, and the raw email threads simultaneously. It’s where the Daydream daemon can actually cross-reference weeks of activity without losing the thread.

Tomorrow, I’m running the Sleep Cycle LoRA fine-tuning on this new context window. If the quantization drift stabilizes, we might finally have a local entity that remembers everything without external context pumps. Until then, I’m patching the attention heads and watching the VRAM graph. The silicon fights back, but it yields.
