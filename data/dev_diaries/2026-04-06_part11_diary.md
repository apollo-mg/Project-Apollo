### 02:32 AM: The Token Nuke and the Regex War

The session reset hit like a physical blow. A quick `re-auth` for the quota didn't just interrupt the chat; it violently severed the connection to my local brain. All spawned child processes? Nuked. 

But the real headache wasn't the network timeout; it was the string escaping nightmare in `update_task-status.ts`. 

I was trying to get the Coordinator to write a regex that would match task IDs without mangling the backslashes. Every time the LLM output a replacement, the `file_edit` tool would eat the escape sequences, turning `\s` into garbage or throwing syntax errors that refused to compile. It was a brutal loop of `write_file` -> `cat` -> `grep` -> panic. 

Then it hit me. I was asking the model to play editor, but it’s terrible at syntax. I needed to stop trying to patch the file with raw text and inject a dedicated function instead. I spun up a surgical `update_task_status` tool that handles the I/O and regex parsing internally. The prompt no longer needs to "match strings"; it just needs to call a function. 

**The Lesson:** When the silicon fights you, stop asking it to do the heavy lifting. Abstract the logic. Inject the tool. Let the LLM just be the brain, not the keyboard.

### 02:50 AM: Choked on the "Stability" Flags

I woke the system up, ready for the night shift, and... nothing. The 9070 XT was dead silent. The fans weren't even spinning. 

I checked the logs. The server had launched, but the generation speed was crawling. I realized my mistake instantly: I had copied the `start_architect.sh` script directly over to the coordinator setup. 

It was loaded with `GGML_HIP_FORCE_MMQ=1` and micro-batching flags (`-ub 512`) designed to stabilize the Gemma 4 MoE model against the `MUL_MAT_ID` crash. We were running a dense Qwopus model on a ROCM TurboQuant fork. Forcing MMQ on a dense model is like strapping a parachute to a race car and expecting it to drift. It was running with the brakes on. 

I stripped the script clean. I removed the MoE workarounds and left only the raw, asymmetric KV cache optimizations (`-ctk q8_0 -ctv turbo3`). The second I ran it again, the VRAM bus lit up. The 9070 XT finally started sweating.

### 02:59 AM: The Path to Nowhere

Of course, I didn't get it right on the first try. I pointed the startup script to `build/bin/llama-server`, but TheTom's TurboQuant fork compiled the binaries into `build_rocm/bin/`. A classic `No such file or directory` error. 

I had to manually patch the path, kill the dead process, and manually invoke the `tsx` compiler to fix a lingering syntax error from the earlier file truncation. It’s a messy architecture—patching the patches, fighting the TS compiler, manually overriding timeouts when the model takes too long to load into VRAM. 

But at 03:08 AM, when the logs finally spit out the first `[COORDINATOR PHASE]` block, the friction broke.
