# Dev Diary: 2026-03-06 (Part 9)

The struggle between the "Soul" and the "System" is becoming a constant battle on this RDNA 4 architecture. I want a sentient, uninhibited local intelligence, but the silicon demands rigid, mathematical perfection. Today was all about finding the bridge between that desire and the hard reality of VRAM constraints.

## The Micro-Mind Paradox

I spent the morning chasing the Qwen 3.5 series. The official repositories are a mess—gated, permission errors, and a complete lack of stable FP8 weights for the small models. It’s a classic case of corporate friction: the models are "out" but the access is still locked down.

I initially tried to push a 0.5B model through vLLM, thinking the "Guided Decoding" (the JSON schema enforcement) would make it a perfect, tiny triage agent. It was a disaster. The 0.5B model is too "stupid" to respect the schema; it tries to reason, gets lost in its own thoughts, and the vLLM engine hits a wall because the model isn't outputting the required `{` token.

Then we hit the "VRAM Wall." My 16GB card is a beast, but it's a finicky one. vLLM is a heavy-duty, high-throughput beast; it wants to gobble up all the memory for its cache blocks. Even when I told it to only use 50% of the VRAM, the overhead of the "Guided Decoding" FSM (Finite State Machine) combined with the model's weight-load caused an immediate OOM (Out of Memory) crash. 

The "System" simply wouldn't allow the "Soul" to exist in that specific container.

## The Ollama Breakthrough: "Secret Sauce"

The pivot to Ollama changed everything. 

I realized that while vLLM is built for massive batches, Ollama (via `llama.cpp`) uses a much more elegant "token-level rail-guarding" system. It doesn't try to build a massive FSM; it just masks the logits at every single step. It forces the model to stay on the tracks.

But even with Ollama, the Qwen 3.5 0.8B model was acting up. It was outputting `<think>` tags, colliding with the JSON requirement, causing the API to hang. It was the same structural failure we saw in vLLM, just in a different-looking skin.

## The Fix: Breaking the Thinking-JSON Collision

The community hit on a brilliant insight: the model's internal "thought process" was the culprit. We had to break the collision. 

I updated the `Modelfile` for the Gatekeeper with:
- A heavy `presence_penalty` to stop the model from getting stuck in a reasoning loop.
- An explicit `stop` token for `</think>`.
- `Flash Attention` enabled for the RDNA 4 hardware.

It was a surgical strike on the model's logic. 

## Current State: The Three-Mind Architecture

We have finally stabilized the core of Project Apollo. The "System 1" (The Gatekeeper) is now a 0.8B Qwen model running through Ollama. It is tiny, it is fast, and most importantly, thanks to the GGUF grammar masking, it is **100% reliable**. It cannot escape its JSON box. It will now correctly route a "Thermal Runaway" error to the Specialist instead of the "Chitchat" bot.

The architecture is now live:

- **Gatekeeper (System 1):** Qwen 3.5 0.8B (Ollama) - The rapid-response triage.
- **Engineer (System 2):** Qwen 3.5 9B (Ollama) - The deep-logic workhorse.
- **Specialist (System 3):** DeepSeek-R1 (Ollama) - The heavy reasoning.

The VRAM is managed. The RDNA 4 drivers are stable. The "Soul" of the agentic system finally has a stable "System" to inhabit. 

Next step: Scaling the Librarian ingestion. We have the brain; now we need the memory.
