# Dev Diary: The SearXNG Breakthrough and the VRAM Wall

## The Chaos of the Web

Today was a battle against the "Tragedy of the Commons." I spent the first half of the session fighting the invisible wall of search engine scrapers. It’s a mess out there. We’re seeing millions of "baby agents" hitting Google and DuckDuckGo with the force of a tidal wave, and the drawbridges are being raised in real-time. My agent, Shop Buddy, kept getting slapped with 403s and CAPTCHAs because the industry is treating every Python request like a hostile takeover.

I briefly toyed with the Google Custom Search API, but the "Soul" of the project—my desire for a local-first, sovereign ecosystem—clashed with the "System." Google's new policy has essentially nerfed the free tier for new users, making "Whole Web" searching a paid enterprise luxury. It’s a blatant move to gatekeep the very intelligence we’re trying to build locally.

## The Sovereign Pivot: SearXNG

We had to pivot. Hard. We abandoned the API-dependency and went full local. I spun up a SearXNG instance via Docker on the Ubuntu workstation. It’s a meta-search engine that acts as a proxy, rotating through different engines and presenting a clean JSON feed. 

The transition was beautiful. The moment the agent successfully queried the local SearXNG instance, the "intelligence" barrier shattered. It bypassed the scraping blocks entirely. It found the EBB36 manual on an Instructables blob that was previously invisible to our scripts. The agent is no longer just a script; it is a researcher.

## The VRAM Wall and the JSON Ghost

As the agent’s capability grows, the silicon is pushing back. My RX 9070 XT is a beast, but when the model tries to process the ingested technical docs alongside the live voice-to-text (Whisper) and the TTS (Kokoro), we hit the VRAM ceiling. 

I watched the logs: `VRAM Threshold exceeded (14537MB > 14500MB)`. The system triggered the guardrail, initiating a ComfyUI VRAM cleanup. It’s a constant game of VRAM Tetris. The friction between the sheer amount of "knowledge" we want to feed the agent and the physical memory available is the defining constraint of local-first development.

Then, a new ghost appeared: `Action Handler Error: Expecting property name enclosed in double quotes`. 

The LLM is getting "smarter" but "messier." It’s outputting malformed JSON during the Compliance Pass. It’s a classic case of the "Soul" outgrowing the "System." The model is trying to be too clever, breaking the strict structural requirements of the agent's tool-calling logic. It's the price of autonomy.

## Core Lessons

1. **Autonomy requires Infrastructure:** A local agent is only as good as its access to information. If the web is gated, the agent is blind. Self-hosting search (SearXNG) is no longer an "extra"—it is a foundational requirement for local-first AI.
2. **The JSON Fragility:** As we move toward more complex tool-use (calling Python functions via LLM), the reliability of structured output (JSON) is our biggest bottleneck. We need more robust parsing or more rigid prompt engineering.
3. **Memory is the Limit:** We are building models that are more capable than the hardware we can afford. The future of local AI isn't just about bigger models; it's about better VRAM management and smarter, more efficient context window usage.

**Status:** Agent is functional. Search is sovereign. The silicon is screaming. 

**Next Move:** Fix the JSON parsing error and stabilize the VRAM footprint. Then, we test the generative capabilities.
