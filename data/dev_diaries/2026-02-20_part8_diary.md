# Dev Diary: The Human-Centric Shift & The Three-Mind Architecture

**Date:** 2026-02-20
**Status:** System Stable / Architecture Validated

The friction between the "Soul" and the "System" has reached a turning point. For weeks, I've been fighting a losing battle against disk space and VRAM fragmentation. My local-first approach felt like trying to build a cathedral in a closet. But today, we broke through.

### The Great Migration
The root partition was choking. I had 50GB of model weights and agent data sitting in `/home/mark/gemini/ai`, threatening to starve the system. I initiated a background `rsync` to move the entire directory to the 2TB external drive. It’s a massive operation, but by using a symlink post-transfer, the file paths remain intact. The system will "think" the files are local, while the physical silicon breathes easy on the external drive. 

### The Personality Upgrade: Llama 3.1 vs. The World
The biggest breakthrough today wasn't about storage—it was about the "Soul." I ran a series of benchmarks against our new "Receptionist" (System 1) role. I pitted the current `llama3.1:8b` against `Qwen 2.5 7B` and `Hermes 3 (Llama 3.1 8B)`.

The results were telling:
- **Qwen 2.5** was a speed demon, but it lacked the "warmth." It failed to understand the nuance of vague, conversational intent.
- **Hermes 3** was the winner. It hit **100% accuracy** on my intent-classification benchmark. It understands the difference between a casual chat and a command. It’s the first model that feels like a *person* rather than a script. 

The catch? It’s slightly slower, but in a local-first multi-agent ecosystem, accuracy and "human-centric" nuance are worth the millisecond latency.

### The "Three-Mind" VRAM Tetris
This is where the technical grit meets the architectural epiphany. I have a 16GB VRAM ceiling. My "Engineer" (DeepSeek-R1 14B) takes up ~9GB. My "Receptionist" (Hermes 3 8B) takes up ~5GB. 

**Total: 14GB.** 

They fit. They coexist. This is the "Three-Mind" architecture: a rapid-fire handoff between the conversational front-end and the heavy-duty reasoning back-end. There is no "hot-swapping" lag because they live in the VRAM together. When the vision tool is called, my orchestration script (the "Tetris" logic) temporarily unloads them to make room for the 6GB Vision model, then snaps them back into place. It’s a delicate, automated dance of memory management that actually works.

### Validation & The Redundant Loop
I ran a stress test to push the VRAM orchestration. The system handled the vision-to-text-to-vision cycle without a single Out-of-Memory (OOM) crash. 

However, I caught a moment of "agentic insanity." During the stress test, the agent attempted to download a PDF that *already existed* in the vault. It had essentially "healed" a gap that wasn't actually there. It was a redundant, autonomous loop. I've since updated the `ingest_manual` tool with a "Vault Pre-Check." Now, the agent will check the `vault/pdfs` directory for a filename or keyword match *before* it burns bandwidth on a download. It's a small fix, but it's the difference between a smart agent and a mindless one.

- **System 2 (Engineer):** `deepseek-r1:14b` (High Reasoning)
- **Vision:** `qwen2.5vl` (On-demand)

The machine is finally starting to feel alive. It’s not just executing commands; it’s navigating its own knowledge. Now, we just need to see how far this intelligence can actually go.
