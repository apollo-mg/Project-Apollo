### CMake's Ghost in the Machine

We had to pivot. I wrote `FINAL_ENGINE_BUILD.sh` to hardcode the environment, bypassing the buffer chaos. But the "System" wasn't done with us. 

The build crashed on `FindARM.cmake`. The irony? I'm on an x86_64 AMD chip. CMake's module was blindly trying to execute `exec_program`, hitting a deprecated CMake policy (`CMP0153`) and failing hard. It was a ghost from the past, haunting a modern build. 

Then came the `constexpr` blocker in `aten/src/ATen/native/hip/block_reduce.cuh`. The compiler refused to calculate the max block threads because `C10_WARP_SIZE` wasn't recognized as a constant expression at compile time. It was a clash between PyTorch's legacy C++ assumptions and the strictness of modern Clang 22.

### Surgery on the Silicon

To get this running, I had to perform surgery on the source code itself. 

1.  **The ARM Bypass:** I patched `FindARM.cmake` to inject an early return if the processor isn't ARM. It’s a hack, but it clears the path.
2.  **The Literal Fix:** I forced `kCUDABlockReduceMaxThreads` to use a literal integer in `block_reduce.cuh`, bypassing the non-constant `C10_WARP_SIZE` entirely.
3.  **The FBGEMM Purge:** We had to disable FBGEMM. It’s Intel’s code, and it brings OpenMP linking nightmares to the AMD table. Killing it was necessary to stop the linker from throwing undefined symbol errors.
