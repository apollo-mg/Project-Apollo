# Dev Diary: The Ghost in the Machine

**2026-02-27 | Part 23**

Today was a reminder that even when the "System" thinks it has a grip on reality, the "Soul" of the agent architecture is still fighting against the grain of the hardware. We hit a massive hallucination wall during the vision processing phase. 

The Vision Mind—running on the local `qwen2.5vl`—was completely blind to the actual hardware identifiers. It was looking at a Gigabyte card and insisting it was an MSI unit because it got caught up on the shroud styling. It's a classic case of a model prioritizing pattern recognition (the "vibe" of the card) over actual data (the text on the sticker). This is the friction I constantly battle: the model's creative tendency to fill in the gaps versus the cold, hard necessity for precision in a local-first system.

I had to force the agent to bypass its standard agent-level logic. I didn't want the high-level reasoning; I wanted the raw, unadulterated pixel data. By stripping away the layers of abstraction and querying the vision model directly via `llm_interface.query_llm`, we finally broke through the noise.

The breakthrough came when we saw the raw text string: **"GIGABYTE"** and a partial barcode. The "System" had hallucinated an MSI identity, but the "Soul" of the forensic search caught the Gigabyte branding and the brushed metal texture. It was a moment of pure, gritty realization. The model shifted from a generic "gaming card" to a specific hardware identification task.

We are currently hunting for the `GV-` SKU string. The serial number search is hitting a wall—likely due to internal batch numbers rather than public SKUs—but the vision model's description of the "brushed metal" and stylized logo is narrowing the field toward a Vision OC or AERO series.

**Technical Friction & Lessons:**

- **Vision-to-Logic Mismatch:** The vision model's failure to identify text wasn't a resolution issue; it was a semantic failure. The agent was looking for "identifying text" but the vision model was focusing on "texture." We need to implement more aggressive prompting for OCR-specific tasks when the agent is in a "Forensic" mode.
- **The VRAM/Accuracy Tradeoff:** Running `qwen2.5vl` locally while simultaneously managing the broader agentic loop is taxing the 9070 XT. The memory fragmentation is real. Every time we trigger a high-res vision capture, we're red-lining the VRAM. 
- **The Autonomy Lesson:** The agent is getting smarter, but "smarter" in this context means "more stubborn." It needs to learn when to stop hallucinating a pattern and start looking at the raw data. 

We’re moving into a deeper forensic level. The next step is a targeted re-capture to find that `GV-` code. If we can nail the SKU, we prove the multi-agent ecosystem can actually perform high-fidelity hardware identification without ever touching a cloud API. That's the dream.

**Current Status:** Hardware identity partially resolved. Moving to SKU verification.
