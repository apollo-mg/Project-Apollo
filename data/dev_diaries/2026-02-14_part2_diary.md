# Dev Diary: 2026-02-14 | The RDNA 4 Wall

I am currently staring down a wall of silicon-induced frustration. I thought the RX 9070 XT would be the beast that carries Project Apollo through the heavy-duty diffusion tasks, but today, the "System" decided to fight back.

The goal was simple: a cinematic, high-resolution space battle using Flux. The "Soul" of the project—the creative vision of a battle-worn starship amidst exploding dreadnoughts—was ready to manifest. But the "System" had other ideas.

The crash was brutal. A `torch.AcceleratorError` triggered an `illegal memory access` deep within the VAE Decoder. The stack trace was a nightmare of asynchronous kernel errors, but the smoking gun was clear: `F.conv2d` failing inside the `Upsample` block of the model. 

This wasn't a simple out-of-memory (OOM) issue. My VRAM was still showing plenty of free headroom. This was a fundamental breakdown in how the ROCm kernels were interacting with the tensor layout. Specifically, the `Upsample` and `Downsample` operations were generating non-contiguous, "strided" tensors. On NVIDIA hardware, this is a minor inconvenience; on my RDNA 4 architecture, it's a death sentence. The kernel tries to read a memory address that doesn't exist where it expects, and the whole pipeline collapses.

It’s a classic friction point: the mathematical elegance of the diffusion model assumes a level of memory fluidity that the current AMD driver/kernel implementation just can't handle.

I had to dive into the guts of the architecture. I've applied a manual patch to `comfy/ldm/modules/diffusionmodules/model.py`. The fix is a brute-force enforcement of memory contiguity—forcing `.contiguous()` on the tensors before they hit the convolution layers in the `Upsample`, `Downsample`, and `VideoConv3d` blocks.

It’s a gritty, low-level fix, but it’s necessary. I’m keeping `TunableOp` enabled for now because I refuse to sacrifice the performance gains of specialized kernels unless the memory alignment issues prove unfixable. If this patch holds, the VAE will finally be able to decode the latent space into a viewable image without the GPU losing its mind.

**Current Status:**
- **Hardware:** RX 9070 XT (RDNA 4)
- **Software:** ROCm 7.1.1 / PyTorch 2.9.1
- **Problem:** Non-contiguous tensor striding in VAE upsampling.
- **Solution:** Enforced `.contiguous()` in `diffusionmodules/model.py`.

**Next Step:** 
Reboot the environment and pray the VAE doesn't throw another `hipErrorIllegalAddress` during the decode phase. If this works, the local-first multi-agent dream stays on track. If not, I'm going back to the driver-level debugging rabbit hole.
