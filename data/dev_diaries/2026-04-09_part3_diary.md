**Dev Diary: 2026-04-09**

The RX 9070 XT is a beast, but even beasts hit their limits. Today, I was wrestling with the quiet creep of VRAM usage on my local `llama.cpp` server. Over twenty hours of uptime, the available memory had slowly bled away, causing my Chrome GUI to stutter every fifteen seconds—a classic sign of PCIe bus saturation when the GPU runs out of native memory.

The root cause was not the KV cache, which is pre-allocated and static. It was the fragmented memory. During active generation, the ROCm backend dynamically requests transient "scratch buffers" for massive matrix multiplications. Over hours, the ROCm memory allocator failed to neatly recycle these tiny blocks, leaving the VRAM map looking like Swiss cheese. When the driver needed a contiguous block for the next math operation, it couldn't find one, so it simply asked the OS for more raw VRAM.

You cannot defragment GPU memory while `llama.cpp` is running. The only solution was a scheduled restart.

I wrote a "Smart VRAM Watchdog" script to handle it. Every five minutes, it checks the `vram_management.py`. If the free VRAM drops below 400MB, it pauses the Daydream Daemon with a lock file, kills the `llama-server`, waits for the VRAM to flush, and restarts the server with a clean stack.

It is a small piece of plumbing, but it preserves the flow. In the local-first multi-agent ecosystem, we cannot afford to lose an epiphany mid-thought to a memory leak. The "Soul" is the creative work; the "System" is the cold, hard limit of the silicon. My job is to ensure the System never silences the Soul.

This Watchdog is the guardrail that keeps the two in balance.
