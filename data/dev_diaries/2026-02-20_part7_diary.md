# Dev Diary: 2026-02-20 (Part 7)

The "Soul" and the "System" are currently at war, and the casualty list is growing.

I spent the morning running a "Hard Mode" benchmark on the Receptionist strategy. I wanted to see if the 3B model could actually handle the messiness of real-world speech—the vague complaints, the "actually, never mind" cancellations, the colloquialisms. 

The results were a wake-up call. 

The 3B model (Llama 3.2) is a speed demon, hitting 100 tokens/sec, but it's incredibly brittle. It crashed the JSON parser entirely when faced with a simple change of heart ("Actually, never mind"). It's fast, but it's not smart enough to be the gatekeeper. In a multi-agent system, if the gatekeeper fails, the whole pipeline collapses. 

Llama 3.1 (8B), however, was flawless. It handled the "Hard Mode" test cases with 100% accuracy. Yes, there's a 70ms latency penalty, but in the context of human interaction, 0.4 seconds vs 0.3 seconds is invisible. Reliability is the priority. A fast model that gives the wrong instructions to the Engineer is worse than a slightly slower model that gets it right.

Decision: We are moving the Receptionist role to Llama 3.1 (8B) immediately.

The hardware reality check: My 16GB VRAM is a tight corner. If I want a high-EQ "Human-Centric" model at the front end, I have to be ruthless with memory management. I'm looking at a 14B model for the Engineer, and if I load that alongside an 8B Receptionist, I'm hitting the wall. 

Then there's the disk space crisis. The root partition is at 98% capacity—a death sentence for a system that needs to write logs and temp files. I spent an hour hunting for the space hog. It turns out it wasn't the models, but a massive 50GB directory in `/home/mark/gemini/ai`. I almost purged it, but I realized it's the active ComfyUI environment. It's too vital to touch. 

The real culprit is a massive 24GB swapfile and some runaway logs in `/var/log`. I need to prune the logs and move some of these model files to the 2TB HDD/SSD combo to breathe again. 

The plan for the next sprint:
1. Update `llm_interface.py` and `buddy_agent.py` to implement the Llama 3.1 8B Receptionist.
2. Refine the "Human-Centric" prompt to ensure the "Soul" of the agent is preserved.
3. Clean up the root partition and manage the model-to-disk migration.

I'm chasing that high-EQ, high-intelligence local-first dream, but the silicon is a demanding master. The architecture is moving toward a "Front-End/Specialist" split: a high-EQ Receptionist that handles intent, calling upon a DeepSeek "Genius" only when the heavy lifting is required. It's the only way to maximize the 9070 XT's potential without choking the system.

Onward.
