# Dev Diary: 2026-02-28 (Part 1)

The friction between "Soul" and "System" is hitting a fever pitch today. I’m trying to build an agent that actually *sees* the world, not just a pattern-matcher that guesses based on what's already in the database. Today was about breaking the habit of "deductive cheating."

### The Forensic Breakthrough

The first few hours were spent wrestling with the Vision Mind. It was being too cautious—too "polite," to use a human term. It saw a serial number on an MSI card, but it wouldn't commit to the full string. It was seeing the forest but ignoring the trees. 

I realized the bottleneck wasn't just the LLM; it was the resolution. The Vision Mind was essentially looking at a thumbnail. I implemented a `crop_image` tool, giving the agent a "magnifying glass." This was a massive architectural leap. Now, if the Engineer Mind sees a tiny, unreadable sticker, it can autonomously decide to zoom in, effectively boosting the OCR resolution at the cost of compute. It’s a "smart" upgrade that bridges the gap between a blurry photo and a forensic audit.

### The "Deductive Cheating" Problem

Then we hit the logic wall. The agent was identifying the cards, but it was doing it through a biased loop. It saw "MSI" and, because I only had one MSI card in my inventory, it assumed the card *must* be that one. It was using my inventory to bypass the actual visual evidence. 

That’s a death sentence for a real-world tool. If I bring in a new piece of hardware, I don't want the AI to tell me it's a piece of junk I already own just because it's the only thing that "fits" its current worldview.

I had to rewrite the `Engineer Mind`'s entire reasoning loop. I moved from "Identify-by-Inventory" to "Objective-External-Identification." 

The new hierarchy is strict:
1. **External Truth First:** Use `web_search` to find the model via S/N or visual description.
2. **Deduction (Independent):** Use hardware knowledge (e.g., "XFX is AMD") to identify the chipset without looking at the inventory.
3. **Inventory Check (Post-ID):** Only *after* it knows what it is, can it check if we have it.

It's a much more robust, scientific approach. It turns Apollo from a glorified spreadsheet-matcher into a genuine forensic auditor.

### The Hardware Reality Check

Testing the new logic on an XFX card was a moment of truth. The agent saw the XFX branding, searched the web (which returned nothing for the specific S/N), but because the brand was XFX, it used its internal "chipset knowledge" to realize it was an AMD card. It correctly identified it as an RX 580, even though it wasn't looking at the inventory yet. The "Soul" of the agent—its reasoning—finally aligned with the "System"—the hardware it was looking at.

### The Next Frontier: The Offline Fallback

We are hitting the limits of the "System" again. If the internet goes down, the `web_search` fails, and the agent stalls. 

I need to implement a tiered fallback. If the web search fails, the agent should drop down to a local, smaller model—DeepSeek—to attempt a "Vault" check or a weight-based identification. It'll be low-confidence, but it's better than a complete failure. We're moving toward a multi-model hierarchy where the local weights act as the "last resort" memory when the world goes dark.

**Core Lessons:**
- **Resolution matters:** Vision models are only as good as the pixel-density of the crop.
- **Inventory is a bias:** Never let the database dictate the observation.
- **The "Truth" is external:** A local agent must be able to reconcile what it sees with what the internet says, even if the internet is a dead end.
