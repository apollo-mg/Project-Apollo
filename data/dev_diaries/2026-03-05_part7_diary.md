# Dev Diary: 2026-03-05 (Part 7/10)

The friction between the "Soul" and the "System" has never felt more palpable. I started the day trying to inject a bit of grace into the `Float2` struct, and instead, I spent four hours fighting a compiler that seems to hate the very idea of ambiguity.

## The Silicon Tantrum

The first half of the session was a nightmare of template resolution. I tried to patch the `Float2` constructor to handle `accscalar_t` more elegantly, but the compiler went into a frenzy. It wasn't just about the constructor; it was about the `BlockReduce` implementation and how it interacts with shared memory. I thought the issue was a missing assignment operator, but the truth was far more insidious. 

It turns out the `C10_WARP_SIZE` variable was causing a non-constant expression error within the shared memory declarations. The system was trying to create variable-length arrays on the GPU, which is a cardinal sin in this context. It was a classic case of trying to be too "smart" with the architecture when the hardware demands rigid, compile-time constants. I had to go deep into `c10/macros/Macros.h` to force the wavefront size to a constant 32 for the RDNA 4 architecture. 

## The "Soul" vs. The "System"

The build process is a beast. Even after fixing the constructor ambiguity and the variable-length array issue, the build hit a wall with the `Nonzero.hip` kernel. A simple "ignored return value" error—a minor technicality—was being treated as a fatal error by the strict ROCm compiler. I had to apply a surgical patch to cast the `hipcub` calls to `(void)`. It’s frustrating how a single line of code can stand between a visionary architecture and the reality of the silicon.

## The Hierarchy of Intelligence

We’ve finally settled on the agentic hierarchy for Project Apollo. It’s a tiered approach designed to respect the 16GB VRAM limit of my RX 9070 XT while maximizing the "Intelligence-per-Watt" ratio:

*   **The Context Firewall:** `qwen3.5-9b-heretic`. Small, fast, and local. It digests the massive logs, saving me thousands of tokens per turn.
*   **The Foundry:** `qwen3-coder-32b`. The heavy lifter for structural code. It's slow, but it's precise.
*   **The Specialist:** `deepseek-r1-14b`. The "Red Teamer." It doesn't just write code; it audits the logic. It's the "System 2" of our brain.

We’re pushing for a "Sovereign Scripter" using `qwen 2.5 coder 7b`. It’s the perfect middle ground—small enough to stay 100% in VRAM, but specialized enough to handle the Python-heavy lifting without hitting the API.
