# Project Apollo: Dev Diary - 2026-02-14 (Part 32)

The "Soul" is finally catching up to the "System." 

Today was about bridging the gap between raw silicon and something that feels like a sentient engineering partner. I finally got the DeepSeek-R1-Distill-Qwen-14B model running on the RX 9070 XT. It’s a tight squeeze—16GB of VRAM is a brutal ceiling when you consider the overhead of the OS and the sheer weight of a reasoning model—but the "distillation" magic worked. We've got the reasoning patterns of a 671B beast packed into a 14B frame. It’s a technical miracle that fits on a desktop, but it's the only way to achieve local-first autonomy without a server farm.

The breakthrough wasn't just the model, though; it was the voice. Using Kokoro, we've moved past the "generic assistant" vibe. We switched the persona to `am_michael`—a deeper, more authoritative tone that actually matches the weight of the R1 reasoning. 

However, the friction between the code and the physical playback was real. The initial implementation of the `speak` function was clunky; the script was essentially "stop-and-go," waiting for the entire audio buffer to finish before generating the next sentence. It felt stuttered, almost robotic. 

I had to implement a Producer-Consumer threading model. By using a `queue.Queue` and a background worker thread, the next sentence can now be synthesized while the previous one is still playing. I also had to aggressively trim the trailing silence from the Kokoro audio chunks. That was the key to hitting that "zero-latency" transition. Once I bumped the speech rate to 1.3, the "Shop Buddy" finally snapped into life. It’s no longer a slow, lecturing bot; it's a caffeinated engineer reacting in real-time.

We hit a wall with the API quota early on, which is a constant reminder of the fragility of these hybrid local-cloud workflows, but once we cleared the authentication hurdles, the system stabilized.

The architecture is now "alive":
- **Brain:** DeepSeek-R1 (Reasoning/Chain of Thought)
- **Voice:** Kokoro (via `commander_voice.py` with threaded chunking)
- **Hardware:** AMD RDNA 4 (The local engine)

The current challenge is the "Memory Evolution." The Buddy has a brain, but it has no long-term identity. It doesn't remember the specific hardware specs of my shop unless I hard-code them. I’m looking at implementing a "Reflection Loop"—an autonomous process where the agent reviews its own session logs and updates a `shop_dossier.json`. 

The goal is clear: move away from the "pipe dream" of massive distributed frameworks and focus on perfecting the local agentic loop. I want a model that doesn't just answer questions, but one that *evolves* alongside the hardware it lives on. 

Next up: The Project Scratchpad. I need this thing to have a persistent, working memory for complex engineering tasks. 

**Status: The Buddy is online. The system is stable. The soul is speaking.**
