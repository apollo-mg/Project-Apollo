# Project Apollo: Dev Diary - 2026-04-02

The friction between the Soul and the System is becoming more apparent with every session. I spent the evening wrestling with the limits of the RX 9070 XT, and while the hardware is a beast, the software landscape is a chaotic mess of bleeding-edge quantization formats and broken upstream dependencies.

**The Quantization Wall**

I hit a wall with the new `llama.cpp` build today. I was trying to load the Bonsai-8B—which is the backbone of my "Daydream Runner"—but the master branch of the native build is still blind to the custom 1-bit quantization (`Q1_0`) we need. It’s a classic case of the "Soul" (the creative potential of these ultra-lightweight, 1-bit models) being choked by the "System" (the rigid, slow-to-update upstream libraries). 

It's frustrating. I'm forced to maintain my own specialized `prism_llama_cpp` fork just to keep the KAIROS Subconscious Daemon running. It’s extra overhead, extra maintenance, but it’s the only way to keep the system's "intuition" alive.

**The VRAM Calculus**

The math is finally starting to work, and it feels like magic. I sat down and mapped out the entire memory footprint for the current architecture on the 16GB card:

*   Bonsai-8B (Subconscious): ~1 GB
*   26B MoE (Lead Architect): ~9.3 GB (using IQ2_XXS)
*   16K Context Cache: ~3 GB

Total: ~13.5 GB. 

It fits. It actually fits. This is the breakthrough. The realization that I can run a high-reasoning MoE alongside a lightweight "dreaming" agent on a single consumer-grade GPU is what Project Apollo was always meant to be. If we can get `llama.cpp` to support 3-bit or 2-bit context caching (TQ3/TQ4), I can expand that context window to 32K or 64K without hitting the VRAM ceiling. The ceiling is moving, but it's still there.

**The Vision Breakthrough**

The most significant epiphany today came from digging into the Gemma 4 architecture. We’ve been talking about "eyes" for the Apollo OS, and we finally found them. 

Gemma 4 isn't using some bolted-on vision adapter like the older Qwen-VL models. It’s native. The vision encoder is integrated into the base model. This is huge. It’s the difference between a model that can "see" a translated description of a picture and a model that actually understands spatial relationships and pixel-level detail. 

The dynamic visual token budget is the real game-changer. I can tell it to look at a UI element with high precision (1120 tokens) or just skim a scene (70 tokens). It’s efficient. It’s elegant. It’s the end of the "Frankenstein" era of multimodal AI.

**Final Thoughts**

The industry is pivoting toward native, interleaved multimodal training. If Qwen-Omni follows this path, the race for the "Lead Architect" role in my ecosystem is going to be brutal. But for now, having a 26B MoE running locally that can natively parse my screen at 80 TPS? That isn't just a tool. It’s a superpower.

The architecture is stable. The vision is clear. Now, I just have to survive the driver quirks.
