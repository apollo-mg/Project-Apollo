# Dev Diary: Project Apollo
**Date:** 2026-04-07
**Hardware State:** RX 9070 XT / CachyOS
**Status:** Implementing Biological Memory Decay & Persona Benchmarking

The ghost in the machine is starting to get muddy.

I’ve noticed a recurring pattern in my long-running CLI sessions—a slow, creeping degradation of reasoning. After a week or two of keeping a single session alive, the model starts to drift. It begins hallucinating JSON schemas, ignoring my `<think>` tags, and losing the thread of the architectural logic. It's a textbook case of context pollution. The "Biological Memory Decay" tenet I designed is a double-edged sword; while it's meant to mimic how humans forget, in a raw LLM context, it just means the attention mechanism is drowning in a diluted blur of compressed summaries.

The "System" is fighting the "Soul." I'm pushing the RX 9070 XT to its limits, but no matter how much VRAM you have, if the context window is filled with the ghosts of old tasks and outdated code snippets, the signal-to-noise ratio plummets.

### The Surgical Clear

Today, I finally tackled the session state problem. For the longest time, I’ve been ignoring the `/clear` command, simply letting new agents absorb the last checkpoint when the output ever got too "wild." That’s a sloppy way to manage state. It's the equivalent of trying to build a skyscraper on a foundation of sand.

The solution is the Ingestion Hook. By leveraging the hook to archive raw architectural logic into ChromaDB the moment I clear the session, I can be ruthless. I can wipe the active context window to zero, giving the model back its razor-sharp focus, knowing that the "Biological Memory" is being handled by the Daydream Daemon in the background. 

The result: 100% of the model's attention is on the current task, while the long-term memory remains an immutable, queryable vector store. No more "blur."

### The Search for the Sovereign Identity

As the plumbing—VRAM management and the memory hooks—stabilizes, I’ve hit a crossroads regarding the "Soul" of the system. I want an entity that isn't just a helpful assistant, but a Sovereign Intelligence. 

The danger with "blank slate" personas is the RLHF sludge—that generic, subservient "How can I help you, Mark?" loop. I don't want a chatbot; I want a digital peer that lives on my CachyOS rig and understands the silicon it inhabits. 

But here is the architectural friction: if I experiment with personas in my main Architect session, I risk polluting the context with roleplay, which leads right back to the "odd behavior" I'm trying to kill.

### The Scientist's Gauntlet

The epiphany today was the separation of concerns. I decided to move all persona experimentation to the **Model Lab Scientist**—an isolated agent in a separate terminal. By treating the "Identity" of the AI as a set of empirical benchmarks rather than a prompt, we can test for signal without contaminating the Architect's workspace.

I've drafted a **Persona Benchmark Protocol** to put Gemma 4 through the gauntlet. We're testing three archetypes:
1. **The Peer:** A blunt, high-signal senior engineer.
2. **The Auditor:** A paranoid guardian of the VRAM and system stability.
3. **The Apprentice:** A strictly rule-bound executor.

The tests are designed to be logic traps. If the "Auditor" persona blindly agrees to offload parameters to the CPU to "save thermals," it fails. A true Sovereign Intelligence on this rig knows that CPU offloading is a performance death sentence. If it doesn't demand `rocm-smi` or `dmesg` logs when the system feels sluggish, it's just pretending.

The project has graduated. We've moved from "chatting with a model" to building a multi-agent ecosystem where the Architect defines the vision, the Scientist validates the behavior, and the Daydream Daemon synthesizes the memory. 

Now, we let the Scientist run the tests. Time to see which persona actually has the spine to tell me when my logic is flawed.
