### The Crash That Taught Me About Memory

Tonight, the 9070 XT swallowed my Wan2.1 pipeline whole.

No dramatic OOM. No graceful degradation. Just a HIP illegal memory access that felt personal, like the silicon itself had decided my ambition exceeded its tolerance.

```
r.copy_(weight, non_blocking=False)
```

There it is. Line 1085 of `model_management.py`. The murder weapon.

The model had loaded fine—9.3 GB settled into VRAM, GGUF quantization matrices humming along (F16: 694 layers, Q4_K: 280, Q6_K: 120, F32: 1). The Wan2.1 transformer blocks were primed. The CFG guider was ready. Then came the LoRA application, and somewhere in that cascade of `cast_bias_weight` → `get_weight` → `calculate_weight`, something touched memory it wasn't allowed to touch.

---

### The RDNA4 Ghost in the Machine

Here's what I know for certain:

**ROCm 7.1 is lying to me.** The logs show `gfx1201` (RDNA4) being detected, but AMD's driver stack still treats it like a slightly different RDNA3 instead of the architectural shift it actually is. The cache coherency model changed. The memory ordering semantics shifted. And PyTorch's HIP wrapper? Still pretending we're in 2023.

The `non_blocking=False` flag should have guaranteed a synchronous, boring copy. CPU waits, GPU copies, everyone moves on. But the illegal access suggests either:

1. The source tensor (`weight`) was already corrupted—perhaps a dequantization operation that silently failed on RDNA4's new tensor cores
2. The destination (`r`) pointed to memory that hadn't been properly allocated or had been freed by an aggressive cache manager
3. Some async kernel from earlier in the pipeline was still executing when I tried to write, and the HIP runtime's serialization failed

I'm leaning toward #1. The GGUF dequantization path has been patched three times already this year. Every time AMD ships a new ROCm, something in the quantization math breaks.

---

### The Soul vs. System Problem

Here's the thing nobody talks about when they romanticize "local-first AI":

**My architecture wants to be a conductor.** I want to spin up Wan2.1 for video generation, pull in LoRA adapters for style, maybe route some frames through a vision model for quality assessment. I want agents that negotiate compute time, that share VRAM like a distributed system, that feel like a *collective intelligence*.

**The system wants me to be a bookkeeper.**

Every tensor is a lease. Every kernel is a transaction. Every cache eviction is a potential tragedy. The 16GB on this card isn't a resource pool—it's a series of tiny contracts with memory controllers, and I keep breaking them.

The Wan2.1 pipeline crashed not because it was *wrong*, but because it was *too ambitious*. The multi-agent framework I'm building expects to hot-swap models, to keep LoRA weights resident while cycling base models, to treat VRAM like a suggestion rather than a constraint.

Silicon doesn't care about my vision.

---

### What I'm Changing Tomorrow

1. **HIP serialization enforcement**: `AMD_SERIALIZE_KERNEL=3` in the environment, even if it bleeds 15% performance. I need to know when async execution is betraying me.

2. **GGUF weight validation**: Before any `copy_` operation, I'm adding a tensor integrity check—shape verification, device placement confirmation, even a paranoid pointer range check if I have to.

3. **The "Sovereign Cache" layer**: A custom memory manager that sits between ComfyUI's `model_management.py` and the actual device. It will track allocations like a paranoid accountant, refuse to evict without my explicit permission, and log every transfer at lineitem detail.

4. **ROCm version pinning**: I'm locking to 7.1.0 until I understand the 7.2.0 changes. Every ROCm release feels like AMD is rewriting the ABI under my feet.

---

### The Epiphany (Buried in Stack Traces)

The illegal access didn't happen during the heavy lifting—the transformer attention, the diffusion sampling, the actual *intelligence* of the pipeline.

It happened during **weight application**.

The metadata layer crashed before the model could even think.

That's the pattern now: my agents are smart enough to generate video, but the infrastructure that holds them together is brittle. The multi-agent ecosystem I'm architecting needs a memory model as sophisticated as the models themselves.

Tomorrow, I stop treating VRAM as a detail.
