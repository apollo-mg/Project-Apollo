# Project Apollo: Dev Diary — 2025-11-21
## The Day I Taught Silicon to Behave

The RX 9070 XT glowed softly in the darkened server room, its 16GB of VRAM barely containing the 14-billion-parameter beast I was trying to force through its gates.

The Wan 2.1 model didn't want to fit. Neither did the kernel fuser, apparently.

### The RoPE Revelation

It started innocently enough—a memory leak that was bleeding us dry during RoPE calculations. The culprit? A naive upcast to float32 that was gobbling 1.5GB of VRAM at peak. 

```python
# Before: The wasteland
freqs_cis = freqs_cis.to(input_tensor.dtype)  # Still upcasting somewhere

# After: Surgical precision  
freqs_cis = freqs_cis.to(input_tensor.dtype)  # Match, don't dominate
```

A single line. One epiphany: *Why upcast when you can downcast?* The frequency tensor bowed to the input's dtype, and suddenly I had breathing room again.

But the real war was just beginning.

### The Illegal Memory Access Plague

```
torch.AcceleratorError: HIP error: an illegal memory access was encountered
```

This error message became my nemesis tonight. Not a crash. Not an OOM. An *illegal memory access*—the kind of vague accusation that suggests the GPU itself was questioning my life choices.

The stack trace led me to the FFN block, specifically to this innocent-looking line:

```python
y = self.ffn(torch.addcmul(repeat_e(e[3], x), self.norm2(x), 1 + repeat_e(e[4], x)))
```

Beautiful, compact, Pythonic. And completely unstable on RDNA 4.

### The Kernel Fuser Betrayal

Here's what I learned tonight: **PyTorch's kernel fuser lies to you.**

It promises optimization. It delivers fragmentation. It sees `torch.addcmul()` feeding directly into `self.ffn()` (which starts with GELU) and thinks: *"How delightful! Let me fuse these into one glorious, unbreakable kernel!"*

Except the kernel breaks.

The fix was almost embarrassing in its simplicity:

```python
# The betrayal
y = self.ffn(torch.addcmul(...))

# The reconciliation
ffn_input = torch.addcmul(...)
y = self.ffn(ffn_input)
```

A temporary variable. A memory barrier. A plea for stability. The kernel fuser, denied its fusion prey, backed off and let the operations breathe separately.

### The Fragmentation Tax

ROCm's memory allocator is... particular. The `expandable_segments` flag—useful on NVIDIA, promised by documentation—doesn't exist on this hardware. Trying to use it was like knocking on a door that wasn't there.

```bash
# The lie
expandable_segments: true

# The truth
max_split_size_mb: 128
```

Setting `max_split_size_mb` to 128 didn't fix fragmentation. It merely made it *manageable*. A smaller cage for the same demon.

### The Architecture of Compromise

Tonight taught me three hard lessons:

1. **Elegance is a vulnerability.** Clean, fused operations are optimization targets—and optimization is where silicon lies to you.

2. **Documentation is a suggestion.** Flags that exist in the docs don't exist on your hardware. The RX 9070 XT is a promise, not yet a reality.

3. **The model doesn't fit.** Not really. The Wan 2.1 14B parameter model barely squeezes onto 16GB even with every trick in the book. We're not running inference tonight—we're running a memory management simulator with dreams of sovereignty.

### Tomorrow's Battlefield

The multi-agent ecosystem can't be built on hardware that refuses to execute its own kernels. Tomorrow I'm disabling the Triton backend entirely, seeing if vanilla PyTorch attention is more honest about what it's doing with my memory.

Or perhaps I'll eat the performance cost and batch the operations manually. Give the scheduler explicit boundaries instead of trusting the fuser's good intentions.

The Sovereign Engine won't be born from compatibility. It'll be born from the scars of incompatibility, patched over one illegal memory access at a time.
