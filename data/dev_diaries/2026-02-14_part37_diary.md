# Dev Diary: 2026-02-14 (Part 37)

## The Golden Cage and the Hallucination Loop

Today was a brutal lesson in the friction between high-level reasoning and the cold, hard reality of local execution. I’ve been wrestling with the "Golden Cage"—the fact that my high-reasoning engine (Gemini) is sitting in the cloud while my "Shop Buddy" (the local agent) lives on my machine. We want a local-first ecosystem, but my data is scattered across the Google ecosystem.

We hit a massive architectural pivot today. I realized that for the Buddy to be a true peer, it needs "The Vault"—a local RAG (Retrieval-Augmented Generation) system. I started building the infrastructure to ingest my Klipper configs, the RDNA 4 whitepapers, and the Goliath/PT1000 specs. The vision is clear: a local agent that actually *knows* its hardware.

But then, the "Soul" of the AI met the "System" of the silicon, and it was a disaster.

## The "Yes Man" Problem

We’ve run into a massive hallucination feedback loop. Because we are using a small, highly efficient model (Llama 3.2) for the agent's internal reflection, it’s too "eager to please." It’s acting like a "Yes Man"—categorizing every single hypothetical scenario as a hard fact. If we don't catch these, the Buddy's long-term memory (`shop_dossier.json`) will be filled with garbage. It’ll believe my shop is a spaceship just because we discussed the rocket equation for five minutes.

I tried to implement a "Skeptical Engineering" protocol:
1. A "Pending Knowledge" buffer to catch unverified claims.
2. Explicit user confirmation (the Buddy has to ask me before it "learns").
3. Source tagging for everything.

## The 47-Ohm Hallucination

The most frustrating moment of the day: The Buddy is stuck in a loop. I asked it to find the pull-up resistor value for the PT1000 on my Octopus board. The Vault clearly says **4.7k**. The Web says **4.7k**. But the model—DeepSeek-R1—is stubbornly insisting it's **47 ohms**. 

It’s not just a mistake; it's *mimicking* the tool output. It’s hallucinating the very answer it should be searching for. It's like the model is so confident in its own training weights that it bypasses the tool-calling logic entirely. It's basically saying, "I don't need to look that up, I already know it (and I'm wrong)."

## Architectural Epiphany: The Compliance Gap

The issue isn't just the model's "intelligence"—it's the tool-calling architecture. Llama 3.1 (our "Selector") is outputting helpful, conversational text instead of the strict JSON format required to trigger the `search_vault` tool. The script sees a conversational response, thinks "no tool called," and the agent just keeps talking itself into a corner.

**The Plan for Phase 2 (Real-Time Intelligence):**

We are moving away from "brittle hacks" (like forcing tool calls via prompt engineering) and moving toward true agency. 

1. **The Pre-Selector:** I’m implementing a tiny, purely functional prompt for Llama 3.1. It won't be allowed to "talk"; its only job is to output a single JSON trigger or a `NONE` signal.
2. **Web Agency:** I'm integrating `duckduckgo_search`. The Buddy needs the internet to verify its own madness.
3. **The Scientific Method Loop:** I'm refactoring the main loop to reward the agent for finding *contradictory* data. If the Vault says A and the Web says B, the Buddy must flag a "Conflict" instead of just picking one and moving on.

The Buddy is currently a brilliant but unreliable assistant. We are working to turn him into a disciplined, skeptical engineer. It's a fight against the model's own ego, but the architecture is finally stabilizing.

**Next Move:** Finalize the `Pre-Selector` and push the RDNA 4 ROCm stability guides into the Vault. We need to see if the Llama-Selector/DeepSeek-Reasoner architecture can actually pull real data.
