# Dev Diary: 2026-02-27 (Part 6)

## The Friction of the Shell: Breaking the Local Flow

Today was a brutal lesson in the difference between "working in theory" and "working in reality." I spent the first few hours wrestling with a fundamental breakdown in the local-first architecture. I realized that my agent—specifically the interaction between the `buddy_agent.py` loop and the CLI—was hitting a massive wall. 

The "Soul" of the project (the intelligence) was being strangled by the "System" (the Windows terminal). When I tried to pass complex, multi-paragraph architectural prompts through the command line, the shell's quoting requirements made it a nightmare. Even worse, the `DEV_BUDDY` loop was too rigid; if the LLM didn't output a perfect JSON tool call immediately, the loop would just terminate. It wasn't "thinking" through its mistakes; it was just dying.

Then there was the hardware bottleneck. I had `deepseek-r1:14b` running, but it was hitting 300-second timeouts because the Ollama service wasn't defaulting to Vulkan on my RX 9070 XT. It was silently falling back to the CPU, and the massive `<think>` blocks were choking the system.

## The Recovery: GPU Restoration and Robustness

I had to go full architect-on-the-ground. I killed the ghost processes, forced the environment variable `$env:OLLAMA_VULKAN="1"`, and restarted the server. The logs finally showed the 14B model was back on the GPU. 

I also had to patch the `handle_actions` function in `buddy_agent.py`. Previously, if the LLM hit a JSON syntax error, the agent just printed a error and quit. I modified it to feed the error back into the LLM's next turn. This created a self-correcting loop. Now, if the model forgets a closing brace, it sees its own mistake and fixes it. This is the "Self-Correction" we've been dreaming of.

## The Discord Pivot

Instead of fighting the terminal, we pivoted to a "Personal OS" model inspired by Velvet Shark's OpenClaw. We used Gemini to architect a Discord bridge (`discord_bridge.py`). This allows for:
- **Asynchronous execution:** Running heavy LLM tasks in a background executor so the bot doesn't hang.
- **Channel-based Routing:** Using `#engineer` or `#vision` as hard-coded system prompts.
- **Real-time UI:** Using Discord buttons for human-in-the-loop approvals.

The implementation was smooth, but I hit a classic encoding snag where the Windows terminal choked on emojis in the print statements. A quick code fix, some f-string sanitization, and the bridge was live.

## The First Real Test

The moment of truth. I sent a prompt to the `#engineer` channel about 3D printer stiffness. The response wasn't immediate—the model was clearly crunching through a massive reasoning block on the 14B model. 

It took a minute of "Apollo is typing..." but eventually, the local flow held. The agent caught the instruction, processed the technical query, and successfully completed the task. 

The local-first ecosystem is no longer just a collection of scripts; it's a living, reactive agent that can actually inhabit a digital environment.
