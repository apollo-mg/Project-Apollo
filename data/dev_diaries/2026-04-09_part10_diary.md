# The Eleven Nodes and the SDMA Test

I sat down today with a handwritten list. Eleven distinct use cases—ranging from the "Live Note Taker" to the heavy "Legal/Technical Analysis." To a venture capitalist, these are eleven startups. To me, they are routing nodes for a single, sovereign architecture.

But the silicon doesn't care about my epiphanies. It only cares about the memory map.

The friction started with Bazzite. `radv` wasn't conformant. The `ggml_backend_init` was failing on Vulkan. That is the "System" pushing back against the "Soul." If I want that 26B-parameter Gemma model to dream in the background while I type, I need the hardware to speak truth to power.

So we switched to ROCm. But ROCm has its own quirks—memory fragmentation, VRAM limits. I was running a 20.5-hour stability test on my RX 9070 XT. Then the question came: Can we push `--cache-ram 2048`? Can the GPU reach directly into that 2GB of DDR system RAM via SDMA, or does the CPU have to spoon-feed the data over PCIe?

The math was simple: 1.2 GB base + 2.0 GB cache = 3.2 GB. The Process Manager showed 3.2 GB held. The allocation was pinned. But the real test is the thunder of the attention mechanism—will the DMA controller hammer that PCIe bus without the driver panicking with a `HIP illegal memory access`?

Today was about trusting the stack. We aren't just running models; we are tuning the bus. We are building the "one ring to rule them all"—the local infrastructure that routes intent to the exact right hardware profile. If the Daydream Daemon survives the night streaming KV cache over PCIe, then Project Apollo is bulletproof.
