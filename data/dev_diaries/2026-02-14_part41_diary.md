# Project Apollo: Dev Diary - 2026-02-14 (Part 41)

The friction between the "Soul" of the agent and the "System" of the silicon is reaching a boiling point. Today was a brutal, beautiful lesson in the volatility of local LLM-driven agency. I spent the morning wrestling with the sheer unpredictability of DeepSeek-R1's reasoning. It's brilliant, but it has a "helpful" bias that completely ignores structural constraints if it thinks a direct answer is more efficient.

**The Orchestrator Breakthrough**

The first major hurdle was tool-calling compliance. We needed the Shop Buddy to act like a real engineer, not just a chatbot. I implemented a Task Orchestrator—a hard-coded, keyword-driven state machine. It’s essentially a "Lead Engineer" layer that overrides the LLM's indecision. If the user says "run a test," the Orchestrator forces the sequence (create, list, delete) without waiting for the LLM to decide to call the tools. 

The result? Total reliability. We achieved 100% tool-call compliance for critical SIT (System Integrity Test) steps. The LLM is still doing the high-level reasoning, but the "System" now guarantees the execution. It's a hybrid architecture: hard-coded logic for safety-critical tasks, and LLM reasoning for peer-level analysis.

**The Memory Corruption & The "Skeptical Learning" Pivot**

Then, things got messy. A catastrophic `write_file` operation truncated my `buddy_agent.py` mid-session, wiping out the core logic. It’s a sobering reminder that when you give an agent autonomy over its own source code, the "System" can literally delete its own "Soul." 

Once I reconstructed the logic, I realized the "Soul" was too eager to believe everything. The knowledge system was becoming a graveyard of hallucinations. I pivoted to "Skeptical Learning v2." I implemented a "Verification Gate" where any new information is dumped into a `pending_knowledge` buffer with `low` confidence. 

The agent doesn't "know" anything new until it's verified. This is where the "Auditor" persona comes in. I've been trying to force the agent to act as its own skeptic, but the reasoning models are too focused on being "helpful" to stop and ask for permission. They just want to keep moving.

**The "Forced Audit" and the Compliance Gap**

I tried injecting mandatory confirmation prompts into the final reasoning pass. It didn't work. The models were simply bypassing the instructions. To fix this, I had to move away from "prompt engineering" and move toward "system enforcement." 

I implemented the **Forced Audit**: a hard-coded check in the Python loop that scans the conversation for pending claims. If a match is found, the system *forces* an injection: "Mark, confirm [CLAIM]?" at the end of the response. It’s no longer a suggestion; it’s a system-level interrupt. This bridges the gap between the LLM's desire to be helpful and the engineering requirement for accuracy.

**The Truth Guardian (Watchdog v1.0)**

The most ambitious part of today's session was the implementation of the **Fact Watchdog**. We're moving toward a truly multi-agent ecosystem where the Buddy isn't alone in his own head. 

The Watchdog is a background thread—a "Truth Guardian"—that periodically samples the `pending_knowledge` and cross-references it against the local `vault`. If there's a discrepancy (like the PT1000 pull-up resistor value being different in the vault vs. the agent's memory), it flags it as `disputed`. 

I’ve even integrated a "Selective Web Search" capability. If a pending claim involves specific versions or technical specs, the Watchdog can reach out to the web to verify. It’s a tiered defense: Local Vault -> Selective Web -> Human Confirmation.

**Current Status & Next Steps**

The Shop Buddy is now a **Self-Auditing Partner**. It is no longer just a reasoning engine; it is a system that actively monitors its own integrity. 

The `pending_knowledge` list was becoming a mess of half-baked ideas, so I've been performing manual "Knowledge Curation" to keep the memory clean. The architecture is finally stabilizing.

Next up: The **Background Watchdog** deployment is officially Phase 3. We are moving from a single-agent setup to a distributed, self-correcting system. The real test will be seeing how much VRAM the Watchdog's Llama 3.2 3B model eats while the main reasoning engine is running. My 9070 XT is about to work very hard.
