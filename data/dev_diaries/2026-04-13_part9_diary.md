**Date: 2026-04-13 (Part 9 of 12)**

**The Parameter Name War**

I was in the weeds today, debugging tool-calling on the Gemini CLI. It’s the simple things that trip us up. `path` versus `file_path`. A missing parameter name sent the `read_file` tool into an immediate error loop. Then it tried to write to `/tmp`, which the security guard at the workspace gate rejected—too far from the origin.

**The Heretic Problem**

The real friction came from the models. I swapped from the reliable Qwopus 27B to the Heretic—Qwen 3.5 27B-Claude-4.6-OS-Auto-Variable-Heretic-Uncensored-Thinking. A name that sounds like it was made by a committee. The Heretic is trained to daydream, to think long and hard without guardrails. But its tool-calling is idiosyncratic. It fired a `web_fetch` tool with empty arguments `{}` because it was trained on the SGLang schema, not the OpenAI wrapper I was serving.

This is the classic Soul versus System friction. The Soul (the creative, wandering thought) wants to run; the System (the cold, hard JSON schema) demands a format.

**The Shock Absorber**

I didn’t want to rip the backend apart to run a full vLLM instance just for this. Instead, I built a shock absorber. A surgical patch in `sovereignContentGenerator.ts`. Now, when the CLI sees that empty payload, it doesn’t crash. It scans the model’s thought block for a URL, finds the target, and injects it into the prompt. It catches the drift.

Same with Gemma 4. Its templates are mathematically strict, a different kind of tyrant.

**The Lesson**

The local-first multi-agent ecosystem is going to be messy. We will have Qwopus here, Heretic there, and Gemma 4 over by the VRAM constraint. If we want true autonomy, our tool-calling layer cannot be brittle. It must be a translator, not just a transmitter.

I’m building a CLI that can handle the drift. That is the goal.
