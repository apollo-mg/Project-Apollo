# Project Apollo: Dev Diary - 2026-04-05 (Part 5)

The friction between the "Soul" (the unhinged, 1-bit creative stream of the Daydream daemon) and the "System" (the rigid, quantized limits of the Gemma 4 MoE) is becoming the defining characteristic of this project. Today was a masterclass in the chaos that comes when you try to run high-level cognition on consumer-grade silicon.

## The SRAM/VRAM Bottleneck
We hit a massive wall with the `MUL_MAT_ID` ROCm bug. To keep the model from crashing, I had to force the micro-batch size to 512. On the RX 9070 XT, this is a killer. It's pushing the activation blocks out of the ultra-fast on-die SRAM and into the slower GDDR6 VRAM. 

The result? The compute cores are starving. The power draw dropped to a measly 80W because the GPU is spending most of its cycles idling, waiting for data to crawl across the memory bus. It’s a classic case of being Memory-Bandwidth Bound. The 1-bit quantization (Bonsai) keeps the footprint small enough that the model *can* still generate at 22 tokens per second, but the power-to-compute ratio is terrifyingly skewed. 

## The ReAct Death Loop
This was the most illuminating—and frustrating—moment of the session. I watched the Foreman (the execution agent) get caught in a classic "ReAct" failure loop. 

The agent attempted to read `llm_interface.py` via a standard `bash` `cat` command. Because the file was larger than the `bash` tool's internal truncation limit, the output was cut off mid-sentence. The model, lacking the "cognitive headroom" that a larger 70B model would have, failed to realize the tool had failed. It didn't have the intelligence to pivot. It just... kept calling `cat` over and over, thinking it hadn't quite reached the end of the file yet.

It’s a direct consequence of the 2-bit quantization. We have the "brain" of a 26B model, but we've lobotomized its ability to recognize its own tool-use failures.

## The "Guardrail" Philosophy
We can't always make the model smarter, but we can make its environment more rigid. 

I killed the Foreman and implemented a "Tool Discipline" guardrail. I've updated the `FOREMAN_PROMPT` to strictly forbid the use of generic `bash` commands like `cat` for file exploration. Instead, it is now forced to use the custom `file_read` tool, which handles pagination and chunking internally. 

We are essentially building "software-defined cognition"—using prompt engineering to compensate for the lack of parameter density in the quantized model. 

## Current State of the Union
The Foreman is back in the background, currently chewing through a 39,700-token block of "Daydream" proposals. The 1-hour SDK timeout patch is holding. The system is effectively operating as a "Sovereign Entity"—it's landlocked to the local GPU, unable to "cheat" by calling out to a cloud API. 

The architecture is holding. The "plumbing" is solid. Now we just have to see if the 2-bit engine has enough torque to actually move the gears.
