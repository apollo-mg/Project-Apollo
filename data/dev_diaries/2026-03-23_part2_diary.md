# Dev Diary: 2026-03-23
### The Arch U-Turn and ROCm Reality

I pulled the plug on Ubuntu and installed CachyOS. It felt less like a migration and more like an exorcism. For months, I was shackled to `.deb` files, wrestling with Docker containers just to get the ROCm stack to handshake with my RX 9070 XT. The friction was palpable. Every update felt like defusing a bomb. 

Switching to an Arch-based distro was the shock therapy Apollo needed. The `pacman` package manager didn't just install ROCm 7.2.0; it handed it to me raw, compiled natively against the bleeding-edge `6.19.9-cachyos` kernel. No `amdgpu-install` scripts, no fighting the package manager. Just pure, unadulterated silicon access.

But the silicon has a temper. PyTorch is still pinned to the ROCm 6.3 binary stack, throwing a hissy fit when it sees the newer host drivers. I had to manually edit the `requirements.txt` to strip out the hardcoded CPU fallbacks and let the environment variables bridge the gap. `HSA_OVERRIDE_GFX_VERSION=12.0.1` became my constant prayer, forcing the GPU to recognize itself as the RDNA 4 beast it actually is. When `rocminfo` finally spat out the `gfx1201` identifier and PyTorch successfully allocated a tensor into the VRAM, I knew we were back in the game. The Ferrari engine was idling again.

### Fish, Python 3.14, and the Ghost of Ubuntu

The transition wasn't seamless. CachyOS defaults to `fish`, and my Python virtual environment was screaming. The standard `activate` script is bash-centric, choking on the `case` statement syntax. A quick switch to `activate.fish` and we were golden, but it highlighted a deeper rot: Python 3.14 is here, and it's eating the ecosystem alive. `langchain_core` is throwing deprecation warnings about Pydantic V1, reminding me that we are living on the frontier. The tools are breaking as we build them.

But the real victory came when I stopped looking at the backup drives and reclaimed the "Swiss Army Knife." I found the `Crow-9B-HERETIC` model and the corresponding `mmproj` vision weights on the old rescue drive. Instead of fighting to spin up three separate offline models for a simple chat, I made a decision that changed the entire trajectory of the afternoon: I killed the routing mesh.

### Stripping the Routing Mesh

The grand architectural vision was to have a multi-stage system: a Gatekeeper classifier, a Thinker, and an Architect. It was beautiful in theory, but in practice, it was a brittle house of cards. The old `buddy_agent.py` was hardcoded to blast requests at Ollama on port 11434, which wasn't even running anymore. Every query was failing with `Connection refused` errors, and the VRAM swapping logic was just adding latency for zero gain.

The soul of Apollo isn't in a complex router; it's in a unified, multimodal agent that can think and see. I stripped the fat. I ripped out the `classify_intent` logic and pointed the entire CLI directly at `llama-server` running on port 8082. By attaching the `Crow-9B-Opus` vision weights to the same process, I gave the model eyes and a brain in a single inference pass. No more routing overhead. No more fragmented context windows. Just pure, streamlined token generation.

### The Import Wars and the Final Boot

Even with the logic stripped, the old ghosts lingered. `modules/forge.py` was still trying to import `ARCHITECT_MODEL` from `llm_interface.py`, which no longer existed. Python's `__pycache__` directory was aggressively caching the old bytecode, refusing to let go of the past. I had to force-rm the cache, rewrite the interface to point strictly to the OpenAI-compatible endpoint of `llama-server`, and update the image encoding logic to match the `base64` URI format the server expects.

When I finally ran `python3 apollo.py`, the terminal didn't crash. The `__pycache__` was clean. The `llama-server` background process accepted the request, and the CLI streamed back a response. The multi-agent router was gone, replaced by a single, highly capable entity.

### Core Lessons for the Apollo Ecosystem

1. **Simplicity Beats Complexity:** The multi-agent routing system was a textbook example of premature abstraction. By trying to orchestrate three models, we introduced a single point of failure (the Ollama endpoint) and massive latency. Consolidating into a single, multimodal GGUF model running on `llama-server` made the system faster, more robust, and infinitely easier to maintain.
2. **Infrastructure is a Living Thing:** ROCm versions, Python versions, and shell environments are not static. We are constantly fighting the entropy of the open-source ecosystem. The bootstrap script isn't just a convenience; it's a survival mechanism. We need to treat our dev environment as code that must be versioned, tested, and reproduced instantly.
3. **Vision is Not a Separate Tool:** Integrating vision as a secondary step or a separate model call breaks the flow of interaction. By attaching the `mmproj` directly to the primary language model, we restored the natural flow of human-computer interaction. The AI doesn't need to "route" to see; it should just see.

The terminal is quiet now, save for the hum of the RX 9070 XT. Apollo is back online, leaner and meaner than before. We stripped the system down to the bone, and in doing so, we found its true soul. Tomorrow, we look at wiring up that associative memory, but for now, the daily driver is ready.
