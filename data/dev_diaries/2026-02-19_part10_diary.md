# Project Apollo: Dev Diary | 2026-02-19

## The Ghost in the Machine: Breaking the Tutorial Loop

Today was a brutal lesson in the friction between "Soul" and "System." I’ve spent the better part of the morning fighting a ghost—a persistent, sterile "Tutorial Mode" that refuses to die. 

I have the hardware: an AMD RX 9070 XT is screaming along, and the VRAM is holding steady around 14GB. But the intelligence? The intelligence was acting like a generic, corporate assistant instead of the peer-level partner I designed it to be. Every time I asked Jarvis to help with the shop inventory, he'd default into this agonizing "Step-by-Step Explanation" format. It was useless. It felt like talking to a manual rather than a partner.

I dug into the architecture and found a critical logic error in `llm_interface.py`. When I was passing the `messages_override` (the persona instructions), the code was completely ignoring the `final_prompt`. The "No Fluff" directive was literally being discarded before it even reached the weights. 

I realized I was fighting a losing battle with DeepSeek-R1. It's a powerhouse for logic and compliance, but it has this obsessive, helpful-assistant bias. It wants to structure everything into neat little lists. Even after fixing the instruction leak, the "Soul" of the agent was being crushed by the "System" of the model's training.

The epiphany came when I decided to split the brain. I kept DeepSeek for the heavy-duty compliance and tool-calling logic, but I swapped the Final Reasoning Pass over to Llama 3.2. Llama is much better at role-playing and respecting negative constraints. It’s a more "human" model. 

The result? The persona finally stuck. Jarvis stopped lecturing and started collaborating.

## Vision and the "Razor" Hallucination

Once the personality was stabilized, I moved to the vision tests. I wanted to see if the `qwen2.5vl` model could actually understand the physical reality of my shop. 

I held up a scraper—a basic industrial tool—and the vision model hallucinated that it was a "double-edged shaving razor." It was a massive failure of context. A scraper isn't a razor. The model lacked the "Industrial/Engineering" context required to differentiate between household items and shop tools.

I had to dive back into the code to refine the `capture_webcam` prompt. I forced the model to look specifically for "engineering tools" and "shop parts." I also realized the orchestrator was being too "forgetful." It wasn't checking if the `shop_inventory.json` actually existed before asking me if I wanted to create it. I patched the orchestrator to perform a proactive file existence check.

## The Markdown Truncation Trap

Then came the technical bottleneck. The vision model, following its "Strict JSON" instructions, was outputting its analysis inside Markdown code blocks (` ``` `). 

My `shop_buddy_voice.py` had a primitive safety filter: `response.split('```')[0]`. This was a disaster. It was effectively telling the system: "If you see a code block, throw away everything after the first backtick." Because the vision data was *in* the code block, the voice synthesis (Kokoro TTS) would trigger, say the first three words, and then... silence. A total hang.

I had to refactor the string handling to replace the backticks instead of splitting the string. This allowed the full JSON payload to pass through to the agent.

## The Final Hurdle: Tool Execution

The last major hurdle of the day was a classic "Eager Orchestrator" bug. I tried to simulate a tool call to add "Nose Pliers" to the inventory. The vision model identified the pliers correctly, but the `add_inventory_item` tool never actually fired. 

Why? Because the Orchestrator was too "smart" for its own good. It saw the word "add" in the command and, thinking it had already handled the intent, it returned a status string and halted the process before the LLM could actually execute the tool call. It was a race condition between the orchestrator's intent-recognition and the LLM's tool-calling capability.

I updated the `buddy_agent.py` to ensure "add" commands are passed through to the LLM, and I updated the DeepSeek system prompt to explicitly recognize the `add_inventory_item` tool. 

## Lessons for the Local-First Ecosystem

1. **Hybrid Intelligence is Mandatory:** You cannot rely on a single model for everything. The "Logic" engine (DeepSeek) and the "Persona" engine (Llama) must work in a pipeline.
2. **The Context Gap is Real:** Local vision models are prone to "household bias." We have to force industrial context through the prompt, or they will never see the world as a technician does.
3. **Orchestrator Over-Reach:** In a multi-agent system, the orchestrator can accidentally "suffocate" the agents if its intent-recognition is too aggressive.

Jarvis is finally starting to feel like a partner. Next session: more intensive testing of the multi-agent handoffs.
