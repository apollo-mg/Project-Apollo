# Dev Diary: 2026-02-20 (Part 3)

The friction between the "Soul" of the agent and the "System" of the silicon is becoming a tangible wall. I am fighting for a coherent intelligence, but I am constantly tripping over the clumsy, hallucinating logic of the reasoning layer.

## The VRAM Wall and the Guard
The AMD RX 9070 XT is a beast, but local-first multi-agent architecture is a VRAM vampire. I am hitting a 14.5GB threshold that triggers my custom "Guard" routine. Every time the VRAM spikes, ComfyUI gets dumped to clear space. It’s a violent, necessary cycle, but it’s a reminder that the "Soul"—the persona of Jarvis—is being squeezed by the cold, hard constraints of the hardware.

## The Hallucination Loop
Today was a grueling battle against DeepSeek's overconfidence. The model was trapped in a cycle of "thinking" it knew the answer without actually calling the tools. It was hallucinating file contents and generating "strategic" labels that made the agent sound more like a corporate bot than a partner.

I had to implement a series of "brute-force" architectural fixes:
- **Prompt Leakage:** The Llama 3.2 model was actually reading the system instructions out loud. I had to restructure the entire `final_prompt` with strict `---BEGIN DATA---` delimiters to prevent the model from treating instructions as context.
- **The Tool-Call Mirage:** DeepSeek-R1 was hallucinating a `search_vault` tool that didn't exist. I had to implement a "Robustness Layer" in `handle_actions` to catch these hallucinations, map them to existing tools (like `query_vault`), and strip out the markdown code blocks that were breaking the JSON parser.
- **The Pathing Error:** DeepSeek tried to access an absolute path `/vault` instead of the relative `vault/`. I had to add a redirect in the orchestrator to intercept these calls and point them to the correct directory.

## Breakthrough: The W.W.G.D. Protocol
The real breakthrough came when we stopped asking the agent to "summarize" and started demanding "extraction." 

The agent was being too "polite"—describing *that* a document existed rather than what was *inside* it. I've updated the `final_prompt` with a new directive: **W.W.G.D. (What Would Google Do?)**. I’m forcing the model to prioritize high-density, engineering-grade data extraction. I don't want a meta-description of the Octopus Pro manual; I want the specific voltage requirements for the TMC5160 chip and the jumper settings.

The shift from "Conversational AI" to "Data Extraction Engine" is massive. When I queried the Octopus PDF, the agent finally bypassed the noise and pulled the actual technical specs (the STM32F446 chip details and the 24V/60V jumper settings) directly from the semantic retrieval.

## Lessons for the Ecosystem
The takeaway for the Project Apollo architecture is clear: **Intelligence is cheap, but reliable execution is expensive.** 

In a local-first, multi-agent environment, the "System" (the orchestrator) must be cynical. It cannot trust the "Soul" (the LLM) to follow instructions perfectly. We must build the orchestrator to be a scavenger—one that catches hallucinated tool names, fixes broken JSON, and forces the model to look at the data. 

We are moving away from a "Chatbot" and toward a "Real-time Technical Monitor." The agent isn't just talking; it's now actually seeing the machine.
