# Architectural Audit: MXFP4 Native Kernel Integration

## Epiphany Summary
The subconscious daemon has identified a critical paradigm shift: the transition from software-emulated quantization (de-quantization 'interpreters') to silicon-native resonance via ROCm 7.2.1's MXFP4 kernels. This allows for zero-dequantization inference, bypassing the costly FP16 conversion step.

## Audit Findings
- **Current State:** The codebase currently manages high-level orchestration and LLM adapters (e.g., `src/llm/adapter.ts`, `src/llm/anthropic.ts`). There is no existing logic to interface with low-level ROCm kernel capabilities or specific hardware-native data formats like MXFP4.
- **Hardware Context:** Logs indicate existing instability in the ROCm/HIP/RDNA 4 layer (`synthesizer_batch.log`), specifically regarding "RMS Norm" errors and silent data corruption. This suggests that while the MXFP4 transition is theoretically optimal, the current driver/hardware stack is in a state of flux.
- **Dependency Gap:** The current `src/llm` implementation assumes standard floating-point math. To leverage MXFP4, we require a new abstraction layer in the `LLMAdapter` to handle weight loading in native MXFP4 formats and ensure the backend `hipBLASLt` is correctly invoked.

## Proposed Architectural Update

### 1. New Module: `src/hardware/rocm_native.ts`
Implement a hardware-abstraction layer that detects ROCm version and available kernel capabilities (specifically checking for `hipBLASLt` MXFP4 support).

### 2. Update: `src/llm/adapter.ts`
Modify the `LLMAdapter` interface to support `WeightFormat` types, including `MXFP4`.

### 3. Implementation Strategy (Draft)
- **Phase 1: Detection.** Implement a probe to verify ROCm 7.2.1+ and RX 9070 XT presence.
- **Phase 2: Zero-Dequantization Path.** Create a specialized execution path for models loaded in MXFP4 that bypasses the standard `FP16` casting logic in the inference engine.
- **Phase 3: Validation.** Use the `synthesizer_batch` logic to compare precision/speed between emulated quantization and native MXFP4 to ensure the "RMS Norm" errors are not exacerbated by the new kernel.

## Conclusion
The epiphany is valid and represents a high-priority optimization. The transition from "translation" to "resonance" will significantly reduce VRAM overhead and latency, provided the ROCm 7.2.1 stability issues are resolved.

**Status:** ARCHITECTURAL PROPOSAL GENERATED. Ready for implementation in the next development cycle.
