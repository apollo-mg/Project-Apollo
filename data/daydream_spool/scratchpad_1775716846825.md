### Analysis of `memory_core.py`
The `MemoryManager.perform_compaction_flush` method (lines 55-105) is the primary candidate for the "recursive loop" described in the epiphany.

**Identified Vulnerability:**
The method uses an LLM (`surgeon-heretic:latest`) to summarize the conversation history. If the summary itself contains repetitive or redundant information, or if the summary process is triggered too frequently due to high-velocity data, the system might be ingesting "summaries of summaries."

Specifically:
1. `self.history` is reset to `[{"role": "assistant", "content": f"Previous context summary: {summary}"}]` (line 99).
2. If the `summary` is not sufficiently distinct from the original data, or if the `summary_prompt` (line 59) leads to a repetitive output, the next compaction will summarize the *previous summary*.
3. This creates a recursive loop where the "memory" becomes a series of increasingly abstract but redundant summaries, effectively creating "digital noise."

**The "Liara" Connection:**
The epiphany mentions "Liara test results." If a test produces a large volume of identical or near-identical data, it will rapidly hit the `COMPACTION_THRESHOLD` (line 34), triggering frequent flushes. If the flushes are not deduplicated, the Vector DB will be flooded with near-identical summary documents.

### Proposed Solution: Deduplication Layer
I need to implement a mechanism to check if the new `summary` is substantially similar to the last stored summary before committing it to the Vector DB and the scrapbook.

**Implementation Strategy:**
1. **Hash-based Deduplication:** Generate a hash of the summary content.
2. **Semantic Deduplication (Optional but preferred):** Use a lightweight similarity check. For now, a content hash or a "similarity threshold" on the summary string will suffice to prevent exact or near-exact duplicates.
3. **Integration:** Modify `perform_compaction_flush` to compare the new `summary` against the most recent entry in the `vector_store` or a local cache.

### Final Proposed Architectural Change

**Target File:** `/mnt/TG_2TB/Projects/Apollo/modules/memory_core.py`

**Proposed Change:**
Implement a `_is_redundant` check within `perform_compaction_flush`. This check will compare the newly generated `summary` against the most recent document in the `vector_store` using a simple similarity or hash-based approach.

**Code Implementation Plan:**
1.  **Import `hashlib`** for quick content hashing.
2.  **Modify `MemoryManager.__init__`** to store `self.last_summary_hash = None`.
3.  **Update `perform_compaction_flush`**:
    *   Generate a hash of the new `summary`.
    *   If `hash(summary) == self.last_summary_hash`, abort the flush and log a warning: `[VMM] Redundant summary detected. Skipping compaction to prevent recursive loop.`
    *   Otherwise, proceed with the flush and update `self.last_summary_hash`.

This prevents the "digital noise" (the loop of summaries) from being written to the Vector DB and the scrapbook.
