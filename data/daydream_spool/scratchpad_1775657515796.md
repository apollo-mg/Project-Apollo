# Scratchpad: Epiphany Investigation
- **Epiphany:** `sed` and regex-based shell commands are prone to corruption when handling special characters (e.g., `\v`) due to shell/tool interpretation conflicts.
- **Actionable Insight:** Ban regex-based shell commands for structural edits; mandate high-level scripting (Python) for literal string handling.
- **Objective:** Audit the codebase for instances of `sed`, `awk`, or other regex-heavy shell commands used for code modification or structural changes.
- **Initial Audit Findings:**
    - Found `sed` usage in `.git/hooks/` (standard git samples). These are likely non-critical for the project's core logic but represent the pattern.
    - Found `sed` in `./.git/hooks/update.sample`.
    - Found `sed` in `./.git/hooks/commit-msg.sample`.
    - The `synthesizer_batch.log` mentions "fragmented shell scripts" as a current identity, which aligns with the Epiphany's warning about "quick" low-level tools.
- **Hypothesis:** The project may contain build scripts, CI/CD pipelines, or maintenance scripts that rely on `sed` for file manipulation, which could be a source of "recursive corruption" if they encounter complex characters.
- **Next Steps:**
    1. Search specifically for `sed` in `.sh`, `.py`, `.js`, or `.yml` files to identify potential automation/build scripts.
    2. Look for `sed` usage in `package.json` scripts.
- **Refined Audit Findings:**
    - The `find` command returned many files in `dist/` and `node_modules/`. These are likely compiled/transpiled files or dependencies, not the source of the problem.
    - I need to focus on the *source* files (e.g., `.ts`, `.py`, `.sh`) rather than the `dist/` or `node_modules/` directories.
    - I will now search for `sed` or `awk` specifically in the source directories, excluding `dist` and `node_modules`.
- **Action Plan:**
    1. Run a targeted `grep` on source files (excluding `dist` and `node_modules`).
    2. Check `package.json` for any `scripts` that use `sed`.
    3. Check for any `.sh` files in the root or `scripts/` directories.
- **Audit Conclusion:**
    - No instances of `sed` or `awk` were found in the core source code (`.ts`, `.py`, `.js`) or build scripts, excluding standard `.git/hooks` and `node_modules`.
    - The `synthesizer_batch.log` entry is the most significant finding, as it explicitly identifies "Script-based (fragmented shell scripts)" as a current state that needs to transition to "Orchestrated (parameterized profiles)". This confirms the Epiphany's concern about the risks of low-level, fragmented shell-based automation.
- **Final Assessment:**
    - The codebase is currently "clean" of dangerous `sed` usage in its primary logic, but the *architectural pattern* of using fragmented shell scripts is present and flagged as a risk in the logs.
    - The Epiphany is valid as a preventative architectural principle.
- **Proposed Action:**
    - Formalize the "High-Level Scripting Mandate" in the project's architectural guidelines.
    - Any future automation involving structural code changes must use Python (or a similar high-level language) with literal string handling to avoid the "regex-shell collision" risk.
    - Prioritize the transition from "Script-based" to "Orchestrated" agent identities as noted in the logs.
