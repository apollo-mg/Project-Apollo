# Apollo Investigation Log: RDNA/gfx1201 MMA Mapping

## Initial State
- **Epiphany:** TileLang backend is biased towards CDNA. Need to implement `mai-insts` feature mapping for `gfx1201` (RDNA) to enable native MMA instruction recognition.
- **Goal:** Audit TileLang C++ backend to identify where architectural paradigms are hardcoded and where `mai-insts` mapping can be extended.

## Investigation Steps
1. Locate TileLang source code.
2. Identify the backend implementation (C++).
3. Search for existing `mai-insts` or MMA instruction mapping logic.
4. Check for `gfx9xx` (CDNA) specific hardcoding.
5. Draft proposal for `gfx1201` integration.
## Findings
- The `rdna4_tilelang_postmortem.md` file confirms the epiphany: TileLang lacks `mai-insts` mapping for `gfx1201`.
- The failure mode is specifically identified as the inability to resolve hardware intrinsics for MMA (Matrix Multiplication-Accumulation) on RDNA4, even when attempting to re-route existing logic.
- The current backend is heavily biased towards CDNA (likely `gfx9xx`) architectures.
- The "Compiler Legalization Trap" mentioned in the logs (FP8 emulation) suggests that the compiler/backend is not yet fully aware of the GFX1201 instruction set capabilities.

## Hypothesis
The TileLang C++ backend likely contains a dispatch mechanism or a feature-mapping registry that maps high-level TileLang operations to specific hardware instructions. This registry currently lacks an entry for `gfx1201` that maps to the `mai-insts` (Matrix Acceleration Instructions) required for RDNA4.

## Proposed Action
1. Locate the C++ source for TileLang's backend (likely in a directory named `tilelang/backend` or similar, though not immediately visible in the top-level `find` results, it might be inside a submodule or a specific project directory).
2. Identify the `InstructionMapper` or `FeatureRegistry` class.
3. Implement a new mapping for `gfx1201` that utilizes `mai-insts` for MMA operations.
