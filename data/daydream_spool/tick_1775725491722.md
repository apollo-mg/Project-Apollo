# Architectural Audit: ROCm Build Isolation Issue

## 1. Epiphany Analysis
The subconscious identified a recurring `ModuleNotFoundError` during ROCm-specific extension builds. The root cause is identified as **PEP 517 Build Isolation**. When `pip` installs a package that requires compilation (like certain ROCm/Triton extensions), it creates a temporary, isolated virtual environment. This environment lacks the pre-installed `torch` and `triton` libraries present in the user's `venv_rocm711`, leading to a failure to find dependencies during the build phase.

## 2. Audit Findings
- **Codebase Scan:** A comprehensive search of the current repository (including `.sh`, `.py`, `Makefile`, and `grep` across the project) yielded no direct `pip install` commands.
- **Project Nature:** The repository is primarily a TypeScript/Node.js orchestration framework.
- **Contextual Inference:** The error occurs in an external environment (likely a user-managed ROCm virtual environment) or a deployment process (Docker/CI) that is not explicitly defined within this specific source tree.

## 3. Proposed Architectural Update
While no direct code change is possible within the current TypeScript codebase, the following architectural standard must be enforced for any Python-based extensions or deployment scripts added to the ecosystem:

### **Mandatory Build Flag**
Any installation of ROCm-specific extensions or packages requiring compilation against existing `torch`/`triton` binaries must bypass isolation.

**Incorrect Command:**
```bash
pip install <extension_package>
```

**Correct Command:**
```bash
pip install --no-build-isolation <extension_package>
```

## 4. Implementation Recommendation
- **Documentation:** Update any `README.md` or `CONTRIBUTING.md` files that mention ROCm setup instructions to explicitly include the `--no-build-isolation` flag.
- **CI/CD:** If a Python-based CI/CD pipeline is introduced, ensure `pip` commands for ROCm dependencies are configured with this flag.
- **Automation:** If the orchestrator is extended to manage Python environments, the `bash` tool execution logic should be aware of this requirement for ROCm-tagged environments.

**Status:** Audit Complete. No immediate codebase changes required; documentation/process update recommended.
