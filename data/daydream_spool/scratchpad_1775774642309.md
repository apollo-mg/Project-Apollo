# Epiphany Investigation: Transition from Information Retrieval to Presence

## Initial Assessment
The epiphany suggests a fundamental shift in how the system handles vocalization. Currently, the system likely treats text-to-speech (TTS) as a post-processing step (Text -> LLM -> Text -> TTS). The goal is to move toward a "stream-based vocalization" model where the voice is a primary sensory output, potentially allowing for prosody, cadence, and real-time interaction that mirrors a "living interlocutor."

## Investigation Plan
1. **Identify current TTS implementation:** Locate where Piper or other TTS engines are invoked.
2. **Analyze the data flow:** Determine if the current architecture waits for full text completion before triggering TTS.
3. **Search for "Piper" or "TTS" in the codebase:** Use `grep` to find relevant modules.
4. **Evaluate "Presence" vs "Retrieval":** Look for architectural patterns that suggest a "side-effect" model versus a "primary stream" model.

## Hypotheses
- **Hypothesis 1:** The current implementation uses a `print()` or `log()` function that triggers a separate TTS process once a newline or end-of-sentence is detected.
- **Hypothesis 2:** The "uncanny valley" mentioned is caused by the latency between text generation and audio playback, or the lack of emotional/prosodic metadata in the text stream.
