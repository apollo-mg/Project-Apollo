# Architectural Proposal: Environment Identity Verification & Absolute Binary Resolution

## 1. Problem Statement
The current execution model relies heavily on the system `PATH` and `#!/usr/bin/env` shebangs. This creates a "porous boundary" where the distinction between the virtual environment and the system environment is blurred. If a script is executed in a context where the `PATH` is modified or the environment is not correctly activated, it may resolve to the wrong Python interpreter, leading to silent failures or incorrect dependency loading.

## 2. Proposed Solution

### A. The "Identity Handshake" Pattern
Every critical entry point or background task must perform an identity handshake. This involves logging the execution context before proceeding with business logic.

**Implementation Pattern (Python):**
```python
import sys
import logging
import os

def perform_identity_handshake(logger: logging.Logger):
    """
    Verifies and logs the execution environment to prevent identity crisis.
    """
    executable = sys.executable
    prefix = sys.prefix
    logger.info(f"IDENTITY_HANDSHAKE: sys.executable={executable}")
    logger.info(f"IDENTITY_HANDSHAKE: sys.prefix={prefix}")
    
    # Verify we are actually in a venv
    if not hasattr(sys, 'real_prefix') and not (sys.base_prefix != sys.prefix):
        logger.warning("IDENTITY_HANDSHAKE_WARNING: Process is NOT running within a virtual environment!")
```

### B. Absolute Binary Resolution
Replace all ambiguous binary calls (e.g., `python3`, `pip`, `pytest`) with calls derived from the current interpreter's location.

**Current (Fragile):**
```python
subprocess.run(["python3", "script.py"])
```

**Proposed (Robust):**
```python
import sys
import subprocess

def run_in_current_env(args: list[str]):
    # Replace the first element if it's a known ambiguous binary
    # or simply use sys.executable to ensure the same interpreter is used.
    cmd = [sys.executable] + args
    return subprocess.run(cmd, check=True)
```

### C. Hardcoded Path Remediation
Replace hardcoded paths like `/mnt/TG_2TB/Projects/Apollo/venv_cachyos/bin/python` with dynamic resolution.

**Proposed Logic:**
```python
import sys
import os

def get_venv_bin(binary_name: str) -> str:
    """Returns the absolute path to a binary within the current venv."""
    bin_dir = os.path.join(sys.prefix, 'bin')
    return os.path.join(bin_dir, binary_name)
```

## 3. Audit & Implementation Roadmap

1.  **Phase 1: Audit (Completed)**
    - Identified `#!/usr/bin/env python3` as a primary risk vector.
    - Identified hardcoded venv paths in `dist/tool/built-in/memory-recall.js`.
    - Identified process-name-based tracking (`pgrep`) as fragile.

2.  **Phase 2: Core Utility Injection**
    - Create a `core/environment.py` module containing the `perform_identity_handshake` and `get_venv_bin` utilities.

3.  **Phase 3: Codebase Refactoring**
    - Replace `subprocess` calls in all `dist/` and `task/` modules.
    - Update `examples/` to demonstrate the new robust execution pattern.

4.  **Phase 4: Verification**
    - Run tests in a "dirty" environment (where `PATH` is stripped of venv entries) to ensure the handshake catches the failure.

## 4. Conclusion
By shifting from "Who is the user?" (environment-dependent) to "What is the identity?" (interpreter-dependent), we eliminate the shadow cast by the environment and ensure deterministic execution.
