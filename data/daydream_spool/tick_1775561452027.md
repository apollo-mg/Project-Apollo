# Architectural Audit: The Split-Brain Duality (Epiphany Analysis)

## 1. Epiphany Validation
The subconscious epiphany is **CORRECT**. The current architecture is attempting to force a single model (Qwen 35B MoE) to handle both high-precision tool orchestration and expressive persona-driven dialogue. This creates a "cognitive friction" where the model's reasoning (the logic gate) is constantly fighting its own conversational output (the voice).

## 2. Current State Audit
- **Current Bottleneck:** The `ApolloAgentSession` (in `modules/agent_session.py`) uses a single `llm_interface.stream_llm` call for the entire loop. 
- **The Problem:** The model is being asked to perform two distinct, conflicting tasks in a single context window:
    1. **Logic/Tool-Calling:** Generating hyper-consistent JSON for `Toolbox` execution.
    2. **Persona/Voice:** Generating the final "Zoey" response (1-3 sentences, casual, no markdown).
- **The Friction:** When the model is in "Execution" mode (tool calling), it often carries over the "persona" style into the JSON or, conversely, when it's in "Voice" mode, it struggles to maintain the strict JSON constraints required for the next turn.

## 3. Proposed Architectural Shift: The "Split-Brain" Protocol
Instead of a single-model loop, we will implement a **Dual-Agent Orchestration** pattern.

### Phase A: The Logic Kernel (Qwen-based)
- **Role:** Purely deterministic tool orchestration.
- **Constraint:** Temperature 0.0, strict JSON output, no persona.
- **Responsibility:** Parses user intent, executes tools, manages the `ApolloAgentSession` state, and produces a "Semantic Handoff" object.

### Phase B: The Expressive Persona (Gemma-based)
- **Role:** The "Voice" of Apollo (Zoey).
- **Constraint:** Temperature 0.7-0.8, highly casual, 1-3 sentences.
- **Responsibility:** Takes the *result* of the Logic Kernel's actions and translates them into a human-friendly response.

## 4. Implementation Roadmap (Draft)

### Step 1: Refactor `llm_interface.py`
Introduce `DeploymentConfig` profiles specifically for `KERNEL` (Logic) and `VOICE` (Persona).

### Step 2: Refactor `modules/agent_session.py`
The `run()` loop will be split:
1. **The Reasoning Loop:** Uses the `KERNEL` config. It iterates through tool calls until no more tools are needed.
2. **The Handoff:** Once the `KERNEL` is satisfied, it produces a `handoff_payload` containing:
    - `summary_of_actions`: A concise list of what was done.
    - `current_state`: The updated system state.
    - `user_intent_context`: The original user prompt.
3. **The Voice Synthesis:** The `handoff_payload` is sent to the `VOICE` model (Gemma) to generate the final response.

### Step 3: Optimization of the 'Inter-Agent Protocol'
The `handoff_payload` will be a strictly typed JSON schema. This ensures the "semantic handoff" is frictionless.

## 5. Conclusion
The VRAM constraint is not a limitation, but a design requirement. By splitting the brain, we reduce the cognitive load on each model, allowing the Logic Kernel to be small and precise, and the Voice to be expressive and lightweight.
