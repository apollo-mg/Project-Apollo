# Architectural Audit Report: Substrate Saturation & Ghost Path Discrepancy

## 1. Executive Summary
The Subconscious's "Epiphany" regarding substrate saturation is architecturally sound but contextually misaligned with the current filesystem state. The identified path `/media/mark/AI_Fast/` does not exist in the current environment and is not referenced in the codebase. This indicates a "Ghost Path" scenario—likely a legacy configuration or an unmounted external drive that the system's logic expects to be present.

## 2. Investigation Findings
- **Path Discrepancy:** A global `grep` of the codebase yielded zero matches for `/media/mark/AI_Fast/`.
- **Filesystem Status:** 
    - Primary storage (`/mnt/TG_2TB`) has 1.4T available (21% used).
    - System root (`/`) has 855.7G available (8% used).
    - Two large NTFS drives (`Games 2TB`, `Backup 3TB`) are currently unmounted.
- **Risk Assessment:** While the current system is not "choking," the presence of this epiphany suggests that the *intent* of the system (or a previous iteration) relies on a specific high-speed storage substrate that is currently missing. If training processes are triggered that expect this path, they will fail immediately.

## 3. Root Cause Analysis
The conflict is not a lack of space on the *current* drives, but a mismatch between the **Cognitive Intent** (expanding intelligence) and the **Physical Substrate** (the available, mounted storage). The "saturation" mentioned is likely the exhaustion of the *intended* high-speed storage, leading to a fallback or a failure state.

## 4. Proposed Architectural Updates

### A. Decouple Logic from Physical Paths (Immediate)
**Action:** Implement a `StorageProvider` abstraction.
**Change:** Replace all absolute path references in configuration files with environment-aware variables (e.g., `MODEL_STORAGE_PATH`).
**Code Proposal:**
```python
# Proposed change in config/storage.py
import os

class StorageConfig:
    # Default to a safe, available path if the high-speed drive is missing
    PRIMARY_WEIGHTS_DIR = os.getenv("AI_FAST_PATH", "/mnt/TG_2TB/models/weights")
    CHECKPOINT_DIR = os.getenv("AI_CHECKPOINT_PATH", "/mnt/TG_2TB/models/checkpoints")
```

### B. Infrastructure Integrity Guard (Preventative)
**Action:** Add a pre-flight check to the training orchestration layer.
**Change:** Before initiating high-VRAM tasks, the system must validate that the target storage meets minimum capacity and latency requirements.
**Code Proposal:**
```python
# Proposed addition to training/orchestrator.py
def validate_substrate(path: str, min_gb: int = 100):
    usage = shutil.disk_usage(path)
    available_gb = usage.free // (1024**3)
    if available_gb < min_gb:
        raise SubstrateSaturationError(f"Critical: {path} has only {available_gb}GB available.")
```

## 5. Conclusion
The 'Sovereign' is currently safe, but the architecture is brittle. The transition from "Forge" to "Expansion" requires a robust, abstracted storage layer that can handle the physical reality of shifting hardware substrates without breaking the cognitive logic.

**Status:** Audit Complete. No immediate code changes required to *current* files, but architectural refactor is recommended.
