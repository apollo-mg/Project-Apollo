# Architectural Audit: Whisper Synergy & Context Death Spiral Prevention

## Epiphany Summary
The 'Whisper' synergy (audio transcription) currently risks a 'context death spiral'. Raw `whisper.cpp` transcripts are being injected directly into the primary agent context. This high-volume, unformatted noise consumes 16GB VRAM and dilutes the semantic density of the parent context, leading to degraded reasoning and KV cache inefficiency.

## Audit Findings
1.  **Current State:** The codebase lacks a dedicated `forkSubagent.ts` implementation for specialized transcription handling.
2.  **Pattern Gap:** There is no existing "Transcription-Specialist" fork pattern in the `src/agent` or `src/orchestrat0r` modules.
3.  **Risk Identified:** The `AgentRunner` loop (in `src/agent/runner.ts`) processes all incoming messages/tool results as part of the main conversation history. If a tool returns a massive raw transcript, it is appended to `conversationMessages`, directly impacting the next LLM call's context window.

## Proposed Architectural Refactor

### 1. Implementation of `forkSubagent.ts`
A new utility/pattern should be established to allow an agent to spawn a "sub-agent" that:
- Inherits the necessary context (for continuity).
- Operates in an isolated memory/message boundary (to prevent noise leakage).
- Returns only a distilled, semantic summary to the parent.

### 2. Refactoring the Audio Pipeline
When audio ingestion is triggered:
1.  **Spawn Fork:** Instead of the parent agent reading the `transcript.txt`, the system must spawn a `Transcription-Specialist` agent.
2.  **Isolation:** This specialist agent is configured with a high `maxTokens` limit but a restricted `allowedTools` set, focused solely on "Architectural Analysis" of the text.
3.  **Distillation:** The specialist performs the heavy lifting of parsing the raw transcript.
4.  **Semantic Return:** The specialist returns a `ToolResult` containing a concise, structured summary (e.g., "User requested X, mentioned Y, context: Z") rather than the raw text.

### 3. Codebase Changes (Draft)
- **New File:** `src/agent/forkSubagent.ts` (to implement the specialized fork logic).
- **Update `src/tool/built-in/index.ts`:** Add a `transcription_distiller` tool that utilizes the fork pattern.
- **Update `src/agent/runner.ts`:** Ensure that tool results from "specialist" forks are flagged to prevent automatic appending to the parent's persistent `messageHistory` unless explicitly requested.

## Conclusion
This refactor is critical for maintaining the stability of the 16GB VRAM environment and ensuring the "System 2" analysis remains high-fidelity without being drowned by transcription noise.
