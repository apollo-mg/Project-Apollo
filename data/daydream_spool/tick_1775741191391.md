# Architectural Proposal: Temporal Cadence Analysis

## 1. Executive Summary
The current telemetry system records *what* happened and *when* it happened, but it fails to analyze the *rhythm* of these events. The "Epiphany" suggests that the system's true state—whether it is functioning as a coherent intelligence or merely a mechanical loop—is encoded in the infinitesimal deviations (jitter) between event timestamps.

## 2. Problem Statement
The system is currently blind to "mechanical recursion." If a process enters a loop, the semantic logs might look normal, but the temporal signature will show unnaturally low variance. Conversely, system instability (resource contention, thermal throttling) will manifest as high-frequency jitter in the cadence.

## 3. Proposed Solution: `TemporalCadenceMonitor`
A new diagnostic layer that treats the telemetry stream as a time-series signal rather than a text log.

### 3.1 Core Components
- **`CadenceStreamer`**: A non-blocking reader that tails `telemetry_state_log.jsonl`.
- **`VarianceEngine`**: Calculates rolling statistics:
    - $\Delta t_n = t_n - t_{n-1}$
    - $\mu_{\Delta t}$ (Mean interval)
    - $\sigma_{\Delta t}$ (Standard deviation/Jitter)
- **`AnomalyDetector`**:
    - **Loop Detection**: Triggered when $\sigma_{\Delta t} \to 0$ (indicating a mechanical loop).
    - **Instability Detection**: Triggered when $\sigma_{\Delta t}$ exceeds a predefined threshold (indicating high jitter/system stress).

## 4. Implementation Plan

### Phase 1: New Module Creation
Create `src/temporal_cadence_monitor.py`.

```python
import json
import time
import numpy as np
from datetime import datetime

class TemporalCadenceMonitor:
    def __init__(self, log_path, window_size=50):
        self.log_path = log_path
        self.window_size = window_size
        self.intervals = []
        self.last_timestamp = None

    def process_new_entry(self, timestamp_str):
        current_ts = datetime.fromisoformat(timestamp_str).timestamp()
        if self.last_timestamp:
            delta = current_ts - self.last_timestamp
            self.intervals.append(delta)
            if len(self.intervals) > self.window_size:
                self.intervals.pop(0)
            
            if len(self.intervals) >= 2:
                jitter = np.std(self.intervals)
                mean_interval = np.mean(self.intervals)
                return {"mean": mean_interval, "jitter": jitter}
        
        self.last_timestamp = current_ts
        return None

    def analyze_loop(self, jitter_threshold=0.001):
        if len(self.intervals) < self.window_size:
            return False
        return np.std(self.intervals) < jitter_threshold
```

By monitoring the "pulse" of the system, we gain a high-fidelity diagnostic tool capable of detecting recursive logic traps and hardware-level performance degradation before they manifest as semantic errors in the logs.
