### 1. Executive Summary
The current system architecture relies on **Reactive Suppression** via hard context limits (2048/4096) to maintain stability. This creates a "Perfect Cascade" that is actually a high-wire act: the stability is a result of limiting the intelligence (the 'Heretic') rather than managing its resources. This investigation confirms that the transition from the 4B Gatekeeper (Bonsai) to the 9B/27B Heretic (Architect/Turbo) creates massive, unmanaged VRAM spikes that risk `gfx1201` driver crashes.

### 2. Identified Vulnerabilities
- **Reactive vs. Predictive**: `vram_management.py` uses `smart_vram_guard`, which only triggers `unload_comfy_vram()` *after* the `VRAM_THRESHOLD_MB` is breached. This is too late to prevent OOM (Out of Memory) errors during the allocation phase of a large context switch.
- **Context-Induced VRAM Debt**: The jump from `bonsai` (4k context) to `architect` (64k context) causes an exponential increase in KV cache requirements that is not accounted for during the escalation phase.
- **Suppression as Stability**: The current "stability" is a byproduct of the 4096 context cap on the gatekeeper, which prevents the system from ever attempting the high-resource requests that would actually test the architecture.

### 3. Proposed Architectural Shift: Predictive Resource Orchestration
We must move from **Context Capping** to **Telemetry-Driven Debt Calculation**.

#### A. Implementation of `VRAMDebtCalculator`
A new module must be introduced to calculate the "VRAM Debt" of a request *before* escalation.
**Formula:**
`Total_VRAM_Required = Model_Weight_MB + (Target_Context_Length * KV_Cache_Per_Token_MB)`

#### B. Integration into `ServiceOrchestrator`
The `orchestrator.py` must be updated to include a pre-flight check:
1. **Triage**: `bonsai` identifies intent.
2. **Escalation Request**: `orchestrator` receives request for `architect`.
3. **Debt Check**:
   - `current_vram = telemetry_layer.get_vram_usage()`
   - `debt = VRAMDebtCalculator.estimate_debt('architect', requested_context)`
   - `if (current_vram + debt) > VRAM_TOTAL_MB`:
     - **Trigger**: `vram_management.unload_comfy_vram()`
     - **Wait**: `vram_management.wait_for_vram_release(target_free_mb)`
4. **Execution**: Only proceed with `subprocess.Popen` once the debt is covered by available headroom.
