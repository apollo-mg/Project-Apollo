# Apollo Scratchpad: ROCm Build Isolation Investigation

## Epiphany Summary
The build process for ROCm extensions fails due to `pip` build isolation. The isolated environment lacks `torch` and `triton`, even though they are present in the active `venv_rocm711`.

## Hypothesis
The build scripts/commands are using standard `pip install` without `--no-build-isolation`, causing the build to fail when compiling extensions that depend on the existing `torch` installation.

## Investigation Plan
1. Search for `pip install` commands in the codebase.
2. Search for any ROCm-specific installation logic or extension compilation.
3. Identify the specific files/scripts that need the `--no-build-isolation` flag.
## Findings
- No direct `pip install` commands were found in the current codebase (searching `.sh`, `.py`, `Makefile`, and general `grep`).
- The codebase appears to be primarily TypeScript/Node.js based (`package.json`, `src/`, `tsconfig.json`).
- The "Epiphany" refers to a `ModuleNotFoundError` involving `torch` and `triton` in a `venv_rocm711` environment. This suggests the failure occurs in an external environment or a process managed by this orchestrator that is not explicitly part of the current repository's source code, OR it is part of a build/deployment process not yet visible in the file tree.
- The error described is a classic PEP 517 build isolation issue.

## Conclusion
The issue is likely occurring in a deployment script, a Dockerfile, or a CI/CD configuration that was not part of the initial `find` results, or it is an instruction for the user/operator to apply when running manual installs in the `venv_rocm711` environment. Since I cannot find the offending command in the current directory, I cannot propose a direct code change to this repository. However, I can propose a documentation update or a template for future ROCm-related installation steps.

## Proposed Action
If a `requirements.txt` or a setup script is added to support ROCm extensions, ensure that `pip install` commands for those extensions include the `--no-build-isolation` flag.
