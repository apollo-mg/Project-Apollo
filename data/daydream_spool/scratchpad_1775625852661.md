# Epiphany Investigation: Parameter-Mapping Middleware for KSampler Translation

## Initial Hypothesis
The "Epiphany" suggests a semantic drift between high-level workflow abstractions and the low-level ComfyUI KSampler schema. Specifically, the system is passing high-level concepts (e.g., 'simple') where the engine expects rigid types (e.g., `int` or specific `enum` strings).

3. **Verify Type Mismatches:** Look for instances where string aliases are used instead of strict enums or integers.
4. **Propose Middleware:** Design a validation/casting layer.

## Findings: Semantic Drift in ComfyUI Workflow Translation

### 1. Identified Translation Layer
The primary translation layer identified is `legacy_vault/tools/generate_image.py`. This script performs direct manipulation of a JSON workflow file (`flux_workflow.json`) before sending it to the ComfyUI API.

### 2. Evidence of Semantic Drift
The script uses hardcoded node IDs and direct key access:
- `workflow["6"]["inputs"]["text"] = prompt`
- `workflow["25"]["inputs"]["noise_seed"] = seed`

While this works for a specific static workflow, it is highly fragile. The "Epiphany" is correct: if the workflow structure changes (e.g., a node is added or re-indexed), the high-level intent (setting the prompt) fails to translate to the low-level schema (the specific node ID).

### 3. Missing Middleware
There is currently **no validation or casting layer** between the high-level `generate(prompt)` call and the `requests.post` call. 
- **Type Safety:** The `seed` is an integer, which is correct, but other parameters (like sampler names or scheduler types) are not present in this specific script, suggesting they might be hardcoded in the JSON or passed elsewhere without validation.
- **Enum Synchronization:** If the workflow JSON contains a string like `"euler"` for a sampler, but a ComfyUI update changes the expected enum to `"euler_ancestral"`, the current implementation has no way to intercept and correct this.

### 4. Proposed Architectural Update: `ParameterMappingMiddleware`
I propose a new module `src/modules/workflow_translator.py` that implements the following:

1.  **Schema Registry:** A mapping of high-level semantic keys (e.g., `prompt`, `seed`, `sampler`, `scheduler`) to their respective node IDs and input keys within a given workflow version.
2.  **Type Casting Engine:** A utility to ensure values match the expected JSON schema (e.g., casting `float` to `int` for step counts, or `str` to `enum` for samplers).
3.  **Enum Synchronizer:** A lookup table that maps common aliases (e.g., `"simple"`, `"fast"`) to the specific string enums required by the active ComfyUI instance.

### 5. Implementation Strategy
- **Step 1:** Create `src/modules/workflow_translator.py`.
- **Step 2:** Refactor `generate_image.py` to use the translator instead of direct dictionary manipulation.
- **Step 3:** Implement a `validate_workflow_payload(payload)` function that runs just before the `requests.post` call.
