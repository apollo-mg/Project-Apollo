# Architectural Audit: Apollo Triage Hook Latency & Structural Enforcement

## 1. Executive Summary
The "Epiphany" regarding the transition from cognitive adherence to structural enforcement is validated by the current implementation of `apollo_triage_hook.py`. However, the current implementation introduces a critical architectural risk: **Synchronous LLM-based blocking**. As the system scales toward high-performance compute, the triage hook acts as a massive latency bottleneck rather than a lightweight gatekeeper.

## 2. Current State Analysis
The `apollo_triage_hook.py` (located in `legacy_vault/core/`) intercepts `read_file` and `run_shell_command` operations for `.log` and `.jsonl` files > 10KB.

**Critical Path Vulnerability:**
- **Synchronous Inference:** The hook calls `query_llm(..., model_override="qwen35-4b-aggressive")`. This is a blocking network/inference call.
- **Execution Flow:** Every time a tool attempts to read a log file, the entire execution thread waits for the LLM to summarize the content before proceeding.
- **Complexity:** $O(\text{Inference Latency})$ per log access.

## 3. Identified Risks
- **Computational Bottleneck:** The "structural enforcement" becomes a "structural drag." The time spent in the hook will eventually exceed the time spent in the actual task.
- **Scaling Failure:** As the system moves toward "operating within defined physics" (high-speed, deterministic execution), the non-deterministic latency of an LLM call breaks the system's performance guarantees.

## 4. Proposed Architectural Update (The "Physics" Model)

To transform the hook from a "suggestion" to a "lightweight constraint," I propose the following refactor:

### A. Asynchronous Triage (Non-Blocking)
Instead of blocking the tool call, the hook should:
1.  **Intercept** the request.
2.  **Spawn** a background task to perform the LLM summary.
3.  **Return** a `decision: allow` with a `metadata: { "triage_pending": true, "file_hash": "..." }` flag.
4.  The system can then consume the summary once it is ready, without stalling the primary execution flow.

### B. Tiered Enforcement Logic
Replace the binary "Allow/Deny" with a tiered approach:
- **Tier 1 (Small/Fast):** Files < 50KB. Direct read. No hook.
- **Tier 2 (Medium/Regex):** Files 50KB - 1MB. Use high-speed regex/grep-based extraction of ERROR/WARNING patterns. No LLM.
- **Tier 3 (Large/LLM):** Files > 1MB. Asynchronous LLM summary.

### C. Local-First Caching
Implement a lightweight, local-first cache for log summaries.
- **Key:** `hash(file_path + last_modified_timestamp)`
- **Value:** `llm_summary_string`
- This ensures that repeated reads of the same log file (common in debugging loops) do not trigger redundant inference.

## 5. Implementation Plan
1.  **Refactor `apollo_triage_hook.py`** to implement the Tiered Enforcement Logic.
2.  **Introduce `triage_cache.py`** for local-first summary storage.
3.  **Update `llm_interface.py`** to support asynchronous backgrounding of triage tasks.
