# Epiphany Investigation: Structural Mismatch in Tool Calling
## Timestamp: 2025-05-22 (Simulated)
## Status: Initializing Audit

### Hypothesis
The current architecture relies on prompting the LLM to output JSON within Markdown blocks. This is inherently probabilistic and prone to failure (crashes/parsing errors) because the model must "decide" to follow the format rather than being "forced" by the decoding process.

### Objective
1. Identify where `web_search` and `diff_inventory` are defined and invoked.
2. Locate the system prompts that currently instruct the model to use Markdown-wrapped JSON.
3. Evaluate the feasibility of migrating these to vLLM-based guided decoding (JSON Schema).

### Investigation Plan
- [ ] Search for `web_search` and `diff_inventory` in the codebase.
- [ ] Search for system prompt templates containing JSON instructions.
- [ ] Identify the inference engine/wrapper used for model execution.
### Findings
- **Confirmed:** The codebase heavily relies on prompting the model to output JSON within Markdown code fences (e.g., ` ```json ... ``` `).
- **Evidence of Failure:** `coordinator.log` and `apollo_coordinator.ts` show explicit error handling for "failed to output a valid JSON directive," confirming the "probabilistic entity" problem.
- **Tool Definitions:** `web_search` is explicitly mentioned in `src/tool/built-in/web-search.ts` and `src/agent/agent.ts`.
- **Architectural Pattern:** The `orchestrator.ts` uses a "Strategy 1: look for a fenced JSON block" approach, which is exactly what the Epiphany identifies as the "post-hoc rule" problem.
- **Missing Tool:** `diff_inventory` was not found in the grep, suggesting it might be a conceptual tool or named differently in the current version, or it's part of a different module. I will search for "inventory" to see if it exists under a different name.

### Proposed Architectural Shift
1. **Move from Prompting to Constraints:** Instead of telling the model "Wrap the JSON in a ```json code fence," we should use vLLM's `guided_decoding` (or similar features in other engines) to enforce the JSON schema at the token level.
2. **Schema Enforcement:** Define strict JSON Schemas for `web_search` and other high-stakes tools.
3. **Refactor Orchestrator:** Remove the regex/string-parsing logic in `orchestrator.ts` that searches for Markdown fences and replace it with a structured output handler that expects valid JSON directly from the engine.
