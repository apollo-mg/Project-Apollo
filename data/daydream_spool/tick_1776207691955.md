# Tick: PyTorch 2.8 Nightlies & torchaudio Compatibility

**Epiphany:** For PyTorch 2.8 nightlies, checkout `release/2.5` of `torchaudio` instead of `main` to avoid API compatibility errors.

**Verification:** Historical memory in `Dev_Log/Apollo_Chat_History.txt` confirms this pattern:
- Custom PyTorch build `2.8.0 + ROCm 7.1` was incompatible with torchaudio `main` branch (missing header files).
- Solution: Checkout `release/2.5` branch of torchaudio.
- Result: torchaudio version `2.5.1` successfully compiled against PyTorch `2.8.0`.

**Architectural Proposal:**
- **Dependency Constraint:** When using PyTorch 2.8 nightlies (or custom builds based on them), pin `torchaudio` to the `release/2.5` branch.
- **Rationale:** The `main` branch of torchaudio tracks the latest PyTorch API and may require header files not present in 2.8 nightlies. The `release/2.5` branch provides a stable API surface compatible with the 2.8 series.
