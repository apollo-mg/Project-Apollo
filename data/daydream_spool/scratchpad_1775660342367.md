# Investigation: Vision-to-Parametric Recursive Feedback Loop
## Timestamp: 2025-05-22 (Simulated)
## Status: Initializing Audit

### Hypothesis
The current 'Vision-to-Parametric' pipeline is likely implemented as a linear sequence: 
`Image -> Qwen2.5-VL (Description/Code) -> CadQuery (Execution) -> Result`.

The Epiphany suggests this is inefficient and lacks error correction. 
The proposed architecture is:
`Image -> Qwen2.5-VL (Error Report) -> DeepSeek-R1 (Parameter Refinement) -> CadQuery (Execution) -> [Loop back to Qwen2.5-VL]`.

### Audit Objectives
1. Locate the existing 'Vision-to-Parametric' or 'Image-to-Code' implementation.
2. Identify the specific modules handling Qwen2.5-VL and DeepSeek-R1.
3. Determine if there is an existing mechanism for "visual delta" or "error reporting".
4. Map the current data flow to see where a feedback loop can be injected.

### Search Strategy
- Search for "Qwen" and "DeepSeek" in the codebase.
- Search for "CadQuery" or "parametric" to find the geometry engine integration.
- Search for "vision" or "image" in relation to code generation.
### Findings: Current Pipeline Analysis
The file `/mnt/TG_2TB/Projects/Apollo/legacy_vault/tests/cad_vision_step.py` confirms the current implementation is a **linear, one-pass sequence**:

1.  **Vision Extraction (Qwen2.5-VL):** Captures image $\rightarrow$ Extracts JSON (primitive, dimensions, features).
2.  **CAD Generation (DeepSeek-R1):** Takes the JSON $\rightarrow$ Generates OnShape FeatureScript.
3.  **Logging:** Saves the result.

**Critical Deficiencies identified:**
- **No Feedback Loop:** There is no step to verify the generated code against the original image.
- **No Error Correction:** If the dimensions are slightly off (e.g., the vision model misreads the ruler), the code is generated once and the process ends.
- **No "Visual Delta":** The model doesn't "see" the result of its own code.

### Proposed Architectural Shift: The "Agentic Loop"
To implement the Epiphany, we must transform this into a recursive loop:

1.  **Initial Generation:** (Current Step 1 & 2).
2.  **Execution & Rendering:** Execute the generated code (e.g., via CadQuery or a headless OnShape instance) to produce a "synthetic" image of the CAD model.
3.  **Visual Verification (The Delta):**
    - Compare the **Original Image** with the **Synthetic Image**.
    - Use **Qwen2.5-VL** to perform a "Visual Delta Analysis".
    - **Prompt for Qwen2.5-VL:** *"Compare the original physical object image with this CAD render. Identify discrepancies in dimensions, shape, or features. Output a structured error report (e.g., 'Diameter mismatch: -0.5mm')."*
4.  **Refinement (DeepSeek-R1):**
    - Feed the **Error Report** back to **DeepSeek-R1**.
    - **Prompt for DeepSeek-R1:** *"The previous CAD model had these errors: [Error Report]. Adjust the parameters in the FeatureScript to correct these discrepancies."*
5.  **Termination:** Repeat until the visual delta is below a threshold or max iterations are reached.

### Implementation Plan (Draft)
- **Module `vision_feedback_loop.py`**: A new orchestrator.
- **Tool `render_cad_to_image`**: To bridge the gap between code and visual verification.
- **Prompt Engineering**:
    - `PROMPT_ERROR_REPORT`: For Qwen2.5-VL to act as a critic.
    - `PROMPT_REFINEMENT`: For DeepSeek-R1 to act as a corrector.
