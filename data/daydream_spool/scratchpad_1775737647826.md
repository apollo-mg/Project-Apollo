## Findings Update:
- `vision_audit_protocol.py` is a sophisticated, multi-turn "Vision-to-Reasoning" loop. It uses a Vision Model (Turn 1) to extract "Architectural Anchor Points" and then a Reasoning Model (Turn 2+) to verify those points using tools like `web_search` and `diff_inventory`.
- This protocol is highly specialized for *hardware identification* (physical objects).
- The Epiphany, however, is about the *aesthetic/visual soul* of the project (the "Sovereign Dashboard").
- The "visual soul" is not about identifying a motherboard; it's about the *design language* (colors, layout, mood, UI/UX direction) that the agent should adhere to when generating responses or planning tasks.

**The Disconnect:**
The current "Vision" capability is purely *reactive* and *descriptive* (identifying what is in an image). It is not *proactive* or *normative* (using a design concept to guide behavior).

**The Solution (Architectural Proposal):**
We need to create a "Design Constraint Layer" in the Agentic Loop.
1. **The Design Registry:** A new file (e.g., `design_intent.json` or a section in `GLASS_COCKPIT.md`) that defines the "Visual Soul" in semantic terms (e.g., "Cyberpunk Minimalist", "High-Contrast Industrial", "Monochromatic Blue/Amber").
2. **The Context Injection:** Modify the core agent loop (`apollo.py`) to ingest this "Design Intent" as a permanent part of the System Prompt.
3. **The Aesthetic Audit:** A new tool/protocol (inspired by `vision_audit_protocol.py`) that doesn't just identify hardware, but audits *output* (text or UI descriptions) against the "Design Intent".
