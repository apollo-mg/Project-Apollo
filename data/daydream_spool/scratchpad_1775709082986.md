# Epiphany Investigation: Ambient Noise Profiling vs. Hard-Coded Silence Thresholds

## Initial Hypothesis
The current system likely uses static thresholds (e.g., `SILENCE_THRESHOLD = 0.05`) to detect when a user has stopped speaking. The Epiphany suggests this is failing because it doesn't account for environmental noise (AC hum, etc.), leading to "recursive loops" or failure to detect speech when the noise floor rises.

## Audit Findings: `wake_up.py`
The `wake_up.py` script confirms the Epiphany's suspicion. It uses `webrtcvad` for Voice Activity Detection (VAD) with a hard-coded "Very Aggressive" mode:

```python
55	    vad = webrtcvad.Vad()
56	    vad.set_mode(3) # 0=Normal, 1=Low Bitrate, 2=Aggressive, 3=Very Aggressive (Filters background noise best)
```

And it uses a fixed silence threshold for stopping the recording:

```python
79	                max_silence_chunks = int((1.5 * RATE) / VAD_CHUNK) # 1.5 seconds of silence
```

### The Problem
1. **Rigid VAD Mode:** While `mode 3` is aggressive, it is still a static mathematical model of what "speech" looks like. It doesn't adapt to the *actual* noise floor of the room. If the AC hum increases, the VAD might either:
    - Fail to detect speech because the signal-to-noise ratio (SNR) drops below the VAD's internal threshold.
    - Or, conversely, if the noise is rhythmic or has certain frequencies, it might trigger the VAD incorrectly.
2. **Fixed Silence Duration:** The `1.5 seconds` of silence is a "cage." If the environment is noisy, the system might struggle to distinguish between a pause in speech and a spike in ambient noise, leading to premature cut-offs or infinite loops if the noise is interpreted as speech.

## Proposed Architectural Shift: `AmbientNoiseDaemon`

Instead of relying solely on `webrtcvad`'s internal logic, we should implement a two-stage detection process:

1. **Stage 1: Noise Floor Profiling (The Daemon)**
   - A background process (or a thread within `wake_up.py`) that continuously samples the audio stream during "silence" periods.
   - It calculates the RMS (Root Mean Square) or spectral density of the ambient noise.
   - It maintains a moving average of this "noise floor."

2. **Stage 2: Dynamic Thresholding**
   - Instead of `vad.is_speech(data, RATE)`, we use the noise floor to set a dynamic energy threshold.
   - `is_speech = current_energy > (noise_floor + margin)`
   - This `margin` can be adjusted dynamically.

3. **Stage 3: Feedback Loop**
   - The `AmbientNoiseDaemon` provides a `noise_floor` value to the `wake_up.py` loop.
   - This allows the system to "learn" the room's silence.
