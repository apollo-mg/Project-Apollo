# Epiphany Investigation: Sovereign Artifact Paradox
## Timestamp: 2024-05-22 (Simulated)
## Subject: Post-Synthesis Protocol & Storage Optimization

### Initial Assessment
The epiphany identifies a systemic bottleneck: the conflict between high-fidelity BF16 weights (Source) and quantized formats (GGUF/EXL2) (Distributed). 
The proposed solution is a 'Post-Synthesis Protocol' to:
1. Prune redundant checkpoints.
2. Migrate LoRA/BF16 assets to cold storage.
3. Optimize the primary workspace.

### Investigation Plan
1. **Audit Workspace Usage:** Identify where large model weights (BF16, GGUF, EXL2) are currently stored.
2. **Identify Redundancy:** Look for checkpoint patterns (e.g., `checkpoint-XXX`) that might be candidates for pruning.
3. **Assess Storage Distribution:** Determine if there is a clear distinction between "Active Workspace" and "Cold Storage" in the current filesystem structure.
4. **Draft Protocol:** Propose a concrete automation script/workflow.

### Findings: Storage Audit
- **High-Density Models Found:** `/mnt/TG_2TB/Projects/Apollo/models/` contains several large GGUF files (10GB - 12GB range).
- **Redundancy/Overlap:** There are multiple versions of Qwen3.5 models (e.g., `Qwen3.5-27B-Claude-4.6-Opus-Reasoning-Distilled-heretic-v2.i1-IQ3_M.gguf` and `Qwen3.5-27B-Claude-4.6-OS-Auto-Variable-Heretic-Uncensored-Thinking.i1-IQ3_M.gguf`).
- **The Paradox Confirmed:** The `models/` directory is currently acting as a "hot" workspace for both quantized assets and potentially large source weights (though only GGUF/safetensors were explicitly listed in the `find` command, the presence of `consolidated.safetensors` suggests BF16/FP16 source weights are also stored here).
- **Missing Infrastructure:** There is no evidence of a dedicated `cold_storage` or `archive` directory within the `Apollo` project structure to handle the "Post-Synthesis" migration.

### Proposed 'Post-Synthesis Protocol' (PSP)
1. **Automated Pruning:** A script to identify and delete `checkpoint-*` directories in training runs older than $N$ days.
2. **Tiered Storage Migration:**
    - **Tier 1 (Hot):** `/mnt/TG_2TB/Projects/Apollo/models/` (Active quantized models for inference).
    - **Tier 2 (Warm):** `/mnt/TG_2TB/Projects/Apollo/archive/weights/` (LoRA adapters and BF16 source weights).
    - **Tier 3 (Cold):** External HDD/Cloud (Long-term storage of completed training runs).
3. **Implementation:** A Python utility `apollo_storage_manager.py` to be integrated into the training pipeline.
