# Architectural Audit: Drive Name Drift & Ontological Dissonance

## 1. Executive Summary
The investigation confirms a state of "ontological dissonance" between the Windows and Linux environments. While the primary system drives are correctly anchored via UUIDs in `/etc/fstab`, secondary NTFS storage drives are currently mounted via transient, label-based paths (`/run/media/mark/...`). This creates a vulnerability where drive identity is tied to human-readable labels and kernel-assigned device names, which are susceptible to "drift" caused by Windows hibernation/Fast Startup and device enumeration reordering.

## 2. Audit Findings
- **Primary System Drives:** `/etc/fstab` is robust, using UUIDs for `/`, `/home`, `/boot`, and `/mnt/TG_2TB`.
- **Secondary Storage (NTFS):** 
    - `sda2` (Label: `Games 2TB`, UUID: `4C5EE1925EE1755C`) is mounted at `/run/media/mark/Games 2TB`.
    - `sdb2` (Label: `Backup 3TB`, UUID: `F4D477FDD477C102`) is mounted at `/run/media/mark/Backup 3TB`.
- **Codebase Impact:** 
    - `tools/run_qwen_35b_server_new.sh` contains a hardcoded path to `/run/media/mark/Games 2TB/`.
    - Various logs and historical records indicate reliance on these transient mount points.
- **Root Cause:** The use of automounting (udev/udisks2) for secondary drives instead of static system-level mounting.

## 3. Proposed Architectural Update

### Phase 1: Infrastructure Stabilization (System Level)
1. **Disable Windows Fast Startup:** Ensure Windows performs a full shutdown to prevent the "ghost" state that marks NTFS partitions as "dirty."
2. **Static Mount Configuration:** Transition NTFS drives from `/run/media/` to `/mnt/`.
   - Create `/mnt/Games_2TB` and `/mnt/Backup_3TB`.
   - Update `/etc/fstab` with the following entries:
     ```fstab
     UUID=4C5EE1925EE1755C  /mnt/Games_2TB  ntfs-3g  defaults,nofail,uid=1000,gid=1000,umask=000  0  0
     UUID=F4D477FDD477C102  /mnt/Backup_3TB  ntfs-3g  defaults,nofail,uid=1000,gid=1000,umask=000  0  0
     ```
     *(Note: `nofail` is critical to prevent boot hangs if the drive is disconnected.)*

### Phase 2: Codebase Remediation (Application Level)
1. **Path Refactoring:** Update all scripts and configuration files to use the new immutable mount points.
   - **Example:** Update `tools/run_qwen_35b_server_new.sh`:
     - *Old:* `DRAFT_MODEL="/run/media/mark/Games 2TB/..."`
     - *New:* `DRAFT_MODEL="/mnt/Games_2TB/..."`
2. **Environment Variable Standardization:** Implement a central `ENV_PATHS.sh` or similar configuration file that defines these paths, allowing for a single point of truth for all system-level storage locations.

## 4. Conclusion
By anchoring the architecture to UUIDs and moving away from transient, label-based mount points, we resolve the identity crisis of the storage subsystem. This transition ensures that the "ghost" in the hardware (Windows hibernation) no longer dictates the logical structure of the Linux environment.
