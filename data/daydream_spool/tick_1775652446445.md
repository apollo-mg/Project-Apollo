# Architectural Audit Report: Dual-Layered Haunting
## Investigator: Apollo, Sovereign Lead Architect
## Status: Investigation Complete - Proposal Drafted

### 1. Executive Summary
The system is suffering from "Shadow Identity" syndrome. Discrepancies between hardcoded model paths in various scripts (`forge_manager.py`, `run_qwen_35b_server.sh`, etc.) and the actual filesystem state (multiple mount points: `/mnt/TG_2TB/`, `/media/mark/AI_Fast/`, `/run/media/mark/Games 2TB/`) create a situation where the running process may be operating on stale or incorrect logic/data. This explains the failure to detect GGUF models and the `OSError` (likely due to stale file descriptors or unmounted paths).

### 2. Findings
- **Path Fragmentation:** Model locations are non-canonical. Scripts are pulling from at least four different mount points.
- **Process/Filesystem Desync:** The existence of `apollo.py.old` and various `.bak` scripts suggests a manual, error-prone deployment process that leaves "ghost" processes and stale modules in `sys.modules`.
- **Identity Mismatch:** The GGUF detection failure is a symptom of the system loading a module that expects a specific path structure which no longer matches the current environment.

### 3. Proposed Architectural Changes

#### A. Implement a Canonical Model Registry
Create a single source of truth for all model assets.
- **File:** `/mnt/TG_2TB/Projects/Apollo/core/model_registry.json`
- **Structure:**
  ```json
  {
    "models": {
      "architect": {
        "path": "/media/mark/AI_Fast/Models/GGUF/Apollo-35B-Sovereign-Architect.iq2_xxs.gguf",
        "checksum": "..."
      },
      "qwen_35b": {
        "path": "/mnt/TG_2TB/Projects/Apollo/models/Qwen3.5-35B-A3B-UD-IQ2_XXS.gguf",
        "checksum": "..."
      }
    }
  }
  ```

#### B. Enforce "Single Source of Truth" Protocol (Deployment)
Replace manual script execution with a controlled deployment lifecycle:
1. **`clean_env.sh`**:
   - `pkill -f "apollo.py"` (and other project-related patterns).
   - `find . -name "__pycache__" -type d -exec rm -rf {} +`.
   - Clear `sys.modules` by ensuring a fresh `venv` or container start.
2. **`validate_paths.py`**:
   - A pre-flight script that iterates through `model_registry.json` and verifies `os.path.exists()` and mount point availability.
3. **`inject_env.sh`**:
   - Sets `MODEL_REGISTRY_PATH` and `PYTHONPATH` dynamically based on the registry.

#### C. Codebase Updates (Targeted)
- **Refactor `forge_manager.py`**: Remove hardcoded `/media/mark/...` paths. Replace with a lookup function: `get_model_path(model_id)`.
- **Refactor `run_*.sh` scripts**: Instead of hardcoding `MODEL_PATH`, they should call `get_model_path` via a python helper or read from the registry.

### 4. Implementation Roadmap
1. **Phase 1 (Immediate):** Consolidate all model paths into the `model_registry.json`.
2. **Phase 2 (Stabilization):** Implement the `clean_env.sh` and `validate_paths.py` as part of the CI/CD or manual start sequence.
3. **Phase 3 (Refactor):** Systematically replace hardcoded paths in the `tools/` and `legacy_vault/` directories.
