# Architectural Proposal: Matryoshka-Tiered Multimodal Retrieval

## Problem Statement
The current RAG pipeline suffers from a "dimensionality explosion" when integrating visual data. Processing high-dimensional multimodal embeddings (e.g., 1024+ dimensions) during the initial retrieval phase causes significant latency and computational overhead, especially as the vector database grows.

## Proposed Solution: Pre-Attentive Dimensionality Tiering
We will implement a two-stage retrieval process inspired by the concept of "pre-attentive" processing in biological vision. This uses Matryoshka-style embeddings to filter candidates using low-dimensional representations before committing to high-precision, high-dimensional reasoning.

### 1. Structural Changes to `Tier2AssociativeCache`
The `Tier2AssociativeCache` (SQLite-based) will be upgraded to support dual-vector storage:
- **`vector_low_dim` (BLOB)**: A truncated version of the embedding (e.g., 128 dimensions). This serves as the "pre-attentive" layer.
- **`vector_full` (BLOB)**: The original high-dimensional embedding (e.g., 768 or 1024 dimensions).

### 2. Implementation Logic

#### A. Ingestion (The `put` method)
When a `MemoryEntry` is added to Tier 2:
1. The system will automatically truncate the `entry.vector` to a predefined `LOW_DIM_SIZE` (e.g., 128).
2. Both the truncated and full vectors will be stored in the SQLite database.

#### B. Retrieval (The `semantic_search` method)
The retrieval process will be split into two stages:
1. **Stage 1: Fast Filtering (Pre-attentive)**
   - Perform a similarity search (dot product or cosine similarity) using only the `vector_low_dim` column.
   - This stage is extremely fast due to the reduced dimensionality and can be optimized with SQLite's math functions or a lightweight index.
   - Retrieve the top $K_{filter}$ candidates (e.g., $K=50$).

2. **Stage 2: High-Precision Re-ranking (Attentive)**
   - For the $K_{filter}$ candidates identified in Stage 1, retrieve their `vector_full` from the database.
   - Perform a high-precision similarity search using the full-dimensional embeddings.
   - Return the top $K_{final}$ results (e.g., $K=5$).

### 3. Expected Benefits
- **Reduced Latency**: The bulk of the search space is pruned using low-cost operations.
- **Scalability**: As visual data increases the dimensionality, the "pre-attentive" layer remains constant in cost, preventing the "paralysis" described in the Epiphany.
- **Efficiency**: Minimizes the amount of high-dimensional data that must be loaded into memory/cache during the initial search phase.

## Implementation Roadmap
1. **Schema Update**: Modify `_init_db` in `src/modules/memory_system.py` to include `vector_low_dim`.
2. **Logic Update**: Update `Tier2AssociativeCache.put` to handle truncation.
3. **Search Update**: Implement the two-stage `semantic_search` logic.
4. **Validation**: Benchmark retrieval latency with and without the Matryoshka layer using a simulated multimodal dataset.
