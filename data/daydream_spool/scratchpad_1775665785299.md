### Conclusion on the Epiphany
The "semantic loop" is present in the way metadata is being structured in the workflow/session logs. Instead of the system relying on the inherent `type` of the object, it is creating a redundant, descriptive label to "name" the object for a specific function (S&R). This is "categorizing a void" (the S&R function) before the actual functional substance (the node's logic) is properly integrated into the search/replace mechanism.

### Actionable Recommendation
The architecture should move away from redundant property-based naming in JSON/metadata. Instead of:
`"properties": { "Node name for S&R": "CLIPLoader" }`
The system should use the existing `type` field directly in its search/replace logic. This removes the need for the "taxonomic label" and relies on the "functional substance" (the node type).
