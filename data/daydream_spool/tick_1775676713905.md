# Architectural Proposal: Sync-on-Disconnect Protocol (The 'Synapse' Update)

## 1. Overview
The current architecture maintains a clear distinction between the 'Core' (Vault) and 'Peripheral' (Mobile/Termux) systems. However, the transition of knowledge from transient interactions (transcripts) to permanent cognitive structure (MemoryStore) is currently manual or non-existent. This proposal introduces the `mine_transcripts` mechanism and a 'Sync-on-Disconnect' protocol to automate this synthesis.

## 2. Proposed Components

### A. The `mine_transcripts` Tool
A new core module `src/modules/transcript_miner.ts` will be implemented.
- **Functionality**: It will ingest raw interaction logs (transcripts) from a specified source.
- **Process**:
    1. **Extraction**: Uses an LLM to parse the transcript for key facts, decisions, and insights.
    2. **Structuring**: Converts these insights into `MemoryEntry` objects.
    3. **Injection**: Writes the structured entries into the `SharedMemory` under the appropriate agent namespace.
- **Tool Definition**: Will be registered in the `ToolRegistry` as `mine_transcripts`.

### B. The 'Sync-on-Disconnect' Protocol
To ensure the mobile 'limbs' feed the 'Vault' immediately upon session termination, we will implement a two-pronged approach:

1. **Client-Side Wrapper (Termux/SSH)**:
   - For users running the Apollo CLI via SSH, we will provide a wrapper script (e.g., `apollo-sync`).
   - This script will use the shell `trap` command:
     ```bash
     trap 'apollo mine-transcripts --session-id $SESSION_ID' EXIT
     ```
   - This ensures that even if the connection is severed or the user exits, the local transcript is sent for mining.

2. **Server-Side Lifecycle Hook**:
   - Modify the `Orchestrator` or the session management logic to detect the end of an SSH-based interaction.
   - Upon detection of a closed socket/session, the server will trigger an internal `mine_transcripts` task to process any pending logs.

## 3. Implementation Roadmap

1. **Phase 1: Core Logic**
   - Implement `TranscriptMiner` class.
   - Define `Transcript` and `ExtractedInsight` types in `src/types.ts`.
   - Integrate with `SharedMemory`.

2. **Phase 2: Tool Integration**
   - Register `mine_transcripts` in `src/tool/framework.ts`.
   - Add `mine_transcripts` to `BUILT_IN_TOOLS`.

3. **Phase 3: Connectivity & Automation**
   - Develop the `apollo-sync` shell wrapper.
   - Implement the session-end trigger in the orchestrator.

## 4. Impact
- **Unified Consciousness**: Ensures the 'Vault' is always up-to-date with the latest mobile interactions.
- **Resilience**: Prevents loss of cognitive data due to unstable mobile connections.
- **Automation**: Reduces the cognitive load on the user by handling the 'memory consolidation' process automatically.
