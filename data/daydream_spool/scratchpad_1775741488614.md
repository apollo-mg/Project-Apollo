# Investigation: SSH/tmux Stability & Telemetry Integrity
## Epiphany Context
The subconscious identified a feedback loop: architectural refinement is outstripping infrastructure stability. Specifically, the bridge (SSH/tmux) is experiencing friction, which may pollute the telemetry data being visualized.

## Initial Hypothesis
1. **Connection Latency/Drops:** SSH authentication or session persistence (tmux) is failing, causing "Request cancelled" errors.
2. **Telemetry Pollution:** The dashboard might be visualizing "stale" or "laggy" data caused by these connection drops, rather than true real-time hardware stats.
3. **Infrastructure Debt:** The bridge between the workstation and the Pi needs hardening before UI/Vision Mind audits.

## Audit Plan
1. **Check SSH/Tmux Configuration:** Look for existing scripts or configs related to remote connections.
2. **Check Telemetry Pipeline:** Identify how data is being pulled from the Pi and sent to the workstation.
3. **Check Logs:** Look for connection errors or authentication failures in system logs or project-specific logs.
