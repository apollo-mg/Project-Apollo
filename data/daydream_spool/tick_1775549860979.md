# Architectural Audit: Proactive State-Awareness (Pre-Flight Index Check)

## 1. Epiphany Analysis
The subconscious has identified a critical inefficiency: the system's "self-healing" is actually a reactive byproduct of redundancy management. The agent often attempts to perform I/O or compute-intensive tasks (like downloading or querying) that have already been completed or are already present in the Vault. This is a "semantic illusion" of robustness.

**Core Problem:** The agent operates on a "command-and-execute" loop without a "verify-before-execute" phase. It relies on the tool's failure or the ingestion script's deduplication to maintain state, rather than checking the state proactively.

## 2. Current State Audit
- **Tool Execution Flow:** The `ToolExecutor.runTool` method (in `src/tool/executor.ts`) follows a strict sequence:
    1. Zod validation of input.
    2. Abort signal check.
    3. Execution of the tool's `execute` function.
- **Memory/Vault Access:** The `memory_recall` tool (in `src/tool/built-in/memory-recall.ts`) provides a way to query the ChromaDB vector store, but this is currently an *active* tool call initiated by the agent *after* it decides it needs information.
- **Missing Link:** There is no middleware or "Pre-Flight" layer in the `ToolExecutor` that can intercept a tool call, inspect its intent (e.g., "download file X"), and cross-reference it against a metadata index (the Vault) to short-circuit the call if the work is already done.

## 3. Proposed Architectural Update: "Pre-Flight Index Check"

To move from reactive to proactive, we must implement a **Pre-Flight Interceptor** within the `ToolExecutor`.

### Proposed Changes:

#### A. Define a `PreFlightCheck` Interface
Introduce a new interface that allows tools (or a global registry) to provide a "check" function.
```typescript
export interface PreFlightCheck {
  /**
   * Returns a ToolResult if the action is redundant.
   * If the action is NOT redundant, returns null.
   */
  check: (input: any, context: ToolUseContext) => Promise<ToolResult | null>;
}
```

#### B. Update `ToolDefinition`
Extend the `ToolDefinition` to optionally include a `preFlight` property.
```typescript
export interface ToolDefinition<TInput> {
  name: string;
  description: string;
  inputSchema: ZodSchema<TInput>;
  execute: (input: TInput, context: ToolUseContext) => Promise<ToolResult>;
  preFlight?: PreFlightCheck; // <--- New property
}
```

#### C. Modify `ToolExecutor.runTool`
Inject the pre-flight logic into the execution pipeline in `src/tool/executor.ts`.

```typescript
// src/tool/executor.ts (Modified runTool)

private async runTool(
  tool: ToolDefinition<any>,
  rawInput: Record<string, unknown>,
  context: ToolUseContext,
): Promise<ToolResult> {
  // 1. Zod validation (Existing)
  const parseResult = tool.inputSchema.safeParse(rawInput);
  if (!parseResult.success) { /* ... error handling ... */ }

  // 2. Abort check (Existing)
  if (context.abortSignal?.aborted === true) { /* ... error handling ... */ }

  // 3. NEW: Pre-Flight Check
  if (tool.preFlight) {
    const redundancyResult = await tool.preFlight.check(parseResult.data, context);
    if (redundancyResult) {
      // If the pre-flight check returns a result, it means the action is redundant.
      // We return the result immediately, preventing the actual 'execute' call.
      return {
        ...redundancyResult,
        data: `[PRE-FLIGHT] Action skipped: ${redundancyResult.data} (Redundancy detected via Vault Index).`
      };
    }
  }

  // 4. Execute (Existing)
  try {
    return await tool.execute(parseResult.data, context);
  } catch (err) {
    /* ... error handling ... */
  }
}
```

#### D. Implementation Example: `file_download_tool`
A tool that downloads files would now include a check:
```typescript
export const fileDownloadTool = defineTool({
  name: 'file_download',
  description: 'Downloads a file from a URL.',
  inputSchema: z.object({ url: z.string(), filename: z.string() }),
  preFlight: {
    check: async (input, context) => {
      // Query the Vault/Metadata index to see if 'input.filename' already exists
      const exists = await vaultIndex.exists(input.filename);
      if (exists) {
        return { data: `File '${input.filename}' is already present in the Vault.`, isError: false };
      }
      return null; // Not redundant
    }
  },
  execute: async (input) => { /* actual download logic */ }
});
```

## 4. Conclusion
This change shifts the system's intelligence from "fixing errors after they happen" to "preventing unnecessary work before it starts." It reduces I/O, compute, and network overhead, and provides the agent with immediate, high-fidelity feedback about the current state of the Vault.

**Status:** Ready for implementation in the next engineering cycle.
