# Architectural Proposal: Environment-First Protocol

## 1. Executive Summary
Following the "Epiphany" regarding recursive processing loops caused by environmental mismatches, this proposal outlines the implementation of a proactive **Environment-First Protocol**. This shifts the system from reactive error-correction (handling failures after they occur) to proactive validation (ensuring the "territory" matches the "map" before execution).

## 2. Problem Statement
Current system failures often stem from:
- **Filesystem Mismatches:** Missing directories or incorrect paths provided by LLMs or hardcoded in scripts.
- **Configuration/Syntax Errors:** Invalid JSON/YAML structures being passed to parsers without prior schema validation.
- **Reactive Error Handling:** Errors are caught only when a service attempt fails, leading to wasted compute and complex recovery loops.

## 3. Proposed Solution: `EnvironmentValidator` Module

### A. Core Component: `src/utils/environment_validator.ts`
A new utility module responsible for pre-flight checks. It will leverage the existing `zod` dependency for schema validation.

**Key Capabilities:**
- `validateFileSystem(paths: string[])`: Verifies existence and write permissions for critical directories.
- `validateSchema<T>(data: unknown, schema: ZodSchema<T>): T`: Ensures configuration/JSON data adheres to expected structures before it reaches the business logic.
- `checkSystemIntegrity()`: A high-level check for essential environment variables and system-level dependencies.

### B. Integration Points
1. **Orchestrator Pre-flight:** Before the `Orchestrator` begins a new task cycle, it must call `EnvironmentValidator.validateFileSystem()` on all paths defined in the current task context.
2. **Tool Execution Guard:** The `ToolExecutor` will be updated to run `validateSchema` on any JSON-based tool arguments before attempting to execute the underlying logic.
3. **Agent Initialization:** Agents will perform a self-check of their local "workspace" upon startup.

## 4. Implementation Plan

### Phase 1: Foundation (Immediate)
- Create `src/utils/environment_validator.ts`.
- Implement `validateFileSystem` using `fs/promises`.
- Implement `validateSchema` using `zod`.

### Phase 2: Integration (Short-term)
- Update `src/tool/executor.ts` to include schema validation for JSON-based tools.
- Update `src/orchestrator/orchestrator.ts` to perform directory checks before task dispatch.

### Phase 3: Hardening (Long-term)
- Implement automated "Environment Health" reporting in logs.
- Add support for validating complex YAML configurations.

## 5. Expected Impact
- **Reduced Error Loops:** Minimizes the "fighting the map" phenomenon by catching path/syntax errors before they trigger service-level failures.
- **Improved Reliability:** Provides deterministic failure points that are easier to debug and log.
- **Compute Efficiency:** Prevents the execution of tasks that are doomed to fail due to environmental constraints.
