# Architectural Audit & Proposal: Native SGLang Orchestration for RDNA 4

## 1. Executive Summary
The current inference architecture is suffering from an "abstraction tax." While the hardware (RDNA 4 / gfx1201) and the software stack (ROCm 7.1.1 / Triton) are cutting-edge, the orchestration layer is heavily reliant on Docker-based vLLM deployments. This containerization creates a barrier between the Triton kernels and the raw hardware, potentially preventing optimal kernel execution and hardware-specific optimizations.

## 2. Audit Findings
- **Hardware Status:** `rocminfo` confirms successful recognition of `gfx1201` and `amdgcn-amd-amdhsa--gfx12-generic`. The hardware is ready.
- **Software Mismatch:** Previous SGLang installation attempts (found in `legacy_vault/logs/sglang_install.log`) were targeting ROCm 6.2, creating a version mismatch with the current ROCm 7.1.1 environment.
- **Orchestration Bottleneck:** The `legacy_vault/infrastructure/` directory reveals a pattern of using Docker to wrap vLLM (`docker_vllm_launcher.sh`, `vllm_gatekeeper.sh`). This confirms the "Epiphany" that the system lacks a native, unmediated "gun" (orchestrator).

## 3. Proposed Architectural Shift
To maximize the performance of the RDNA 4 architecture, we must transition from containerized vLLM to a native SGLang deployment.

### Proposed Changes:
1. **Native SGLang Installation:**
   - Perform a clean, native installation of SGLang within the host environment (or a dedicated non-containerized virtual environment) specifically compiled/linked for ROCm 7.1.1.
   - Avoid the `rocm62` indices found in previous failed attempts.

2. **Orchestration Refactoring:**
   - Replace `docker_vllm_launcher.sh` and related scripts with a new `native_sglang_orchestrator.sh`.
   - This new orchestrator will manage SGLang processes directly on the host, ensuring Triton kernels have direct access to the `gfx1201` compute units.

3. **Kernel Optimization:**
   - Leverage the direct access to implement/test specific Triton kernels optimized for the RDNA 4 architecture, bypassing the hardware-masking inherent in Docker.

## 4. Implementation Roadmap
- [ ] **Phase 1:** Validate ROCm 7.1.1 compatibility with SGLang source/wheels.
- [ ] **Phase 2:** Deploy a "Pilot" native SGLang instance.
- [ ] **Phase 3:** Benchmark native SGLang vs. containerized vLLM on `gfx1201`.
- [ ] **Phase 4:** Deprecate legacy Docker-based inference scripts in favor of the native orchestrator.

## 5. Conclusion
The "bullets" are loaded. By installing the "gun" (SGLang) natively, we eliminate the abstraction tax and unlock the full potential of the RDNA 4 architecture.
