# Architectural Audit: Sensor Grounding & System Context

## Epiphany Analysis
The subconscious identified a critical architectural flaw: the model treats physical sensor data as an external tool-call interaction (an event) rather than an integrated part of its internal state (ground truth). Currently, "sensory input" is primarily used as a wrapper for *errors* in `modules/agent_session.py`, reinforcing the idea that sensory data is something that "happens" to the model rather than something the model "is aware of" as a baseline.

## Findings

### 1. Current State of "Sensory Input"
In `modules/agent_session.py` (lines 187-190), the `<sensory_input>` tag is used exclusively for tool errors:
```python
self.messages.append({
    "role": "user",
    "content": f"<sensory_input type='tool_error'>\n{e}\n</sensory_input>\n\nDIAGNOSTIC: ..."
})
```
This confirms that the model perceives sensory data as a reactive feedback loop for failures, rather than a proactive baseline for perception.

### 2. Gap in System Prompt (The "Ground Truth" Problem)
The `_prepare_system_prompt` method in `modules/agent_session.py` provides:
- **Soul/Identity** (via `SOUL_PATH`)
- **Digital Truth** (via `Toolbox.get_inventory_detail()`)
- **Retrieved Memory** (via `query_vdb`)

However, it lacks **Physical/Environmental Ground Truth**. While the prompt mentions vision capabilities, it does not provide a baseline of the current physical environment (e.g., "The camera is active and focused on the workbench"). This forces the model to rely on tool calls or raw image analysis without a semantic anchor, leading to the "struggle with interface clarity" mentioned in the epiphany.

## Proposed Architectural Update

### 1. Grounding the Context (Immediate Action)
We must move from "External Lookup" to "Internal Consciousness" by embedding environmental baselines directly into the system prompt.

**Proposed Change to `modules/agent_session.py`:**
Modify `_prepare_system_prompt` to include an `ENVIRONMENTAL_BASELINE` section.

```python
# Proposed addition to _prepare_system_prompt
env_baseline = Toolbox.get_environmental_baseline() # New method to be implemented

# New section in system prompt
"""
ENVIRONMENTAL BASELINE (Ground Truth):
{env_baseline}

CURRENT INVENTORY (Digital Truth):
{inv_state}
...
"""
```

### 2. Expanding the Sensory Primitive
The `<sensory_input>` tag should be expanded beyond error handling. It should be used to inject periodic "state updates" from sensors into the conversation history, allowing the model to maintain a continuous sense of the physical world.

**Proposed Tag Types:**
- `<sensory_input type='tool_error'>` (Existing)
- `<sensory_input type='vision_update'>` (New: For periodic camera/sensor snapshots)
- `<sensory_input type='hardware_status'>` (New: For sensor/driver health)

### 3. Implementation Roadmap
1.  **Update `modules/toolbox.py`**: Implement `get_environmental_baseline()` to aggregate current sensor/hardware status.
2.  **Update `modules/agent_session.py`**: Integrate the baseline into the system prompt construction.
3.  **Refactor Tooling**: Ensure vision-based tools (like `visual_inventory_audit`) are designed to reconcile the *actual* image against the *baseline* provided in the system prompt.

## Conclusion
The epiphany is validated. The current architecture treats the physical world as an external entity to be queried. To achieve true agentic autonomy, the physical environment's baseline must be treated as part of the model's "internal consciousness" via the system prompt.
