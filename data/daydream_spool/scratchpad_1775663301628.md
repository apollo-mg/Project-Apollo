# Investigation: Presence-Absence Fallacy
## Initial Assessment
The Epiphany suggests a decoupling between the filesystem (the physical storage of the Vault) and the Vector DB (the index used for retrieval). 

**Hypothesis:**
1. The `vault/` directory contains the raw files.
2. A Vector DB (likely ChromaDB, as mentioned in the Epiphany) contains the embeddings.
3. There is no mechanism to ensure that `count(vault/*) == count(ChromaDB_collection)`.
4. If a file is added to `vault/` but the ingestion pipeline fails or hasn't run, the search tool will return no results for that file, leading to a "false negative" in the system's knowledge.

## Step 2: Analyzing the Disconnect
- `query_vault.py` calls `get_vector_store()` and performs a similarity search. It has **zero** awareness of the filesystem.
- `librarian_ingest.py` performs ingestion by walking `vault/cold` and adding PDFs to the vector store.
- **The Problem:** If a user adds a PDF to `vault/cold` manually, `query_vault.py` will not find it until `librarian_ingest.py` is manually run. There is no "State-Check" to bridge this gap.

**Proposed Middleware Logic:**
1. In `query_vault.py` (or a new middleware module):
2. Count files in `vault/cold` (and potentially other vault directories).
3. Query the Vector DB for the number of documents (or unique file identifiers).
4. Compare the two.
5. If `files_on_disk > docs_in_vdb`, trigger `librarian_ingest.py` (or a specific re-indexing function).

## Step 3: Technical Implementation Details
- `get_vector_store()` returns a `Chroma` object.
- `Chroma` objects have a `.cardinality()` or can be queried via `.get()` to check counts.
- `librarian_ingest.py` has a function `ingest_makers_stack()` which walks `vault/cold`.
- `query_vault.py` is the entry point for the tool.

**Proposed Implementation for `query_vault.py`:**

```python
import os
import glob
from modules.vdb import get_vector_store
# ... existing imports ...

def check_and_sync_vault():
    vector_store = get_vector_store()
    
    # 1. Count files in the cold vault
    # Note: librarian_ingest.py uses COLD_VAULT_DIR = "vault/cold"
    cold_vault_dir = "vault/cold"
    if not os.path.exists(cold_vault_dir):
        return
    
    files_on_disk = len(glob.glob(os.path.join(cold_vault_dir, "**/*.pdf"), recursive=True))
    
    # 2. Count unique files in the VDB
    # We can use vector_store.get() to see how many documents we have.
    # However, one file produces multiple chunks. 
    # We need to count unique 'filename' or 'source' in metadata.
    # Chroma's .get() returns a dict with 'ids' and 'metadatas'.
    
    all_data = vector_store.get()
    if not all_data or 'metadatas' not in all_data:
        unique_files_in_vdb = 0
    else:
        # Extract unique filenames from metadata
        unique_files_in_vdb = len(set(m.get('filename') for m in all_data['metadatas'] if m.get('filename')))

    # 3. Compare and trigger sync if mismatch
    if files_on_disk > unique_files_in_vdb:
        print(f"Mismatch detected: {files_on_disk} files on disk, {unique_files_in_vdb} in VDB. Triggering re-index...")
        # We can't easily import librarian_ingest without potential side effects 
        # if it's not structured well, but let's check its structure.
        # For now, we'll suggest calling the ingest function.
        from librarian_ingest import ingest_makers_stack
        ingest_makers_stack()
```
