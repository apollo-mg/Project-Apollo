# Architectural Proposal: Hardware-Constraint-First (MHA) Deployment Logic

## Epiphany Summary
The transition from heavy UNet models to SDXL-Turbo during ROCm 7.2 kernel validation revealed that model selection should be driven by hardware constraints (VRAM/Disk) rather than just model capability. The "failure" of a large download was actually the optimal signal for a more efficient, hardware-aligned path.

## Proposed Architectural Change: Model-to-Hardware Alignment (MHA)

Instead of a blind model download/execution pipeline, we propose integrating a pre-flight "Hardware-Constraint-First" check.

### 1. Core Logic Integration
We will introduce a `HardwareProfile` interface and a `ModelRegistry` that maps model identifiers to their estimated resource requirements (VRAM, Disk, Compute Intensity).

### 2. Implementation Plan

#### A. Define Hardware Profile (New Module/Type)
In `src/types.ts`, define:
```typescript
export interface HardwareProfile {
  readonly vramRequiredGB: number;
  readonly diskSpaceRequiredGB: number;
  readonly computeIntensity: 'low' | 'medium' | 'high';
}

export interface ModelResourceRequirements {
  readonly modelId: string;
  readonly profile: HardwareProfile;
}
```

#### B. Implement MHA Logic in `Agent` or `Orchestrator`
Modify the agent initialization or task dispatching logic to perform a "Constraint Check":

1. **Scan Environment:** Use `os` or system calls to detect available VRAM and Disk space.
2. **Validate Model:** Compare `AgentConfig.model` requirements against available resources.
3. **Auto-Fallback/Selection:** If `vramRequiredGB > availableVRAM`, the system should automatically switch the `model` identifier to a "Hardware-Aligned" alternative (e.g., switching from a full UNet to SDXL-Turbo) before the download/load phase begins.

### 3. Concrete Code Changes (Draft)

#### `src/agent/agent.ts` (or a new `src/hardware/profiler.ts`)
```typescript
// Proposed logic for Agent initialization
async function validateModelAlignment(config: AgentConfig): Promise<AgentConfig> {
  const hardware = await getSystemHardwareProfile();
  const requirements = await getModelRequirements(config.model);

  if (requirements.profile.vramRequiredGB > hardware.availableVRAM) {
    console.warn(`[MHA] Model ${config.model} exceeds VRAM. Falling back to hardware-aligned model.`);
    return {
      ...config,
      model: selectOptimalModel(config.model, hardware) 
    };
  }
  return config;
}
```

## Conclusion
By moving the decision point from "Post-Failure" (reactive) to "Pre-Flight" (proactive), we transform a system error into a deterministic optimization step. This ensures that the pipeline is always hardware-aligned, maximizing throughput and minimizing "No space left" or OOM errors.
