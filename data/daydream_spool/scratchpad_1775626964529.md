# Investigation: Contrastive Learning for Harvester Loop Optimization
## Timestamp: 2025-05-22 (Simulated)
## Status: Initializing Audit

### Hypothesis
The "Harvester" loop (likely responsible for data collection/fine-tuning preparation) currently collects "correct" data but lacks the "error-delta" context. To implement the Epiphany's insight, we need to identify:
1. The component responsible for generating/collecting training data (The Harvester).
2. The component that validates/corrects it (The Janitor).
3. The data format used for fine-tuning (JSONL/Dataset files).

### Search Strategy
1. Search for "Harvester" in the codebase to find the implementation.
2. Search for "Janitor" to find the correction mechanism.
3. Examine `training_failures.jsonl`, `training_memory.jsonl`, and `training_success.jsonl` to see the current data structure.
4. Look for SQL-related training data to verify the "hallucination vs resolution" context.
### Findings
1. **Data Structure Analysis**:
   - `training_failures.jsonl`: Contains simple prompt/response/expected_tag pairs. It represents "hard" failures where the model failed to produce the correct tag or format.
   - `training_success.jsonl`: Contains successful prompt/response/expected_tag pairs.
   - `training_memory.jsonl`: Contains complex "conversation" objects with a `small_model_output` (containing a `<think>` block and a summary) and a `refined_summary`. This is the "Janitor" output.

2. **The "Alchemy of Failure" Identification**:
   - The `training_memory.jsonl` file is the key. It contains the `small_model_output` (the "hallucination" or "incompetent" attempt) and the `refined_summary` (the "resolution" or "fact").
   - The `small_model_output` includes a `<think>` block. This is where the model's "logic" is exposed.
   - The "Janitor" (the process that generates `refined_summary`) is essentially performing the "alchemy" by comparing the `small_model_output` to the ground truth.

3. **The Gap**:
   - Currently, the training data seems to be used to teach the model to produce the `refined_summary`.
   - However, the "Epiphany" suggests we should not just teach the *result*, but the *divergence*.
   - The current training data (specifically in `training_memory.jsonl`) provides the *correct* answer, but it doesn't explicitly force the model to learn *why* its previous thought process was wrong.

### Proposed Architectural Update: Contrastive Training Curriculum
To implement the "Contrastive Learning" insight, we need to modify the data pipeline that prepares the fine-tuning dataset.

**Proposed Change: The "Delta-Mapping" Schema**
Instead of a single `refined_summary` target, we should introduce a `contrastive_pair` in the training JSONL.

**New Schema Example:**
```json
{
  "conversation": [...],
  "error_analysis": {
    "hallucination_pattern": "Logical leap: assumed 'user_id' index was sufficient without checking statistics.",
    "divergence_point": "The model failed to consider the impact of stale statistics on the query planner.",
    "correction_logic": "The error was not in the index existence, but in the planner's state. The fix requires an ANALYZE command."
  },
  "target_output": "Running `ANALYZE` to update stale statistics resolved the 5-second SQL join latency..."
}
```

**Implementation Steps:**
1. **Update `training_memory.jsonl` Generator**: Modify the script (likely part of the `Harvester` or `Janitor` logic) to generate an `error_analysis` field. This field must explicitly describe the "delta" between the `small_model_output` and the `refined_summary`.
2. **Refine the 'Janitor' Prompt**: The Janitor (the LLM that corrects the small model) must be prompted to:
   - Identify the specific logical error in the `<think>` block.
   - Categorize the error (e.g., "Stale Statistics", "Type Mismatch", "Circular Dependency").
   - Formulate the "Contrastive Delta".
3. **Fine-tuning Objective**: Update the training script to use a loss function that penalizes the model not just for the wrong summary, but for failing to identify the error pattern in its own `<think>` block.

### Conclusion
The epiphany is valid. The current system is a "Janitor" that cleans up messes. To evolve, it must become a "Professor" that explains *why* the mess happened. The transition from "Correcting Output" to "Mapping Divergence" is the key to structural intelligence.
