# Architectural Audit Report: Environment Path Abstraction

## 1. Executive Summary
The "Epiphany" regarding friction in 'Final Burn' attempts is validated. The codebase exhibits significant "path-dependency debt," where critical execution scripts (including training and telemetry) rely on hardcoded absolute paths (`/mnt/TG_2TB/Projects/Apollo/...`). This creates a fragile environment where filesystem shifts or containerization cause immediate execution failure (`ENOENT`).

## 2. Audit Findings
- **Path Density:** High. Multiple core scripts (`deep_sleep_triage.py`, `telemetry_layer.py`, `batch_log_processor.py`) contain hardcoded absolute paths.
- **Critical Failure Points:**
    - `deep_sleep_triage.py`: Hardcoded paths for `SPOOL_DIR` and `TRAINING_DATASET` threaten the model training pipeline.
    - `telemetry_layer.py`: Hardcoded `telemetry_state_log.jsonl` path risks data loss/corruption if the environment changes.
    - `modules/voice.py`: Hardcoded paths for binaries and models make the module non-portable.
- **Root Cause:** The architecture currently "maps the physical" (hardcoded paths) rather than "trusting the abstract" (environment-aware configuration).

## 3. Proposed Architectural Update: `ApolloConfig` Layer

### Objective
Transition from manual directory traversal and hardcoded strings to a centralized, `pathlib`-based configuration singleton.

### Implementation Specification

#### A. New Module: `core/config.py`
Implement a `ApolloConfig` class that:
1.  **Resolves Root Dynamically:** Uses `Path(__file__).resolve().parents[n]` to find the project root, with an override via `APOLLO_ROOT` environment variable.
2.  **Defines Standardized Paths:**
    - `ROOT`: Project base directory.
    - `DATA_DIR`: `ROOT / "data"`
    - `SPOOL_DIR`: `ROOT / "data/daydream_spool"`
    - `LOG_DIR`: `ROOT / "log_chunks"`
    - `MODULES_DIR`: `ROOT / "modules"`
    - `MODELS_DIR`: `ROOT / "models"`
3.  **Provides Validation:** A `validate()` method to ensure all required directories exist before execution begins.

#### B. Refactoring Strategy (Read-Only Audit)
The following files require immediate refactoring to replace hardcoded strings with `ApolloConfig` attributes:
- `tools/liara_indexer.py`
- `batch_log_processor.py`
- `archive/generate_dev_log.py`
- `moe_shootout.py`
- `telemetry_layer.py`
- `deep_sleep_triage.py`
- `modules/voice.py`

## 4. Conclusion
Standardizing the environment through this abstraction layer will eliminate the "labyrinth" of the local filesystem. It transforms the architecture from a rigid, path-dependent structure into a portable, abstract-ready system capable of supporting high-intensity "Final Burn" cycles without manual intervention.

**Status:** Audit Complete. Proposal Ready for Implementation.
**Recommendation:** Immediate implementation of `core/config.py` and phased refactoring of identified scripts.
