# Investigation Log: Epiphany - Identity as a Continuous Feedback Loop
## Timestamp: 2025-05-22 (Simulated)
## Status: Initializing Audit

### Objective
Investigate the implementation of 'Static Dossier' vs 'Recent Context' in `buddy_agent.py` and propose a 'Promotion Logic' to transition patterns from context to core axioms.

### Initial Observations
- The Epiphany suggests that the current distinction is artificial.
- The goal is to implement a mechanism where high-frequency/high-significance patterns in the 'Recent Context' are promoted to the 'Core Axiom set' (formerly Static Dossier).
- This prevents personality oscillation.

### Plan
1. Examine `buddy_agent.py` to understand how it currently handles dossier and context.
2. Identify the data structures used for 'Static Dossier' and 'Recent Context'.
3. Propose the `Promotion Logic` implementation.
### Current State Analysis
- `CitizenDossier` in `modules/core.py` manages the `DOSSIER_PATH` (`shop_dossier.json`).
- It has a `DEFAULT_STRUCTURE` with categories like `identity`, `projects`, `preferences`, `philosophy`, `history`, and `brainstorming_seeds`.
- `ApolloAgentSession._prepare_system_prompt` loads the `SOUL_PATH` (`SOUL.md`) and retrieves memory via `query_vdb`.
- The "Static Dossier" mentioned in the Epiphany likely refers to the `CitizenDossier` (or `SOUL.md`).
- The "Recent Context" is the `self.messages` list in `ApolloAgentSession`.

### Proposed Architectural Change
1. **Rename/Refactor**: Rename `CitizenDossier` to `CoreAxiomSet`.
2. **Implement Promotion Logic**:
    - Create a new class/module `modules/promotion_engine.py`.
    - This engine will track the frequency and significance of "insights" or "patterns" extracted from the `ApolloAgentSession` history.
    - When a pattern (e.g., a specific user preference or a discovered system truth) appears with a frequency above a threshold $T$ within a sliding window of $N$ turns, it is "promoted".
    - Promotion involves calling `CoreAxiomSet.add_insight(category, claim)`.
3. **Integration**:
    - In `ApolloAgentSession._finalize_session`, after logging to Foundry, trigger the `PromotionEngine`.
    - The `PromotionEngine` will analyze the `self.results` and `self.final_answer` to identify potential new axioms.

### Technical Implementation Details
- **Data Structure for Tracking**: A lightweight SQLite database or a JSON file (`data/promotion_candidates.json`) to store candidate axioms and their occurrence counts.
- **Promotion Criteria**:
    - `count >= threshold`
    - `confidence_score` (derived from LLM analysis of the pattern's stability).
- **Code Changes**:
    - `modules/core.py`: Update `CitizenDossier` $\rightarrow$ `CoreAxiomSet`.
    - `modules/agent_session.py`: Add call to `PromotionEngine.process_session(...)` in `_finalize_session`.
    - New file: `modules/promotion_engine.py`.
