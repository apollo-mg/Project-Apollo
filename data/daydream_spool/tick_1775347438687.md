# Architectural Audit: Epiphany - Model Role Segregation & Memory Bandwidth Optimization

## 🧠 Epiphany Summary
The 'L3 Scratchpad' micro-optimization approach is a fallacy for dual-socket EPYC systems. True sovereignty is achieved by leveraging massive DDR5 capacity and bandwidth through **Model Role Segregation**. Instead of a monolithic model, the Apollo OS must implement a heterogeneous orchestration layer that routes tasks based on 'Output Intent'.

## 🔍 Audit Findings
1.  **Current State (Monolithic/Sub-optimal):**
    *   `llm_interface.py` currently uses a single `UNIFIED_MODEL` (`Qwen3.5-35B-A3B-UD-IQ2_XXS`) for all queries.
    *   The system lacks an "Intent Router" to distinguish between 'Conversation/Reasoning' and 'Metrological/Vision' tasks.
    *   The current architecture treats the system as a single-model interface, ignoring the potential for specialized model routing.

2.  **Hardware Alignment:**
    *   The system is running on high-capacity DDR5 (EPYC), but the software is currently optimized for low-latency/small-cache models, which fails to utilize the "Semantic Reservoir" of the massive RAM pool.

## 🏗️ Proposed Architectural Update: "The Intent-Based Router"

### 1. Implementation of `IntentRouter`
We must move away from `UNIFIED_MODEL` in `llm_interface.py` and implement a routing logic.

**Proposed Logic:**
*   **Route A: Metrological/Vision (JSON-Strict/Data Extraction)**
    *   *Target:* `Qwen2.5-VL` (or equivalent vision-specialized model).
    *   *Trigger:* Presence of `image_path` or keywords like "extract", "json", "table", "data".
*   **Route B: High-Reasoning/Philosophical (Sovereign/Uncensored)**
    *   *Target:* Large-parameter models (405B+ or high-quantization 70B+).
    *   *Trigger:* High-complexity reasoning prompts, philosophical queries, or "deep thought" requests.
*   **Route C: Conversational/General (Standard)**
    *   *Target:* Current `Qwen3.5-35B` (The "Workhorse").

### 2. Codebase Modification Plan (Draft)

**File: `llm_interface.py`**
*   **Change:** Replace `UNIFIED_MODEL` constant with a `MODEL_REGISTRY` dictionary.
*   **Change:** Modify `query_llm` and `stream_llm` to accept an `intent` parameter or perform auto-detection.

```python
# PROPOSED REGISTRY
MODEL_REGISTRY = {
    "METROLOGY": "Qwen2.5-VL-7B-Instruct", # For vision/JSON
    "REASONING": "Llama-3-405B-Instruct", # For deep sovereignty
    "CONVERSATION": "Qwen3.5-35B-A3B-UD-IQ2_XXS" # Default
}

def detect_intent(prompt, image_path):
    if image_path:
        return "METROLOGY"
    # Simple heuristic or a tiny 'router' model call
    if any(word in prompt.lower() for word in ["analyze", "extract", "json", "data"]):
        return "METROLOGY"
    return "CONVERSATION"
```
