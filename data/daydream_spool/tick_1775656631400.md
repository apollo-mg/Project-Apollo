# Architectural Proposal: Semantic Sanitization Layer (Digital Buffer)

## 1. Executive Summary
To resolve the paradox of hyper-personalized utility vs. digital invisibility, we will implement a 'Semantic Sanitization' layer. This layer acts as a one-way valve between the local, high-context LLM environment and the global, public web-search modules. It ensures that private user context (e.g., "Mark's threshold") is translated into commodity-grade queries (e.g., "Product X price") before any external network requests are dispatched.

## 2. Identified Vulnerability
The current implementation of `modules/sovereign_search.py` passes the raw `query` string directly to the `DDGS` (DuckDuckGo) engine. If the orchestrator passes a query containing personal identifiers, specific financial thresholds, or private preferences, these are transmitted in plaintext to the search provider, creating a significant privacy leak.

## 3. Proposed Architectural Changes

### A. New Component: `modules/semantic_sanitizer.py`
A new module dedicated to the "Translation" of intent. It will utilize the existing `llm_interface` to perform context-stripping.

**Proposed Implementation Logic:**
```python
import llm_interface

def sanitize_query(user_query: str) -> str:
    """
    Translates a high-context, private query into a zero-context, 
    commodity-grade search term.
    """
    sanitization_prompt = (
        "You are a Semantic Sanitizer. Your goal is to strip all personal "
        "identifiers, private context, and specific user-related thresholds "
        "from a query, converting it into a generic, commodity-grade search "
        "term suitable for a public search engine. \n\n"
        "Rules:\n"
        "1. Remove names, specific locations, or personal identifiers.\n"
        "2. Convert specific thresholds (e.g., 'Mark's budget') into generic terms.\n"
        "3. Output ONLY the sanitized search term. No explanation.\n\n"
        f"User Query: {user_query}\n"
        "Sanitized Query:"
    )
    
    try:
        # Use the existing LLM interface to perform the translation
        sanitized = llm_interface.query_llm(sanitization_prompt).strip()
        return sanitized
    except Exception as e:
        # Fallback to raw query if sanitization fails, but log the error
        print(f"[!] Sanitization failed: {e}. Falling back to raw query.")
        return user_query
```

### B. Integration: `modules/sovereign_search.py`
Modify the `sovereign_search` entry point to intercept the query.

**Proposed Code Change:**
```python
# modules/sovereign_search.py

from modules.semantic_sanitizer import sanitize_query # New Import

# ... (existing code)

def sovereign_search(query):
    """The master search loop with semantic sanitization."""
    # NEW: Sanitize the query before it touches the web
    sanitized_query = sanitize_query(query)
    print(f"[*] Sanitized Query: '{sanitized_query}' (Original: '{query}')")
    
    raw_data = perform_search(sanitized_query) # Use sanitized version
    if not raw_data:
        return "No results found."
    # ... (rest of function)
```

## 4. Impact Assessment
- **Privacy:** High improvement. Prevents identity leakage to third-party search providers.
- **Utility:** Minimal impact. The intelligence is preserved in the *intent* of the query, even if the *context* is stripped.
- **Latency:** Slight increase due to the additional LLM call for sanitization. This is a necessary trade-off for the "Digital Buffer" architecture.

## 5. Implementation Roadmap
1. **Phase 1:** Create `modules/semantic_sanitizer.py`.
2. **Phase 2:** Integrate `sanitize_query` into `modules/sovereign_search.py`.
3. **Phase 3:** Validate with test cases (e.g., "What is the price of a laptop for Mark's $500 budget?" -> "Laptop price").
4. **Phase 4:** Monitor for "over-sanitization" where queries become too generic to be useful.
