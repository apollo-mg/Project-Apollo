# Architectural Audit: Hardware Fidelity Metadata Integration

## 1. Executive Summary
The "Epiphany" identified a critical gap in the agent's self-awareness: the disconnect between its cognitive reasoning requirements and its actual hardware constraints (quantization/VRAM). To prevent "high-precision hallucinations" (where the agent attempts complex logic that its current bit-depth cannot reliably sustain), we must integrate real-time hardware telemetry into the LLM's context window.

## 2. Audit Findings
- **Telemetry Availability:** High. `vram_management.py` and `system_monitor.py` already provide the necessary raw data (VRAM usage, CPU/RAM stats).
- **Context Injection Point:** `llm_interface.py` is the bottleneck. Currently, it constructs messages using a static `DeploymentConfig` without regard for real-time hardware state.
- **Missing Link:** There is no mechanism to translate "VRAM usage" or "Model ID" into a "Cognitive Fidelity Score" that the LLM can interpret.

## 3. Proposed Architectural Update

### A. New Component: `FidelityMonitor`
Create `src/modules/fidelity_monitor.py` to aggregate:
- **VRAM Headroom:** From `vram_management.py`.
- **Quantization Level:** Extracted from the active model name in `model_manifest.json` or `DeploymentConfig`.
- **System Load:** From `system_monitor.py`.

### B. Context Injection (The "Fidelity Header")
Modify `llm_interface.py` to prepend a structured metadata block to the `system_message`.

**Proposed Header Format:**
```text
[SYSTEM_FIDELITY_REPORT]
- VRAM_FREE: {x} MB
- QUANTIZATION: {y} (e.g., Q5_K_M, FP8)
- COGNITIVE_CAPACITY: {z} (Low/Medium/High)
- INSTRUCTION: Adjust reasoning depth and complexity to match current bit-depth.
[END_REPORT]
```

### C. Implementation Logic
1. **`llm_interface.py`**: Update `query_llm` to accept a `fidelity_report` string.
2. **`orchestrator.py`**: Before calling `query_llm`, call `FidelityMonitor.get_report()` and pass the result.

if fidelity_report:

### `src/modules/fidelity_monitor.py` (New File)
```python
import vram_management
import system_monitor

class FidelityMonitor:
    @staticmethod
    def get_report(model_name: str) -> str:
        vram = vram_management.get_gpu_stats()
        free_vram = vram.get("vram_total_mb", 0) - vram.get("vram_used_mb", 0)
        
        # Simple heuristic for cognitive capacity
        capacity = "High" if free_vram > 8000 else "Medium" if free_vram > 4000 else "Low"
        
        return (
            f"[SYSTEM_FIDELITY_REPORT]\n"
            f"- VRAM_FREE: {free_vram:.0f}MB\n"
            f"- MODEL: {model_name}\n"
            f"- COGNITIVE_CAPACITY: {capacity}\n"
            f"[END_REPORT]"
        )
```

## 5. Risk Assessment
- **Token Overhead:** Minimal (~50-100 tokens).
- **Latency:** Negligible (telemetry calls are fast).
- **Benefit:** Significant reduction in "hallucination-by-precision-loss" during high-complexity tasks.
