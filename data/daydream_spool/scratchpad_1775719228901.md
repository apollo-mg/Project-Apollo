# Investigation: RDNA 4 Patch Preservation
## Objective
Identify RDNA 4 specific patches and assess if the logic/rationale is preserved or lost during reset cycles.

## Initial Hypothesis
The current workflow relies on ephemeral patches that are not decoupled from the main branch or documented in a way that survives a `git reset --hard`.
## Findings: RDNA 4 Patch Vulnerability
- **Detection**: The RDNA 4 issue is identified in `synthesizer_batch.log` as hardware-level instability (ROCm/HIP) causing "RMS Norm" errors and silent data corruption.
- **Current State**: No explicit RDNA 4 or RMS Norm workarounds were found in the `src/` directory. This suggests the "patches" mentioned in the Epiphany might be:
    1. External to this repository (e.g., system-level ROCm/HIP patches).
    2. Applied via scripts like `patch_coordinator.py` (though that script only modifies prompts/configs).
    3. Implemented in a way that is not currently indexed by standard grep (e.g., dynamic injection or external binary dependencies).
- **Risk Assessment**: The `deep_purge.sh` script cleans build artifacts and submodules but does not perform a `git reset --hard`. However, the Epiphany explicitly mentions `git reset --hard`. If the user is performing manual resets to recover from the "corruption loop," any local, uncommitted patches to the ROCm/HIP environment or the codebase are at high risk of being lost.
- **Conclusion**: The "why" is currently missing from the codebase. There is no documentation of the specific hardware-level discrepancies being addressed.

## Proposed Architectural Update: "The Logic Vault"
To prevent the "patch and purge" cycle, we must decouple hardware workarounds from the ephemeral codebase.

1. **Implement a `hardware_workarounds.json` or `.md` file**: This file must reside in a persistent directory (or be committed to a dedicated `infrastructure-fixes` branch).
2. **Formalize Patch Extraction**: Before any `git reset` or `deep_purge`, a mandatory step must be added to extract the diff of any hardware-related changes.
3. **Automated Verification**: Add a check in the build/test pipeline that verifies if known RDNA 4 workarounds are present when the hardware is detected.
