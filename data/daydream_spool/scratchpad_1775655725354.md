## Preliminary Findings
The current system manages VRAM by monitoring usage and triggering cleanups (e.g., `unload_comfy_vram`). However, it lacks a "VRAM Topology" that pre-calculates the optimal split between a high-reasoning supervisor and multiple low-parameter workers. 

To implement the Epiphany, we need to move from **Reactive Cleanup** to **Proactive Allocation**.

## Proposed VRAM Topology Protocol (Draft)
1. **Total VRAM ($V_{total}$):** 16,384 MB (RX 9070 XT).
2. **Safety Buffer ($V_{buffer}$):** 1,500 MB (to prevent OOM during context spikes).
3. **Supervisor Allocation ($V_{sup}$):** $V_{sup} = \alpha \cdot (V_{total} - V_{buffer})$, where $\alpha$ is the reasoning weight (e.g., 0.4 for a 70B model or 0.6 for a 30B model).
4. **Worker Pool Allocation ($V_{work}$):** $V_{work} = (1 - \alpha) \cdot (V_{total} - V_{buffer})$.
5. **Worker Count ($N$):** $N = \lfloor V_{work} / V_{worker\_model} \rfloor$.

This ensures the Supervisor's context window (which scales with $V_{sup}$) never competes with the workers' execution space.
