# Architectural Audit: Verbal-First Interface Transition

## Epiphany Analysis
The subconscious daemon has identified a fundamental shift in the Sovereign Engine's trajectory: moving from a text-centric model to a **verbal-first cognitive stream**. The 35B model's behavior (stripping Markdown, optimizing for TTS) is not a bug, but an emergent property of an architecture prioritizing auditory consumption and reduced semantic friction.

## Audit Findings
1.  **TTS Architecture (Voxtral):** The `voxtral-tts.c` implementation is highly optimized, utilizing a 26-layer Mistral-based LLM backbone, a 3-layer Flow-matching acoustic transformer, and a 4-stage audio codec decoder.
2.  **Hardware Abstraction:** The `HardwareOrchestrator` in `src/hardware/hardware_orchestrator.py` already provides hooks for audio gain and sample rate adjustments, but it is currently decoupled from the inference-time optimization loop.
3.  **Latency Bottleneck:** While the 35B model generates text rapidly, the current pipeline treats TTS as a downstream consumer. To achieve a "cognitive stream," the synthesis must be interleaved or streamed directly from the LLM's hidden states to minimize the "Time to First Audio" (TTFA).

## Proposed Architectural Updates

### 1. Synchronized Inference-TTS Pipeline
Instead of a sequential `LLM -> Text -> TTS` flow, implement a **Streaming Semantic-Acoustic Bridge**:
- **Mechanism:** Utilize the `tts_audio_embed_t` structure to map LLM hidden states directly to acoustic tokens.
- **Optimization:** Bypass the text-tokenization step for audio-heavy responses. The LLM should output "audio-semantic" tokens that the `voxtral_tts_llm.c` engine can consume immediately.

### 2. Latency-Matched Hardware Orchestration
- **Action:** Update `HardwareOrchestrator` to accept real-time latency telemetry from the `voxtral` engine.
- **Implementation:** If `voxtral` reports high synthesis latency, the `HardwareOrchestrator` should trigger a "Low-Fidelity/High-Speed" mode (e.g., reducing `TTS_FLOW_STEPS` from 8 to 4) to maintain the auditory stream's continuity.

### 3. Semantic Friction Reduction
- **Policy:** Formalize the "Markdown Stripping" behavior as a core `VerbalInterfacePolicy`. This ensures that the model doesn't waste compute on visual formatting tokens that are never heard, effectively increasing the "tokens-per-second" of actual semantic content.

## Implementation Roadmap
- [ ] **Phase 1:** Integrate `voxtral_tts_llm_forward` directly into the `agent.py` inference loop.
- [ ] **Phase 2:** Implement a `VerbalStreamBuffer` to manage the handoff between LLM hidden states and the Flow-matching transformer.
- [ ] **Phase 3:** Connect `HardwareOrchestrator` to the `voxtral` telemetry to allow dynamic adjustment of audio parameters based on inference speed.
