# Architectural Proposal: System 2 Ingestion Scaling

## 1. Problem Statement
The current `email_ingest.py` implementation is a sequential, synchronous process that processes emails one-by-one. It includes an artificial 2-second delay between every email and performs $O(N^2)$ file I/O by re-writing the entire `processed_email_ids.json` file for every single email. This creates a massive throughput bottleneck, preventing the 'System 2' layer from keeping pace with the 'System 1' data acquisition.

## 2. Proposed Changes

### A. Concurrency Model (The "Engine" Upgrade)
- **Transition to `ThreadPoolExecutor`:** Replace the single-threaded `for key in new_keys` loop with a worker pool. This allows multiple emails to be analyzed by the LLM simultaneously, maximizing GPU utilization.
- **Semaphore-based Rate Limiting:** Instead of `time.sleep(2)`, implement a `threading.BoundedSemaphore` to limit the number of concurrent LLM requests to a safe number (e.g., 4-8) to prevent VRAM exhaustion.

### B. State Management Optimization
- **Batch State Updates:** Move `save_json_list(PROCESSED_FILE, ...)` outside the loop. Update the `processed_ids` set in memory and write to disk only once per batch or once per hour.
- **SQLite Transition (Long-term):** Recommend moving from a JSON list to a local SQLite database for `processed_email_ids` to allow $O(1)$ lookups and insertions.

## 3. Impact Assessment
- **Throughput:** Expected increase from ~0.4 emails/sec (due to 2s sleep) to ~2-4 emails/sec (depending on LLM latency and concurrency).
- **Resource Efficiency:** Higher GPU utilization; lower disk I/O overhead.
- **Risk:** Increased VRAM pressure. This must be tuned via `MAX_WORKERS`.

## 4. Implementation Priority
1. **High:** Implement `ThreadPoolExecutor` and remove `time.sleep(2)`.
2. **Medium:** Move `save_json_list` out of the loop.
3. **Low:** Migrate to SQLite for processed IDs.
