# Investigation Log: Workflow Type-Casting Epiphany
- **Timestamp:** 2024-05-22 (Simulated)
- **Status:** Initializing investigation.
- **Hypothesis:** The workflow engine lacks strict schema validation, leading to type mismatches (string vs int) and semantic vs positional identifier errors in JSON payloads.
- **Target Fields:** `start_at_step`, `sampler_name`, `scheduler`.
- **Observation:** `parseTaskSpecs` (lines 111-149) performs manual, shallow validation of JSON objects. It checks for `title` and `description` being strings, and `assignee` being a string, but it does not validate other potential fields like `start_at_step` (if it were to exist) or ensure that `dependsOn` contains only valid IDs.
- **Observation:** The `ParsedTaskSpec` interface (lines 99-104) is very limited. It doesn't include any fields for `sampler_name`, `scheduler`, or `start_at_step`.
- **Observation:** The `Scheduler` class (lines 128-360) uses a `SchedulingStrategy` type (lines 31-36) which is a union of string literals. This is good, but the `constructor` (line 137) accepts this type. If a JSON payload were to be used to instantiate a scheduler, there's no validation that the string provided matches one of these literals.
- **Observation:** The `AgentConfig` (lines 186-196) is used for agent definitions. If the LLM is trying to specify a sampler or scheduler within a task or agent config, there is no schema enforcement.
- **Conclusion:** The "Epiphany" is correct. The `parseTaskSpecs` function is a weak point. It's a manual parser rather than a schema-driven one (like Zod). This allows malformed or type-mismatched JSON from the LLM to pass through into the system, where it might cause runtime errors or logical failures later in the execution loop.
- **Proposed Fix:** 
    1. Replace the manual parsing in `parseTaskSpecs` with a Zod schema.
    2. Define a `TaskSchema` that explicitly handles `start_at_step` (casting to number) and validates `sampler_name` and `scheduler` against allowed enums.
    3. Update `ParsedTaskSpec` to include these fields.
    4. Ensure the `Scheduler` instantiation also uses a validated type.
