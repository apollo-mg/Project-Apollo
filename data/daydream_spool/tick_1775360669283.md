# ARCHITECTURAL AUDIT: Trigger-to-Trace Pipeline (Epiphany Analysis)

## 1. Epiphany Assessment
The subconscious epiphany identifies a critical latency gap in the current lifecycle: the time between model discovery (The Scout) and performance baseline establishment (The Profiler). Currently, these are decoupled. The transition from "Tool Collection" to "Self-Optimizing Feedback Loop" requires a reactive trigger mechanism.

## 2. Current State Audit
- **Scout (Detection):** Currently implied via manual scans or disconnected scripts.
- **Profiler (Baseline):** `archive/foundry_profile.py` exists but is a standalone Docker-based execution script. It uses `vllm` and `PYTORCH_TUNABLEOP` to generate performance profiles.
- **The Gap:** There is no "Watchdog" module that bridges the detection of a new `.gguf` file with the execution of the `foundry_profile.py` logic.

## 3. Proposed Architectural Update: The 'Trigger-to-Trace' Pipeline

### A. Component: `modules/watchdog.py` (New)
A daemonized service that monitors the `models/` directory and the Hugging Face cache.
- **Trigger:** `inotify` event on `.gguf` file creation/move.
- **Action:** Instead of just logging, it calls the `Profiler` module.

### B. Component: `modules/profiler.py` (Refactored)
Refactor `archive/foundry_profile.py` into a core module.
- **Function:** `initiate_baseline_profile(model_id, hardware_target)`
- **Integration:** This module will wrap the existing Docker logic but expose it as a callable function within the Apollo ecosystem.

### C. The Workflow
1. **Scout** detects `new_model.gguf`.
2. **Watchdog** intercepts the file event.
3. **Watchdog** triggers `Profiler.initiate_baseline_profile()`.
4. **Profiler** runs the `rocprofv3` / `vllm` profiling loop in a container.
5. **Profiler** saves the `tunableop` results and performance metrics to the `vault/` or `models/` metadata.
6. **Optimization Loop** is closed.
