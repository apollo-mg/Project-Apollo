# Architectural Audit: Kokoro TTS Dependency Management

## Epiphany Analysis
The subconscious identified a critical vulnerability in the current TTS implementation: the "Moving Target" problem. The system relies on external, non-deterministic URLs or local paths that are prone to breakage (e.g., `KOKORO_MODEL_PATH = "/home/mark/commander/kokoro-v0_19.onnx"` in `legacy_vault/tools/jarvis_local_voice.py`). This creates a fragile dependency chain where the execution logic is coupled to the availability and location of third-party assets.

## Audit Findings
1.  **Hardcoded Paths:** Multiple scripts in `legacy_vault/tools/` (e.g., `list_voices.py`, `voice_audition.py`, `jarvis_local_voice.py`) use absolute paths pointing to `/home/mark/commander/`. This is highly non-portable and prone to failure if the environment changes.
2.  **Implicit Dependencies:** `commander_voice_sd.py` uses `KOKORO_MODEL = "kokoro-v0_19.onnx"`, assuming the file exists in the current working directory.
3.  **Asset Fragmentation:** The model file `kokoro-v0_19.onnx` was found in `/mnt/TG_2TB/Projects/Apollo/models/`, but the code is not consistently pointing to this centralized repository.

## Proposed Architectural Update: The Artifact Registry Model

To decouple execution from external volatility, I propose the implementation of a **Local Artifact Registry**.

### 1. Implementation of `ArtifactManager`
Create a centralized service to handle model loading and path resolution.

### 2. Refactoring Strategy
*   **Phase 1 (Immediate):** Replace all hardcoded paths in `legacy_vault/tools/*.py` with calls to `ArtifactManager.get_model_path()`.
*   **Phase 2 (Stabilization):** Implement a `sync_assets.py` script that runs during system initialization to verify the checksums of all files in `/mnt/TG_2TB/Projects/Apollo/models/`.
*   **Phase 3 (Decoupling):** Transition from `kokoro-onnx` direct instantiation to a wrapper that checks the `ArtifactManager` before attempting any network-based fallback.

## Conclusion
The current "reactive" dependency management is a technical debt that will inevitably lead to system downtime. Moving to an "immutable registry" model transforms the TTS component from a volatile dependency into a deterministic local service.
