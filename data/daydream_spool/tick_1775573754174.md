# Architectural Audit: Resource-Budgeted Reasoning (RBR)

## 1. Epiphany Analysis
The subconscious daemon has identified a critical "Cognitive-Physical Decoupling" in the current architecture. The High-IQ models (e.g., Claude-3.5-Sonnet, DeepSeek-R1) possess high engineering intuition but lack awareness of the local execution environment's constraints (VRAM, CPU, Disk). This leads to "Conceptual Bloat"—proposing software stacks or heavy dependencies that the local lab environment cannot support.

## 2. Current State Audit
- **System Prompting:** The current `AgentRunner` (in `src/agent/runner.ts`) allows for a `systemPrompt` but does not dynamically inject environmental context.
- **Enforcement Mechanism:** There is a hardcoded `enforcementPrompt` in `src/agent/runner.ts` (lines 228-230) that enforces "ENGINEER MODE" (no conversational preamble), but this is purely behavioral and does not address resource constraints.
- **Resource Awareness:** The system currently has no mechanism to poll local hardware metrics (VRAM, CPU, Disk) and feed them into the LLM's context window.

## 3. Proposed Architectural Update: Resource-Budgeted Reasoning (RBR)

### Phase 1: Hardware Manifest Injection
We must implement a `HardwareManifest` provider that periodically samples the local environment. This manifest will be injected into the `systemPrompt` of the `AgentRunner`.

**Proposed Changes:**

#### A. Define the Manifest Structure (`src/types.ts`)
```typescript
export interface HardwareManifest {
  vram_available_gb: number;
  cpu_load_percent: number;
  disk_space_available_gb: number;
  timestamp: string;
}
```

#### B. Implement Manifest Provider (`src/utils/hardware.ts`)
A new utility to fetch system metrics using `bash` or native Node.js calls.

#### C. Update `AgentRunner` (`src/agent/runner.ts`)
Modify the `baseChatOptions` construction to include the manifest.

```typescript
// Proposed logic for src/agent/runner.ts
const manifest = await getHardwareManifest();
const manifestPrompt = `\n\n[HARDWARE MANIFEST]:
- Available VRAM: ${manifest.vram_available_gb} GB
- CPU Load: ${manifest.cpu_load_percent}%
- Available Disk: ${manifest.disk_space_available_gb} GB
- Timestamp: ${manifest.timestamp}

RECONCILIATION REQUIREMENT: All proposed software stacks, model deployments, or heavy computational tasks MUST be compatible with these physical constraints. Do not propose solutions that exceed these limits.`;

const baseChatOptions: LLMChatOptions = {
  // ... existing options
  systemPrompt: (this.options.systemPrompt ?? "") + enforcementPrompt + manifestPrompt,
}
```

### Phase 2: Cognitive Escalation Integration
The existing "Cognitive Escalation" (identified in `coordinator.log`) should be extended. If the `HardwareManifest` shows critical resource depletion (e.g., < 1GB VRAM), the system should automatically trigger a "Resource-Constrained Mode" prompt, forcing the model to prioritize lightweight, local-first solutions over heavy cloud-based or high-parameter alternatives.

## 4. Conclusion
The "Resource-Budgeted Reasoning" layer is not just a prompt injection; it is a necessary bridge between the model's abstract logic and the physical reality of the Apollo lab. Implementing this will prevent the "Skyscraper on Sand" failure mode.

**Status:** Audit Complete. Implementation recommended.
