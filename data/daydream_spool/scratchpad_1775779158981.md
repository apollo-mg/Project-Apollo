## Epiphany Audit: Complexity Threshold & Search-and-Extract Mode
**Timestamp:** 2024-05-22 (Simulated)
**Status:** Investigating

### Hypothesis
The "Buddy" persona (passive semantic absorption) fails when the information density of a file or the sheer volume of the codebase exceeds the effective context window of the agent. This leads to "information dilution," where the agent loses the signal in the noise.

The proposed "Complexity Threshold" aims to trigger a mode switch:
1. **Reading Mode (Passive):** Used for small, high-context files where semantic understanding is paramount.
2. **Search-and-Extract Mode (Active):** Triggered by large files or broad architectural queries. Uses `grep`, `find`, and `bash` to surgically isolate relevant code segments before attempting to "read" them.

### Audit Plan
1. **Identify Codebase Scale:** Determine the average and maximum file sizes in the project to establish a baseline for the "Complexity Threshold."
2. **Analyze Tool Usage Patterns:** Check if previous interactions (if any are logged) show signs of "reading the haystack" (e.g., excessive `file_read` calls on large files).
3. **Propose Architectural Guardrails:** Define the specific metrics (file size in KB, line count, or directory depth) that trigger the mode switch.
### Findings: Codebase Scale & Complexity
- **Total Project Size:** ~76MB.
- **Dependency Noise:** The majority of the volume is in `node_modules` (e.g., `typescript`, `esbuild`), which should be strictly excluded from semantic analysis.
- **Core Logic Scale:** The core application files (excluding `node_modules` and `vault`) are relatively small, with the largest being `package-lock.json` (~63KB) and `coordinator.log` (~52KB).
- **Critical Observation:** The largest "logic" files identified are around 29KB-30KB (e.g., `orchestrator.ts`). While not massive, they represent the upper bound of "Reading Mode" efficiency.

### Proposed Complexity Thresholds
Based on the audit, I propose the following architectural triggers:

1. **File Size Threshold (The "Hard Limit"):**
   - **Threshold:** > 50KB.
   - **Action:** If a `file_read` request targets a file > 50KB, the agent must first attempt to use `grep` or `find` to locate specific symbols/patterns rather than reading the whole file.

2. **Context Density Threshold (The "Semantic Limit"):**
   - **Threshold:** > 500 lines of code (LOC) in a single file.
   - **Action:** If a file exceeds 500 LOC, the agent should prioritize `grep` to map the structure (e.g., searching for `class`, `interface`, or `function` definitions) before attempting to read specific implementation details.

3. **Search-and-Extract Protocol:**
   - **Step 1:** Identify the target (e.g., "How does the orchestrator handle errors?").
   - **Step 2:** Instead of `file_read('src/orchestrator/orchestrator.ts')`, execute `grep -n "error" src/orchestrator/orchestrator.ts`.
   - **Step 3:** Use `file_read` with `offset` and `limit` on the specific line numbers identified by `grep`.

### Conclusion
The "Buddy" failure is likely due to attempting to ingest files like `package-lock.json` or large log files in their entirety. Implementing these thresholds will force the "Lead Engineer" persona to act surgically.
