# Architectural Audit: Harvester Schema Standardization

## Epiphany Summary
The distinction between 'Local' and 'Cloud' is a lifecycle. The 'Harvester' must bridge the gap by ensuring the data pipeline is 'burst-ready'. Standardizing the JSONL schema for high-parameter models (32B+) during the 7B local phase is critical for seamless scaling.

## Audit Findings
- **Current State:** The existing training datasets (e.g., `/mnt/TG_2TB/Projects/Apollo/training_success.jsonl`) utilize a shallow schema: `{"prompt": "...", "response": "...", "expected_tag": "..."}`.
- **Deficiency:** This schema lacks the structural depth required for advanced reasoning models. It misses `system_prompt`, `context` (conversation history/environment state), `thought_trace` (Chain of Thought), and `metadata` (model version/complexity).
- **Risk:** Transitioning to a 32B model with this shallow data will result in poor reasoning performance, as the model will lack the context and reasoning traces necessary to leverage its increased parameter count.

## Proposed Architectural Update: "Deep JSONL" Standard

To enable "Cloud Bursting," the Harvester must be updated to produce a standardized, high-fidelity schema.

### Proposed Schema Definition
```json
{
  "id": "string (uuid)",
  "timestamp": "string (iso8601)",
  "system_prompt": "string",
  "context": {
    "conversation_history": "array[object]",
    "environment_state": "object",
    "tool_outputs": "array[object]"
  },
  "instruction": "string",
  "thought_trace": "string (Chain of Thought)",
  "response": "string",
  "metadata": {
    "model_scale": "string (e.g., 7B, 32B)",
    "source": "string",
    "complexity_score": "float"
  }
}
```

## Implementation Roadmap

1. **Phase 1: Harvester Re-implementation**
   - Create `src/modules/harvester_v2.py` to implement the "Deep JSONL" schema.
   - Ensure the harvester captures `thought_trace` from the agent's internal reasoning steps.

2. **Phase 2: Pipeline Integration**
   - Update `ingest_chats.py` and any other ingestion scripts to utilize the `harvester_v2` logic.
   - Ensure all local 7B training data is generated using this schema.

3. **Phase 3: Validation**
   - Run a validation script to ensure all `.jsonl` files in `data/` conform to the new schema before any "Cloud Burst" upload.
