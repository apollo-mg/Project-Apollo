# Architectural Audit: Confidence-to-Compute Mapping Protocol

## 1. Epiphany Analysis
The current architecture lacks a "Pre-frontal Cortex" to mediate between the sensory input (STT/Wakeword) and the generative output (ComfyUI/Wan). The "Ear" (STT) and the "Hand" (Generative Video) operate in silos. This leads to two critical failure modes:
- **Computational Waste:** High-intensity generative nodes are triggered by low-confidence, noisy audio signals.
- **Hallucination/Noise:** Low-intent audio triggers complex latent space traversals, resulting in "noise-induced" hallucinations.

## 2. Current State Audit
- **Sensory Layer (The Ear):** The STT/Wakeword pipeline (likely implemented via external APIs or local models) emits transcription results. While `src/types.ts` defines `LLMRespoense` and `ContentBlock`, there is no explicit `ConfidenceScore` type integrated into the orchestration flow.
- **Orchestration Layer (The Pre-frontal Cortex):** The `src/orchestrator/orchestrator.ts` manages agent runs and task execution, but it currently treats all valid transcriptions as equal triggers for the next task.
- **Generative Layer (The Hand):** The ComfyUI/Wan nodes are treated as standard tools within the `src/tool` framework, lacking a mechanism to receive "intent intensity" or "confidence" metadata.

## 3. Proposed Architectural Update: "Confidence-to-Compute" Protocol

### A. Type Definition Update (`src/types.ts`)
Introduce a `ConfidenceMetadata` type to be attached to `ContentBlock` or `LLMRespoense`.
```typescript
export interface ConfidenceMetadata {
  readonly confidence: number; // 0.0 to 1.0
  readonly intent_score: number; // 0.0 to 1.0
}
```

### B. Orchestrator Logic Update (`src/orchestrator/orchestrator.ts`)
Modify the `Orchestrator` to implement a gating mechanism.
1. **Low Confidence (< 0.4):** Trigger `LightweightLLMTask`. Only perform text-based reasoning or clarification.
2. **Medium Confidence (0.4 - 0.7):** Trigger `StandardAgentTask`. Use standard LLM reasoning and basic tool use.
3. **High Confidence (> 0.7):** Trigger `HeavyComputeTask`. Unlock the `Wan/CLIP` generative video nodes.

### C. Tool Implementation Update (`src/tool/built-in/`)
Update the tool execution context (`ToolUseContext`) to include `confidence` metadata, allowing generative tools to adjust their own sampling parameters (e.g., higher guidance scale for high-confidence prompts) based on the trigger's certainty.

## 4. Implementation Roadmap
1. **Phase 1:** Extend `src/types.ts` to include confidence metrics in the message/response schema.
2. **Phase 2:** Implement the `ConfidenceGate` within the `Orchestrator` to route tasks based on the threshold.
3. **Phase 3:** Refactor the generative video nodes to accept `confidence` as a parameter to modulate computational complexity.
