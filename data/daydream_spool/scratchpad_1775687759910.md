# Epiphany Investigation: Asynchronous Job-Queue Transition
## Timestamp: 2025-05-22 (Simulated)
## Status: Investigating

### Hypothesis
The current architecture relies on synchronous HTTP requests for heavy LLM tasks (specifically 35B MoE models). Given the VRAM constraints (16GB) and the computational latency of these models, the system experiences "hanging" states. The Epiphany suggests moving to an asynchronous model (polling/webhooks) to decouple the request from the response.

### Investigation Plan
1. **Identify the Request/Response Layer:** Locate the code responsible for making HTTP requests to the LLM servers (likely `llm_interface.py`, `orchestrator.py`, or `apollo.py`).
2. **Audit Current Implementation:** Check if requests are blocking/synchronous.
3. **Identify the Server Side:** Check how the LLM server (likely `vllm` or `llama.cpp` based on file list) is being interacted with.
4. **Propose Architecture Change:** Design a job-queue pattern.
