# Epiphany Investigation: Standardizing Environment via Abstraction Layer

## Initial Assessment
The epiphany suggests that the system suffers from "path-dependency friction." Scripts (like 'Wild Child') and training processes are likely hardcoded to specific filesystem paths, leading to fragility when the environment shifts or when scaling. The transition from "mapping the physical" to "trusting the abstract" implies we need a centralized configuration/environment management system.

## Hypothesis
1.  **Hardcoded Paths:** Multiple scripts in the codebase likely contain absolute paths or complex `os.path.join` logic that assumes a specific directory structure.
2.  **Lack of Single Source of Truth:** There is no central `config.py` or `.env` management system that dictates where data, logs, and models reside.
3.  **Complexity Overhead:** The "labyrinth" mentioned refers to the manual traversal required to find assets, which increases the risk of failure during "Final Burn" (high-intensity execution) cycles.

## Investigation Plan
1.  **Audit Codebase for Path Patterns:** Search for common path-related patterns (e.g., `/mnt/`, `os.path`, `pathlib`, `os.environ`).
2.  **Identify "Wild Child" and Training Scripts:** Locate the scripts mentioned in the epiphany to see how they handle storage.
3.  **Evaluate Current Configuration Method:** Determine if there is an existing `config` module or if it's fragmented.
4.  **Draft Proposal:** Design a `CoreConfig` abstraction.
## Findings from Path Audit
- **High Prevalence of Absolute Paths:** The `grep` results show a massive amount of hardcoded `/mnt/TG_2TB/Projects/Apollo/` paths in logs and potentially in the code. This confirms the "mapping the physical" problem.
- **Fragility:** The logs show `ENOENT` errors when scripts attempt to access files in `/mnt/TG_2TB/Projects/Apollo/modules/` or `/mnt/TG_2TB/Projects/Apollo/src/`. This suggests that the directory structure is either being moved or the scripts are assuming a structure that isn't consistently present.
- **Complexity:** The "labyrinth" is real. Scripts are trying to find `cognitive_escalation.py`, `pvl_engine.py`, `agent_session.py`, etc., using absolute paths that might change if the project is relocated or if the environment is containerized.

## Proposed Solution: The `ApolloEnvironment` Abstraction
Instead of scripts using `os.path.join('/mnt/TG_2TB/Projects/Apollo/', 'modules', '...')`, they should use a centralized configuration object.

### 1. Create `core/config.py`
This module will:
- Detect the project root dynamically (e.g., using `pathlib.Path(__file__).parent.parent`).
- Define standard directory paths (e.g., `DATA_DIR`, `MODULES_DIR`, `LOG_DIR`, `MODEL_DIR`).
- Provide a single source of truth for all pathing.

### 2. Implementation Strategy
- **Phase 1: Discovery.** Use `grep` to find all instances of `/mnt/TG_2TB/Projects/Apollo/` in `.py` files.
- **Phase 2: Abstraction.** Replace these hardcoded strings with calls to `ApolloConfig.PROJECT_ROOT / '...'`.
- **Phase 3: Environment Injection.** Allow overriding these paths via environment variables (e.g., `APOLLO_ROOT`) to support different deployment environments without code changes.

## Final Architectural Proposal: The "Apollo Core Configuration" Layer

### 1. Implementation of `core/config.py`
Create a singleton configuration class that uses `pathlib` for all operations.

```python
import os
from pathlib import Path

class ApolloConfig:
    # 1. Determine Root: Use environment variable or fallback to relative path discovery
    ROOT = Path(os.getenv("APOLLO_ROOT", Path(__file__).resolve().parents[2]))
    
    # 2. Standardized Sub-directories
    DATA_DIR = ROOT / "data"
    LOG_DIR = ROOT / "log_chunks"
    MODULES_DIR = ROOT / "modules"
    MODELS_DIR = ROOT / "models"
    SPOOL_DIR = ROOT / "data/daydream_spool"
    
    # 3. Specific File Constants
    STATE_FILE = DATA_DIR / "liara_state.json"
    TELEMETRY_LOG = ROOT / "telemetry_state_log.jsonl"
    TRAINING_DATASET = ROOT / "v8_memory_dataset.jsonl"
    
    @classmethod
    def validate(cls):
        """Ensure all critical directories exist."""
        for path in [cls.DATA_DIR, cls.LOG_DIR, cls.SPOOL_DIR]:
            path.mkdir(parents=True, exist_ok=True)
```

### 2. Refactoring Plan (The "Abstraction Shift")
- **Step 1:** Replace all `"/mnt/TG_2TB/Projects/Apollo/..."` strings with `ApolloConfig.PATH_NAME`.
- **Step 2:** Implement a `pre-flight` check in the main `apollo.py` entry point that calls `ApolloConfig.validate()`.
- **Step 3:** Update CI/CD or execution scripts to set `APOLLO_ROOT` if the environment is non-standard.

### 3. Expected Outcome
- **Zero Friction:** Moving the project to a new drive or container requires changing exactly one environment variable.
- **Reliability:** Eliminates `ENOENT` errors caused by path mismatches between different execution contexts (e.g., manual shell vs. automated batch).
- **Scalability:** Allows for easy implementation of "Hub ID" logic by mapping abstract IDs to these standardized paths.
