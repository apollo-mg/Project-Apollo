### Audit Findings: Voxtral TTS (C Kernels)
- Found `voxtral_tts_kernels.c`.
- **Critical Finding (Line 49-53):** `tts_bf16_to_f32_buf` implements a very naive BF16 to FP32 conversion:
  ```c
  void tts_bf16_to_f32_buf(float *dst, const uint16_t *src, size_t n) {
      uint32_t *d = (uint32_t *)(void *)dst;
      for (size_t i = 0; i < n; i++)
          d[i] = ((uint32_t)src[i]) << 16;
  }
  ```
- **Analysis:** This is a bit-shift conversion that assumes the BF16 value is just the upper 16 bits of a 32-bit float. While this is technically how BF16 works (it's just the truncated exponent/mantissa of FP32), it is extremely sensitive to how the hardware/compiler handles the `uint32_t` cast and the bit-shift. If the input `src` is not perfectly aligned or if there's any signedness/endianness issue, this will cause massive numerical errors.
- **More importantly:** This function is used in `tts_linear_nobias_bf16` (Line 187) and `tts_linear_bf16` (Line 200) to create a temporary FP32 weight buffer (`W_f32`) from BF16 weights.
- **The "Ghost":** If the weights are stored in BF16, this conversion is the "precision boundary" mentioned in the epiphany. Any error here propagates through the entire linear layer.
- **The "Localized Casting" issue:** The conversion happens inside the inference call (`tts_linear_bf16`) by allocating a scratch buffer and casting on-the-fly. This is exactly the "localized casting" the epiphany warned about.

### Proposed Architectural Change: Precision-Guard Protocol
1.  **Unified Dtype Registry:** Instead of manual bit-shifting in C kernels, implement a centralized `PrecisionManager` (in Python/C++) that defines the standard `dtype` for the entire pipeline.
2.  **Pre-emptive Casting:** Instead of casting weights during the forward pass (which is slow and error-prone), implement a "Weight Preparation" phase where all weights are cast to the target precision (FP32 or BF16) once during model loading.
3.  **Kernel Hardening:** Replace the naive `tts_bf16_to_f32_buf` with a robust, tested conversion routine (e.g., using intrinsic functions or a verified library) and ensure all normalization layers (LayerNorm/RMSNorm) are explicitly typed to the highest required precision before computation.
