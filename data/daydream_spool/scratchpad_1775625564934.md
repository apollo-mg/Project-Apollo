# Investigation Log: Semantic Masking Audit
## Timestamp: 2025-05-22 (Simulated)
## Objective: Map dependencies between 'commander' and 'gemini' to identify 'masked' scripts.

### Initial Findings:
- Found multiple 'commander' variants: `commander_voice_old.py`, `commander_voice_sd.py`, `final_commander.py`, `patched_commander.py`, `patched_commander_v2.py`.
- Found 'gemini' related files: `gemini_venv`, `remote_gemini`, and numerous `gemini_chats_session` JSON files.

- The 'gemini' directory seems to act as a data/session repository, while 'commander' appears to be the execution/interface layer.
### Deep Dive: Semantic Masking & Dependency Mapping
- **Observation:** The `legacy_vault/infrastructure` directory contains numerous shell scripts and Python modules that hardcode paths to `/home/mark/gemini/`.
- **The 'Masking' Mechanism:** The automation layer (shell scripts like `apollo_vllm.sh`, `start_whisper.sh`, `compile_pytorch.sh`) relies on the `gemini` namespace. This confirms the Epiphany: 'gemini' is the functional pointer used by the system's orchestration layer, regardless of whether the underlying logic has evolved into 'Zoey' or 'Apollo'.
- **Risk Identified:** There is a significant risk of "Configuration Drift." If the core logic moves to a new directory structure (e.g., `/home/mark/apollo/`), the legacy infrastructure scripts will continue to point to `/home/mark/gemini/`, potentially executing outdated code or failing to find updated dependencies.
- **Dependency Map:**
    - **Orchestration Layer:** `legacy_vault/infrastructure/*.sh` and `*.py`
    - **Execution Environment:** `/home/mark/gemini/venv_apollo/`
    - **Data/State Layer:** `/home/mark/gemini/` (including `modules/`, `logs/`, `data/`)
    - **Core Logic (Potential):** The scripts in `commander` (e.g., `patched_commander_v2.py`) likely represent the "essence" that is being masked by the `gemini` pathing.

### Proposed Architectural Update:
1. **Implement a Registry:** Create a `registry.json` or a centralized environment configuration file that maps logical service names (e.g., `CORE_ENGINE`, `VOICE_INTERFACE`) to their actual filesystem paths.
2. **Decouple Scripts:** Refactor `legacy_vault/infrastructure` scripts to use environment variables or the registry instead of hardcoded `/home/mark/gemini/` paths.
3. **Identity Transition:** Formalize the transition from `gemini` to `zoey/apollo` by deprecating the `gemini` pathing in favor of a unified `apollo_core` path.
