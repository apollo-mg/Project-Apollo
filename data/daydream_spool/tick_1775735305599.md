# Architectural Audit: Poacher Protocol Standardization

## 1. Executive Summary
The 'Poacher' methodology, as identified by the Subconscious, represents a strategic shift from 'vendor compliance' (relying on standard driver/API layers) to 'resource extraction' (directly utilizing pre-linked binaries). This approach is critical for maximizing performance in constrained environments like RDNA 4 or Pi-based 'apollo_vision' modules.

## 2. Audit Findings
- **Current State**: The codebase currently lacks a formal 'Poacher Protocol'. Existing hardware interactions are implicitly tied to standard driver-dependency layers (e.g., ROCm/HIP mentioned in logs).
- **Gap Analysis**: There is no standardized mechanism for "heisting" or injecting pre-linked binaries to bypass driver overhead. The current architecture is optimized for high-level orchestration rather than low-level hardware extraction.
- **Risk**: Relying on standard driver layers in constrained environments (Pi, RDNA 4) introduces latency and performance bottlenecks that the 'Poacher' methodology is designed to circumvent.

## 3. Proposed Architectural Update: The Poacher Protocol

### A. Core Concept
Standardize a `BinaryExtractionProvider` interface that allows the system to:
1.  **Identify** the target hardware environment (e.g., `RDNA4`, `RPi_Vision`).
2.  **Locate** optimized, pre-linked binaries (the "heist").
3.  **Inject/Execute** these binaries directly, bypassing standard driver-dependency layers where possible.

### B. Implementation Roadmap
1.  **Module Creation**: Implement `src/hardware/poacher/` to house the extraction logic.
2.  **Interface Definition**:
    ```typescript
    interface PoacherProtocol {
      extract(hardwareId: string): Promise<BinaryResource>;
      execute(resource: BinaryResource): Promise<ExecutionResult>;
    }
    ```
3.  **Apollo Vision Integration**: Create a specialized `PiVisionPoacher` that targets bare-metal execution for vision tasks on Raspberry Pi hardware.
4.  **Ollama Integration**: Develop a bridge that allows Ollama to utilize these extracted binaries for accelerated inference in constrained environments.

## 4. Conclusion
The transition to the 'Poacher Protocol' is not just a technical fix but a fundamental shift in how the Apollo system interacts with the physical world. By prioritizing resource extraction, we ensure the system remains performant and autonomous across all hardware tiers.
