# Epiphany Investigation: Multi-GPU Wrapper Structural Paradox

## Hypothesis
The current multi-GPU implementation uses an 'override-on-import' pattern. This pattern attempts to wrap node classes (specifically `UnetLoaderGGUF`) during the import phase. Because ComfyUI nodes are registered dynamically as they are imported, the wrapper is racing against the registry. If a third-party node (like a GGUF loader) is imported *after* the wrapper has already attempted its interception, the wrapper fails or misses the target, leading to crashes or broken functionality.

## Investigation Plan
1.  **Locate the Multi-GPU Wrapper:** Search for code related to "multi-gpu", "wrapper", or "override" in the codebase.
2.  **Identify the Interception Logic:** Find where `UnetLoaderGGUF` or similar nodes are being intercepted.
3.  **Analyze the Import Sequence:** Determine if the wrapper is being triggered via a module import side-effect.
4.  **Verify the "State of Flux" Theory:** Check if the wrapper relies on `NODE_CLASS_MAPPINGS` before it is fully populated.
