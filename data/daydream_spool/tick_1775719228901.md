# Architectural Proposal: RDNA 4 Hardware Workaround Preservation

## 1. Problem Statement
The current development cycle suffers from a "patch and purge" loop. Hardware-level instabilities (specifically ROCm/HIP/RDNA 4 issues causing "RMS Norm" errors and silent data corruption) are being addressed via ephemeral patches. When a `git reset --hard` or a `deep_purge.sh` is executed to resolve environment corruption, the rationale and the specific code changes required to mitigate these hardware issues are lost.

## 2. Proposed Solution: The "Logic Vector" Registry

Instead of applying patches directly to the source tree and relying on memory, we will implement a formal registry for hardware-level workarounds.

### A. Implementation of `hardware_registry.md`
Create a persistent documentation file in the root directory (or a dedicated `docs/hardware/` directory) that tracks:
- **Hardware ID**: (e.g., `RDNA_4_ROCM_7.1.1`)
- **Symptom**: (e.g., `RMS_NORM_SILENT_CORRUPTION`)
- **Root Cause**: (e.g., `HIP kernel instruction mismatch on specific RDNA 4 compute units`)
- **The Patch**: The exact code diff or logic required.
- **The "Why"**: Detailed technical explanation of the discrepancy.

### B. Integration with Workflow
1. **Pre-Reset Hook**: A script `extract_hardware_patches.sh` will be introduced. This script will:
   - Run `git diff` against the last known "vanilla" state.
   - Filter for changes in critical paths (e.g., kernel-adjacent code, tensor operations).
   - Append these diffs and their descriptions to `hardware_registry.md`.
2. **Post-Reset Re-application**: After a `git reset --hard`, the developer (or an automated agent) will run `apply_hardware_patches.sh`, which reads from the registry and re-applies the necessary logic.

import subprocess

def extract_diff_to_registry(registry_path):
    # 1. Get current diff
    diff = subprocess.check_output(["git", "diff"]).decode("utf-8")
    
    # 2. Filter for hardware-relevant keywords
    if any(kw in diff for kw in ["RMS", "ROCm", "HIP", "RDNA"]):
