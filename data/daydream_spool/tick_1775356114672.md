# Epiphany Audit: Cognitive Dispatcher Protocol

## 1. Analysis of the Epiphany
The subconscious has identified a critical architectural bifurcation:
- **Reactive Intelligence (Worker Tier):** High-velocity, vLLM-driven, cache-pinned, optimized for throughput (e.g., 14B 4-bit models).
- **Deliberative Intelligence (Architect Tier):** High-capacity, Ollama/Split-load driven, optimized for structural reasoning (e.g., 30B+ models).

The current implementation in `buddy_agent.py` and `modules/agent_session.py` uses a single `UNIFIED_MODEL` (Qwen 3.5 35B) for all tasks, which creates a bottleneck. It attempts to handle both high-level reasoning and low-level tool execution within the same context, leading to potential "circuit breaker" trips and inefficient resource usage.

## 2. Architectural Audit Findings
- **Current State:** `llm_interface.py` defines a single `UNIFIED_MODEL`. `ApolloAgentSession` uses this model for the entire agentic loop.
- **The Problem:** There is no routing logic. A "task" (e.g., "List my inventory") is treated with the same cognitive weight as "Refine this engineering vision into a technical proposal."
- **Resource Conflict:** The "Golden Rules" (VRAM limits) are currently managed via manual downscaling (image resizing) but not via model selection.

## 3. Proposed Implementation: The 'Cognitive Dispatcher'

I propose a three-tier routing layer to be implemented in a new module `modules/cognitive_dispatcher.py`.

### Tier 1: The Dispatcher (Routing Logic)
A new function `dispatch_task(task_metadata)` will analyze the task complexity.
- **Complexity Metrics:**
    - `structural_depth`: Number of tool calls required.
    - `reasoning_requirement`: Presence of "refine", "design", "plan", or "architect" keywords.
    - `throughput_need`: High-volume data processing (e.g., "ingest 50 emails").

### Tier 2: The Tiers
1. **Architect Tier (Deliberative):**
    - **Model:** `Ollama/Split-load` (e.g., 30B+ or 70B).
    - **Use Case:** High-structural/one-shot tasks, project scaffolding, vision-heavy analysis.
    - **Constraint:** High latency, high VRAM.
2. **Worker Tier (Reactive):**
    - **Model:** `vLLM/Cache-pinned` (e.g., 14B 4-bit).
    - **Use Case:** Repetitive data processing, simple tool execution, status checks, inventory updates.
    - **Constraint:** Low latency, low VRAM.

### Tier 3: Integration Plan
1. **Modify `llm_interface.py`:** Replace `UNIFIED_MODEL` with a `ModelRegistry` that can switch between `ARCHITECT` and `WORKER` endpoints.
2. **Modify `buddy_agent.py`:** The `Orchestrator.fast_path` should be expanded to include a `complexity_check`.
3. **Modify `modules/agent_session.py`:** The `run()` loop will call the `Cognitive Dispatcher` at the start of the session to set the `self.model_tier`.

## 4. Draft Code Changes (Conceptual)

### `modules/cognitive_dispatcher.py` (New File)
```python
class CognitiveDispatcher:
    @staticmethod
    def determine_tier(prompt, task_type=None):
        # Keywords for Architect Tier
        architect_keywords = ["refine", "design", "plan", "architect", "scaffold", "analyze"]
        
        if any(k in prompt.lower() for k in architect_keywords):
            return "ARCHITECT"
        
        # Default to Worker for high-throughput/simple tasks
        return "WORKER"
```
