## Hypothesis
The current implementation of `buddy_agent.py` likely treats all retrieval results (whether from vector databases or grep-based keyword searches) as equally valid, leading to "noise" being synthesized as "signal".

## Deep Dive: `toolbox.py` Analysis
- `search_file_content` (line 266) returns a raw string of matches: `f"{file_path}:{line_num}: {line.strip()}"`.
- `query_vdb` (in `vdb.py`) returns a raw string: `f"--- Source: {source} ---\n{doc.page_content}\n"`.
- Both tools return plain text. There is no metadata regarding "confidence" or "source type" (Vector vs. Grep) being passed to the LLM in a structured way.
- The LLM receives these as part of the `<retrieved_memory>` block in `agent_session.py`.
- The LLM has no mathematical way to distinguish between a high-similarity vector match and a simple keyword match unless it "guesses" based on the text content, which is exactly the "noise vs signal" problem described in the epiphany.

## Conclusion
The epiphany is correct. The architecture is "flat". To implement "hierarchical skepticism", we need:
1. A standardized `RetrievalResult` object (or JSON structure) that includes:
    - `content`: The actual text.
    - `source_type`: `vector` or `grep`.
    - `confidence_score`: A float (0.0 to 1.0).
    - `metadata`: Any additional context (e.g., file path, similarity score).
2. Updates to `query_vdb` and `search_file_content` to return this structured data.
3. Updates to `ApolloAgentSession._prepare_system_prompt` to parse this structured data and present it to the LLM in a way that allows for "weighting".

## Proposed Architectural Change
**Protocol: `ConfidenceMetadata`**
Instead of:
`--- Source: path/to/file --- \n Content`

The agent should receive:
```json
[
  {
    "type": "vector",
    "confidence": 0.89,
    "content": "...",
    "source": "path/to/file"
  },
  {
    "type": "grep",
    "confidence": 0.4,
    "content": "...",
    "source": "path/to/file"
  }
]
```
The system prompt should then instruct the agent: "When evaluating retrieved memory, weigh 'vector' sources higher than 'grep' sources unless the 'grep' match is highly specific."
