# Architectural Proposal: Cognitive Overhead Metric Integration

## 1. Executive Summary
Following a subconscious epiphany regarding the zero-sum nature of cognitive resource allocation, this proposal outlines the integration of a 'Cognitive Overhead' metric. This metric will quantify the mathematical trade-off between VRAM dedicated to sensory perception (Vision/Audio) and VRAM reserved for high-order reasoning (Logic).

## 2. Proposed Changes

### A. Model Manifest Schema Update (`model_manifest.json`)
To enable attribution, every model entry must be categorized.
**Proposed Schema Extension:**
```json
{
  "id": "model_id",
  "name": "Model Name",
  "category": "sensory" | "logic",
  "estimated_vram_mb": 12000,
  "type": "..."
}
```

### B. VRAM Management Enhancement (`vram_management.py`)
Introduce a tracking mechanism for active model footprints.
**New Functionality:**
- `get_active_model_footprint(category: str) -> int`: Returns the sum of `estimated_vram_mb` for all currently loaded models of a specific category.
- `calculate_cognitive_overhead() -> dict`:
    - `sensory_vram`: Sum of active sensory VRAM.
    - `logic_vram`: Sum of active logic VRAM.
    - `overhead_ratio`: `sensory_vram / (sensory_vram + logic_vram)`.

### C. Telemetry Integration (`telemetry_layer.py`)
The `ImmutableTelemetryLayer` will be used to log `COGNITIVE_OVERHEAD_REPORT` events. This allows for historical analysis of how sensory input density correlates with reasoning degradation.

### D. System Monitoring (`system_monitor.py`)
Integrate `vram_management.py` into the `get_system_stats()` function to ensure the primary telemetry heartbeat includes the `cognitive_overhead` metric.

## 3. Mathematical Model
The metric will be tracked as:
$$\text{Cognitive Overhead} = \frac{\sum VRAM_{\text{sensory}}}{\sum VRAM_{\text{sensory}} + \sum VRAM_{\text{logic}}}$$

A high ratio indicates a "Sensory-Heavy" state, signaling that the model's reasoning headroom is being compressed.

## 4. Implementation Roadmap
1. **Phase 1**: Update `model_manifest.json` with categories and estimates.
2. **Phase 2**: Implement attribution logic in `vram_management.py`.
3. **Phase 3**: Expose metric via `system_monitor.py` and `telemetry_layer.py`.
4. **Phase 4**: (Future) Implement automated model offloading based on overhead thresholds.
