# Architectural Proposal: VRAM Orchestration Protocol

## 1. Problem Statement
The current `AgentPool` manages concurrency using a logical semaphore, which limits the *number* of concurrent agent runs. However, it lacks awareness of the *physical* resource requirements (VRAM) of the models being executed. In multi-agent scenarios, particularly when mixing high-fidelity models (e.g., Q6_K quantization) with resident orchestrators, the cumulative VRAM footprint can exceed the hardware limit (16GB), triggering disk swap and breaking the real-time reasoning loop.

## 2. Proposed Solution: `VRAMOrchestrator`
We will implement a resource-aware orchestration layer that treats VRAM as a finite, consumable resource, similar to how the `Semaphore` treats concurrency.

### 2.1 Core Components

#### A. `VRAMManager` (New)
A singleton or orchestrator-scoped service that tracks the current VRAM allocation.
- **State:** `current_usage_gb: number`, `total_capacity_gb: number`.
- **Methods:**
  - `request(required_gb: number): Promise<boolean>`: Attempts to reserve VRAM.
  - `release(amount_gb: number): void`: Frees VRAM.
  - `getAvailableHeadroom(): number`: Returns remaining capacity.

#### B. `ModelResourceProfile` (Update to `AgentConfig`)
Extend `AgentConfig` to include resource metadata.
```typescript
export interface AgentConfig {
  // ... existing fields
  readonly resourceProfile?: {
    readonly model_id: string;
    readonly quantization: 'Q4_K_M' | 'Q5_K_M' | 'Q6_K';
    readonly estimated_vram_gb: number;
  };
}
```

#### C. `VRAM-Aware AgentPool` (Update to `AgentPool`)
Modify `AgentPool.run` to integrate with `VRAMManager`.
1. Before `semaphore.acquire()`, call `VRAMManager.request(agent.vram_requirement)`.
2. If `request` fails (insufficient headroom), the pool can:
   - **Wait:** Queue the request until `release()` is called.
   - **Downgrade:** (Advanced) Trigger a fallback to a lower-quantization model profile.

## 3. Implementation Roadmap

### Phase 1: Resource Tracking (Immediate)
- [ ] Update `src/types.ts` to include `resourceProfile` in `AgentConfig`.
- [ ] Implement `src/orchestrator/vram_manager.ts`.
- [ ] Integrate `VRAMManager` into `AgentPool.run` and `AgentPool.runParallel`.

### Phase 2: Intelligent Quantization (Future)
- [ ] Implement a `QuantizationDowngrade` mechanism in `LLMAdapter`.
- [ ] If `VRAMManager` reports critical pressure, the `AgentRunner` will attempt to load a `Q4_K_M` version of the requested model instead of `Q6_K`.

## 4. Impact Assessment
- **Fidelity vs. Velocity:** This protocol prioritst "Velocity" (preventing swap) by ensuring "Fidelity" (quantization level) is only as high as the physical hardware allows.
- **Complexity:** Minimal impact on existing API; `AgentConfig` remains backward compatible.
- **Performance:** Negligible overhead for VRAM tracking.
