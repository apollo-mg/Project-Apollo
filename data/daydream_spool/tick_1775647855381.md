# Architectural Audit Report: Temporal Disconnect in Error Reporting

## 1. Executive Summary
The investigation confirms the validity of the "Epiphany" regarding the temporal disconnect between execution and observation. The current diagnostic framework is susceptible to "delayed shadows"—errors occurring in asynchronous execution contexts (specifically GPU kernels) that are not caught until the execution context has already migrated or the process has returned a misleading success status.

## 2. Findings
- **Asynchronous Blindness:** The system relies on standard process-level error catching (`try/catch` in `src/tool/executor.ts`). While this works for synchronous logic, it fails to capture errors in asynchronous device-side execution (e.g., ROCm/HIP kernels) which may only manifest after the host process has moved on.
- **Lack of Synchronization:** No existing configuration in the codebase utilizes `AMD_SERIALIZE_KERNEL` or `TORCH_USE_HIP_DSA` to force synchronous verification.
- **Orchestration Gap:** The Node.js orchestrator (via `ToolExecutor`) treats the completion of a sub-process (like a Python script) as a proxy for task success, without ensuring the internal state of the device-side execution is synchronized.

## 3. Proposed Architectural Changes

### A. Environment Variable Injection
Modify the process-spawning logic (likely within the `ToolExecutor` or the specific tool implementations that call `child_process`) to inject synchronization variables.

**Target Variables:**
- `AMD_SERIALIZE_KERNEL=3`
- `TORCH_USE_HIP_DSA=1`

### B. Configuration-Driven Synchronization
Introduce a `forceSync` flag in `ToolExecutorOptions` to allow developers to enable strict, synchronous execution during debugging or high-integrity runs.

**Proposed `ToolExecutorOptions` Update:**
```typescript
export interface ToolExecutorOptions {
  maxConcurrency?: number;
  /** 
   * If true, injects environment variables to force synchronous 
   * kernel execution and device-side assertions. 
   */
  forceSync?: boolean;
}
```

### C. Implementation Strategy
1. **Update `src/types.ts`** to include the `forceSync` property in `ToolExecutorOptions`.
2. **Update `src/tool/executor.ts`** to propagate this flag through the `ToolUseContext`.
3. **Update Tool Implementations:** Any tool that spawns a sub-process (e.g., Python/ML tools) must check `context.forceSync` and apply the corresponding environment variables to the `spawn`/`exec` call.

## 4. Conclusion
By shifting from passive observation to active, synchronous verification, the system will bridge the temporal gap, ensuring that errors are caught at the moment of inception rather than as delayed shadows.
