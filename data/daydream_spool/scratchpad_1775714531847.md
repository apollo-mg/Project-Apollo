# Epiphany Investigation: Structural Mismatch in Multi-GPU Wrapper

## Hypothesis
The `execution.py` engine is designed for sequential, single-context execution. The multi-GPU wrapper attempts to distribute work across multiple devices, but the core engine's state management (likely context-bound or device-bound) is not designed to handle asynchronous or multi-device context switching. This leads to a loss of context during `process_inputs`.

- This confirms the "async execution loop" mentioned in the epiphany. The mismatch occurs when the wrapper tries to distribute nodes/tasks across multiple GPUs, but the `execution.py` logic (specifically `process_inputs`) expects a single-device context or fails to maintain state when the execution context is swapped/interrupted by the wrapper.

## Refined Hypothesis
The multi-GPU wrapper is likely intercepting the execution flow to assign tasks to different GPUs. However, `execution.py` (the ComfyUI engine) maintains a global or thread-local state (like `current_device` or `execution_context`) that is not being updated or synchronized by the wrapper. When `process_inputs` is called, it attempts to use the state of the "brain" (the main process), which may no longer match the "body" (the specific GPU assigned by the wrapper).
