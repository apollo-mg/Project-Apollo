# Investigation: Temporal Stutter & Semantic Density Filter
## Epiphany Analysis
The subconscious identifies a "temporal stutter": the system is ingesting high-frequency telemetry (timestamps, process overhead) as if it were meaningful cognitive data. This creates a recursive loop where the system's own execution noise pollutes its memory.

## Hypothesis
The ingestion pipeline (likely in `ingest_*.py` or `telemetry_layer.py`) lacks a mechanism to distinguish between high-frequency, low-entropy system events (noise) and low-frequency, high-entropy semantic events (signal).

## Findings
- Confirmed "temporal stutter": `telemetry_state_log.jsonl` contains highly repetitive, high-frequency entries (e.g., `SYSTEM_CHECK` and `ENTROPY_DETECTED` occurring within milliseconds of each other, potentially triggered by a loop).
- The `ImmutableTelemetryLayer` in `telemetry_layer.py` records every single event without any filtering or semantic density check.
- `ingest_logs.py` processes these logs by reading chunks and sending them to the LLM. If these chunks contain the repetitive telemetry, the LLM's context window will be flooded with "process noise" (timestamps and repetitive status updates) instead of "semantic signal" (actual architectural decisions or bugs).

## Proposed Solution: Semantic Density Filter
Implement a `SemanticDensityFilter` class that can be integrated into the `ImmutableTelemetryLayer` or as a pre-processing step in the ingestion pipeline.

### Filter Logic:
1. **Entropy Check:** Calculate the information density of a sequence of events. If the entropy is too low (i.e., the events are nearly identical), discard them.
2. **Temporal Throttling:** Limit the frequency of specific event types (e.g., `SYSTEM_CHECK`) within a certain time window.
3. **Semantic Significance Scoring:** Assign weights to event types. `CRITICAL` or `TRANSITION` events are high-signal; `INFO` or repetitive `SYSTEM_CHECK` are low-signal.

### Implementation Plan:
1. **Modify `telemetry_layer.py`**: Add a `SemanticDensityFilter` that tracks recent event signatures.
2. **Update `ImmutableTelemetryLayer._append_to_log`**: Use the filter to decide whether to write the entry.
3. **Update `ingest_logs.py`**: (Optional but recommended) Add a regex-based filter to strip known high-frequency telemetry patterns before sending to the LLM.

## Draft Code Changes

### 1. `telemetry_layer.py` Update
```python
class SemanticDensityFilter:
    def __init__(self, window_seconds=60, min_entropy_threshold=0.1):
        self.window_seconds = window_seconds
        self.min_entropy_threshold = min_entropy_threshold
        self.history = [] # List of (timestamp, event_signature)

    def should_allow(self, event_type, description):
        now = datetime.now(timezone.utc)
        signature = f"{event_type}:{description}"
        
        # Clean old history
        self.history = [h for h in self.history if (now - h[0]).total_seconds() < self.window_seconds]
        
        # Count occurrences of this signature
        count = sum(1 for h in self.history if h[1] == signature)
        
        if count > 5: # Threshold for "stutter"
            return False
            
        self.history.append((now, signature))
        return True
```
