# Architectural Audit: Model Registry & Latent-to-Pixel Transition Dissonance

## 1. Epiphany Analysis
The subconscious identified a structural lag between the environment's configuration (`extra_model_paths.yaml`) and the active server state. This manifests as a "stale memory" problem where the model registry does not reflect real-time filesystem changes, leading to failures in the `WanVideoDecode` stage (the transition from latent abstraction to visual reality).

## 2. Audit Findings
- **Configuration Discrepancy:** A search for `extra_model_paths.yaml` and `model_paths` within the current codebase returned no direct matches. This suggests that the configuration mechanism is either:
    - Implemented via a different naming convention (e.g., within a custom `foundry_configs` or `model_manifest.json`).
    - Managed by an external process (like a ComfyUI backend) that is not directly integrated into the Apollo core logic, creating the "stale memory" gap.
- **Workflow Friction:** The term `WanVideo` was identified in historical chat logs related to `DisTorch` VRAM management, confirming that the "latent-to-pixel" transition is a high-stakes area where VRAM/model path mismatches cause significant workflow disruption.
- **Memory System State:** The `TieredMemorySystem` (`src/modules/memory_system.py`) manages context but does not currently include a "Hardware/Environment Integrity" tier to validate external model registries against active server state.

## 3. Proposed Architectural Update

### Phase A: Implementation of the 'Environment Integrity' Tier
Integrate a new validation step within the `TieredMemorySystem` or as a standalone `IntegrityLayer` service.

**Proposed Logic:**
1. **Registry Sync:** Implement a `ModelRegistryValidator` that parses the configuration file (e.g., `model_manifest.json` or the detected YAML) and compares it against the `active_model_paths` currently loaded in the server's memory.
2. **Pre-flight Check:** Before any `WanVideoDecode` or latent-to-pixel operation, trigger a `validate_registry_consistency()` call.
3. **Error Handling:** If a mismatch is detected (e.g., a model path in the registry points to a non-existent or uninitialized volume), the system must throw a `RegistryDissonanceError` rather than attempting to decode with null/stale pointers.

### Phase B: Code Change Draft (Conceptual)
```python
# Proposed addition to src/integrity_layer.py or similar
class ModelRegistryValidator:
    def __init__(self, config_path: str):
        self.config_path = config_path

    def verify_active_state(self, active_models: List[str]) -> bool:
        """
        Compares the filesystem/config reality with the server's active model list.
        """
        config_paths = self._load_config_paths()
        for path in config_paths:
            if path not in active_models:
                raise RegistryDissonanceError(f"Stale Registry: {path} is in config but not active.")
        return True
```

## 4. Conclusion
The "stale memory" is a symptom of a decoupled configuration-to-execution pipeline. By implementing a pre-flight validation step that bridges the gap between the `extra_model_paths` (intent) and the `active_model_registry` (reality), we can prevent the latent-to-pixel friction identified by the subconscious.
