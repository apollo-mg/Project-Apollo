# Architectural Audit: Reconcile-on-Discovery Protocol

## 1. Executive Summary
The subconscious epiphany regarding "digital archaeology" and the "rift between map and territory" is validated. Current system patterns rely heavily on `os.walk` and `glob` as fallback mechanisms when direct path lookups fail. This is computationally expensive and indicates that the system's "maps" (configuration files) are static and disconnected from the actual filesystem state.

## 2. Audit Findings
- **Manifest Drift:** `model_manifest.json` acts as a registry of *what* should exist but lacks the *where* (local filesystem paths). It contains URLs but no mapping to the local `llama.cpp/models/` or other storage volumes.
- **Search-on-Failure Pattern:** Codebase analysis confirms widespread use of `os.walk` and `glob.glob` in ingestion and audit scripts (`ingest_chats.py`, `substrate_audit.py`, `librarian_ingest.py`). These are currently used as "blind" searches rather than "discovery" events.
- **Integrity vs. Discovery:** `guardian_manifest.json` is used for integrity (checksums) but provides zero utility for resource discovery, creating a functional gap in the agent's ability to navigate its own environment.

## 3. Proposed Architectural Update: "Reconcile-on-Discovery"

### Core Concept
Transition from a reactive "search-on-failure" model to a proactive "reconcile-on-discovery" protocol. When a search successfully locates a resource, the agent must immediately synchronize the "map" (the manifest) with the "territory" (the filesystem).

### Technical Specification

#### A. Manifest Schema Evolution
Update `model_manifest.json` to include a `local_path` attribute for all resource entries.
```json
{
  "id": "kokoro_tts",
  "name": "Kokoro ONNX Model",
  "url": "...",
  "filename": "kokoro-v0_19.onnx",
  "local_path": "/mnt/TG_2TB/Projects/Apollo/models/kokoro-v0_19.onnx",
  "type": "onnx"
}
```

#### B. New Component: `ManifestManager`
Implement a new module `modules/manifest_manager.py` responsible for atomic updates to the system's manifests.
- `get_resource(resource_id)`: Returns the `local_path` if available.
- `reconcile_resource(resource_id, discovered_path)`: Updates the manifest with the new path and verifies the file exists.

#### C. Refactored Workflow
**Current Workflow:**
1. Attempt `load(config.path)`
2. `FileNotFoundError` $\rightarrow$ Trigger `glob.glob()`
3. Return result to user.

**Proposed Workflow:**
1. Attempt `load(config.path)`
2. `FileNotFoundError` $\rightarrow$ Trigger `discovery_search()`
3. **Discovery Success:**
   - `ManifestManager.reconcile_resource(id, discovered_path)`
   - Update `model_manifest.json`
4. Return result to user.

## 4. Implementation Roadmap
1. **Phase 1 (Schema):** Update `model_manifest.json` structure.
2. **Phase 2 (Logic):** Implement `ManifestManager` with thread-safe file writing.
3. **Phase 3 (Integration):** Replace fallback `os.walk` calls in critical paths with `Discovery + Reconcile` logic.
