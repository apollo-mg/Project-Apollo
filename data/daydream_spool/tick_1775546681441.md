# Architectural Audit: Hybrid Precision Dispatcher (HPD)

## 1. Epiphany Analysis
The subconscious has identified a critical failure mode in the current monolithic quantization approach. The RDNA 4 architecture exhibits non-uniform stability, where Attention modules are resilient to Int8 quantization, but MLP (Multi-Layer Perceptron) layers trigger kernel-specific crashes.

**Status:** **VALIDATED**. The `synthesizer_batch.log` confirms hardware-level instability (ROCm/HIP/RDNA 4) causing "RMS Norm" errors, which aligns with the epiphany's observation of layer-specific instability.

## 2. Current State Audit
- **Quantization Strategy:** Currently non-existent in the high-level TypeScript orchestration layer. The framework treats LLM interaction as a black box via `LLMAdapter`.
- **Hardware Awareness:** The current `LLMAdapter` implementations (`AnthropicAdapter`, `OpenAIAdapter`) are cloud-based and do not interact with local hardware kernels.
- **The Gap:** The "Hybrid Precision Dispatcher" cannot be implemented in the current TypeScript orchestration layer because the quantization/kernel execution happens at the C++/ROCm/HIP level (likely in a local inference engine like llama.cpp or vLLM, which is not currently represented in this codebase).

## 3. Proposed Architectural Update

To implement the **Hybrid Precision Dispatcher**, we must introduce a new abstraction layer that sits between the `LLMAdapter` and the underlying inference engine.

### Phase A: Interface Expansion
Modify `src/types.ts` to support precision-aware configuration.

```typescript
// src/types.ts additions

export type PrecisionMode = 'int8' | 'fp16' | 'fp32' | 'hybrid';

export interface PrecisionConfig {
  mode: PrecisionMode;
  // For hybrid mode: mapping layer types to precision
  layerMapping?: {
    attention: PrecisionMode;
    mlp: PrecisionMode;
  };
}

export interface LLMChatOptions {
  // ... existing properties
  precision?: PrecisionConfig;
}
```

### Phase B: The Hybrid Precision Dispatcher (HPD)
Since this framework orchestrates agents, the HPD should be implemented as a "Hardware-Aware Adapter Wrapper."

1.  **Create `src/llm/hybrid_dispatcher.ts`**:
    - This class will wrap an existing `LLMAdapter`.
    - It will intercept `chat` and `stream` calls.
    - It will inject the `precision` configuration into the provider's request (if the provider supports it) or, more critically, pass it to a local inference engine via a custom header or parameter.

2.  **Implementation Logic**:
    - If `precision.mode === 'hybrid'`:
        - The dispatcher identifies the model architecture (if known).
        - It instructs the local backend to use `Int8` for `Attention` kernels.
        - It instructs the local backend to use `FP16` (or higher) for `MLP` kernels.

### Phase C: Local Inference Integration
The current codebase is primarily an orchestration layer for cloud APIs (Anthropic/OpenAI). To realize the epiphany, we must add support for a **Local Inference Adapter** (e.g., `LocalROCmAdapter`) that communicates with a local engine capable of receiving these precision instructions.

## 4. Implementation Roadmap

1.  **[Immediate]** Update `src/types.ts` to include `PrecisionConfig`.
2.  **[Short-term]** Implement `LocalROCmAdapter` in `src/llm/` that accepts `PrecisionConfig`.
3.  **[Medium-term]** Develop the `HybridPrecisionDispatcher` wrapper to manage the logic of switching precisions based on layer-type stability.
4.  **[Long-term]** Integrate with the hardware-level driver layer to ensure the `RMS Norm` errors are bypassed by the precision fallback.

## 5. Conclusion
The epiphany is a profound insight into the limitations of monolithic quantization. While the current TypeScript codebase is an orchestration layer, it provides the perfect entry point for a **Hybrid Precision Dispatcher** that can manage hardware-aware model execution.

**Recommendation:** Proceed with the implementation of `PrecisionConfig` in the core types to enable hardware-aware orchestration.
