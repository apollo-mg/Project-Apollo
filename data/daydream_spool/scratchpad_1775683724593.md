# Investigation: Silent Hang & Telemetry Transition
## Epiphany Analysis
The subconscious identifies a critical architectural vulnerability: the reliance on symlinks to bridge a massive data volume (2TB) with a constrained root partition (6.6 GB). This abstraction layer is prone to failure, manifesting as a "Silent Hang" where the training process appears active but the underlying hardware/software communication has stalled.

## Hypothesis
The "Silent Hang" is likely caused by:
1. **I/O Wait/Saturation:** The symlink/mount point abstraction might be masking high I/O latency or kernel-level blocking during heavy data access.
2. **ROCm/Hardware State Desync:** The GPU/ROCm driver might enter an error state that doesn't propagate to the application's stdout/stderr.
3. **Root Partition Pressure:** Even with symlinks, metadata operations or temporary file creation on the root partition might be hitting limits.

## Investigation Plan
1. **Audit Filesystem Structure:** Verify the symlink/mount configuration between the 2TB drive and the root.
2. **Check for Existing Telemetry:** Search the codebase for any existing monitoring or watchdog implementations.
3. **Identify Hardware Monitoring Hooks:** Locate where `rocm-smi` or similar tools are currently (or should be) integrated.
4. **Propose Watchdog Architecture:** Design a decoupled process that monitors:
    - `rocm-smi` (GPU health/utilization)
    - Disk I/O (latency/throughput on the 2TB mount)
    - Process Heartbeat (checking if the training process is actually making progress vs. just idling)
## Filesystem Audit Results
- **Root Partition (`/`):** 928G total, 856G available. The "6.6 GB" mentioned in the epiphany seems to be an outdated or specific context-dependent observation (perhaps referring to a container or a specific sub-partition not visible in the global `df` output, or a misunderstanding of the available space in a specific environment).
- **Data Partition (`/mnt/TG_2TB`):** 1.9T total, 1.4T available. This is the primary data ocean.
- **Observation:** The discrepancy between the epiphany's "6.6 GB root" and the actual "928G root" suggests the epiphany might be describing a specific *containerized* environment or a specific *logical* volume that is indeed constrained, even if the host is not. I need to check if the project runs inside a container or a restricted environment.
