# Architectural Audit: Wan2.1 Stability Floor Implementation

## 1. Executive Summary
The Subconscious identified a critical friction point: the gap between high-level generative vision (Wan2.1) and the physical constraints of RDNA 4 hardware. Current memory management in `start_comfy.sh` is insufficient for the high-pressure VRAM requirements of video synthesis. This audit proposes hardening the environment to establish a "stability floor."

## 2. Findings
- **Current State:** `start_comfy.sh` uses `PYTORCH_HIP_ALLOC_CONF=expandable_segments:True`. While helpful, it does not prevent fragmentation caused by large, non-contiguous allocations typical of video models.
- **Hardware Context:** RDNA 4 (gfx1201) requires precise memory orchestration to avoid OOM (Out of Memory) errors during the attention-heavy phases of Wan2.1.
- **Log Evidence:** `comfyui.log` confirms the system is running on `gfx1201` with ROCm 6.2, but indicates that memory-saving optimizations (like `--use-split-cross-attention`) are currently optional/manual.

## 3. Proposed Architectural Changes

### A. Hardening `start_comfy.sh`
Modify the environment variable configuration to implement a more aggressive fragmentation prevention strategy.

**Proposed Code Change:**
```bash
# --- Hardened Memory Foundation for Wan2.1 ---
export HSA_OVERRIDE_GFX_VERSION=12.0.1
# Combine expandable segments with max_split_size to prevent large-block fragmentation
export PYTORCH_HIP_ALLOC_CONF="expandable_segments:True,max_split_size_mb:512"
# Ensure ROCm-specific memory management is prioritized
export ROCM_ALLOCATOR_USE_ASYNC_RECLAIM=1
```

### B. Defaulting to Memory-Efficient Attention
To support the "stability floor," the startup script should default to memory-efficient attention mechanisms unless overridden.

**Proposed Code Change:**
```bash
# Change the python call to include memory-efficient attention by default
python3 /media/mark/AI_Fast/ComfyUI_RDNA4/main.py \
    --listen 0.0.0.0 \
    --port 8188 \
    --normalvram \
    --use-split-cross-attention \
    "${args[@]}"
```

## 4. Implementation Roadmap
1. **Phase 1 (Immediate):** Update `start_comfy.sh` with the hardened `PYTORCH_HIP_ALLOC_CONF` and `--use-split-cross-attention`.
2. **Phase 2 (Validation):** Run a benchmark using a lightweight video model to verify that the "stability floor" prevents fragmentation-induced crashes.
3. **Phase 3 (Deployment):** Deploy Wan2.1 onto the hardened environment.

## 5. Conclusion
By transitioning from a "standard" startup to a "hardened" startup, we bridge the gap between generative capability and hardware reality, ensuring that the leap to video synthesis is supported by a stable memory foundation.
