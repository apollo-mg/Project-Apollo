# Architectural Audit: Apollo Training Bridge Automation

## 1. Epiphany Analysis
The subconscious identified a "ritualistic bottleneck" in the transition from curated data to physicalized training. The current process relies on manual file uploads to a remote Jupyter environment (RunPod), which is high-friction and prone to human error.

## 2. Audit Findings
- **Current State:** The `APOLLO_CLOUD_RUNBOOK.md` (referenced in chat history) dictates a manual "Upload Arrow" process in Jupyter Lab for `apollo_curated_v1.jsonl` and `train_apollo_cloud.py`.
- **Bottleneck:** The "visual bridge" is the manual movement of files from the local filesystem to the remote cloud instance.
- **Risk:** Discrepancies between local data versions and remote training runs, and the cognitive load of manual execution.

## 3. Proposed Architectural Update: "The Apollo Forge"

To eliminate the manual ritual, I propose the implementation of a programmatic bridge.

### A. The `Forge` Module
A new utility suite located in `scripts/forge/` designed to automate the deployment pipeline.

#### Component 1: `forge_package.py`
- **Function:** Scans the `data/` directory for the latest curated `.jsonl` files.
- **Action:** Bundles the dataset, the `train_apollo_cloud.py` script, and a `requirements.txt` into a single, versioned `.tar.gz` archive.
- **Metadata:** Generates a `manifest.json` within the archive containing the timestamp and dataset checksum.

#### Component 2: `forge_deploy.py`
- **Function:** Handles the transfer of the package to the remote environment.
- **Mechanism:** 
    - **Option 1 (SSH/SCP):** If the RunPod instance allows SSH, use `scp` to push the archive.
    - **Option 2 (Cloud-Pull):** If SSH is restricted, the script will upload the archive to a temporary S3/R2 bucket or a known web endpoint, providing the user with a single `wget` command to run in the remote terminal.

#### Component 3: `forge_execute.sh`
- **Function:** A remote-side shell script (included in the package) that automates the "Step 4" of the current runbook.
- **Action:** 
    1. Unpacks the archive.
    2. Installs dependencies (`unsloth`, `torchao`, etc.) using a cached approach to save time.
    3. Executes `python train_apollo_cloud.py`.

### B. Updated Workflow (The "One-Command" Goal)
The new manual ritual will be replaced by:
1. `python scripts/forge/forge_package.py --target cloud`
2. Copy-paste a single command provided by the script into the remote terminal:
   `wget [URL] && tar -xzf package.tar.gz && bash forge_execute.sh`
