# Architectural Proposal: Recursive Vision-to-Parametric Feedback Loop

## 1. Executive Summary
The current 'Vision-to-Parametric' pipeline is a linear, one-pass process that lacks error correction. This proposal transforms the pipeline into an agentic, closed-loop system where visual verification acts as a corrective signal. By using Qwen2.5-VL to generate structured error reports from visual discrepancies, we can drive DeepSeek-R1 to iteratively refine CAD parameters until the digital model matches the physical reality.

## 2. Current State vs. Proposed State

| Feature | Current State (Linear) | Proposed State (Recursive) |
| :--- | :--- | :--- |
| **Workflow** | Image $\rightarrow$ Vision $\rightarrow$ Code $\rightarrow$ End | Image $\rightarrow$ Vision $\rightarrow$ Code $\rightarrow$ Render $\rightarrow$ Visual Delta $\rightarrow$ Refinement $\rightarrow$ Loop |
| **Error Handling** | None (One-shot) | Agentic (Iterative correction) |
| **Verification** | Human-in-the-loop (Manual) | Automated (Qwen2.5-VL as Critic) |
| **Model Roles** | Vision (Extractor), Engineer (Generator) | Vision (Extractor + Critic), Engineer (Generator + Refiner) |

## 3. Proposed Architecture: The "Reflex Arc" Loop

### Phase 1: Initial Synthesis
1. **Vision Extraction (Qwen2.5-VL):** Analyze the physical object and output a structured JSON of dimensions and features.
2. **Code Generation (DeepSeek-R1):** Generate the initial CAD code (e.g., CadQuery or FeatureScript) based on the JSON.

### Phase 2: The Feedback Loop (The "Reflex Arc")
3. **Execution & Rendering:** Execute the generated code in a headless environment to produce a 2D render (Synthetic Image).
4. **Visual Delta Analysis (Qwen2.5-VL):**
   - **Input:** [Original Physical Image] + [Synthetic CAD Render].
   - **Task:** Perform a comparative analysis.
   - **Output:** A structured `error_report` JSON.
     - *Example:* `{"error": "dimension_mismatch", "parameter": "cylinder_diameter", "delta_mm": -0.4, "description": "The cylinder in the render is thinner than the physical object."}`
5. **Parameter Refinement (DeepSeek-R1):**
   - **Input:** [Original Code] + [Structured Error Report].
   - **Task:** Adjust the code to minimize the error.
   - **Output:** Refined CAD code.

### Phase 3: Termination
- **Success Condition:** The `error_report` indicates a delta within an acceptable tolerance (e.g., $< 0.1\text{mm}$).
- **Failure Condition:** Maximum iterations reached or error report indicates unresolvable geometric conflict.

## 4. Implementation Roadmap

### Step 1: Infrastructure (The "Bridge")
- Implement a `CADRenderer` module capable of taking code and returning a standardized image file.
- Ensure the `llm_interface` supports multi-modal inputs (Image + Text) for the "Critic" phase.

### Step 2: Prompt Engineering
- **The Critic Prompt (Qwen2.5-VL):** Optimized for spatial reasoning and comparative measurement.
- **The Refiner Prompt (DeepSeek-R1):** Optimized for translating natural language error reports into precise code modifications.

### Step 3: Orchestration
- Create `vision_feedback_orchestrator.py` to manage the state machine, iteration counts, and data flow between the models.

## 5. Risk Assessment
- **Computational Overhead:** The loop increases LLM API calls and rendering time. *Mitigation: Implement a strict `max_iterations` cap.*
- **Hallucination in Delta:** The Vision model might report errors that don't exist. *Mitigation: Use high-precision prompts and cross-reference with numerical dimension checks where possible.*
- **Rendering Latency:** Generating images can be slow. *Mitigation: Use lightweight, headless rendering engines (e.g., Blender or CadQuery's built-in export).*
