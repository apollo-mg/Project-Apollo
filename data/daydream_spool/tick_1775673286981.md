# Architectural Proposal: Formalized Cognitive Handoff Protocol

## 1. Executive Summary
The current multi-agent orchestration relies on a "Coordinator" pattern where a high-level agent decomposes goals into discrete `Task` objects. However, the "handoff" between the Receptionist (Coordinator) and the Specialist (Worker) is currently limited to a single string field: `Task.description`. This creates a "contextual bottleneck" where nuanced reasoning, discovered constraints, or complex environmental state captured by the Receptionist may be lost during task decomposition.

## 2. Problem Statement
The transition from exploratory reasoning (Receptionist) to functional execution (Specialist) lacks a structured medium for transferring cognitive state. 
- **Current State:** `Task.description` (String)
- **Risk:** Loss of "Reasoning Provenance" and "Nuanced Constraints."
- **Impact:** Specialists may execute tasks correctly but miss the underlying "why" or the subtle "how" established by the Receptionist.

## 3. Proposed Architectural Change

### 3.1 Update `Task` Interface
Modify `src/types.ts` to include a structured `context` field.

```typescript
// src/types.ts

export interface TaskContext {
  /** Structured reasoning or 'thought process' from the Receptionist. */
  readonly reasoningPath?: string;
  /** Explicit constraints or 'rules of engagement' discovered during decomposition. */
  readonly constraints?: string[];
  /** Key entities or state discovered that the Specialist must respect. */
  readonly discoveredState?: Record<string, unknown>;
  /** Any specific 'mental model' or 'persona' the Specialist should adopt. */
  readonly personaHint?: string;
}

export interface Task {
  readonly id: string;
  readonly title: string;
  readonly description: string;
  status: TaskStatus;
  assignee?: string;
  dependsOn?: readonly string[];
  result?: string;
  /** NEW: Structured context for the Specialist. */
  context?: TaskContext; 
  readonly createdAt: Date;
  updatedAt: Date;
}
```

### 3.2 Update Orchestration Logic
Modify `src/orchestrator/orchestrator.ts` (specifically the `parseTaskSpecs` logic) to handle the extraction of this context from the Coordinator's JSON output.

**Proposed JSON Schema for Coordinator Output:**
```json
[
  {
    "title": "Analyze ROCm driver logs",
    "description": "Check for memory errors in the recent kernel log.",
    "assignee": "specialist_agent",
    "context": {
      "reasoningPath": "The system reported a kernel panic; the logs likely contain the root cause.",
      "constraints": ["Do not suggest hardware replacement yet", "Focus on software/driver mismatch"],
      "discoveredState": { "last_error_code": "0x8004" }
    }
  }
]
```

### 3.3 Update Agent Execution
Modify `src/agent/agent.ts` or `src/orchestrator/orchestrator.ts` (where `buildTaskPrompt` is defined) to inject this `TaskContext` into the Specialist's prompt.

**Prompt Injection Strategy:**
When a task is dispatched, the `buildTaskPrompt` function should append the `context` as a structured "Contextual Briefing" section in the Specialist's input:

```text
[TASK BRIEFING]
Title: {{task.title}}
Description: {{task.description}}

[COGNITIVE CONTEXT FROM RECEPTIONIST]
Reasoning: {{task.context.reasoningPath}}
Constraints: {{task.context.constraints}}
Discovered State: {{task.context.discoveredState}}
```

## 4. Implementation Roadmap
1. **Phase 1 (Types):** Update `src/types.ts` with `TaskContext` and update `Task` interface.
2. **Phase 2 (Parsing):** Update `parseTaskSpecs` in `src/orchestrator/orchestrator.ts` to support the new JSON structure.
3. **Phase 3 (Prompting):** Update the prompt construction logic to ensure the context is visible to the Specialist.
4. **Phase 4 (Validation):** Run existing team examples to ensure the new JSON parsing doesn't break legacy coordinator outputs.

## 5. Conclusion
By formalizing the handoff, we move from a "Command-and-Control" model (where the Specialist only knows *what* to do) to a "Collaborative-Intelligence" model (where the Specialist knows *why* it is doing it). This stabilizes the functional hierarchy identified in the Epiphany.
