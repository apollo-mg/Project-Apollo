# Architectural Audit: Tiered Intelligence Hierarchy

## 1. Executive Summary
The current architecture suffers from a "Binary Fallback" pattern. It treats local models as a safety net for cloud failures rather than a functional component of a tiered intelligence system. This leads to high latency and queue congestion when the system attempts to use heavy cloud models for trivial tasks.

## 2. Identified Architectural Rift
- **Current State:** `Cloud (Primary) -> Local (Fallback on Error)`.
- **Problem:** The system is "reactive" to failures rather than "proactive" about task complexity.
- **Symptom:** High latency in the `TaskQueue` and frequent timeouts in `openai.ts` and `anthropic.ts` because the system is attempting to solve low-complexity problems with high-complexity tools.

## 3. Proposed Solution: The Tiered Nervous System
We will transition from a fallback model to a **Routing Model**.

### A. The Reflex Layer (GigaChat 3.1 Lightning)
- **Role:** Immediate, low-latency response.
- **Use Cases:** Task formatting, simple entity extraction, status updates, basic instruction following, and "chatter" management.
- **Integration:** A new provider in `src/llm/gigachat.ts`.

### B. The Deliberative Layer (Cloud APIs)
- **Role:** Deep reasoning and complex synthesis.
- **Use Cases:** Multi-step reasoning, complex code generation, long-context synthesis, and strategic planning.
- **Integration:** Existing Anthropic/OpenAI providers.

## 4. Implementation Roadmap

### Phase 1: Complexity Classification
- Update `src/task/types.ts` to include a `complexity_score` (1-10) and `latency_sensitivity` (boolean) in the `Task` definition.
- Implement a lightweight `ComplexityClassifier` (using the Reflex Layer itself) to tag incoming tasks.

### Phase 2: Intelligence Routing
- Create `src/orchestrator/router.ts`.
- **Logic:**
  ```typescript
  if (task.complexity < 4 || task.latency_sensitivity) {
    return Providers.REFLEX_LAYER; // GigaChat 3.1 Lightning
  } else {
    return Providers.DELIBERATIVE_LAYER; // Cloud
  }
  ```

### Phase 3: Queue Optimization
- Implement "Priority Lanes" in `src/task/queue.ts`.
- Reflex tasks bypass the standard `TaskQueue` to prevent being stuck behind heavy deliberative tasks.

## 5. Conclusion
By implementing this hierarchy, we decouple the user experience from cloud latency. The "Reflex Layer" provides the illusion of instantaneous response, while the "Deliberative Layer" provides the necessary depth, creating a unified, tiered nervous system.
