# Architectural Audit: SSH/SCP Transport Failure in RunPod Deployments

## 1. Epiphany Analysis
The subconscious daemon has identified a critical bottleneck in the deployment pipeline. The current architecture relies on SCP (Secure Copy Protocol) for transferring training payloads to RunPod instances. However, the RunPod SSH proxy acts as a selective filter, rejecting SCP-specific sub-protocols or handshake patterns, leading to "Unknown" errors and wasted GPU billing cycles while the system attempts to retry a fundamentally incompatible transport method.

## 2. Audit Findings
- **Current State:** The codebase (specifically the `Fleet Orchestrator` mentioned in `coordinator.log`) is designed to manage the `Boot → Train → Zip → Upload → Verify` lifecycle.
- **Identified Friction:** The transport layer (SCP) is the point of failure. The "Unknown" error loop indicates that the connection is established (SSH is working), but the file transfer protocol (SCP) is being blocked or mismanaged by the proxy.
- **Resource Impact:** High. GPU instances are being provisioned and billed while the deployment logic hangs in a retry loop, attempting to use a blocked protocol.

## 3. Proposed Architectural Update

### Objective
Transition from SCP-based file transfers to a protocol-agnostic, stream-based transfer method that utilizes the existing SSH tunnel without requiring additional sub-protocols.

### Technical Specification: The "Pipe-and-Cat" Pattern
Instead of:
`scp local_file.py user@host:/remote/path/local_file.py`

Implement:
`cat local_file.py | ssh user@host "cat > /remote/path/local_file.py"`

### Implementation Plan
1.  **Identify Deployment Modules:** Locate the `Fleet Orchestrator` (referenced as `fleet_orchestrator.py` in logs) and any associated `RepositoryUploader` or `DeploymentManager` classes.
2.  **Refactor Transport Logic:**
    - Replace `subprocess.run(['scp', ...])` or equivalent library calls with a standard SSH command execution.
    - Use `stdin` to pipe the file buffer directly into the SSH process.
3.  **Validation:**
    - Implement a checksum verification step (`sha256sum`) immediately after the pipe to ensure payload integrity.
    - Ensure the `Verify` stage of the lifecycle is updated to handle the new transfer method.

## 4. Conclusion
The transition to a stream-based transfer via `cat` over SSH will bypass the proxy's SCP filtering, ensuring that training payloads are delivered immediately upon instance availability, thereby minimizing idle GPU costs.
