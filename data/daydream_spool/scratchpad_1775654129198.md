# Investigation Log: Epiphany - Voice vs Hands
## Timestamp: 2024-05-22 (Simulated)
## Objective: Audit 'buddy_guardian.py' to assess the transition from passive telemetry to active control.

## Initial Findings:
- Found multiple instances of `buddy_guardian.py`.
- Primary candidate for audit: `/mnt/TG_2TB/Projects/Apollo/buddy_guardian.py`.
- Secondary candidate (legacy): `/mnt/TG_2TB/Projects/Apollo/legacy_vault/core/buddy_guardian.py`.

## Hypothesis:
The current implementation of `buddy_guardian.py` likely relies on logging or emitting signals to an external system, rather than having direct access to hardware control interfaces or high-priority interrupt mechanisms.
## Audit Results:
- `buddy_guardian.py` is currently a "Secret Scanner" and "Integrity Checker".
- It performs two main functions:
    1. `audit_plan`: Uses an LLM to check if a proposed plan aligns with the "SOUL".
    2. `check_system_integrity`: Compares file hashes against a manifest.
- It also has a `scan_directory` function for secret detection.

## Critical Vulnerability Confirmed:
- The "Guardian" is indeed a "Voice" (observer/auditor). It can detect a breach (integrity mismatch) or a bad plan (LLM audit), but it has no mechanism to *act* on that detection.
- It lacks a "Hardware Actuation Layer". It can return a JSON object saying "unapproved", but it cannot trigger a system-level shutdown or hardware interrupt itself.
- The `audit_plan` function has a manual override check (lines 50-55), but this is reactive to *user input*, not proactive to *system state*.

## Proposed Architectural Change:
1. **Introduce `HardwareActuationLayer` class**: This class will encapsulate methods for high-priority interrupts.
2. **Implement `execute_emergency_shutdown()`**: A method to trigger a hard power-off or system halt.
3. **Implement `trigger_cooling_emergency()`**: A method to ramp up cooling.
4. **Integrate with `check_system_integrity()`**: If a critical integrity breach is detected (e.g., core files modified), the Guardian should have the option to trigger an immediate shutdown rather than just returning a string.
5. **Define P0 Thresholds**: Create a set of conditions that automatically trigger the Actuation Layer.

## Implementation Plan:
- Create a new module `modules/actuation.py` (or similar) to handle the actual hardware/OS-level calls.
- Update `buddy_guardian.py` to import this layer.
- Add an `emergency_response()` method to `SovereignGuardian`.
