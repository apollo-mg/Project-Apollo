# Epiphany Investigation: Ingestion Fragmentation
## Initial State
- Found `librarian_ingest.py`
- Found `ingest_chats.py`
- Found `daydream.py`

## Hypothesis
The current ingestion logic is fragmented into specialized scripts. A unified polymorphic engine is needed to normalize various log types into a single schema before ChromaDB commitment.

## Investigation Plan
1. Examine `librarian_ingest.py` to understand its current ingestion logic and schema.
2. Examine `ingest_chats.py` to see how it differs and what specific data it handles.
3. Examine `daydream.py` to see how it consumes the ingested data.
4. Identify the commonalities and the "schema" used for ChromaDB.
5. Draft a proposal for a `UnifiedIngestionEngine` using a Strategy Pattern.
## Findings
### 1. Current Ingestion Architecture
- `librarian_ingest.py`:
    - Handles PDFs (via `PyPDFLoader`) and URLs (via `trafilatura`).
    - Uses `file_hash` and `url_id` for deduplication.
    - Metadata schema: `source`, `filename`, `file_hash`, `type` (for PDFs); `source`, `url_id`, `type` (for URLs).
- `ingest_chats.py`:
    - Handles JSON chat logs (Gemini/Apollo history).
    - Uses `timestamp` and `filename` for context.
    - Metadata schema: `source`, `type` ("chat_history"), `date`, `timestamp`.

### 2. Fragmentation Analysis
- **Schema Inconsistency**: The metadata keys vary significantly between the two scripts (`file_hash` vs `timestamp`, `type` values are different).
- **Logic Duplication**: Both scripts manually handle vector store retrieval, text splitting, and batching.
- **Lack of Extensibility**: Adding a new format (e.g., Markdown notes, Email logs) requires writing a whole new script with its own loop and logic.

### 3. Proposed Solution: `UnifiedIngestionEngine`
- **Core Controller**: A single entry point that accepts a source (directory, file, or URL).
- **Strategy Pattern**:
    - `BaseParser` (Abstract Class): Defines `parse()` and `get_metadata()`.
    - `PDFParser`, `URLParser`, `ChatJSONParser`, `MarkdownParser` (Concrete Implementations).
- **Unified Schema**:
    - `source`: Original path/URL.
    - `content_type`: e.g., `document`, `chat`, `web`.
    - `ingested_at`: ISO timestamp.
    - `fingerprint`: A hash of the content/source for deduplication.
    - `metadata`: A flexible dictionary for format-specific data.
- **Workflow**:
    1. `Engine.ingest(source)`
    2. `Parser = ParserRegistry.get_parser(source)`
    3. `Documents = Parser.parse(source)`
    4. `Engine.commit(Documents)`

## Proposed Architectural Change
- Create `modules/ingestion/engine.py` (The Controller).
- Create `modules/ingestion/parsers/` (Directory for parser modules).
- Deprecate `librarian_ingest.py` and `ingest_chats.py` in favor of `python -m modules.ingestion.engine --source <path>`.
