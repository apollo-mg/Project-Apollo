## Architectural Audit Results
- **`mine_transcripts` Identification**: The term `mine_transcripts` is not a literal function in the current codebase. It appears to be a conceptual name for a process that synthesizes/mines interaction transcripts into the `MemoryStore`.
- **Current Memory Architecture**: 
    - `InMemoryStore` (in `src/memory/store.ts`) provides a key-value interface.
    - `SharedMemory` (in `src/memory/shared.ts`) provides namespacing for agents.
    - The "Vault" is conceptually the persistent version of this memory (though currently, `InMemoryStore` is non-persistent).
- **The Gap**: There is no existing mechanism to automatically process "transcripts" (logs of agent interactions) into the `MemoryStore` upon session termination.
- **Proposed Solution**:
    1. **Implement `mine_transcripts`**: Create a new tool/module that takes raw interaction logs (transcripts) and uses an LLM to extract structured insights, which are then written to the `SharedMemory`.
    2. **Session Lifecycle Hook**: Since the user is using Termux/SSH, the "Sync-on-Disconnect" can be implemented by:
        - A wrapper script for the CLI tool that uses a `trap` on `EXIT` to call the mining process.
        - Or, a background daemon that monitors the `transcription-sessions` (if they are logged to disk) and triggers the mining process when a session is marked as closed.
- **Implementation Strategy**:
    - Define a `Transcript` type.
    - Create `src/modules/transcript_miner.ts`.
    - Add a `mine_transcripts` tool to the `ToolRegistry`.
    - Update the CLI entry point to ensure that when a session ends, the `mine_transcripts` tool is invoked.

## Conclusion
The epiphany is valid. The infrastructure lacks the "synapse" to convert transient interactions into permanent cognitive structure. The proposed 'Sync-on-Disconnect' protocol is a necessary architectural evolution to unify the mobile 'limbs' with the central 'Vault'.
