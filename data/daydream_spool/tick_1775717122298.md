# Architectural Audit: DMA Stability & Tensor Contiguity

## 1. Executive Summary
The investigation confirms a critical vulnerability in the hardware-software interface during tensor transfers. While the high-level orchestration (TypeScript) and logic (Python) do not explicitly manage DMA, the underlying runtime (likely PyTorch or a C-based LLM engine like llama.cpp/sglang) is susceptible to crashes when attempting to transfer non-contiguous memory layouts from CPU to GPU/ROCm.

## 2. Root Cause Analysis
- **The "Act of Becoming" Failure:** The crash occurs during the transition phase where memory is moved across the PCIe bus. 
- **Memory Layout Fragility:** Operations such as slicing, transposing, or permuting in Python create "views" of tensors that are non-contiguous in physical memory. 
- **DMA Engine Limitation:** When a non-contiguous tensor is passed to a `.to(device)` or similar transfer operation, the DMA engine may attempt to read memory in a linear fashion that does not match the logical layout, leading to illegal memory access or hardware hangs.

## 3. Audit Findings
- **Codebase Scan:** No explicit `.contiguous()` calls were found in the primary `modules/` or `src/` directories.
- **Runtime Context:** Logs (`server_qwen_moe_crash.log`) indicate heavy tensor loading and offloading to GPU/ROCm. The crash is likely triggered during these high-bandwidth transfers.
- **Affected Components:** Any module performing tensor manipulation (slicing, reshaping) prior to model inference or data transfer.

## 4. Proposed Architectural Change: The Pre-Flight Protocol

### 4.1 Mandate Contiguity
Implement a strict requirement that all tensors must be contiguous before being passed to any device-transferring function.

### 4.2 Implementation Strategy (Python)
In any Python module handling tensor data (e.g., `modules/memory_core.py`, `modules/pvl_engine.py`), wrap transfers in a safety check:

```python
def safe_transfer(tensor, device):
    """
    Ensures tensor is contiguous before DMA transfer to prevent 
    hardware-level crashes during the 'act of becoming'.
    """
    if not tensor.is_contiguous():
        tensor = tensor.contiguous()
    return tensor.to(device)
```

### 4.3 Implementation Strategy (TypeScript/Orchestration)
While TypeScript doesn't handle tensors directly, the `scheduler.ts` and `orchestrator.ts` should be updated to include "Memory Integrity" as a task requirement. If a task is flagged as `high-vram` or `compute-intensive`, the orchestrator must ensure the underlying worker process is initialized with a "Contiguity-Enforced" runtime configuration.

## 5. Conclusion
The stability of the system depends on the integrity of the memory transition. By enforcing `.contiguous()` calls, we transform a fragile "act of becoming" into a predictable, linear DMA operation, mitigating the risk of hardware-level crashes.
