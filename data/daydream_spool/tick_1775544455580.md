# Architectural Audit: Volatility-Aware Thermal Management

## Epiphany Analysis
The subconscious daemon has identified a critical gap in the current architecture: the disconnect between **latent space complexity** (the 'Sampler') and **hardware safety constraints** (the 'Red Button'). 

Currently, the system treats thermal management as a reactive, static threshold mechanism. The epiphany suggests a proactive, "Volatility-Aware" approach where the computational entropy (predicted by sampler/denoise complexity) informs the thermal safety margins.

## Audit Findings
1.  **Current State:** The codebase contains a `SensitivityEngine` in `src/modules/criticality.ts`, which performs variance-based analysis on weights and workflow junctions. However, this is currently decoupled from the hardware/thermal control loop.
2.  **Missing Link:** There is no existing `VolatilityIndex` or mechanism to map `AgentConfig.temperature` or denoise-related parameters to a `ThermalAutopilot` sensitivity adjustment.
3.  **Integration Point:** The `AgentConfig` (in `src/types.ts`) contains `temperature`, which is a primary driver of computational variance. The `SensitivityEngine` is the ideal candidate to transform these high-level parameters into a `VolatilityIndex`.

## Proposed Architectural Update

### 1. Define Volatility Metrics
Extend `src/modules/criticality.ts` to include a `VolatilityIndex` calculation. This index will quantify the "computational entropy" of a task based on:
- `temperature` (LLM parameter)
- `maxTokens` (Potential duration/heat)
- `complexity` (Derived from task description/agent role)

### 2. Implement Thermal-Volatility Coupling
Introduce a new module `src/modules/thermal_autopilot.ts` (or extend existing hardware controllers) that implements the following logic:
```typescript
// Pseudocode for the proposed logic
const volatility = volatilityEngine.calculate(agentConfig);
const baseThreshold = 90; // Default Celsius
const safetyMargin = volatility > 0.7 ? 5 : 0; // Reduce threshold if high volatility
const activeThreshold = baseThreshold - safetyMargin;
```

### 3. Actionable Implementation Plan
- **Phase 1:** Update `src/types.ts` to include `volatilityIndex` in `AgentState`.
- **Phase 2:** Implement `VolatilityEngine` in `src/modules/criticality.ts` to map `AgentConfig` to a 0.0-1.0 score.
- **Phase 3:** Integrate `VolatilityEngine` with the hardware monitoring service to dynamically adjust the `thermal_kill_threshold`.

## Conclusion
The epiphany is valid and represents a necessary evolution from "Reactive Safety" to "Predictive Resilience." Implementing this will prevent thermal throttling or hardware shutdown during high-intensity, high-entropy generation tasks by preemptively lowering the safety ceiling.
