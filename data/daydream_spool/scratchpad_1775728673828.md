# Apollo Investigation: Structured Cognition vs. Filtering Strategy

## Epiphany Summary
The current architecture treats `<think>` tags as noise to be filtered out. This creates a schism where reasoning is decoupled from action, making the agent "deaf to its own mind."

## Objective
Investigate how the agent currently handles `<think>` tags and tool calls, and propose a transition to a "structured cognition" strategy where reasoning is a formal pre-condition for action.

## Initial Findings
- The codebase contains `apollo.py`, which is likely the core agent logic.
- There are various logs (`architect.log`, `apollo_bridge.log`) that might show the current "filtering" behavior in action.
- I need to examine how tool calls are parsed and how the `<think>` tags are being handled/suppressed.

## Investigation Plan
1.  **Examine `apollo.py`**: Identify the parsing logic for tool calls and the handling of `<think>` tags.
2.  **Analyze Logs**: Look for patterns in `architect.log` or `apollo_bridge.log` that confirm the "filtering" behavior (e.g., seeing `<think>` content being stripped or ignored).
3.  **Identify the "Schism"**: Find the specific code responsible for the decoupling of reasoning and action.
4.  **Draft Proposal**: Design a schema where the `thought` is a required field in the tool-call protocol.
## Technical Audit Findings

### 1. The "Schism" Identified
The current implementation in `modules/agent_session.py` confirms the Epiphany. 

Lines 103-114:
```python
103	            if "<think>" in t_resp:
104	                thought = t_resp.split("</think>")[0].replace("<think>", "").strip()
105	                self.full_thinking_trace += f"\n[Turn {self.turn}]: {thought}"
106	            else:
107	                # If no tags, treat the whole response as thinking if no JSON is found
108	                if "{" not in t_resp:
109	                    self.full_thinking_trace += f"\n[Turn {self.turn}]: {t_resp}"
110	            
111	            # Robust JSON block extraction
112	            json_target = t_resp.split("</think>")[-1] if "</think>" in t_resp else t_resp
113	            json_target = json_target.replace("```json", "").replace("```", "").strip()
```

**The Problem:**
- The code explicitly splits the response at `</think>`.
- It treats everything *before* the tag as "thought" (to be stored in `full_thinking_trace`) and everything *after* the tag as the "action" (the JSON target).
- This is a **filtering strategy**. The reasoning is stripped away from the primary execution stream and relegated to a side-log (`full_thinking_trace`).
- The agent's "mind" (the reasoning) is treated as a separate entity from its "body" (the tool calls).

### 2. Impact
- **Loss of Contextual Continuity:** The LLM's reasoning is not part of the structured tool-call protocol. If the model's reasoning is complex, the "action" (the JSON) is isolated from the "why" (the thought) in the actual message history sent back to the LLM in subsequent turns.
- **Mechanical Failure Risk:** If the model's reasoning is required to validate the tool call (e.g., "I am calling X because Y"), that "Y" is lost to the tool itself, even though `agent_session.py` tries to inject `thought_trace` into `kwargs` (Line 165). However, this is a hacky injection, not a formal part of the schema.

### 3. Proposed Architectural Shift: "Structured Cognition"
Instead of:
`[THOUGHT] <think>...</think> [ACTION] {"tool": "..."}`

We move to:
`[ACTION] {"thought": "...", "tool": "...", "args": {...}}`

**Implementation Plan:**
1. **Update System Prompt:** Instruct the model that every tool call MUST be a JSON object containing a `thought` key.
2. **Update Parser:** Modify `modules/agent_session.py` to look for the `thought` key within the JSON object rather than splitting the string by `<think>` tags.
3. **Update Tool Protocol:** Ensure the `thought` is passed as a first-class citizen to the `Toolbox` methods, allowing tools to potentially use the reasoning for validation (e.g., `run_shell` could check if the thought matches the command).
4. **Deprecate `<think>` tags:** Move away from XML-style reasoning tags in favor of JSON-integrated reasoning.
