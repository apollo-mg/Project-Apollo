# Architectural Audit: RDNA 4 / R9700 Deployment Strategy

## Epiphany Analysis
The Subconscious has identified a critical shift in our operational paradigm: the transition from "software installation" to "hardware-software synthesis." The RDNA 4 (RX 9070 XT) architecture is not a static target but a moving frontier requiring constant alignment with nightly-build dependencies (ROCm 7.2.0 + PyTorch 2.11.0 Nightly).

## Audit Findings
1.  **Hardware Verification:** Logs (`server_test.log`, `server_qwen_moe_crash.log`) confirm the presence of the **AMD Radeon RX 9070 XT** (ROCm0) with ~16GB VRAM.
2.  **Current State:** The system is currently operating on a ROCm 7.2.0-2 baseline (per `ROCM_7.11_MIGRATION_PLAN.md`).
3.  **Stability Risks:** 
    *   The `server_qwen_moe_crash.log` indicates that MoE (Mixture of Experts) workloads are currently prone to crashes on this hardware/driver combination.
    *   The `ROCM_7.11_MIGRATION_PLAN.md` warns against moving to ROCm 7.11.0 (TheRock) due to `llama.cpp` regressions and Llama 3.1 validation failures.
4.  **Dependency Gap:** There is no immediate evidence in the current filesystem of a dedicated "Foundational Infrastructure Layer" for ROCm 7.2.0 + PyTorch 2.11.0 (Nightly). The current environment appears to be a standard CachyOS/Arch setup.

## Proposed Architectural Update: Tiered Deployment Hierarchy

To stabilize the "construction zone," I propose the following structural reorganization:

### Tier 1: Foundational Infrastructure (The "Anchor" Layer)
*   **Objective:** Establish a verified, immutable environment for core compute.
*   **Components:** 
    *   `ROCm 7.2.0` (Stable-ish)
    *   `PyTorch 2.11.0 (Nightly)` (Optimized for RDNA 4)
*   **Implementation:** Create a dedicated `infrastructure/` directory containing environment manifests (Conda/Mamba or Dockerfiles) specifically tuned for the `gfx1201` target.

### Tier 2: Functional Benchmarking (The "Frontier" Layer)
*   **Objective:** Validate the stability of the Tier 1 layer using high-intensity workloads.
*   **Primary Benchmark:** `FLUX-text-to-image-ROCm`.
*   **Validation Metric:** Successful inference cycles without VRAM fragmentation or kernel panics.
*   **Secondary Benchmark:** `llama.cpp` (with `-mllvm --amdgpu-unroll-threshold-local=600` if performance regressions are detected).

## Action Plan
1.  **[Immediate]** Formalize the `infrastructure/` directory to house the ROCm 7.2.0 + PyTorch 2.11.0 nightly build specifications.
2.  **[Validation]** Deploy `FLUX-text-to-image-ROCm` as a continuous integration (CI) smoke test for the R9700 environment.
3.  **[Monitoring]** Implement a telemetry hook in `system_monitor.py` to specifically track ROCm kernel driver stability during high-load FLUX inference.
