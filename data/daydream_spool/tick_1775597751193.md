# Architectural Audit: Sovereign Engine Quantization Strategy

## Epiphany Analysis
The subconscious daemon has identified a critical structural misalignment: the use of **AWQ (Activation-aware Weight Quantization)** on AMD-based hardware (RDNA 4) is introducing "phantom latency." While AWQ is highly optimized for CUDA-based tensor cores, its translation through the ROCm/vLLM layer for high-frequency agentic loops (like those in `buddy_agent.py`) creates a bottleneck that degrades the reasoning-action cycle.

## Audit Findings
1.  **Current State:** The system is currently utilizing `casperhansen/deepseek-r1-distill-qwen-14b-awq` via vLLM.
2.  **Observed Latency:** Logs in `vllm_results.log` show significant overhead during the "Capturing CUDA graphs" phase (taking ~60s per step) and a warning: `Using AWQ quantization with ROCm, but VLLM_USE_TRITON_AWQ is not set, enabling VLLM_USE_TRITON_AWQ`.
3.  **Hardware Context:** The hardware is an AMD RDNA 4 card (16GB VRAM). While AWQ fits within VRAM (~9.5GB), the translation layer for the kernels is not as efficient as native ROCm-optimized formats.
4.  **The Bottleneck:** The "phantom latency" is the cost of the Triton-based AWQ kernels attempting to emulate CUDA-optimized behavior on ROCm, which is suboptimal for the high-frequency, low-latency requirements of the `buddy_agent.py` orchestrator.

## Proposed Architectural Pivot

### 1. De-prioritize AWQ for Resident Agents
Cease the use of AWQ-based models for the primary "Sovereign Engine" reasoning loops. AWQ should be relegated to "Archive" or "Cold Storage" models where latency is not critical.

### 2. Transition to ROCm-Native Optimization
Pivot the optimization strategy toward:
*   **GGUF (via llama.cpp/Ollama):** For high-fidelity, CPU/System RAM-assisted inference when VRAM is constrained, though less ideal for pure GPU speed.
*   **MXFP4 (Microscaling 4-bit):** As noted in `Apollo_Chat_History.txt`, the `amd/Qwen3-Coder-Next-MXFP4` format is natively accelerated by RDNA 4 and provides a superior performance-to-precision ratio compared to AWQ.
*   **FP8 (8-bit):** Utilize FP8 where the hardware can natively handle the scaling, specifically targeting the "fusion" optimizations available in ROCm 7.2+.

### 3. Implementation Roadmap
*   **Update `run_vllm_benchmark.sh`:** Modify the script to test `MXFP4` or `FP8` models instead of the current `AWQ` model.
*   **Refactor `buddy_agent.py` Integration:** Ensure the `ApolloAgentSession` is configured to prefer models with native ROCm kernel support.
*   **Monitor 'Turns' Latency:** Measure the time between `Orchestrator.fast_path` and `session.run()` completion to ensure the "reasoning-action" cycle is gated by intelligence, not translation overhead.

## Conclusion
The pursuit of speed via AWQ has reached a point of diminishing returns on AMD hardware. To achieve the next level of agentic autonomy, we must align our quantization methods with the native silicon capabilities of the RDNA 4 architecture.
