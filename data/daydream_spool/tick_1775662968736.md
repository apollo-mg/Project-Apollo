# Architectural Audit: Reflex-to-Cognition Hand-off Protocol

## 1. Executive Summary
The transition from the 'DeepScaler' (Worker Tier) to the 'Architect' (Architect Tier) is currently a **static, pre-execution decision**. While this minimizes latency for simple tasks, it creates a "Cognitive Trap": if the initial heuristic or the 0.6B model misclassifies a complex task as 'SIMPLE', the system will attempt to solve it with insufficient reasoning capacity, leading to failure or hallucination.

## 2. Identified Vulnerabilities
- **Static Routing:** The `CognitiveDispatcher.route_task` method makes a single decision at the start. There is no mechanism for a Worker to "realize" it is out of its depth and escalate to the Architect mid-stream.
- **Latency Shock:** The throughput drop from ~50 TPS (Worker) to ~27 TPS (Architect) is not managed. The user experiences this as a sudden "hang" or "sluggishness" because the system lacks a transitionary state.
- **Context Fragmentation:** While `TaskContext` exists, the current implementation does not explicitly define how the "internal monologue" or "intermediate reasoning steps" of a Worker are handed over to the Architect during an escalation.

## 3. Proposed Architectural Changes

### A. Implementation of `CognitiveEscalation`
Modify `_execute_worker` to monitor for an `[ESCALATE]` token in the model output.
```python
# Proposed logic for modules/cognitive_dispatcher.py
async def _execute_worker(self, task: TaskContext) -> Dict[str, Any]:
    response = await self.query_llm(task.user_input, self._worker_config)
    if "[ESCALATE]" in response:
        # Re-route to Architect immediately
        task.tier = Tier.ARCHITECT
        task.complexity = TaskComplexity.COMPLEX
        return self._execute_architect(task)
    return {"status": "success", "output": response}
```

### B. Latency Smoothing (The "Transition" State)
Introduce a `Transitioning` state in the `TaskContext`. When a task is escalated, the API should return a `202 Accepted` with a status of `transitioning_to_architect`. This manages user expectations by signaling that the system is shifting from "Reflex" to "Deep Reasoning" mode.

### C. Contextual Hand-off
The `TaskContext` must be augmented to include a `reasoning_trace` field. If a Worker escalates, it must append its partial reasoning to this field so the Architect can resume from the point of failure rather than starting from scratch.

## 4. Conclusion
The current architecture is a "Single-Brain" model masquerading as a "Tiered" system. To achieve true biological-style latency simulation, we must move from **Static Routing** to **Dynamic Escalation**.
