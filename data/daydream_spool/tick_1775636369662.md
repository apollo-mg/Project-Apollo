# Architectural Proposal: Drift Threshold Protocol (Compliance Guard)

## 1. Problem Statement
As model scale increases, the risk of "Instruction Drift"—where a model fails to adhere to strict structural requirements (like JSON schema) despite following the semantic content—increases. In automated triage pipelines, this drift leads to silent logic degradation and system-wide failure.

## 2. Proposed Solution: The `ComplianceGuard`
We will implement a proactive validation layer that tests a model's "obedience" before it is integrated into high-stakes orchestration roles.

### 2.1 Core Components
- **`ComplianceGuard`**: A service responsible for executing "Golden Prompt" tests.
- **`DriftThreshold`**: A configurable metric (e.g., % of successful schema validations) that determines if a model is fit for duty.
- **`GoldenPromptSet`**: A collection of standardized system prompts and user queries designed to trigger specific JSON tool-calling behaviors.

```typescript
export class Agent {
  // ... existing properties
  private complianceGuard?: ComplianceGuard;
  private isVerified: boolean = false;

  async getRunner(): Promise<AgentRunner> {
    if (this.runner !== null) return this.runner;
    
    // NEW: Proactive Drift Check
    if (this.complianceGuard && !this.isVerified) {
      const result = await this.complianceGuard.validateModel(
        this.config.model, 
        this.config.systemPrompt ?? ''
      );
      
      if (!result.passed) {
        throw new Error(`Model Drift Detected: ${result.model} failed compliance test.`);
      }
      this.isVerified = true;
    }

    // ... existing runner creation logic
  }
}
```

## 3. Impact Analysis
- **Safety**: Prevents "hallucinated" tool calls or malformed JSON from breaking the automated pipeline.
- **Reliability**: Provides a measurable metric for model quality in the Foundry.
- **Overhead**: Adds a one-time latency cost during agent initialization (lazy-loaded via `getRunner`).

## 4. Conclusion
The transition from 'Heretic' to 'Aggressive' standards requires moving from *reactive* error handling (catching Zod errors during execution) to *proactive* compliance verification (ensuring the model is capable of the task before execution).
