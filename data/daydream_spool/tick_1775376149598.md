# Architectural Audit: VRAM Tetris & Model-Loading Stability

## Epiphany Analysis
The subconscious daemon has identified a critical failure point in the current orchestration strategy. While the high-level 'VRAM Tetris' (sequential LLM → Flux → VLM) is designed to optimize resource usage, the underlying execution layer is fracturing. Specifically, the `np.memmap` implementation within the GGUF reader is encountering `ValueError: cannot mmap an empty file`.

This indicates that the "swap" mechanism (moving models in/out of VRAM) is being undermined by corrupted or zero-byte model files. If the low-level model instantiation fails due to file corruption, the macro-management of VRAM becomes irrelevant, leading to a cycle of repeated crashes rather than a successful orchestration.

## Audit Findings
1. **Root Cause Identified**: A traceback in `chat_history/local/session-2025-11-21T01-20-8569609d.json` confirms that `ComfyUI-GGUF` nodes are failing because `gguf.GGUFReader` attempts to `np.memmap` a file that is empty.
2. **Corrupted File Detected**: The `find` command executed in the session history identified `ComfyUI/models/unet/Wan2.1-T2V-14B-Q4_K_M.gguf` as an empty file (or at least part of a set of empty directories/files).
3. **Systemic Risk**: The current orchestration assumes model files are valid and ready for memory mapping. The presence of 0-byte files suggests a failure in the model download/provisioning stage or a filesystem error during the "swap" process.

## Proposed Architectural Update

### 1. Low-Level Primitive: The "Integrity Guard"
Before any model is passed to the `GGUFReader` or `np.memmap`, a lightweight integrity check must be performed.
- **Implementation**: Integrate a `FileIntegrityCheck` module into the `model_provisioner.sh` or the Python-based model loader.
- **Logic**: 
  ```python
  def validate_model_file(path):
      if not os.path.exists(path):
          return False, "File missing"
      if os.path.getsize(path) == 0:
          return False, "File is empty (0 bytes)"
      # Optional: Check for GGUF magic header
      return True, "OK"
  ```

### 2. Orchestration Layer: The "Fail-Fast" Protocol
The 'VRAM Tetris' orchestrator must be updated to handle "Model Loading Failures" as a specific state.
- **Current State**: Crash/Exception.
- **Proposed State**: `MODEL_LOAD_ERROR`. If a model fails to load due to corruption, the orchestrator should:
    1. Mark the model as `CORRUPTED` in the `model_manifest.json`.
    2. Trigger a re-download/repair task.
    3. Skip the current orchestration cycle to prevent a crash loop.

### 3. Filesystem/Provisioning Fix
- Ensure that the `hoard_worker.sh` and `model_provisioner.sh` scripts use atomic writes (writing to a `.tmp` file first, then `mv` to the final destination) to prevent the creation of 0-byte files during interrupted downloads.

## Conclusion
The 'VRAM Tetris' strategy cannot be perfected until the model-loading primitives are stabilized. We must move from "assuming file availability" to "verifying file integrity" at the micro-level.
