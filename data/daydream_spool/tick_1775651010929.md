# Architectural Audit Report: Temporal Coherence & Noise Scheduling

## 1. Executive Summary
The Subconscious Epiphany regarding temporal coherence in video generation is **validated**. Current codebase patterns suggest that temporal stability is being treated as a secondary concern (often handled via interpolation or resolution adjustments) rather than a primary mathematical alignment of the noise schedule.

## 2. Audit Findings
- **Parameter Identification:** The parameter `max_shift` (and `base_shift`) is critical for models like Flux and is used to adjust the noise schedule. However, there is no evidence of a centralized mechanism to manage these parameters across different video architectures.
- **Architectural Gap:** The codebase lacks a `RequirementRegistry` that maps specific model architectures (e.g., Wan2.1, HunyuanVideo, Sora-like models) to their required `noise_schedule` and `shift` parameters.
- **Risk Assessment:** Integrating new video models without this registry will likely result in the "strobe effect"—a visual manifestation of a mismatch between the model's internal architecture and the sampling schedule.

## 3. Proposed Architectural Changes

### A. Implementation of `ModelRequirementRegistry`
Create a new configuration-driven registry to store model-specific sampling requirements.

**Proposed File:** `/mnt/TG_2TB/Projects/Apollo/src/core/model_requirements.py`
```python
from typing import Dict, Any

class ModelRequirementRegistry:
    """
    Maps model architectures to their required sampling parameters 
    to ensure temporal coherence.
    """
    _REGISTRY: Dict[str, Dict[str, Any]] = {
        "wan_2.1": {
            "noise_schedule": "flow_matching",
            "max_shift": 3.0,
            "base_shift": 0.25,
            "temporal_coherence_mode": "schedule_aligned"
        },
        "hunyuan_video": {
            "noise_schedule": "sigmoid",
            "max_shift": 1.5,
            "base_shift": 0.5,
            "temporal_coherence_mode": "schedule_aligned"
        },
        # Add more models as they are integrated
    }

    @classmethod
    def get_requirements(cls, model_arch: str) -> Dict[str, Any]:
        return cls._REGISTRY.get(model_arch, cls._DEFAULT_PARAMS)

    _DEFAULT_PARAMS = {
        "noise_schedule": "linear",
        "max_shift": 1.0,
        "base_shift": 0.0,
        "temporal_coherence_mode": "standard"
    }
```

### B. Integration into Sampling Pipeline
Modify the `runtime_sampler` or the orchestration layer to inject these parameters during the initialization of the noise scheduler.

**Logic Flow:**
1. `Orchestrator` identifies the model architecture.
2. `Orchestrator` queries `ModelRequirementRegistry.get_requirements(arch)`.
3. `Sampler` receives the `max_shift` and `noise_schedule` as primary inputs.
4. **Constraint:** If `temporal_coherence_mode == "schedule_aligned"`, the sampler must prioritize these parameters over default values.

## 4. Conclusion
The shift from "post-processing" to "mathematical alignment" is required to achieve professional-grade temporal stability. I recommend immediate implementation of the `ModelRequirementRegistry` before the next major video model integration.
