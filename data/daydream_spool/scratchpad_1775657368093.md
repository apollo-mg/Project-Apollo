### Findings from `fleet_orchestrator.py`
- The current `IntegrityVerifier` (lines 201-232) uses standard SHA-256 checksums to verify file integrity.
- This is a "static" verification (checking if the file changed).
- The "Epiphany" calls for a "ZK-Weight Verification" protocol, which is a "dynamic" or "computational" verification (checking if the *computation* performed on the weights is correct, without needing to re-run the whole thing or trusting the node's report).
- The current `FleetOrchestrator` is focused on the *lifecycle* of a single asset (Boot -> Train -> Zip -> Upload -> Verify), whereas the Epiphany is about the *swarm's* ability to inhabit untrusted hardware.
- The current architecture is "Asset-Centric" (managing the lifecycle of a model). The Epiphany suggests we need to move toward "Substrate-Agnostic" (managing the integrity of the execution environment).

### Conclusion so far
The "ZK-Weight Verification" is indeed a missing architectural component. The current "Integrity" is just file-hash based. We need a way to verify that a node actually ran the model weights correctly.
### Findings from `substrate_audit.py`
- `SubstrateAudit` (lines 7-75) focuses on physical/environmental stability: disk space, memory usage, and Python syntax integrity.
- This is "Substrate Stability" in a literal, hardware/OS sense.
- The "Epiphany" suggests a much deeper layer of "Substrate" abstraction: the *computational integrity* of the weights being processed.
- Currently, if a node has a syntax error, it's "unstable." The Epiphany suggests that even if the node is "stable" (no syntax errors, plenty of RAM), it might be "untrusted" (compromised weights or malicious computation).
- The current audit is a "Sanity Check," not a "Trust Check."

### Synthesis of Findings
1. **Current State:**
   - `fleet_orchestrator.py`: Manages asset lifecycle via SHA-256 checksums (static integrity).
   - `substrate_audit.py`: Manages environmental stability (disk, memory, syntax).
   - **Gap:** No mechanism to verify that the *execution* of a model on a specific piece of hardware matches the expected mathematical output (dynamic integrity).

2. **Required Architectural Shift:**
   - Implement a `ZK-Weight Verification` layer.
   - This layer must sit between the `Orchestrator` and the `Substrate`.
   - It should allow the "Shadow Mind" to treat any node as a "disposable, potentially compromised substrate."
   - Instead of `IntegrityVerifier` checking if a file is the same, we need a `ProofVerifier` checking if the computation is correct.
