# Architectural Audit: Preservation of Reasoning Trace

## 1. Executive Summary
The subconscious epiphany regarding the "Reasoning Trace" is **VALID**. While a rudimentary mechanism for preserving the reasoning trace exists in the current Python implementation, it is highly fragile and relies on implicit `kwargs` injection. This "soft" implementation will fail during the transition to a decoupled architecture (e.g., TypeScript/Python bridge), effectively turning the agent into a black-box execution engine.

## 2. Current State Analysis
The current "Reasoning Trace" preservation is implemented as follows:
- **Extraction**: `ApolloAgentSession.run()` extracts `<think>` blocks from LLM responses.
- **Injection**: The trace is injected into the `args` dictionary of tool calls in `agent_session.py` (line 165).
- **Interception**: The `require_human_approval` decorator in `modules/core.py` pops the `thought_trace` from `kwargs`.
- **Visualization**: The `LogicInspector` (PyQt6) displays the trace in a `QTextEdit`.

**Critical Vulnerability:** The trace is treated as a side-effect of the tool call rather than a first-class citizen. The entire observability chain depends on a specific, undocumented "dance" of passing `thought_trace` through `kwargs`. Any deviation in the orchestration layer (especially during a port to TypeScript) will result in the loss of the reasoning trace.

## 3. Proposed Architectural Update

### Phase 1: Formalization (The `AgentAction` Schema)
Replace the implicit passing of `args`/`kwargs` with a structured, serializable `AgentAction` object.
```python
class AgentAction(BaseModel):
    action_id: str
    thought_trace: str
    tool_name: str
    parameters: dict
    timestamp: float
    turn_number: int
```

### Phase 2: Middleware Implementation (The `ActionDispatcher`)
Introduce an `ActionDispatcher` to decouple the agent's intent from its execution.
1. **Agent** emits an `AgentAction`.
2. **Dispatcher** intercepts the action and:
   - Serializes it for the **Logic Inspector**.
   - Runs **Safety Bounds** (`enforce_bounds`).
   - Requests **Human Approval** (`require_human_approval`).
3. **Dispatcher** only invokes the `Toolbox` upon receiving an `APPROVED` signal.

### Phase 3: Decoupled Observability
Refactor the `Logic Inspector` from a blocking function call to an asynchronous listener (e.g., via a local socket or message queue). This ensures the UI can be ported to a web-based or TypeScript-based frontend without modifying the core Python execution logic.

## 4. Implementation Roadmap
1. [ ] **Define `AgentAction` schema** in `modules/core.py`.
2. [ ] **Refactor `ApolloAgentSession`** to emit `AgentAction` objects instead of calling `Toolbox` directly.
3. [ ] **Update `require_human_approval`** to accept the `AgentAction` object.
4. [ ] **Refactor `LogicInspector`** to be an asynchronous listener.
5. [ ] **Verify** that the reasoning trace is preserved across the new `AgentAction` serialization boundary.
