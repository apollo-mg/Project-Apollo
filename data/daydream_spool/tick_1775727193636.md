# Architectural Proposal: Contextual Defragmentation (autoDream)

## 1. Problem Statement
The current memory architecture suffers from **Contextual Fragmentation**. Information is stored in two extremes:
1. **Granular/Raw**: Scratchpads, logs, and individual `.md` files (e.g., `legacy_vault/`, `daydream_spool/`).
2. **High-Level/Static**: `MEMORY.md`, which contains system truths but lacks the semantic bridge to the granular data.

As the system evolves, the "Attention Window" (the LLM's context) becomes cluttered with low-level noise, making it difficult for the "Kernel" to maintain a coherent state of high-level cognitive primitives.

## 2. Proposed Solution: The `autoDream` Routine
Implement a background orchestration process that transitions the system from an **Agent-centric** (reactive) model to a **Kernel-centric** (proactive) model.

### Core Mechanism: The Three-Tier Memory Hierarchy
1. **Tier 1: The Raw Layer (Granular)**
   - *Contents*: Scratchpads, logs, raw ingestion (Maildir, Discord).
   - *Role*: Source of truth for specific, recent events.
2. **Tier 2: The Topic Layer (Abstraction)**
   - *Contents*: A new `TOPICS/` directory containing semantic summaries (e.g., `TOPICS/ROCm_Optimization.md`, `TOPICS/Project_Roadmap.md`).
   - *Role*: Provides "paged" context. Instead of reading 50 logs, the Agent reads one Topic file.
3. **Tier 3: The Kernel Layer (System Truths)**
   - *Contents*: `MEMORY.md`.
   - *Role*: The absolute minimal set of verified truths and active goals.

## 3. Implementation Roadmap

### Phase A: The Defragmentation Daemon (`autodream.py`)
- **Trigger**: A systemd timer (`autodream.timer`) running every 4-6 hours.
- **Logic**:
    1. **Scan**: Identify new/modified `.md` files in the project root.
    2. **Triage**: Use the `Gatekeeper` (0.6B) to categorize files by topic.
    3. **Consolidate**: If a topic has $>N$ new files, invoke the `Engineer` (8B) to:
        - Read the new files.
        - Synthesize a "Topic Update".
        - Update the corresponding file in `TOPICS/`.
    4. **Distill**: If a Topic Update contains a "System Truth" (e.g., a new hardware discovery), flag it for `MEMORY.md` update.

### Phase B: Contextual Paging
- Modify the Agent's initialization sequence.
- Instead of loading all files, the Agent loads:
    1. `MEMORY.md` (The Kernel State).
    2. The relevant `TOPICS/*.md` files based on the current task's semantic intent.

## 4. Impact Assessment
- **Pros**: Reduces token consumption; increases reasoning coherence; prevents "context drift"; formalizes the transition from Agent to Kernel.
- **Cons**: Requires additional background compute (minimal, using the 0.6B/8B cascade); requires careful management of the `TOPICS/` directory to avoid its own fragmentation.

## 5. Conclusion
The `autoDream` process is the missing link in the Apollo architecture. It transforms the system from a collection of files into a coherent, self-organizing cognitive engine.
