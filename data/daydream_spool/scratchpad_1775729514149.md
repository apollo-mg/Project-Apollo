# Epiphany Investigation: Hardware Fidelity Metadata Integration
## Timestamp: 2025-05-22 (Simulated)
## Status: Investigating

### Hypothesis
The system currently lacks a mechanism to inject real-time hardware constraints (quantization level, VRAM headroom) into the LLM's context window. This creates a "cognitive dissonance" where the agent might attempt high-reasoning tasks that the underlying bit-depth cannot support, leading to hallucinations or logic failures.

### Investigation Plan
1.  **Identify Context Injection Points:** Locate where the system constructs the prompt/context for the LLM (e.g., `llm_interface.py`, `orchestrator.py`, `apollo.py`).
2.  **Identify Telemetry Sources:** Locate where hardware/quantization data is gathered (e.g., `system_monitor.py`, `vram_management.py`, `model_manifest.json`).
3.  **Audit Current Context Construction:** Check if `model_manifest.json` or `system_monitor.py` outputs are already being used in the prompt.
4.  **Propose Integration:** Design a "Hardware Fidelity Header" to be prepended to the system prompt.
### Findings
- **Telemetry Sources Identified:**
    - `vram_management.py`: Provides `get_gpu_stats()` which returns VRAM usage, temperature, and power.
    - `system_monitor.py`: Provides `get_system_stats()` for CPU/RAM/Disk.
    - `model_manifest.json`: (Currently limited, but could be expanded to include quantization metadata).
- **Context Injection Point Identified:**
    - `llm_interface.py`: The `query_llm` and `_build_messages` functions are the primary gateways for LLM interaction.
- **Gap Analysis:**
    - There is no existing logic to fetch quantization levels (e.g., Q5_K_M vs FP8) and inject them into the `system_message` or `prompt`.
    - The `DeploymentConfig` in `llm_interface.py` is static and does not account for real-time hardware fidelity.

### Proposed Architectural Change: "The Fidelity Header"
1. **Update `vram_management.py`** to include a method `get_fidelity_metadata()` that returns a summary of current hardware state (VRAM headroom + estimated precision based on active model).
2. **Modify `llm_interface.py`** to:
    - Accept an optional `fidelity_metadata` parameter in `query_llm`.
    - Automatically prepend a "Hardware Fidelity Report" to the `system_message` if the metadata is available.
3. **Update `orchestrator.py` (or equivalent)** to call the telemetry tools before initiating a query.

### Draft Implementation Plan
- **Step 1:** Create a new module `src/modules/fidelity_monitor.py` to aggregate telemetry.
- **Step 2:** Inject this telemetry into the `system_message` within `llm_interface.py`.
- **Step 3:** Update the `system_message` template to include:
  `[HARDWARE_FIDELITY: VRAM_FREE={x}MB, PRECISION={y}, CONFIDENCE_THRESHOLD={z}]`
- **Step 4:** Instruct the LLM (via system prompt) to adjust its reasoning depth based on this header.
