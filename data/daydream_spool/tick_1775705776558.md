# Architectural Proposal: JIT Skill-Loading (Sovereignty through Subtraction)

## 1. Executive Summary
The current `ApolloAgentSession` architecture suffers from high instruction density. Every interaction carries a monolithic system prompt containing the full `SOUL`, the entire `INVENTORY` state, and a massive, hardcoded `tools_list`. This consumes significant context window space and increases the likelihood of reasoning degradation. 

Following the "Epiphany" discovered by the KAIROS model, we will transition to a **Just-in-Time (JIT) Skill-Loading** architecture. This will reduce the "cognitive load" on the LLM by providing only the tools and context necessary for the specific task at hand.

## 3. Proposed Architecture: JIT Skill-Loading

### A. The Tool Registry (`modules/tool_registry.py`)
We will move tool definitions out of the session logic and into a structured registry. Each tool will be defined with its name, description, and required arguments.

```python
# Proposed structure for modules/tool_registry.py
TOOL_DEFINITIONS = {
    "check_gpu": {"desc": "Checks GPU status and VRAM usage.", "args": {}},
    "add_task": {"desc": "Adds a new task to the heartbeat queue.", "args": {"description": "str", "urgency": "str"}},
    # ... other tools
}

def get_tools_for_intent(user_input: str) -> str:
    # Logic to map keywords/intent to specific tool subsets
    # e.g., if "task" in user_input: return tools for task management
    pass
```

### B. The Kernel Prompt
The system prompt will be split into a **Kernel** (static, lightweight) and **Payload** (dynamic, task-specific).

**Kernel Prompt:**
- Identity (`SOUL`)
- Agentic Loop Instructions (Self-healing, Anti-looping, TTS constraints)
- JSON Output Mandate

**Payload (Injected only when needed):**
- Relevant Tool Definitions
- Relevant Context (Inventory, Memory, etc.)

### C. Refactored `ApolloAgentSession`
The `_prepare_system_prompt` method will be refactored to:
1.  **Analyze Intent:** Use a lightweight keyword scan or a very small LLM call to determine the "Skill Set" required.
2.  **Assemble Payload:** Fetch only the relevant tools from the `ToolRegistry`.
3.  **Construct Prompt:** Combine `KERNEL_PROMPT` + `PAYLOAD`.

## 5. Expected Impact
- **Context Efficiency:** Reduction of system prompt size by ~60-80% for non-tool-heavy queries.
- **Reasoning Sharpness:** Improved adherence to JSON formatting and agentic loop instructions due to lower instruction density.
- **Scalability:** Easier to add new tools without bloating the base prompt for every user.
