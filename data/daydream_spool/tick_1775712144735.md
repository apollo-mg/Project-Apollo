# Architectural Audit: Cognitive Stability & Memory Paging

## 1. Epiphany Analysis
The "Pre-fill Spike" and "digital seizure" are real-world manifestations of the synchronous, blocking nature of the current `MemoryManager.perform_compaction_flush()` implementation. The system's "intelligence" (the reasoning loop) is held hostage by the "machine" (the hardware/OS) because the semantic compaction process (summarization) is a heavy, blocking I/O and compute operation that occurs exactly when the context window is most strained.

## 2. Identified Bottleneck
**File:** `/mnt/TG_2TB/Projects/Apollo/modules/memory_core.py`
**Mechanism:** 
- `perform_compaction_flush()` is called synchronously when `current_session_tokens >= COMPACTION_THRESHOLD`.
- It performs a blocking `requests.post` to the LLM for summarization.
- It performs blocking Vector DB and File I/O.
- **Result:** The main inference loop is halted during this process, causing a massive latency spike (the "stutter") that disrupts temporal coherence and risks hardware-level instability if the system is already under memory pressure.

## 3. Proposed Architectural Update: "Asynchronous Cognitive Paging"

To prevent the "ghost from vanishing," we must transition from **Reactive Blocking Compaction** to **Predictive Asynchronous Paging**.

### A. Refactor `MemoryManager` (The Paging Engine)
- **Asynchronous Execution:** Move `perform_compaction_flush` to a background thread/process.
- **Predictive Triggering:** 
    - `COMPACTION_THRESHOLD_LOW` (60%): Triggers the background summarization.
    - `COMPACTION_THRESHOLD_HIGH` (80%): The "Hard Limit" where the system must wait for the background task to finish before accepting more input.
- **Tiered Memory Model:**
    - **L1 (VRAM/RAM):** Active `self.history`.
    - **L2 (Warm Cache):** A lightweight, local JSON buffer for recent context.
    - **L3 (Cold Storage):** The Vector DB and `memory_chronicle.md`.

### B. Refactor `ApolloAgentSession` (The Cognitive Loop)
- **State Awareness:** The session must be aware of the `MemoryManager` state (`IDLE`, `COMPACTING`, `CRITICAL`).
- **Latency-Aware Reasoning:** If `MemoryManager` reports `CRITICAL` status (high hardware latency/swap usage), the agent should switch to a "Lean Reasoning" mode (shorter, more direct responses) to reduce the computational footprint.

### C. Refactor `apollo.py` (The Hardware Orchestrator)
- **Proactive Monitoring:** Integrate real-time VRAM/RAM monitoring. If memory pressure is detected, signal the `MemoryManager` to initiate a "Pre-emptive Flush" before the model hits a hard limit.
