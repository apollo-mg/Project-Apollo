# Architectural Audit: Transition from Prompt-Based JSON to Guided Decoding

## 1. Executive Summary
The investigation confirms the "Epiphany": the current system architecture relies on probabilistic prompting to achieve structured output. The `orchestrator.ts` and `apollo_coordinator.ts` files demonstrate a pattern of instructing models to wrap JSON in Markdown code fences and then using regex/string parsing to extract it. This is a fragile "post-hoc" approach that leads to the observed "failed to output a valid JSON directive" errors in `coordinator.log`.

## 2. Identified Vulnerabilities
- **Parsing Fragility:** `src/orchestrator/orchestrator.ts` uses string slicing and regex to find ```json blocks. This is highly susceptible to model hallucinations or formatting deviations.
- **Instructional Overhead:** System prompts are cluttered with "Strict JSON" instructions (e.g., `examples/apollo_coordinator.ts:19`), which consumes context window and increases the likelihood of the model ignoring the constraint.
- **Error Loops:** The `coordinator.log` shows repeated retries when the model fails to adhere to the Markdown-wrapped JSON format, indicating a cycle of failure that cannot be solved by better prompting alone.

## 3. Proposed Architectural Update

### Phase 1: Schema Definition
Migrate all tool definitions from text-based descriptions to strict JSON Schemas. 
- **Target Tools:** `web_search`, `bash`, `file_read`, `file_write`, `file_edit`, `grep`, and any other high-stakes tool.
- **Implementation:** Utilize the existing `src/tool/framework.ts` to ensure schemas are compatible with the LLM's expected input format.

### Phase 2: Engine-Level Enforcement (Guided Decoding)
Replace the current "prompt and parse" loop with vLLM-based guided decoding.
- **Mechanism:** Instead of appending "Respond ONLY with JSON" to the prompt, pass the `inputSchema` to the inference engine.
- **Benefit:** The engine will only sample tokens that satisfy the JSON schema, making it mathematically impossible for the model to output malformed JSON or incorrect Markdown fences.

### Phase 3: Orchestrator Refactoring
- **Remove:** The regex-based extraction logic in `src/orchestrator/orchestrator.ts`.
- **Implement:** A direct JSON response handler that receives the structured output from the engine.
- **Cleanup:** Strip all "Wrap in ```json" instructions from system prompts to reduce token noise and focus the model on the task logic rather than the formatting logic.

## 4. Implementation Plan (Draft)
1. **Audit** all tool definitions in `src/tool/built-in/` to ensure they have valid JSON Schemas.
2. **Modify** the LLM client (e.g., `src/llm/openai.ts` or `src/llm/anthropic.ts`) to support passing a `guided_decoding` parameter.
3. **Update** the `Orchestrator` to pass these schemas during the generation phase.
4. **Verify** by running the `apollo_coordinator.ts` example and monitoring for the disappearance of "failed to output a valid JSON directive" errors.
