# Epiphany Investigation: Intelligence Location (DSP vs. Distributed)
## Timestamp: 2024-05-22 (Simulated)
## Status: Initializing Audit

### Hypothesis
The current codebase/infrastructure may be suffering from architectural ambiguity regarding audio processing. We are likely mixing "Black Box" (dedicated DSP/USB) and "Distributed Node" (ESP32/Networked) paradigms without a clear strategic boundary. This leads to technical debt in how audio streams are ingested and processed.

### Investigation Plan
1. **Identify existing audio ingestion patterns:** Search for references to XMOS, USB audio, ESP32, ESPHome, or specific DSP implementations.
2. **Map the 'Intelligence Location':** Determine if current modules assume local processing (Linux pipeline) or remote/distributed processing (Networked assets).
3. **Audit Hardware Procurement/Config files:** Check if hardware configurations are hardcoded to specific processing models.
4. **Assess Latency/Scalability trade-offs:** Look for bottlenecks in the current audio pipeline.

### Investigation Update: No Direct Audio Code Found
- **Observation:** A deep scan of the `src/` directory and common patterns (audio, mic, dsp, esp, xmos) yielded no direct implementation of audio processing or hardware interfacing.
- **Inference:** The current codebase is a high-level orchestration/agent framework (LLM adapters, task queues, team messaging, memory stores). It does *not* currently contain the audio processing layer mentioned in the Epiphany.
- **Conclusion:** The Epiphany is likely a *strategic directive* for a future or parallel module that has not yet been integrated into this specific repository, or it refers to a hardware-level dependency that is external to this software orchestration layer.
- **Architectural Risk:** If we begin building audio-related agents or tools within this framework, we risk creating "tight coupling" to a specific hardware model (e.g., assuming a USB stream is always available) unless we explicitly define the 'Intelligence Location' as a configuration parameter.

### Proposed Architectural Guardrail
To prevent the "Cognitive Loop" described, we should implement a `HardwareAbstractionLayer` (HAL) or a `ProcessingParadigm` configuration in `src/types.ts`. This will allow the agents to know whether they are operating in a "Black Box" (Local DSP) or "Distributed Node" (Networked) environment.
