# Architectural Proposal: Formalizing the Planar Screen Contract

## 1. Executive Summary
The current "Planar Screen" architecture relies on an implicit contract where the Logic Engine (`adventure.py`) generates a complete UI layout tree and writes it to `data/ui_state.json`. While this achieves decoupling, it creates a high degree of cognitive load for any new logic engine, as they must understand the internal widget hierarchy of the Visual Engine (`dynamic_canvas.py`).

To achieve true "Ghost Interface" autonomy, we must transition from a **UI-Driven** model to a **State-Driven** model.

## 2. Current vs. Proposed Architecture

| Feature | Current (UI-Driven) | Proposed (State-Driven) |
| :--- | :--- | :--- |
| **Logic Engine Responsibility** | Game Logic + UI Layout Construction | Game Logic + State Updates |
| **Visual Engine Responsibility** | Parsing UI Tree + Rendering | Mapping State to UI Templates + Rendering |
| **Contract Type** | Implicit (Structural) | Explicit (Schema-based) |
| **Extensibility** | Low (Requires UI knowledge) | High (Requires only State knowledge) |

## 3. Proposed JSON Schema (`ui_state_schema.json`)
The new contract will define a strict `game_state` object.

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "Planar Screen State Contract",
  "type": "object",
  "properties": {
    "version": { "type": "string", "const": "1.0" },
    "timestamp": { "type": "string", "format": "date-time" },
    "game_state": {
      "type": "object",
      "properties": {
        "location": { "type": "string" },
        "vitals": {
          "type": "object",
          "properties": {
            "health": { "type": "integer", "minimum": 0, "maximum": 100 },
            "oxygen": { "type": "integer", "minimum": 0, "maximum": 100 }
          },
          "required": ["health", "oxygen"]
        },
        "alert_level": { "type": "string", "enum": ["NORMAL", "WARNING", "CRITICAL"] }
      },
      "required": ["location", "vitals", "alert_level"]
    }
  },
  "required": ["version", "timestamp", "game_state"]
}
```

## 4. Implementation Roadmap

### Phase 1: Schema Definition
- Create `data/ui_state_schema.json`.
- Integrate `jsonschema` into the project dependencies.

### Phase 2: Logic Engine Refactor (`adventure.py`)
- **Remove:** The `update_dradis_ui` method's complex `payload` construction.
- **Add:** A simplified `update_ui_state` method that:
    1. Constructs a minimal `game_state` object.
    2. Validates the object against the schema.
    3. Writes the validated JSON to `data/ui_state.json`.

### Phase 3: Visual Engine Refactor (`dynamic_canvas.py`)
- **Remove:** The recursive `build_widget` logic that parses arbitrary UI trees.
- **Add:** A `TemplateManager` that:
    1. Loads a predefined UI layout (e.g., "Sci-Fi Adventure Template").
    2. Maps `game_state` values (e.g., `game_state.vitals.health`) to specific widget properties (e.g., `label.setText`).
    3. Provides a fallback "Awaiting State..." view.

## 5. Conclusion
By formalizing this contract, we transform the Planar Screen from a mere "remote display" into a robust, reactive environment. This allows the "Logic Engine" to focus entirely on the narrative and simulation, while the "Visual Engine" handles the aesthetic manifestation of that reality.
