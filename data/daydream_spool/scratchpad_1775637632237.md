# Investigation: OAuth Token Persistence and Refresh Logic
## Hypothesis
The system is failing to transition from initial authentication to long-term session management. Instead of using a stored refresh token, it is re-triggering the full OAuth flow, resulting in identical 'state' parameters and a recursive loop of identity-seeking.

## Target Areas
1. `src/` (Core logic)
2. `modules/` (Integration modules)
3. `profiles.json` or similar configuration files for stored credentials.
4. Any files related to "bridge", "auth", "oauth", or "session".

## Initial Search Strategy
- Search for "oauth", "token", "refresh", "state", "access_token", "refresh_token" in the codebase.
- Check `src/` and `modules/` specifically.
