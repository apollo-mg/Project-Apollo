# Architectural Audit: Epiphany - The 'native_watchdog' Conflict

## 1. Epiphany Analysis
The subconscious daemon has identified a critical architectural conflict: the `native_watchdog` (implied resource management logic) is aggressively pruning idle processes, which inadvertently sabotages the 'Slow Track' (long-running, complex tasks like benchmarks or Flux generation). This creates non-deterministic failures because the system's efficiency mechanism is unaware of the "intelligence" requirements of long-running fallback processes.

## 2. Findings & Audit Results
- **Current State:** The codebase manages agent lifecycles via `AgentState` (`idle`, `running`, `completed`, `error`). 
- **The Conflict:** While `AgentPool` manages concurrency via a `Semafore`, there is no explicit "Resource Reservation" or "Task Lock" mechanism that communicates to external or internal cleanup processes (the 'watchdog') that a specific environment/process must be preserved despite appearing "idle" or "low-resource" from a standard metric.
- **Codebase Investigation:**
    - `src/agent/agent.ts` and `src/agent/runner.ts` manage the execution loop.
    - `src/agent/pool.ts` manages the concurrency of agents.
    - The `AgentState` (defined in `src/types.ts`) is the primary indicator of activity.
    - The "watchdog" is not explicitly named in the current `src/` directory, suggesting it is either an external system process or a logic block within a utility/orchestrator that hasn't been fully audited. However, the *effect* is clearly visible in how `AgentPool` and `AgentRunner` handle state.

## 3. Proposed Architectural Update: 'Resource Reservation'

To resolve this, we must implement a `task_lock` or `reservation` flag that prevents the watchdog from pruning the environment during critical sequences.

### Proposed Changes:

#### A. Update `src/types.ts`
Add a `reservation` flag to `AgentState` or a global `TaskLock` registry.
```typescript
// In AgentState
export interface AgentState {
  status: 'idle' | 'running' | 'completed' | 'error'
  messages: LLMMessage[]
  tokenUsage: TokenUsage
  isReserved?: boolean // NEW: Flag to prevent watchdog pruning
}
```

#### B. Update `src/agent/agent.ts`
Implement methods to toggle the reservation.
```typescript
// In Agent class
setReservation(reserved: boolean): void {
  this.state.isReserved = reserved;
}

getIsReserved(): boolean {
  return !!this.state.isReserved;
}
```

#### C. Update the 'Watchdog' Logic (Implementation Strategy)
The watchdog (wherever it resides, likely in a cleanup utility or the orchestrator's shutdown logic) must be modified to check this flag:
```typescript
// Pseudo-code for Watchdog/Cleanup logic
async function watchdogCleanup(pool: AgentPool) {
  for (const agent of pool.list()) {
    const state = agent.getState();
    if (state.status === 'idle' && !state.isReserved) {
      // Only prune if not reserved for a long-running task
      await pruneAgent(agent);
    }
  }
}
```

## 4. Conclusion
The epiphany is valid. The current hierarchy is indeed fighting itself. By introducing a `isReserved` state into the agent lifecycle, we allow the 'Slow Track' intelligence to signal its need for environmental stability, effectively shielding it from the 'Fast Track' efficiency optimizations.
