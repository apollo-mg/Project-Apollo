The 'sensory integrity check' should involve:
1. Verifying how `buddy_agent.py` consumes visual data.
2. Checking if `desktop_eyes.py` (or similar) has validation mechanisms (e.g., checksums, timestamping, or visual consistency checks).
3. Identifying if there's a gap between the moment a screenshot is taken and when the VLM processes it, where "tool-induced artifacts" could occur.

## Plan:
1. Examine `buddy_agent.py` to see how it interacts with visual inputs.
2. Examine `desktop_eyes.py` to understand the capture mechanism.
3. Search for any existing "integrity" or "validation" logic in the codebase.
## Findings:
- `buddy_agent.py` uses `SovereignGuardian.check_system_integrity()` (line 49) to check system integrity.
- It also uses `ApolloAgentSession` (line 62) which takes an `image_path`.
- The "integrity" check currently seems to be a general system check, not specifically a "sensory integrity check" for the vision pipeline.
- The `image_path` is extracted from the user input via regex (line 56).

## Next Steps:
1. Investigate `buddy_guardian.py` to see what `check_system_integrity()` actually does.
2. Investigate `modules/agent_session.py` to see how it handles the `image_path` and if it performs any validation on the image.
3. Investigate `desktop_eyes.py` to see how images are captured and if there's any metadata (like timestamps) that could be used for a sensory integrity check.
## Findings:
- `SovereignGuardian.check_system_integrity()` (lines 91-121) is a file-level integrity check. It compares the SHA-256 hashes of core files against a manifest (`guardian_manifest.json`).
- This is a *static* integrity check (code/config), not a *sensory* integrity check (visual/perceptual).
- The Epiphany's "sensory integrity check" is indeed missing. The current system verifies that the *brain* (code) hasn't been tampered with, but it doesn't verify that the *eyes* (screenshots) are seeing reality.

## Next Steps:
1. Investigate `modules/agent_session.py` to see how it handles the `image_path`.
2. Investigate `desktop_eyes.py` to see how it captures screenshots.
3. Formulate a proposal for a `SensoryIntegrityCheck` module or method.
   - This could involve:
     - Verifying the timestamp of the image file.
     - Checking for visual artifacts (e.g., black frames, frozen content).
     - Comparing the image hash/metadata with the expected capture time.
## Findings:
- `desktop_eyes.py` uses `spectacle` (line 29) for Linux/KDE captures.
- The capture process is a simple `subprocess.run` call.
- There is NO validation of the resulting image file (e.g., checking if it's a valid image, checking its size, or checking its timestamp).
- `analyze_desktop` (line 35) performs a downscale/conversion (lines 47-55) but this is for transmission efficiency, not integrity.
- `buddy_agent.py` (line 62) passes an `image_path` to `ApolloAgentSession`.
- `ApolloAgentSession.run` (line 93) passes this `image_path` to `llm_interface.stream_llm`.

## Conclusion:
The "sensory integrity check" is indeed missing. The system assumes that if `capture_screen()` returns a path, the image at that path is a valid, recent, and accurate representation of the current state.

## Proposed Architectural Update:
Implement a `SensoryIntegrityCheck` class/module.

### 1. Proposed `SensoryIntegrityCheck` Logic:
- **Temporal Validation:** Compare the file's `mtime` (modification time) with the current system time. If the delta is too large (e.g., > 5 seconds), flag it as a "stale sensory input".
- **Visual Integrity (Basic):** 
    - Check if the file size is suspiciously small (e.g., < 1KB, which might indicate a failed capture or a black frame).
    - Use `PIL` to check if the image is actually readable and not corrupted.
    - (Advanced) Check for "frozen" content by comparing hashes of consecutive captures (though this might be too heavy for a simple check).
- **Integration Point:**
    - Call this check inside `desktop_eyes.py` before returning the path.
    - Call this check inside `ApolloAgentSession` before passing the image to the LLM.

### 2. Draft Implementation Plan:
- **Step 1:** Create `modules/sensory_integrity.py`.
- **Step 2:** Add a `validate_image(path)` method to this module.
- **Step 3:** Update `desktop_eyes.py` to use this validation.
- **Step 4:** Update `buddy_agent.py` or `ApolloAgentSession` to handle "Sensory Integrity Failure" gracefully (e.g., by alerting the user or retrying the capture).
