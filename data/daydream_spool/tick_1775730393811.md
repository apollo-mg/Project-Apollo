# Architectural Audit: Recursive Resource Exhaustion Loop

## 1. Epiphany Validation
The investigation confirms the "Observer Effect" hypothesis. The `CognitiveEscalation` module (`modules/cognitive_escalation.py`) utilizes blocking and heavyweight telemetry calls (`psutil.cpu_percent(interval=1)` and `subprocess.run(['ping', ...])`) within the primary error-handling path. During periods of high VRAM or CPU pressure, these calls introduce significant latency and context-switching overhead, which triggers further timeouts and error-handling cycles, creating a recursive failure loop.

## 2. Identified Critical Flaws
- **Synchronous Blocking:** The 1-second block in `psutil.cpu_percent` stalls the execution thread during critical error states.
- **Process Spawning Overhead:** Spawning a `ping` subprocess during resource exhaustion exacerbates system instability.
- **Reactive vs. Predictive:** The system reacts to OOM/errors after they occur, rather than managing a memory budget to prevent them.

## 3. Proposed Architectural Changes

### A. Decouple Telemetry (Asynchronous Monitoring)
**Target File:** `modules/cognitive_escalation.py`
- **Change:** Implement a `SystemHealthMonitor` running in a background `threading.Thread`.
- **Mechanism:** The monitor will update a thread-safe `SystemHealth` singleton at a fixed interval. The `CognitiveEscalation` module will perform **O(1) reads** from this singleton instead of performing **O(N) syscalls/process spawns**.
- **Benefit:** Eliminates the blocking "Observer Effect" from the main execution path.

### B. Predictive Memory-Budgeting
**Target File:** `modules/cognitive_dispatcher.py`
- **Change:** Implement a `predict_resource_requirement(task_complexity)` method.
- **Mechanism:** Use a heuristic-based model (e.g., `Complexity_Score * Model_Parameter_Count`) to estimate VRAM requirements before task dispatch.
- **Benefit:** Allows the `CognitiveDispatcher` to reroute tasks to lower-tier models *before* a hardware-level OOM occurs.

### C. Lightweight Probes
- Replace `subprocess.run(['ping', ...])` with a non-blocking socket connection check.
- Replace `psutil.cpu_percent(interval=1)` with `psutil.cpu_percent(interval=None)` to utilize non-blocking delta calculations.

## 4. Implementation Roadmap (Draft)
1. **Phase 1 (Immediate):** Refactor `CognitiveEscalation` to use a background monitoring thread and non-blocking reads.
2. **Phase 2 (Stability):** Replace all `subprocess` calls in the telemetry path with lightweight library calls.
3. **Phase 3 (Intelligence):** Integrate the predictive budgeting logic into the `CognitiveDispatcher` to enable proactive resource management.
