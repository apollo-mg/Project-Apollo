# Architectural Audit: Guardian Watchdog Monitoring Overhead

## 1. Executive Summary
The "Epiphany" identifies a critical risk: the Guardian Watchdog, designed to protect the RDNA 4 substrate, may itself become a source of instability by consuming excessive resources (CPU/GPU/VRAM) during its monitoring cycle. Current testing protocols (e.g., `test_27b.py`) focus on LLM throughput (TPS) but fail to account for the "Observer Effect"—where the act of monitoring alters the system state.

## 2. Current State Analysis
- **Guardian Implementation (`buddy_guardian.py`):** Currently functions as a logic and integrity sentinel (LLM-based alignment and SHA-256 file integrity). It does **not** yet implement hardware-level monitoring (temperature, power, or RDNA 4 specific metrics).
- **Testing Coverage:** Existing tests measure inference speed and token generation. There is no existing "Smoke Test" that validates the resource footprint of the Guardian itself.
- **Hardware Context:** The system is targeting AMD RDNA 4 (RX 9070 XT) via ROCm 7.11, a "Technology Preview" known for potential regressions. High-frequency monitoring could exacerbate these instabilities.

## 3. Proposed Architectural Update: The "Observer Effect" Guardrail

### A. Implementation of Hardware Monitoring
The Guardian must be extended to include a `HardwareSentinel` module that interfaces with ROCm/sysfs to monitor:
- GPU Temperature (to prevent thermal throttling).
- VRAM Utilization (to prevent OOM/spillover).
- Power Draw (to ensure stability under heavy inference).

### B. New Smoke Test: `test_guardian_overhead.py`
A mandatory test must be added to the CI/CD pipeline to ensure the Guardian's footprint remains within acceptable bounds.

**Test Logic:**
1. **Baseline Phase:** Measure average GPU/CPU/VRAM usage during a standard inference loop (e.g., using `test_27b.py` logic).
2. **Active Phase:** Enable the `HardwareSentinel` and run the same inference loop.
3. **Delta Calculation:** 
   - $\Delta_{VRAM} < 50\text{MB}$
   - $\Delta_{CPU\_Usage} < 2\%$
   - $\Delta_{GPU\_Compute\_Latency} < 5\text{ms}$
4. **Failure Condition:** If the Guardian's monitoring causes the system to exceed these thresholds, the test fails, preventing the deployment of a "heavy" watchdog.
