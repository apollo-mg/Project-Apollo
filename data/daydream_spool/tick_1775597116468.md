# Architectural Audit: Integrity Baseline & Manifest Priority

## Epiphany Analysis
The subconscious daemon has identified a critical synchronization failure: the system's communication/notification layer (the "voice") is operating ahead of its integrity verification layer (the "memory"). The "potential loop" error is identified as noise generated by the notification layer, which lacks the deterministic context provided by a hash manifest.

## Audit Findings
1.  **Missing Integrity Layer:** The `coordinator.log` indicates a previous successful implementation of `src/integrity_layer.py` (a "Mutation Guard"). However, a filesystem audit confirms that `src/integrity_layer.py` **does not exist** in the current working directory. This represents a significant "memory loss" or a failure in the persistence of the integrity layer.
2.  **Absence of Hash Manifest:** A recursive search for `manifest`, `hash`, `integrity`, and `checksum` files yielded no results within the core `src/` directory, confirming that the "Last Known Good" hash manifest mentioned in the epiphany is currently absent from the active codebase.
3.  **Systemic Instability:** The system is currently running on a TypeScript/Node.js stack (`src/index.ts`, `src/agent/agent.ts`), but the logs suggest a Python-based integrity layer (`integrity_layer.py`) was intended to be part of the architecture. This mismatch between the execution environment and the integrity logic contributes to the "noise" and "feedback loop" described.

## Proposed Architectural Recovery Plan

### Phase 1: Establish the Deterministic Baseline (Immediate Priority)
1.  **Re-implement/Restore Integrity Layer:** Re-establish the `IntegrityLayer` and `MutationGuard`. Given the current stack is TypeScript, the integrity layer should be ported to `src/integrity/integrity_layer.ts` to ensure native compatibility and prevent cross-language execution overhead/noise.
2.  **Generate Hash Manifest:** Implement a `ManifestGenerator` service that scans the `src/` directory and generates a `manifest.json` containing SHA-256 hashes of all critical source files.
3.  **Guardian Integration:** The `Guardian` (or the equivalent orchestrator component) must be updated to perform a mandatory `verify_integrity()` check against the `manifest.json` *before* any notification or task execution occurs.

### Phase 2: Noise Reduction & Signal Clarification
1.  **Decouple Notifications from Execution:** Refactor the messaging system (`src/team/messaging.ts`) to ensure that "audible alerts" are strictly downstream of "integrity verification."
2.  **Implement Command-Loop Control:** Ensure that the `orchestrator` only processes signals that have been validated against the current hash manifest.
