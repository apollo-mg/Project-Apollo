# Epiphany Investigation: Sovereign Reserves & Offline Viability
## Timestamp: 2026-02-27
## Objective: Audit the dependency graph of the MoE swarm and local-first architecture to ensure no reliance on centralized/cloud APIs that could be severed.

## Initial Hypothesis:
The 'local-first' architecture might have 'hidden' dependencies in:
1. `llm_interface.py` (API calls to external providers).
2. `orchestrator.py` (Coordination logic).
3. `model_provisioner.sh` or `model_manifest.json` (How models are fetched/updated).
4. `src/` (Core logic).
5. `requirements.txt` (External libraries that might require internet for runtime/telemetry).

## Investigation Plan:
1. Scan `llm_interface.py` and `orchestrator.py` for HTTP/API calls.
2. Check `model_manifest.json` for remote URLs.
3. Check `requirements.txt` for telemetry or cloud-dependent packages.
4. Audit `src/` for any `requests`, `urllib`, or `aiohttp` usage that isn't explicitly local.
## Findings:
- Found `package-lock.json` in `tmp/open-multi-agent/` containing `@anthropic-ai/sdk` and `openai`. This is a potential vulnerability if this sub-project is part of the core MoE swarm.
- Need to check if `llm_interface.py` or `orchestrator.py` actually uses these or if they are just leftover artifacts in `tmp/`.
- Need to check `model_manifest.json` for remote model URLs.
- Need to check `requirements.txt` for any cloud-based telemetry.

## Next Steps:
1. Inspect `llm_interface.py` for actual API usage.
2. Inspect `orchestrator.py` for actual API usage.
3. Inspect `model_manifest.json`.
4. Inspect `requirements.txt`.
## Findings Update:
- `llm_interface.py` contains a `DEPLOYMENT_CONFIGS` dictionary.
- The `local` and `default` configurations use `http://127.0.0.1:8082/v1/chat/completions`. This is a local endpoint (likely `llama.cpp` or `vLLM` running locally).
- There is a `remote` configuration pointing to `https://api.example.com/v1/chat/completions` with `gpt-4-turbo`. This is a clear external dependency.
- **Critical Risk:** If the system is accidentally set to `remote` or if a component defaults to `remote` when `local` fails, the "Sovereign Reserve" is compromised.
- The `ACTIVE_DEPLOYMENT` is currently set to `"default"`, which points to the local endpoint.
- However, the existence of the `remote` config means the code *can* reach out to the internet.

## Next Steps:
1. Check `orchestrator.py` to see how it selects the deployment configuration.
2. Check `model_manifest.json` to see if model weights are being pulled from remote URLs.
3. Check `requirements.txt` for any telemetry/cloud-based packages.
## Findings Update:
- `profiles.json` confirms that the primary models (`architect`, `turbo`, `whisper`, `bonsai`) are all using local paths for their `.gguf` or `.bin` files.
- `architect` and `turbo` use `llama-server` binaries located in local `tmp/` directories.
- `whisper` uses a local `whisper-server` binary.
- `bonsai` uses a local `llama-server` binary.
- All models are hosted on local filesystems (`/mnt/TG_2TB/AI/Models/...` or `/mnt/TG_2TB/Projects/Apollo/models/...`).
- The `host` settings in `args` are either `0.0.0.0` (listening on all interfaces) or `127.0.0.1` (loopback).
- **Conclusion on Models:** The model weights themselves are local and do not require internet access to load.

## Final Audit Summary:
1. **Model Weights:** 100% Local. No remote fetching detected in `profiles.json`.
2. **Inference Engines:** Local binaries (`llama-server`, `whisper-server`).
3. **API Interface:** `llm_interface.py` has a `remote` configuration, which is a "trap" or a fallback. While the code *can* connect to `api.example.com`, the current `ACTIVE_DEPLOYMENT` is `default`, which points to `127.0.0.1:8082`.
4. **Dependency Risk:** The `package-lock.json` in `tmp/open-multi-agent/` suggests that some experimental or auxiliary tools might have cloud dependencies (Anthropic/OpenAI), but these are not part of the core `ServiceOrchestrator` or the primary `llm_interface.py` used by the Sovereign Architect.

## Recommendation:
- **Hardening:** Explicitly remove the `remote` configuration from `llm_interface.py` to prevent accidental or malicious redirection to external APIs.
- **Verification:** Ensure that `requirements.txt` does not contain any packages that perform mandatory "phone-home" telemetry (e.g., certain versions of telemetry libraries).
- **Sovereign Status:** The core MoE swarm (Architect, Turbo, Bonsai) is architecturally sound for offline operation.
