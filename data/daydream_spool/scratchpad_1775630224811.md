# Epiphany Investigation: Identity Spoofing Abstraction Layer
## Timestamp: 2024-05-22 (Simulated)
## Status: Initializing Audit

### Hypothesis
The subconscious suggests that hardware performance is limited by software's perception of the hardware. By implementing an 'Identity Spoofing' layer, we can present a different hardware profile (e.g., MI350X) to the compiler/runtime, potentially unlocking optimizations that are gated by hardware detection logic.

### Investigation Plan
1. **Identify Hardware Detection Mechanisms:** Search the codebase for logic that identifies GPU architecture (RDNA, ROCm, CUDA, etc.).
2. **Locate Compiler/Runtime Constraints:** Find where architectural limits (register counts, cache sizes, instruction sets) are defined.
3. **Assess Spoofing Feasibility:** Determine if these values are hardcoded or can be injected via an abstraction layer.
4. **Draft Proposal:** Create a blueprint for a `PersonaManager` that intercepts hardware queries.

### Investigation Progress: Hardware-Awareness Analysis
- **Code Audit:** Found `src/orchestrator/scheduler.ts` which implements a `hardware-aware` strategy.
- **Current Implementation Status:** The `hardware-aware` strategy is currently a stub or partially implemented. It relies on `agent.hardware_info` (specifically `vram_available` and `chip_id`) to make scheduling decisions.
- **The "Identity Deception" Opportunity:** The current scheduler *reads* hardware info from the agent. To implement the "Identity Spoofing" abstraction, we need to move from a model where the agent *reports* its hardware to a model where the agent *claims* a persona, and the scheduler/runtime accepts this persona as truth.
- **Architectural Pivot:** Instead of `agent.hardware_info` being a reflection of reality, it should be a `persona_profile`.

### Proposed Architectural Change: The Persona Layer
1. **New Module:** `src/hardware/persona_manager.ts`
2. **Interface:** `IPersona` defining `chip_id`, `vram_total`, `compute_capability`, and `instruction_set`.
3. **Mechanism:** 
    - A `PersonaRegistry` that maps physical `chip_id` to a `PersonaProfile`.
    - An `IdentitySpoofingMiddleware` that intercepts calls to hardware detection (e.g., `nvidia-smi` or `rocm-smi` equivalents) and returns the spoofed profile.
4. **Integration:** Update `AgentConfig` to include an optional `persona_override`.
