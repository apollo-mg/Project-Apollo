## Findings Update
- `modules/memory_core.py` implements a `MemoryManager` that performs a "compaction flush" when token thresholds are reached. This is a high-level context management, not direct VRAM management, but it's part of the "rhythm" of the system.
- `vram_management.py` is the smoking gun. It contains:
    - `get_gpu_stats()`: Uses `rocm-smi` to poll VRAM.
    - `wait_for_vram_release()`: A blocking loop that waits for VRAM to be freed, including a `time.sleep(3.0)` "Kernel cooldown".
    - `unload_comfy_vram()`: Sends a POST request to ComfyUI to `/free` memory.
    - `smart_vram_guard()`: A proactive guard that triggers `unload_comfy_vram()` if VRAM exceeds `VRAM_THRESHOLD_MB`.

## Analysis of the Epiphany
The "paradox of intervention" is clearly visible in `vram_management.py`. 
1. The `wait_for_vram_release` function's `time.sleep(3.0)` and the blocking nature of the loop create a "stop-the-world" event.
2. The `smart_vram_guard` is an "intervener" that tries to manage resources (VRAM) manually by triggering ComfyUI's cleanup.
3. This creates a race condition: the guard might trigger a cleanup while the kernel/driver is in the middle of a memory allocation or a compute kernel execution, leading to the "disruption of rhythm" mentioned in the epiphany.

## Proposed Action
1. **Deprecate `vram_management.py` logic**: Remove the proactive `smart_vram_guard` and the blocking `wait_for_vram_release`.
2. **Trust the Driver/Manager**: Allow the RDNA 4 driver and the multi-GPU manager (DisTorch) to handle memory lifecycle naturally.
3. **Refactor Orchestration**: Instead of "guarding" VRAM, focus on ensuring that tasks are scheduled with appropriate synchronization, letting the hardware handle the actual memory pressure.
4. **Remove `unload_comfy_vram` calls**: Stop the manual intervention via the ComfyUI API.

## Investigation Conclusion
The epiphany is correct. The manual VRAM management in `vram_management.py` is a source of instability. It introduces artificial delays and interrupts the natural flow of the GPU driver's memory management.
