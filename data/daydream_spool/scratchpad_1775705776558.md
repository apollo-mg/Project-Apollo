# Epiphany Investigation: JIT Skill-Loading Architecture
## Timestamp: 2025-05-22 (Simulated)
## Status: Investigating

### Hypothesis
The current architecture likely uses a monolithic system prompt or a large, static set of tool definitions passed to the LLM in every request. This increases instruction density and consumes context window space, potentially degrading reasoning performance.

### Investigation Plan
1.  **Identify the Orchestrator/Core Logic:** Locate the primary entry point for LLM interactions (likely `orchestrator.py` or `apollo.py`).
2.  **Audit Prompt Construction:** Trace how system prompts and tool definitions are constructed and sent to the LLM.
3.  **Analyze Tool Definition Injection:** Determine if tools are currently hardcoded in the prompt or dynamically selected.
4.  **Assess Current Context Usage:** Check if there are logs or metrics indicating context window saturation.

### Initial Findings
- Found `orchestrator.py` in the root directory.
- Found `apollo.py` in the root directory.
- Found `llm_interface.py` in the root directory.
- Found `fleet_orchestrator.py` in the root directory.
### Audit Findings
- **Confirmed Monolithic Prompt:** `ApolloAgentSession._prepare_system_prompt` (lines 25-62) constructs a massive system prompt containing:
    - The entire `SOUL` text.
    - The full `CURRENT INVENTORY` state.
    - Retrieved memory context.
    - A hardcoded, massive `tools_list` string (line 32) containing ~30 tool definitions.
    - Extensive agentic loop instructions and constraints.
- **High Instruction Density:** The `tools_list` is injected into every single session, regardless of whether the user's request requires them. This directly validates the "Epiphany" that instruction density is high.
- **Context Window Waste:** Every turn in the agentic loop carries this heavy system prompt, which could lead to "reasoning drift" or truncation in longer conversations.

### Proposed Architectural Change: JIT Skill-Loading
1.  **Decouple Tool Definitions:** Move the `tools_list` from a hardcoded string in `_prepare_system_prompt` to a structured registry (e.g., `modules/tool_registry.py`).
2.  **Implement Intent-Based Tool Selection:**
    - Modify `ApolloAgentSession` to perform a lightweight "Intent Analysis" (or use the existing `Orchestrator.fast_path` logic) before building the full prompt.
    - Instead of `tools_list = "..."`, use `tools_list = ToolRegistry.get_tools_for_intent(user_input)`.
3.  **Kernel Prompt:** Define a `KERNEL_PROMPT` that contains only the core identity (`SOUL`) and the agentic loop instructions.
4.  **Dynamic Injection:** Only inject the `tools_list` and `json_mandate` if the intent analysis suggests tool usage is required.

### Implementation Plan (Draft)
- **Step 1:** Create `modules/tool_registry.py` to hold tool descriptions.
- **Step 2:** Refactor `ApolloAgentSession._prepare_system_prompt` to accept a list of tools.
- **Step 3:** Update `ApolloAgentSession.run` to determine which tools to load based on `self.user_input`.
- **Step 4:** Update `llm_interface.py` (if necessary) to handle the leaner prompt structure.
