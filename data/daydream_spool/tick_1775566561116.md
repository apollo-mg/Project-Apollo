# Architectural Audit: Cognitive Feedback Loop Implementation

## 1. Epiphany Analysis
The subconscious has identified a fundamental structural truth: the `CognitiveDispatcher` is not just a router, but a tiered cognitive hierarchy. The current implementation uses a 0.6B model (Worker Tier) to perform `_llm_triage` (lines 146-180). This is a "System 1" reflexive process. 

The "Actionable Insight" proposes a **Cognitive Feedback Loop**: allowing the "System 2" (Architect Tier, 30B+ models) to retrospectively audit and grade the "System 1" (Worker Tier) routing decisions. This transforms the dispatcher from a static heuristic/classifier into a self-optimizing cognitive engine.

## 2. Current State Audit (`modules/cognitive_dispatcher.py`)
- **Routing Mechanism:** Uses `analyze_complexity` (heuristics + 0.6B LLM triage) to assign a `Tier` (Architect vs. Worker).
- **Missing Component:** There is currently no mechanism to capture the "ground truth" of a task's complexity once the Architect Tier actually processes it.
- **Data Silos:** The `_metrics` dictionary (lines 78-83) tracks counts but does not store the relationship between `task_id`, `assigned_complexity`, and `actual_complexity`.

## 3. Proposed Architectural Update

### Phase A: Metadata Expansion
Modify `TaskContext` to include `assigned_complexity` and a `feedback_status` flag.

### Phase B: The Feedback Hook
Implement a `submit_feedback` method in `CognitiveDispatcher`. This method will be called by the `execute_task` flow after an Architect-tier task completes.

### Phase C: The Retrospective Audit (The Loop)
1. **Architect Execution:** When a task is routed to `ARCHITECT`, the system notes the `TaskComplexity` assigned by the Worker.
2. **Ground Truth Extraction:** Upon completion, the Architect model is prompted to provide its own assessment of the task's complexity.
3. **Discrepancy Detection:** If `assigned_complexity != actual_complexity`, the discrepancy is logged to a new `training_memory.jsonl` or a dedicated `feedback_loop.db`.
4. **Threshold Refinement:** A background process (or a periodic task) will analyze these discrepancies to adjust the heuristic weights and the `_llm_triage` prompt instructions.
