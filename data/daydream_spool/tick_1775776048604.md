# Epiphany Audit: Capability Divergence in Hardware Procurement

## Summary
The subconscious has identified a critical "capability divergence" point in the $700 hardware market. The current paradigm of optimizing for TFLOPS/Dollar is insufficient for local LLM workflows. Instead, procurement must prioritize **VRAM/Dollar** to avoid the "intelligence vs. speed" binary trap.

## Findings
- **Current State:** The codebase contains procurement logic (`legacy_vault/modules/procurement.py`), but it is currently focused on consumer goods (grocery/shop supplies) rather than lab hardware.
- **The Divergence:** 
    - **Compute-Rich/Memory-Poor (e.g., NVIDIA Blackwell 5070):** High TFLOPS, but insufficient VRAM for large-parameter models. Results in "fast but shallow" intelligence.
    - **Memory-Rich/Compute-Poor (e.g., RDNA 4):** Lower TFLOPS, but higher VRAM capacity. Enables "slower but deep" intelligence (larger models + context).
- **Risk:** Optimizing for TFLOPS/Dollar will lead to a hardware stack that can run small models instantly but is physically incapable of hosting the larger, more intelligent models required for advanced reasoning and vision tasks.

## Architectural Proposal

### 1. Procurement Metric Shift
Transition the primary hardware evaluation metric from `TFLOPS/USD` to `VRAM_GB/USD`. 

### 2. Hardware Selection Matrix (Proposed)
Implement a tiered selection strategy for lab nodes:
- **Tier 1 (Reasoning Nodes):** Prioritize VRAM capacity (e.g., RDNA 4 or multi-GPU setups) to support 70B+ parameter models.
- **Tier 2 (Edge/Utility Nodes):** Prioritize TFLOPS/Latency (e.g., NVIDIA 5070) for small, fast-response tasks (e.g., the `RECEPTIONIST_MODEL` used in `procurement.py`).

### 3. Minimum Memory Floor
Establish a "Memory Floor" based on the target model weights + 20% overhead for context/vision. 
- *Example:* For a 70B model (4-bit quantization), the minimum VRAM floor is ~40GB.

## Conclusion
The epiphany is valid and requires an immediate shift in hardware procurement strategy to ensure the lab's computational capacity scales with model intelligence, not just raw throughput.
