# Architectural Audit: State-First Contingency Rule

## 1. Executive Summary
The investigation confirms the validity of the "Epiphany" regarding procedural rigidity. The current `AgentRunner` architecture implements a strict "Observe -> Act -> Observe" loop that treats all tool errors as logical feedback for the LLM. When a systemic error (e.g., 401 Unauthorized, Network Timeout) occurs, the agent enters an infinite loop of attempting to resolve the error using the same failing tool-path, rather than pivoting to environmental diagnostics.

## 2. Root Cause Analysis
- **Error Homogeneity:** In `src/agent/runner.ts`, tool errors are caught and converted into `ToolResult` objects with `isError: true`. The distinction between a "logical error" (e.g., `File Not Found`) and a "systemic error" (e.g., `401 Unauthorized`) is lost.
- **Loop Rigidity:** The `AgentRunner.stream` loop is designed to feed error messages back to the LLM as `user` role messages. This forces the LLM to "reason" its way out of a network failure, which is ineffective when the tool-calling mechanism itself is the bottleneck.
- **Lack of Priority Override:** There is no mechanism to intercept a specific error signature and inject a high-priority "Diagnostic Mode" instruction that bypasses standard conversational flow.

## 3. Proposed Architectural Update: "State-First" Contingency

### A. Systemic Error Detection
Introduce a `SystemicErrorDetector` utility to classify error messages.
- **Signatures:** `401`, `403`, `ECONNREFUSED`, `ETIMEDOUT`, `ENOTFOUND`, `DNS_RESOLUTION_FAILURE`.

### B. The "Diagnostic Pivot" (Implementation in `runner.ts`)
Modify the tool execution loop in `src/agent/runner.ts` (lines 373-384):

```typescript
// Proposed logic within the tool execution catch block
} catch (err) {
  const message = err instanceof Error ? err.message : String(err);
  const isSystemic = SystemicErrorDetector.isSystemic(message);
  
  if (isSystemic) {
    // 1. Flag the state (internal tracking)
    this.state.status = 'recovering_environment';
    
    // 2. Inject a high-priority System Message to force a pivot
    conversationMessages.push({
      role: 'system',
      content: [{
        type: 'text',
        text: `[CRITICAL SYSTEM ERROR]: A systemic environmental error was detected: ${message}. 
               You are now in DIAGNOSTIC MODE. 
               Bypass your previous task. Use low-level tools (e.g., bash) to verify 
               network connectivity, authentication, or DNS settings before proceeding.`
      }]
    });
    
    // 3. Return the error as a tool result so the loop continues, 
    // but the LLM now has the System instruction to pivot.
    result = { data: message, isError: true };
  } else {
    result = { data: message, isError: true };
  }
}
```

### C. Impact
- **Pros:** Breaks infinite loops; provides a deterministic path for error recovery; reduces token waste on failed retries.
- **Cons:** Requires careful tuning of the `SystemicErrorDetector` to avoid false positives (e.g., a tool returning "401" as a valid logical response).

## 4. Conclusion
The "State-First" contingency rule is a necessary evolution for the framework's robustness. It transforms the agent from a purely reactive loop into an environmentally-aware system capable of self-diagnostic recovery.
