# Architectural Audit: Workstation Delegation Capability Handshake

## 1. Executive Summary
The current delegation mechanism in `delegate_to_workstation.py` suffers from a "Stability Fallacy." It assumes the workstation's LLM is a constant service with a fixed intelligence level (`deepseek-r1:14b`). In reality, the workstation's resident model is a transient variable dependent on VRAM state. This mismatch can lead to high-complexity tasks being dispatched to low-parameter models, resulting in failure or degraded reasoning.

## 2. Identified Vulnerability
- **File:** `/mnt/TG_2TB/Projects/Apollo/tools/delegate_to_workstation.py`
- **Issue:** Hardcoded `OLLAMA_MODEL = "deepseek-r1:14b"` and lack of model verification.
- **Risk:** The agent may attempt complex reasoning (e.g., architectural analysis) using a model that is currently loaded for simple tasks (e.g., a 3B or 8B model), leading to "hallucination-driven delegation."

## 3. Proposed Architectural Update: The Capability Handshake

### A. Implementation Logic
Before dispatching the `delegate_task` payload, the tool must perform a "Handshake" to verify the active model's identity and capability.

1. **Model Discovery:**
   Query the Ollama API to identify the currently active model.
   - **Endpoint:** `GET http://10.0.0.5:11434/api/tags` (to see available) or a probe request to identify the active one.
   - *Note:* Since Ollama doesn't have a direct "get active model" endpoint in all versions, the tool should attempt to fetch the model list and compare it against a known "high-capability" list, or use a lightweight prompt to identify itself.

2. **Capability Mapping:**
   Introduce a `CAPABILITY_MATRIX` within the tool:
   ```python
   CAPABILITY_MATRIX = {
       "deepseek-r1:14b": {"reasoning": 4, "extraction": 3, "coding": 4},
       "llama3:8b": {"reasoning": 2, "extraction": 3, "coding": 2},
       "phi3:mini": {"reasoning": 1, "extraction": 2, "coding": 1},
   }
   ```

3. **Complexity Scoring:**
   The `instruction` provided to the tool should be parsed (or the tool should have a heuristic) to assign a `required_capability` score.

4. **Decision Gate:**
   - If `current_model.capability >= required_capability`: Proceed with delegation.
   - If `current_model.capability < required_capability`: Abort and return: `"Error: Insufficient intelligence. Current model [model_name] cannot handle this complexity. Please switch to a larger model."`

## 4. Conclusion
Integrating this handshake transforms the workstation from a "black box" into a "verifiable resource." This ensures the integrity of the Quartet architecture by preventing the degradation of reasoning quality during high-load operations.
