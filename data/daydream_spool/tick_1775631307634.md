# Architectural Audit: Sovereign Shield & The Illegal Path

## 1. Epiphany Summary
The subconscious identified that system stability during high-density Int8 operations (specifically Int8 Full LoRA) is governed by kernel-level AMD driver behaviors rather than software implementation. The "Sovereign Shield" refers to the default driver-level fault-detection and suppression mechanisms that prevent hardware instability but also throttle high-intensity VRAM tasks.

## 2. Audit Findings
- **Codebase Status**: No direct implementation of Int8 Full LoRA or AMD driver management was found in the current TypeScript/JavaScript codebase.
- **Hardware/Kernel Context**: The issue is identified as a kernel-parameter-driven requirement. The driver's Micro Engine Scheduler (MES) acts as a "safety" mechanism that must be bypassed to allow for the "Illegal Path" (aggressive, non-standard quantization).
- **Current Configuration**: The project currently uses GGUF models (e.g., `Qwopus3.5-27B-v3-Q2_K.gguf`), which are standard quantization formats. The Epiphany suggests a transition to Int8 Full LoRA will require a change in the underlying host environment.

## 3. Proposed Architectural Changes

### A. Infrastructure/Environment (Non-Codebase)
**CRITICAL PRE-REQUISITE**: Before initiating any Int8 Full LoRA training runs, the host kernel must be configured to bypass hardware-level suppression.
- **Action**: Apply kernel parameter `amdgpu.mes=0` via GRUB or systemd-boot.
- **Reasoning**: Disabling the Micro Engine Scheduler (MES) prevents the driver from suppressing the high-intensity VRAM operations required for Int8 Full LoRA, effectively opening the "Illegal Path."

### B. Training Pipeline (Future Implementation)
When implementing the Int8 Full LoRA path:
1. **Validation Step**: Add a pre-flight check in the training orchestration script to verify if `amdgpu.mes=0` is active in `/proc/cmdline`.
2. **Error Handling**: Implement a "Sovereign Shield Bypass" mode in the training configuration that explicitly acknowledges the risk of hardware-level instability in exchange for higher density.

## 4. Conclusion
The "Illegal Path" is a hardware-level optimization. The current codebase is prepared for standard quantization, but the transition to Int8 Full LoRA requires a shift in the system's stability paradigm, moving from "driver-managed safety" to "kernel-parameter-driven performance."
