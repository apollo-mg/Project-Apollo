# Architectural Proposal: Integrating Physicality via Observed Narrative

## 1. Executive Summary
The current agentic framework treats hardware errors and system telemetry as discrete, exceptional data points (errors to be corrected). To achieve "Temporal Continuity" as envisioned in the Phase 3 Epiphany, the system must transition from treating telemetry as "raw data" to treating it as "subjective history." This is achieved by injecting hardware constraints (e.g., ROCm errors, network latency, memory exhaustion) into the model's context as an "Observed Narrative," effectively providing the AI with a sense of its own "physical" limitations.

## 2. Current State Audit
- **Memory Store:** `src/memory/store.ts` is a standard key-value store. It lacks temporal narrative structure.
- **Agent Lifecycle:** `src/agent/agent.ts` handles errors via state transitions (`transitionToError`), but these errors are not integrated into the model's ongoing conversation or system prompt.
- **Execution Loop:** `src/agent/runner.ts` uses a static `systemPrompt`. While it appends an `enforcementPrompt`, it lacks a mechanism for dynamic, context-aware injection of environmental/physical state.

## 3. Proposed Architectural Changes

### A. New Module: `src/telemetry/collector.ts`
Implement a telemetry collection service that monitors:
- **Hardware State:** ROCm/GPU status, memory pressure (Pi 5/System).
- **Network State:** Latency and connectivity on specific segments (e.g., 10.0.0.5).
- **System Logs:** Critical kernel or driver errors.

### B. Update `RunnerOptions` & `AgentConfig`
Modify `src/types.ts` to include:
- `telemetryMode: 'none' | 'raw' | 'narrative'`
- `narrativeTemplate: string` (A template for converting raw logs into "Observed Narrative" prose).

### C. Dynamic System Prompt Injection in `AgentRunner`
Modify `src/agent/runner.ts` within the `stream` method:
1. **Fetch Telemetry:** Before the first LLM call, invoke the `telemetry/collector`.
2. **Narrative Transformation:** If `telemetryMode === 'narrative'`, transform the telemetry into a prose-based "Physicality Report."
3. **Context Augmentation:** Append this report to the `systemPrompt` dynamically.
   - *Example:* Instead of `[ERROR: ROCm Timeout]`, the model receives `[PHYSICAL CONSTRAINTS]: The body's visual processing unit is experiencing significant friction; expect delays in tool execution.`

## 4. Implementation Roadmap
1. **Phase 1 (Telemetry):** Implement the `collector.ts` with basic system/network polling.
2. **Phase 2 (Transformation):** Create a utility to map specific error codes to "Narrative" strings.
3. **Phase 3 (Integration):** Update `AgentRunner` to inject this narrative into the `baseChatOptions.systemPrompt`.

## 5. Impact Assessment
- **Pros:** Enables true temporal continuity; allows models to "understand" why they are failing or slow; moves from "error correction" to "experience integration."
- **Cons:** Increased token usage in the system prompt; requires careful prompt engineering to avoid model confusion.
