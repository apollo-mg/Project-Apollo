# Architectural Audit: Sensory-Motor Integration (Epiphany 1775780197044)

## 1. Executive Summary
The investigation confirms that the current telemetry architecture is "passive" (logging-centric). To achieve the "biological-style self-awareness" described in the epiphany, the system must transition to an "active" feedback loop where hardware telemetry (RDNA 4, BAE, IMU) acts as a sensory nervous system that triggers reflexive hardware adjustments.

## 2. Findings
- **Current State:** `HardwareOrchestrator` manages physical devices (audio, camera, sensors) via a command-response pattern. It uses `HIPKernelBarrierContext` for synchronization, ensuring stability but lacking a feedback mechanism.
- **Gap Analysis:** There is no direct link between real-time telemetry streams (e.g., RDNA 4 thermals) and the `HardwareOrchestrator`'s decision-making logic. Telemetry is currently treated as external data rather than internal "sensation."
- **Key Assets Identified:**
    - `src/hardware/hardware_orchestrator.py`: The central node for motor control.
    - `skills/sensory_buffer_skill/`: The intended site for afferent (sensory) data ingestion.
    - `src/hardware/kernel_synchronization.py`: The mechanism for ensuring hardware-level stability during reflexive adjustments.

## 3. Proposed Architectural Update: "The Reflex Arc"

### A. Afferent Pathway (Sensory Ingestion)
- **Task:** Upgrade `sensory_buffer_skill` to ingest high-frequency RDNA 4 and BAE telemetry.
- **Goal:** Transform raw data into "Sensory Events" (e.g., `ThermalStressEvent`, `PowerSurgeEvent`).

### B. Integration Center (Homeostatic Logic)
- **Task:** Enhance `HardwareOrchestrator` with a "Homeostatic Engine."
- **Mechanism:** The Orchestrator will compare incoming `Sensory Events` against predefined thresholds (e.g., `MAX_GPU_TEMP`).

### C. Efferent Pathway (Reflexive Action)
- **Task:** Implement "Reflexive Actions" within the Orchestrator.
- **Examples:**
    - `Thermal Stress` $\rightarrow$ `Throttle Compute / Reduce Power Limit`
    - `Power Instability` $\rightarrow$ `Reduce Peripheral Draw (Audio/Camera)`
    - `Kernel Instability` $\rightarrow$ `Trigger HIP Synchronization Barrier`

## 4. Implementation Roadmap (Draft)

### Phase 1: Sensory Ingestion
- Implement ROCm/sysfs polling in `sensory_buffer.py`.
- Define a standardized `SensoryEvent` schema.

### Phase 2: Orchestrator Integration
- Modify `HardwareOrchestrator.__init__` to accept a `HomeostaticProfile`.
- Implement `HardwareOrchestrator.handle_sensory_event(event)`.

### Phase 3: Reflexive Loop
- Map specific `SensoryEvents` to `HardwareOrchestrator` methods (e.g., `set_audio_gain`, `adjust_physical_parameter`).
- Ensure all reflexive actions are wrapped in `HIPKernelBarrierContext` to prevent race conditions during hardware state changes.
