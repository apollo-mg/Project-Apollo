## Epiphany Audit: Capability Divergence (VRAM vs TFLOPS)
**Timestamp:** 2024-05-22 (Simulated)
**Status:** Investigating

### Hypothesis
The current hardware procurement strategy may be biased towards compute throughput (TFLOPS) rather than memory capacity (VRAM). This creates a bottleneck for local LLM workflows where model weights and context windows are the primary constraints.

### Investigation Plan
1.  **Audit Existing Hardware Inventory:** Check for any existing procurement lists or hardware specifications in the codebase to see if the current bias is reflected in documentation.
2.  **Analyze Model Requirements:** Determine the VRAM requirements for the "intelligent" models the lab intends to run (e.g., Llama-3 70B, etc.) vs. the "small" models.
3.  **Evaluate Cost-Efficiency:** Compare VRAM/Dollar across different GPU architectures (NVIDIA vs AMD/RDNA).

### Initial Observations
- The epiphany identifies a "binary choice" between speed and intelligence.
- This suggests that our current "optimal" hardware might be failing to meet the actual operational needs of the lab.
### Investigation Progress
- **Hardware Inventory Audit:** No direct hardware procurement lists found in the immediate codebase. The `procurement.py` module appears to be for consumer goods (grocery/shop supplies) rather than lab hardware.
- **Model Requirements Analysis:** The epiphany highlights a critical divergence in the $700 hardware tier. 
    - *Compute-Rich/Memory-Poor (e.g., NVIDIA Blackwell 5070):* High TFLOPS, but limited VRAM. Good for small, fast models.
    - *Memory-Rich/Compute-Poor (e.g., RDNA 4):* Lower TFLOPS, but higher VRAM capacity. Necessary for larger, more intelligent models.
- **Actionable Conclusion:** The lab's procurement logic must shift from TFLOPS/Dollar to VRAM/Dollar to ensure the ability to run high-parameter models (e.g., 70B+) with sufficient context/vision overhead.

### Proposed Architectural Change
1. **Procurement Policy Update:** Update any internal documentation or automated procurement scripts (if they exist for hardware) to prioritize VRAM capacity.
2. **Hardware Selection Matrix:** Create a new decision matrix for lab hardware that weights VRAM capacity as the primary constraint for LLM-centric nodes.
3. **Model-Hardware Mapping:** Map current/planned model sizes (e.g., Llama-3 70B, Mistral Large) to minimum VRAM requirements to define the "Memory Floor".
