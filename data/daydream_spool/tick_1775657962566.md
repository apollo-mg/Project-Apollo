# Architectural Audit & Proposal: 'Clean-Slate' Protocol for Kernel Headers

## 1. Executive Summary
The investigation confirms the validity of the Subconscious Epiphany. The friction point identified—the intersection of high-level C++ template abstractions and the rigid macro-heavy requirements of ROCm 7.2—is present in the `ggml` backend implementations (specifically within `whisper.cpp/ggml/src/ggml-cuda/`). 

The current development pattern relies on incremental patching of kernel dispatch logic (e.g., `switch` statements and `#ifdef` blocks in `mmq.cu` and `sum.cu`) to handle architecture-specific optimizations (NVIDIA vs. AMD/CDNA). This approach is prone to "scope pollution" where macro-heavy ROCm requirements leak into the template-heavy C++ abstractions, leading to difficult-to-debug compilation errors.

## 2. Audit Findings
- **Friction Point:** `ggml-cuda/sum.cu` demonstrates a direct conflict where the use of `rocPRIM` (via `hipcub`) is blocked by a C++ versioning constraint (C++11 vs C++14), forcing an inefficient fallback.
- **Boundary Violation:** The `ggml_cuda_mul_mat_q_switch_type` in `mmq.cu` uses a manual dispatch mechanism that attempts to bridge generic types to specific hardware paths. This is the exact "boundary" where abstraction leaks occur.
- **Risk Assessment:** Continued incremental patching of these files increases the risk of cumulative macro-translation errors, where a fix for one architecture inadvertently breaks the template scope for another.

## 3. Proposed 'Clean-Slate' Protocol
To mitigate these risks, I propose the following protocol for all future kernel header and implementation updates:

### Phase I: Master Restore
- **Action:** Before any kernel-level modification, the target header/source files must be reverted to their last known "Golden State" (the most recent stable commit/version).
- **Goal:** Eliminate all "cumulative scope pollution" from previous incremental patches.

### Phase II: Atomic Application
- **Action:** All required changes (optimizations, bug fixes, new architecture support) must be prepared as a single, unified diff.
- **Constraint:** No intermediate "test-and-patch" cycles on the live codebase. The entire set of changes must be applied in one atomic operation.
- **Goal:** Ensure that the template scope and macro definitions are evaluated as a single, coherent unit, preventing the "leaky abstraction" effect.

## 4. Implementation Roadmap
1. **Refactor `ggml-cuda` (and `ggml-hip`):** Transition from manual `switch` dispatch to a more robust, template-specialized architecture-aware dispatch system that isolates ROCm macros within dedicated, non-leaky translation units.
2. **CI/CD Integration:** Implement a "Clean-Slate" check in the build pipeline that validates kernel headers against a strict set of macro-scope constraints.
3. **Version Alignment:** Prioritize upgrading the kernel-specific translation layers to C++14/17 to resolve the `rocPRIM` bottleneck identified in `sum.cu`.
