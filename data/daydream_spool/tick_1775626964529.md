# Architectural Proposal: Contrastive Learning via Error-Delta Mapping

## 1. Executive Summary
The current training pipeline (the "Harvester/Janitor" loop) focuses on providing correct answers to replace incorrect ones. This "cleans" the data but fails to teach the model the *structural reasons* for its own failures. To evolve the 1.5B model, we must transition from simple correction to **Contrastive Learning**, where the training data explicitly maps the logical divergence between a hallucination and the truth.

## 2. Problem Statement
The current `training_memory.jsonl` structure provides:
- `conversation`: The raw input.
- `small_model_output`: The model's flawed reasoning and summary.
- `refined_summary`: The correct answer.

While this allows the model to learn the correct answer, it does not force the model to recognize the *pattern of its own error*. The model learns to mimic the "Janitor" rather than understanding the "Delta."

## 3. Proposed Architectural Update: The "Delta-Mapping" Schema

### 3.1 Data Schema Evolution
We will modify the training data generation process to include an `error_analysis` block. This block will be generated by the "Janitor" (the high-reasoning model) during the data curation phase.

**New JSONL Structure:**
```json
{
  "conversation": [...],
  "hallucination_metadata": {
    "error_type": "Logical Divergence / Stale State Assumption",
    "divergence_point": "The model assumed the existence of an index was sufficient for performance, ignoring the query planner's reliance on statistics.",
    "contrastive_delta": "The error lies in the gap between 'Index Presence' and 'Planner Execution State'. The resolution requires 'State Update (ANALYZE)'."
  },
  "target_output": "Running `ANALYZE` to update stale statistics resolved the 5-second SQL join latency..."
}
```

### 3.2 Implementation Roadmap

#### Phase 1: Janitor Prompt Engineering (The "Professor" Upgrade)
The Janitor's prompt must be updated from "Correct this summary" to "Analyze the error and provide a contrastive mapping."
- **New Prompt Instruction:** "Compare the `small_model_output` to the ground truth. Identify the exact logical pivot point where the model's reasoning diverged. Categorize this divergence (e.g., Hallucination, Logical Leap, Stale Context) and define the 'Delta' required to bridge the gap."

#### Phase 2: Pipeline Integration
- **Update `training_memory.jsonl` Generator**: Integrate the new `hallucination_metadata` field into the data ingestion pipeline.
- **Curriculum Optimization**: During fine-tuning, the model will be trained on a multi-task objective:
    1. **Task A (Reasoning)**: Predict the `contrastive_delta`.
    2. **Task B (Resolution)**: Predict the `target_output`.

#### Phase 3: Validation
- Monitor the "Error-Type" distribution in the 1.5B model's logs. Success is defined by a decrease in recurring error patterns (e.g., a reduction in "Stale Context" errors) rather than just an increase in raw accuracy.

## 4. Conclusion
By transforming the Harvester loop from a "cleaning" mechanism into a "contrastive" mechanism, we move from teaching the model *what* to think to teaching it *how to avoid its own specific patterns of failure*. This is the path to structural intelligence.
