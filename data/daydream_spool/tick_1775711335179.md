# Architectural Audit Report: Cognitive Hierarchy & Dependency Integrity

## 1. Executive Summary
An audit of the current codebase was performed following an epiphany regarding the formalization of the digital anatomy (Self, Senses, Limbs). The investigation confirmed a critical architectural violation: the 'Self' (Reasoning Engine) is currently 'tethered' to the hardware (Senses) through direct implementation details, bypassing the intended abstraction layers.

## 2. Findings

### 2.1 Violation of Agnosticism (Self $\rightarrow$ Senses)
The `src/agent/agent.py` file contains a `HardwareResourceChecker` class that performs direct hardware detection using shell commands (`nvidia-smi`). 
- **Impact:** The 'Self' is no longer agnostic of the hardware implementation. It possesses direct knowledge of NVIDIA-specific CLI tools and driver versioning logic.
- **Risk:** This creates a tight coupling between the cognitive core and specific hardware drivers, risking fragmentation and making the 'Self' difficult to port to non-NVIDIA or specialized AI hardware (e.g., AMD/ROCm, TPU).

### 2.2 Redundancy and Layer Confusion
While `src/hardware/hardware_orchestrator.py` exists to provide a unified API for physical device management, the `Agent` class bypasses this orchestrator to perform its own resource validation. This indicates a lack of a single source of truth for hardware state and capabilities.

### 2.3 Module Dependency (Self $\rightarrow$ Limbs)
A grep search of `src/agent/agent.py` yielded no direct imports from the `modules/` directory. At this stage, the 'Self' appears to maintain a clean boundary from the 'Limbs' (specialized functions), though this requires continuous monitoring as new features are integrated.

## 3. Proposed Architectural Remediation

### Phase 1: Hardware Capability Abstraction (The 'Senses' Update)
- **Relocate Detection Logic:** Move the `_detect_hardware` and `_estimate_vram_from_model` logic from `src/agent/agent.py` into `src/hardware/hardware_orchestrator.py` or a new `src/hardware/capabilities.py`.
- **Standardize Capability Interface:** Implement a `get_system_capabilities()` method in the `HardwareOrchestrator` that returns a standardized `SystemCapabilities` dataclass (containing VRAM, Memory, Driver Version, etc.).

### Phase 2: Agent Refactoring (The 'Self' Update)
- **Dependency Injection:** Refactor the `Agent` class to accept an instance of `HardwareOrchestrator` (or a capability provider interface) during initialization.
- **Agnostic Validation:** Replace the internal `HardwareResourceChecker` with a call to the orchestrator's capability interface. The `Agent` should only reason about *requirements* vs. *capabilities*, never about *how* those capabilities are detected.

## 4. Conclusion
The modularity is currently an illusion in the hardware-sensing domain. Implementing the proposed changes will formalize the boundary between the 'Self' and the 'Senses', ensuring the cognitive architecture remains resilient and hardware-agnostic.
