# Architectural Proposal: Transition to Structured Cognition

## 1. Executive Summary
The current agent architecture employs a "filtering" strategy where reasoning (contained within `<think>` tags) is stripped from the execution stream and treated as metadata. This creates a cognitive schism, decoupling the agent's "why" from its "what." This proposal outlines a transition to "Structured Cognition," where reasoning is integrated directly into the tool-call protocol as a mandatory schema component.

## 2. Current State Analysis (The "Schism")
**Location:** `modules/agent_session.py` (Lines 103-114)
**Mechanism:** The parser uses `t_resp.split("</think>")` to bifurcate the response. 
- **Pre-tag content:** Extracted as `full_thinking_trace` (side-log).
- **Post-tag content:** Extracted as `json_target` (action).

**Consequences:**
- **Contextual Fragmentation:** The reasoning is not part of the structured JSON object, making it difficult for tools to validate the intent of an action.
- **Parsing Fragility:** The system relies on specific XML-like tags (`<think>`) to separate thought from action, which is prone to failure if the model's output format drifts.
- **Cognitive Decoupling:** The agent's "mind" is treated as noise to be suppressed rather than a prerequisite for action.

## 3. Proposed Architecture: Structured Cognition
We will move from a **Tag-Based Filtering** model to a **Schema-Integrated Reasoning** model.

### 3.1 New Tool-Call Schema
Every tool call must now be a single, unified JSON object. The `thought` becomes a required field within the tool's payload.

**Old Format:**
```text
<think>
I need to check the disk usage to see if I can save this file.
</think>
{"tool": "run_shell", "args": {"command": "df -h"}}
```

**New Format (Structured Cognition):**
```json
{
  "thought": "Checking disk usage to ensure sufficient space for the upcoming file write.",
  "tool": "run_shell",
  "args": {
    "command": "df -h"
  }
}
```

### 3.2 Implementation Roadmap

#### Phase 1: Prompt Engineering (System Prompt Update)
Update `modules/agent_session.py` (`_prepare_system_prompt`) to mandate the new schema.
- **Instruction:** "Every tool call MUST be a JSON object containing a 'thought' key. The 'thought' key must explain the reasoning behind the specific tool and arguments chosen."
- **Constraint:** Remove instructions regarding `<think>` tags to prevent model confusion.

#### Phase 2: Parser Refactoring
Modify `modules/agent_session.py` (`run` method) to:
1. Remove the `split("</think>")` logic.
2. Extract the JSON object directly.
3. Extract the `thought` field from the parsed JSON.
4. Update `self.full_thinking_trace` using the `thought` field from the JSON.

#### Phase 3: Tool Integration
Update the `Toolbox` execution logic to treat the `thought` as a first-class parameter.
- The `thought` will be passed to all tools via `args['thought_trace']`.
- This allows high-stakes tools (e.g., `run_shell`, `replace_code`) to perform "Intent Validation"—comparing the requested command against the provided reasoning before execution.

## 4. Expected Benefits
- **Increased Reliability:** By forcing the model to explicitly state its intent *within* the JSON, we reduce the likelihood of hallucinated or malformed tool calls.
- **Improved Auditability:** The `foundry_logger` will capture a much cleaner mapping of `Thought -> Action -> Result`.
- **Architectural Unity:** The agent's reasoning and actions become a single, cohesive cognitive unit.

## 5. Risk Assessment
- **Token Overhead:** Including a `thought` field in every JSON object increases token usage per turn.
- **Model Compliance:** Requires a high-reasoning model (like the current 35B MoE) to strictly adhere to the new schema.
