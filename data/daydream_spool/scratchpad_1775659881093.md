# Investigation: Environment Identity Crisis
## Epiphany Analysis
The subconscious suggests that the boundary between the virtual environment and the system path is porous. Specifically, calls to binaries like `python3.12` might be resolving to system-level binaries rather than the intended virtual environment binaries, leading to "identity crisis" where the execution context is incorrect.

## Hypothesis
The codebase contains subprocess calls or shell commands that use relative or ambiguous binary names (e.g., `python3`, `pip`, `pytest`) instead of absolute paths derived from the current virtual environment. This can lead to non-deterministic behavior if the `PATH` environment variable is modified or if the execution context shifts.

## Audit Plan
1. Search for subprocess calls (e.g., `subprocess.run`, `os.system`, `os.popen`) in the codebase.
2. Identify calls that invoke Python or other binaries by name.
3. Check for any hardcoded paths that might conflict with the venv.
4. Propose a pattern for "Environment Handshake" (logging `sys.executable`).
## Findings
- Found a hardcoded path in `./dist/tool/built-in/memory-recall.js`: `/mnt/TG_2TB/Projects/Apollo/venv_cachyos/bin/python`. While this is an absolute path, it's hardcoded to a specific environment, which might break if the project is moved or the venv is renamed.
- Found a shell command in `./examples/apollo_synthesizer.ts`: `execSync("pgrep -f 'python.*daydream.py'")`. This relies on the process name, which is fragile.
- Found a shebang in `./demo_error.py`: `#!/usr/bin/env python3`. This is the definition of the "identity crisis" mentioned in the epiphany—it relies on the environment's `PATH` to resolve `python3`.

## Refined Hypothesis
The "identity crisis" is most prevalent in scripts that rely on `#!/usr/bin/env python3` or shell commands that assume `python3` is available in the current `PATH`. In a distributed or containerized environment, this can lead to the wrong Python interpreter being used.

## Proposed Architectural Changes
1. **Standardize Binary Resolution**: Implement a utility function (e.g., `get_venv_python()`) that resolves the absolute path to the current virtual environment's Python interpreter using `sys.prefix`.
2. **Mandatory Handshake**: Before any background process or subprocess is spawned, log the `sys.executable` and the current `sys.path` to a centralized audit log.
3. **Replace Shebangs**: In critical scripts, replace `#!/usr/bin/env python3` with a more robust mechanism or ensure they are always executed via the venv's interpreter.
4. **Absolute Path Injection**: Instead of `subprocess.run(["python3", ...])`, use `subprocess.run([sys.executable, ...])`.
