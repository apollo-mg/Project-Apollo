# Investigation: Benchmark Metric Inaccuracy (CoT Tokenization)

## Hypothesis
The current benchmarking logic likely strips `<think>` tags and uses a heuristic (1.3x word-to-token) to estimate token counts. This underestimates the actual computational cost of the Chain of Thought (CoT) process, leading to skewed efficiency metrics.

## Investigation Plan
1. Locate the benchmarking logic/scripts.
2. Identify the specific code responsible for calculating token counts or processing model outputs.
3. Verify if `<think>` tags are being stripped and if a heuristic is being used.
4. Propose a fix: Integrate a real tokenizer (e.g., `tiktoken`) and include the full CoT token count.

## Initial Findings
- Project root identified.
- Log files like `bonsai_bench.log` and `bonsai_cpu_gpu_bench.log` suggest benchmarking is happening.
- `batch_log_processor.py` might be involved in processing results.
## Identified Culprit
Found a direct match for the heuristic in `legacy_vault/tools/sglang_test.py`:
`tokens = len(response.split()) * 1.3`

This confirms the "1.3x word-to-token heuristic" mentioned in the Epiphany. While this file is in `legacy_vault`, it indicates a pattern of using naive estimation rather than actual tokenization.

## Current State of Benchmarking
- The `open-multi-agent` directory (likely the active framework) uses `totalTokenUsage.output_tokens` and `input_tokens` which are populated from LLM responses (e.g., `anthropic.ts` and `openai.ts`).
- However, the Epiphany suggests that the *actual* measurement loop (the one that generates the benchmark results) might be stripping `<think>` tags before calculating these counts, or using a separate script that relies on the heuristic.
- The `anthropic.ts` file shows it handles `thinking` blocks:
  `text: [Thinking Process]\n${(block as any).thinking}\n[/Thinking Process]`
- If the benchmark runner uses the `output_tokens` from the API, it *should* be accurate, but if it's post-processing the text and re-calculating tokens using a heuristic, it will be wrong.

## Proposed Architectural Change
1. **Eliminate Heuristics:** Remove all instances of `len(text.split()) * 1.3`.
2. **Deterministic Tokenization:** Implement a standard tokenizer (e.g., `tiktoken` for OpenAI-style or `anthropic`'s specific logic) within the benchmark runner.
3. **Preserve CoT for Measurement:** Ensure the benchmark runner receives the *raw* model output (including `<think>` tags) before any UI-centric stripping occurs.
4. **Update Metric Definition:** Redefine "Efficiency" as `Total Tokens (Input + CoT + Output) / Time`.

## Next Steps for Audit

- Check `batch_log_processor.py` to see if it performs any post-hoc token estimation.
