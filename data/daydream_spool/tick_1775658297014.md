# Architectural Proposal: Mitigating Memory Fragmentation in Generative Workflows

## 1. Executive Summary
The "Daydream" daemon, which handles high-dimensional generative tasks, is experiencing significant memory fragmentation and VRAM bottlenecks. This is not a logic error but a resource ceiling issue. To resolve this, we must transition from a "brute force" memory allocation strategy to a more flexible, segment-aware approach.

## 2. Proposed Changes

### A. Environment Level: CUDA Memory Management
**Target:** The execution environment of the `daydream.py` process.
**Change:** Inject `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` into the process environment.

**Implementation Detail:**
Locate the script or service responsible for launching `daydream.py`. 
If launched via a shell script (e.g., `start_daydream.sh` or similar), update the execution line:
```bash
# OLD
python daydream.py --config config.yaml

# NEW
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
python daydream.py --config config.yaml
```

### B. Application Level: KSampler Resource Scaling
**Target:** The Python implementation of the KSampler (likely within `modules/` or a sub-module of the generative engine).
**Change:** Implement a "Resource-Aware Scaling" mechanism.

**Proposed Code Logic (Pseudo-code for Python):**
```python
def get_sampler_params(base_resolution, base_batch_size):
    try:
        # Check available VRAM
        available_vram = torch.cuda.mem_get_info()[0] 
        # Threshold for "High Pressure" (e.g., < 2GB free)
        if available_vram < 2 * 1024**3:
            logger.warning("Low VRAM detected. Scaling down KSampler parameters.")
            return (base_resolution // 2, base_batch_size // 2)
        return (base_resolution, base_batch_size)
    except Exception:
        return (base_resolution, base_batch_size)
```

## 3. Impact Assessment
- **Memory Stability:** High. `expandable_segments` reduces the frequency of OOM errors caused by fragmentation.
- **Performance:** Minimal impact on throughput, but significantly higher reliability for long-running "Daydream" cycles.
- **Complexity:** Low. Requires only environment variable changes and a small logic gate in the sampler initialization.

## 4. Verification Plan
1. **Monitor Fragmentation:** Run the `daydream.py` daemon and monitor `nvidia-smi` for "sawtooth" memory patterns.
2. **Stress Test:** Execute a high-resolution batch task and verify that the system does not crash with a `CUDA out of memory` error.
3. **Log Audit:** Ensure the `PYTORCH_CUDA_ALLOC_CONF` variable is correctly detected in the daemon's startup logs.
