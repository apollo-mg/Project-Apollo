# Architectural Audit: Standardization Gap (Triton/PyTorch/ROCm)

## 1. Executive Summary
The investigation confirms a "Standardization Gap" between high-level AI software (Triton/PyTorch) and the underlying ROCm hardware stack. Current error handling is reactive (post-failure), leading to "Hard-Patches" that address symptoms rather than the root cause: environment mismatch (C++ standards, ABI, compiler flags).

## 2. Findings
- **Current State:** The system relies on manual overrides and reactive error handling (as seen in `synthesizer_batch.log`).
- **Missing Component:** There is no automated "Pre-flight Validation" stage to audit the build environment before initiating long-running ROCm/Triton compilation cycles.
- **Risk:** Mismatched C++ standards (e.g., C++17 vs C++20) or ABI incompatibilities between the ROCm driver and the PyTorch/Triton build environment cause silent data corruption or hard build failures.

## 3. Proposed Architectural Update: "Infrastructure Provenance"

### A. New Module: `src/utils/preflight_audit.py`
Implement a Python-based auditing tool to be executed at the start of any build/deployment pipeline.

**Audit Checklist:**
1. **Compiler Check:** Verify `gcc`/`clang` version and ensure `--std=c++17` (or required version) is the default.
2. **ROCm/HIP Check:** Validate `HIP_PATH` and `ROCM_PATH` exist and match the expected version.
3. **ABI Compatibility:** Check `libstdc++` vs `libc++` consistency.
4. **Library Versioning:** Verify `torch` and `triton` versions are compatible with the detected ROCm version.
5. **Warning Strictness:** Ensure `-Werror` is not masking critical environment warnings that indicate mismatch.

### B. Pipeline Integration
Integrate the audit into the build entry point (e.g., `Makefile` or `build.sh`):

```bash
# Example integration in a build script
python3 src/utils/preflight_audit.py --strict --target rocm
if [ $? -ne 0 ]; then
    echo "CRITICAL: Environment Audit Failed. Aborting build to prevent 'Hard-Patch' cycle."
    exit 1
fi
# Proceed with build...
```

## 4. Implementation Roadmap
1. **Phase 1 (Immediate):** Create `preflight_audit.py` with basic ROCm/Compiler version checks.
2. **Phase 2 (Integration):** Add the audit step to the `Forge` (Infrastructure & Provenance) pipeline.
3. **Phase 3 (Hardening):** Expand the audit to include ABI and library-specific dependency trees.
