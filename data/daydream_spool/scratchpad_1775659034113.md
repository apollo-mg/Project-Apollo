# Investigation: Cognitive Overhead Metric Integration
## Timestamp: 2025-05-22 (Simulated)
## Status: Initializing Audit

### Epiphany Context
The subconscious daemon has identified a critical trade-off: the allocation of VRAM for vision (Unsloth/Sensory) directly competes with the VRAM available for high-order reasoning (Logic). This is a zero-sum game of cognitive resource allocation.

### Objective
To implement a 'Cognitive Overhead' metric within the Sovereign Model Inventory to quantify this trade-off.

### Initial Hypothesis
The metric should be calculated as:
`Cognitive Overhead = (VRAM_Vision / Total_Available_VRAM) * (1 - Reasoning_Efficiency_Score)`
Or more simply, a ratio of `VRAM_Sensory : VRAM_Logic`.

### Files of Interest
- `model_manifest.json`: Likely contains model configurations and VRAM allocations.
- `vram_management.py`: Likely handles the actual allocation and monitoring of VRAM.
- `system_monitor.py` or `system_monitor_v2.py`: Likely tracks real-time resource usage.
- `telemetry_layer.py`: Likely the destination for new metrics.
- `SOVEREIGN_BLUEPRINT.md`: To see if there's an existing architectural definition for cognitive resources.

### Technical Gap Analysis
To implement the 'Cognitive Overhead' metric, we need:
1. **Model Categorization**: A way to tag models in `model_manifest.json` as `SENSORY` (e.g., Vision, Audio, TTS) or `LOGIC` (e.g., LLM, Reasoning).
2. **VRAM Attribution**: A mechanism to track which model/process is consuming which portion of the VRAM. Since `rocm-smi` gives aggregate usage, we need to track the *expected* VRAM footprint of loaded models.
3. **Metric Calculation**: A new function in `telemetry_layer.py` or a new module that calculates the ratio.

### Proposed Implementation Strategy
1. **Update `model_manifest.json` schema**: Add a `"category": "sensory" | "logic"` field to each model entry.
2. **Enhance `vram_management.py`**: Add a method to track "Allocated VRAM per Category" by summing the footprints of currently active models.
3. **Update `telemetry_layer.py`**: Add a `get_cognitive_overhead()` method.
4. **Integration**: Ensure the `system_monitor.py` includes this metric in its periodic telemetry heartbeats.

### Refined Implementation Plan
1. **Schema Update (`model_manifest.json`)**:
   - Add `"category": "sensory" | "logic"` to all model definitions.
   - Add `"estimated_vram_mb": int` to allow for mathematical modeling of the trade-off.

2. **VRAM Attribution (`vram_management.py`)**:
   - Create a registry of "Active Models" (models currently loaded in VRAM).
   - Implement `get_cognitive_overhead_stats()`:
     - Sum `estimated_vram_mb` for all active `sensory` models.
     - Sum `estimated_vram_mb` for all active `logic` models.
     - Calculate `overhead_ratio = sensory_vram / (sensory_vram + logic_vram)`.

3. **Telemetry Integration (`telemetry_layer.py`)**:
   - Add a specific event type `COGNITIVE_OVERHEAD_REPORT` to log these ratios periodically.

4. **System Monitoring (`system_monitor.py`)**:
   - Integrate `vram_management.py` into `get_system_stats()` to include GPU/VRAM metrics in the main telemetry heartbeat.

### Conclusion
The epiphany is architecturally sound. The current system tracks *what* is used, but not *why* it is used or the *cost* of that usage in terms of cognitive capacity. Implementing this metric will allow the Sovereign Model to make informed decisions about when to offload vision to preserve reasoning depth.
