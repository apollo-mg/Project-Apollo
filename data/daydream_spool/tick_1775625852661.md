# Architectural Proposal: Workflow Translation Middleware

## 1. Problem Statement
The current generative workflow relies on direct, hardcoded manipulation of JSON workflow files (e.g., `legacy_vault/tools/generate_image.py`). This creates a "semantic drift" where high-level intent (e.g., "set the prompt") is tightly coupled to fragile, low-level schema details (e.g., "Node 6, input 'text'"). Any change in the ComfyUI workflow structure or engine enums (samplers, schedulers) results in execution failure.

## 2. Proposed Solution: `WorkflowTranslationLayer`
Implement a middleware component that decouples high-level workflow abstractions from the low-level ComfyUI JSON schema.

### Core Components:
1.  **`SemanticMapper`**: Maps abstract concepts (e.g., `sampler_type`, `step_count`, `seed`) to specific Node IDs and input keys based on a registered workflow profile.
2.  **`TypeCaster`**: A validation engine that ensures all parameters conform to the expected JSON types (e.g., casting `float` to `int` for `start_at_step`, or ensuring `noise_seed` is a valid integer).
3.  **`EnumSynchronizer`**: A lookup table that maps human-readable aliases (e.g., `"simple"`, `"fast"`, `"standard"`) to the specific string enums required by the current ComfyUI version (e.g., `"euler_ancestral"`, `"dpmpp_2m_sde"`).

## 3. Implementation Plan

### Phase 1: Infrastructure (New Module)
Create `src/modules/workflow_translator.py` containing:
- `WorkflowProfile`: A dataclass defining the mapping for a specific workflow version.
- `Translator`: The main class providing `translate(workflow_json, semantic_updates)` method.

### Phase 2: Refactoring
Refactor `legacy_vault/tools/generate_image.py` to remove direct dictionary access:
```python
# OLD
workflow["6"]["inputs"]["text"] = prompt
workflow["25"]["inputs"]["noise_seed"] = seed

# NEW
translator = WorkflowTranslator(profile="flux_v1")
updates = {"prompt": prompt, "seed": seed}
workflow = translator.apply_updates(workflow, updates)
```

### Phase 3: Validation
Integrate a pre-flight check in the `requests.post` call to validate the final payload against the expected schema.

## 4. Expected Impact
- **Resilience**: Workflows can be updated/re-indexed without breaking the agent's logic.
- **Stability**: Eliminates type-mismatch errors (e.g., passing a string where an integer is expected).
- **Abstraction**: Allows the agent to think in "concepts" rather than "node IDs".
