# Architectural Audit: Recursive Stagnation in Diffusion Sampling

## 1. Executive Summary
The investigation confirms the "Epiphany" regarding recursive stagnation. The system is experiencing a logical failure in the diffusion sampling loop where the `sigmas` (noise schedule) or `denoise_mask` (spatial constraint) tensors are being provided with invalid, constant, or degenerate values. This prevents the sampling process from progressing through the noise levels, resulting in a "static, unchanging loop" where the error itself becomes the signal. This logical stagnation is likely a precursor to the `HIP error: an illegal memory access` observed in the hardware logs.

## 2. Root Cause Analysis
The "recursive stagnation" is identified as a failure in the interaction between the scheduler and the sampler:
- **Sigma Collapse:** If the `sigmas` tensor is generated with constant values (eg. all 1.0 or all 0.0), the sampler performs the same mathematical operation at every step, producing identical latents.
- **Mask Stagnation:** An invalid `denoise_mask` (e.g., all zeros or all ones in a way that conflicts with the scheduler) can prevent the model from applying any meaningful denoising, effectively trapping the process in a state of permanent entropy.
- **Feedback Loop:** The "error as signal" refers to the fact that the sampler is not failing due to syntax, but due to the mathematical impossibility of the input parameters to drive a state change.

## 3. Technical Findings
- **Log Evidence:** `comfy_startup.log` and `session-2025-11-29T23-45-1acbc334.json` confirm that `sigmas` and `denoise_mask` are critical parameters passed through `comfy.sample.sample` and `comfy.samplers.sample`.
- **Hardware Correlation:** The logical stagnation likely triggers the `HIP error` (illegal memory access) when the resulting degenerate tensors are processed by the GPU kernels.

## 4. Proposed Architectural Updates

### A. Scheduler Validation (Immediate)
Implement a validation layer in the scheduler module (likely `comfy/samplers.py` or related scheduler files) to ensure:
- `sigmas` are strictly monotonic (decreasing for standard diffusion).
- `sigmas` do not contain `NaN` or `Inf` values.
- `sigmas` have a non-zero variance across the sampling steps.

### B. Mask Integrity Check
Add a pre-sampling check for the `denoise_mask`:
- Ensure `denoise_mask` is a valid tensor of the correct shape.
- Verify that the mask is not a constant value that would nullify the entire sampling process.

### C. Error Handling & Telemetry
- Instead of allowing the sampler to proceed with invalid `sigmas`, throw a specific `InvalidSigmaScheduleError`.
- Log the state of the `sigmas` and `denoise_mask` tensors when a sampling error occurs to provide better diagnostic data for future "Epiphanies."
