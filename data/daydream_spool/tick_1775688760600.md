# Architectural Audit Report: RDNA/ROCm Optimization

## 1. Executive Summary
The investigation confirms a significant architectural misalignment between the software's hardware assumptions and the actual consumer-grade RDNA silicon being utilized. Current logs (`synthesizer_batch.log`) explicitly document hardware-level instability, silent data corruption, and "RMS Norm" errors attributed to ROCm/HIP/RDNA 4 friction.

## 2. Root Cause Analysis
- **Paradigm Mismatch:** The system is currently operating without a dedicated containerization layer for hardware-specific optimizations. It relies on standard ROCm/HIP execution, which is optimized for CDNA (Data Center) stability.
- **JIT Latency & Instability:** On RDNA hardware, the Just-In-Time (JIT) compilation of kernels introduces significant latency and potential for runtime instability, leading to the observed "Cognitive Dissonance" and "Contextual Blindness" in the logs.
- **Lack of Kernel Caching:** There is no existing mechanism to pre-compile and cache kernels for specific RDNA architectures (e.g., `gfx1030`, `gfx1100`).

## 3. Proposed Architectural Pivot: Bespoke Containerization
To resolve this, we must move away from "turnkey" ROCm images and implement a custom containerization strategy.

### Proposed Changes:
1. **Custom Dockerfile Implementation:**
   - Create a `Dockerfile.rdna` that uses a minimal base image.
   - Integrate `hipcc` and `rocminfo` to detect specific RDNA architectures.
   - Implement a pre-compilation step during the build phase to generate and cache `.hsaco` (HIP) kernels for the target architecture.
   
2. **Kernel Caching Layer:**
   - Implement a persistent volume mount for `/var/cache/rocm/kernels` to ensure that once a kernel is compiled for a specific RDNA version, it is reused across container restarts.

3. **Environment Lockdown:**
   - Use the "Infrastructure Provenance" protocol to ensure that the runtime environment matches the pre-compiled kernel architecture exactly, preventing JIT fallback.

## 4. Implementation Roadmap
- [ ] **Phase 1:** Develop `Dockerfile.rdna` with architecture-specific compilation.
- [ ] **Phase 2:** Integrate kernel caching into the CI/CD pipeline.
- [ ] **Phase 3:** Validate stability by monitoring "RMS Norm" errors and silent data corruption metrics in the `synthesizer_batch.log`.
