# Architectural Audit: Contextual Blindness & Path-Resolution Discrepancy

## 1. Epiphany Summary
The system is suffering from **'Contextual Blindness'** in its data pipelines (F5-TTS) and module registries (ComfyUI). The core issue is an **Assumption-Based Pathing** model where the system assumes a singular, static directory structure. However, the runtime environment is multi-pathed and dynamic, often driven by hidden configuration layers (e.g., `extra_model_paths.yaml` in ComfyUI) or directory shuffles during the 'Prepare' phase.

## 2. Audit Findings
- **Discrepancy Identified:** Manual probes (e.g., `os.path.exists`) return `True` while the system's internal path-resolution logic (e.g., `get_folder_paths`) returns `False` or points to different locations.
- **Root Cause:** The system relies on index-based access (e.g., `[0]`) or hardcoded relative paths, which fails when the environment injects additional paths via configuration files or dynamic mounting.
- **Current State of `modules/core.py`:** The current `core.py` implements safety bounds (`enforce_bounds`) and human approval (`require_human_approval`), but lacks a systemic **Environment Audit** layer to validate path integrity before execution.

## 3. Proposed Architectural Shift: 'Discovery-Based Pathing'
Instead of assuming paths, the system must implement a mandatory **Environment Audit** step in every pipeline.

### Proposed Implementation Strategy:
1. **Mandatory Audit Step:** Every module/pipeline must call an `audit_environment()` function.
2. **Path Discovery:** Use the system's own path-resolution logic (e.g., the ComfyUI `folder_paths` API) rather than manual `os.path` checks.
3. **Asset Verification:** Log the *entire* list of discovered paths and verify the presence of required assets (metadata, nodes, models) across *all* discovered paths.
4. **Failure Mode:** If the audit fails (e.g., a required asset is missing from a path that the system *claims* to be using), the pipeline must abort immediately with a "Contextual Blindness Error" rather than attempting to execute with stale/incorrect assumptions.

## 4. Draft Proposal for `modules/core.py` (Conceptual)
```python
def audit_environment(required_assets: dict[str, list[str]]):
    """
    Performs a mandatory discovery-based audit.
    required_assets: { 'folder_type': ['asset_name_1', 'asset_name_2'] }
    """
    # 1. Discover all paths via the system's internal registry
    discovered_paths = system_registry.get_all_paths() 
    
    # 2. Log the entire reality
    logger.info(f"ENVIRONMENT AUDIT: Discovered paths: {discovered_paths}")
    
    # 3. Verify assets across ALL paths
    for folder_type, assets in required_assets.items():
        found_any = False
        for path in discovered_paths[folder_type]:
            if all(os.path.exists(os.path.join(path, a)) for a in assets):
                found_any = True
                break
        if not found_any:
            raise EnvironmentAuditError(f"Critical asset mismatch in {folder_type}")
```

## 5. Conclusion
The transition from "Assumption" to "Discovery" is required to resolve the friction in the F5-TTS and ComfyUI modules. This audit must be treated as a first-class citizen in the Sovereign Engine's execution lifecycle.
