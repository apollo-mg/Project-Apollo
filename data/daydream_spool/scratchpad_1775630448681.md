# Investigation: SlimeVR Sensor Fusion to VMC Broadcast Mapping
## Epiphany Analysis
The subconscious suggests a decoupling between the IMU data (sensor fusion) and the VMC (Virtual Motion Capture) broadcast layer. The VMC protocol is sending packets, but the payload is effectively zeroed out (0.0), implying the data pipeline is intact but the data source is empty or not being mapped correctly.

## Initial Hypothesis
1. The SlimeVR server is receiving IMU data but failing to process it into a usable state.
2. The VMC broadcast module is reading from a buffer or state object that is not being updated by the sensor fusion engine.
3. There is a mismatch in the data structure/units between the fusion output and the VMC input.

## Investigation Plan
1. Locate the SlimeVR server implementation or the bridge component.
2. Identify the sensor fusion logic.
3. Identify the VMC broadcast logic.
4. Trace the data flow from IMU input -> Fusion -> VMC output.
