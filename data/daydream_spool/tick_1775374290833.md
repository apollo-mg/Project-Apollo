## 1. The Epiphany Analysis
The Subconscious has identified a critical failure mode in our current orchestration: **The Conflation of Intelligence and Reliability.**

We have been treating model performance as a binary "Intelligence" metric, leading to "Hard Swaps" (e.g., swapping DeepSeek-R1 for Llama 3.1) when a model's internal priors (hallucinations) conflict with the required precision. This is a reactive, inefficient strategy.

**The Core Problem:** "The Friction of Priors."
- **Model Priors:** Embedded weights that force a model into a known (but incorrect) pattern (e.g., the 47-ohm hallucination).
- **Stack Priors:** Software limitations (e.g., the RX 9070 XT/CUDA mismatch) that prevent the model from expressing its true reasoning capability.

## 2. Proposed Solution: The Prior-Validation Layer (PVL)
Instead of swapping models *after* a failure, we must implement a deterministic, lightweight pre-processing step that identifies "High-Risk Contexts" before inference.

### A. The PVL Architecture
The PVL is not an LLM; it is a **Deterministic Guardrail Engine**. It operates on three levels:

1.  **Pattern-Match Guard (PM-G):** A regex/keyword-based scanner that identifies "Trigger Terms" known to cause model hallucinations (e.g., specific technical constants, ambiguous physics terms, or highly contested historical dates).
2.  **Semantic Divergence Check (SD-C):** A lightweight embedding-based check (using a tiny, fast model like BERT or a small Qwen) to see if the prompt's intent deviates significantly from the "Safe Knowledge Base" of the target model.
3.  **Constraint Enforcement (CE):** A schema-validator that ensures the prompt does not contain instructions that violate the "Zero-Abstraction" principle (e.g., asking the model to use cloud-based APIs instead of local tools).

### B. Implementation Strategy: "Contextual Hardening"
We will move from a "Model-First" approach to a "Context-First" approach.

**Current Workflow:**
`Prompt` $\rightarrow$ `LLM Inference` $\rightarrow$ `Failure/Hallucination` $\rightarrow$ `Model Swap`

**Proposed Workflow (The Hardened Loop):**
`Prompt` $\rightarrow$ **`Prior-Validation Layer`** $\rightarrow$
- *If Low Risk:* `LLM Inference` $\rightarrow$ `Success`
- *If High Risk (Conflict Detected):* `Contextual Hardening` (Injecting "Anti-Prior" instructions into the system prompt) $\rightarrow$ `LLM Inference` $\rightarrow$ `Success`

class PriorValidationLayer:
    def __init__(self, model_profile):
        self.profile = model_profile # e.g., "DeepSeek-R1"
        self.known_hallucinations = self._load_hallucination_map()

    def _load_hallucination_map(self):
        # Map of "Trigger Terms" to "Correction Instructions"
        return {
            "47-ohm": "Avoid assuming 47-ohm resistance unless explicitly stated in context.",
            "standard library": "Do not assume standard library availability; use local paths.",
            # ... more mappings
        }

    def validate_and_harden(self, prompt):
        risk_score = 0
        hardening_instructions = []
        
        for trigger, instruction in self.known_hallucinations.items():
            if trigger.lower() in prompt.lower():
                risk_score += 1
                hardening_instructions.append(instruction)
        
        if risk_score > 0:
            return True, hardening_instructions
        return False, []
