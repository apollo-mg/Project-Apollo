# Architectural Audit: Protocol Compliance Benchmark (PCB)

## Epiphany Summary
The current diagnostic tools (`buddy_diagnostics.py`) are reactive, checking system health and roadmap completion via string matching and regex. The epiphany suggests transforming these into a **quantitative gatekeeper** for model deployment. Instead of just checking if the "LLM Brain" is online, we must validate the *intelligence* of the model (specifically the 9B distilled model) by measuring its ability to adhere to structural protocols (Roadmap entries, Action Tags, and JSON schemas) without falling into "thinking loops" or meta-commentary.

## Current State Analysis
- **`buddy_agent.py`**: Acts as the high-fidelity session orchestrator but lacks a formal feedback loop for model compliance.
- **`buddy_diagnostics.py`**: Currently performs hardware, connectivity, and basic roadmap parsing. The `parse_roadmap` method uses regex to find completed items, but it is a "dumb" check—it doesn't validate the *quality* of the model's output against the roadmap.
- **Tension Point**: There is a gap between the "Structure" (regex reliability) and "Intelligence" (model discipline).

## Proposed Architectural Update: The Protocol Compliance Benchmark (PCB)

I propose upgrading `buddy_diagnostics.py` to include a new module: `IntelligenceValidator`.

### 1. New Component: `IntelligenceValidator`
This component will not check hardware, but rather "Model Compliance." It will:
- **Task Generation**: Trigger a controlled prompt to the 9B model (e.g., "Generate a roadmap entry for Phase 14").
- **Regex/Schema Validation**: Use the existing regex patterns to verify if the output matches the required `[x] **Title**: Description` format.
- **Meta-Commentary Detection**: Use a secondary check (or a specific regex) to detect if the model included "Here is your roadmap entry:" or other conversational filler that violates the "Engineer" persona.
- **Success Rate Metric**: Instead of a binary "OK/FAIL", it will report a `Compliance Score (%)`.

### 2. Integration Plan
- **Step 1: Update `buddy_diagnostics.py`**:
    - Add `check_model_compliance()` to the `run()` loop.
    - Implement `_validate_output_format(output_string)` using the regex patterns found in `parse_roadmap`.
- **Step 2: Implement `run_diagnostic_benchmark()`**:
    - A new method that runs a battery of "Compliance Tests" (Roadmap generation, Action Tag emission, JSON schema adherence).
- **Step 3: Deployment Gate**:
    - Modify the deployment script (or the `buddy_agent.py` startup) to refuse execution if the `Compliance Score` falls below a threshold (e.g., 95%).

```python
def check_model_compliance(self):
    # 1. Trigger a test prompt via llm_interface
    test_prompt = "Generate a roadmap entry for a new feature called 'Quantum Memory'."
    raw_output = llm_interface.query(test_prompt)
    
    # 2. Validate against strict regex
    # Pattern: - [x] **Title**: Description
    pattern = r'^- \[x\] \*\*([^\]]+)\*\*: .+'
    matches = re.findall(pattern, raw_output)
    
    # 3. Check for meta-commentary (The "Thinking Loop" check)
    # If the output contains more than 10% non-structural text, it's a failure.
    if len(matches) > 0 and not self._has_meta_commentary(raw_output):
        self._log("Model Intelligence", "OK", "Protocol compliance verified.")
    else:
        self._log("Model Intelligence", "FAIL", "Model failed structural/meta-commentary check.")
```

## Conclusion
By moving from "Is the model running?" to "Is the model behaving?", we transform the diagnostic suite from a maintenance tool into a **Sovereign Quality Assurance** engine. This ensures that the 9B model's "intelligence" is actually being measured, not just its availability.
