# Architectural Proposal: Transition from Static Dossier to Recursive Core Axiom Set

## 1. Executive Summary
The current architecture maintains a rigid distinction between a "Static Dossier" (persistent identity) and "Recent Context" (transient session memory). This creates a "personality lag" where the agent's core identity fails to evolve with the user's changing needs or discovered system truths. 

Following the "Epiphany" discovered by the KAIROS model, we propose redefining the dossier as a **Core Axiom Set** and implementing a **Promotion Logic** to transform high-significance patterns from transient context into persistent axioms.

## 2. Proposed Changes

### A. Refactor `modules/core.py`
- **Rename**: `CitizenDossier` $\rightarrow$ `CoreAxiomSet`.
- **Update**: Rename `DOSSIER_PATH` to `AXIOM_PATH`.
- **Schema Update**: Add a `metadata` field to each category to track `last_updated` and `stability_score`.

### B. New Module: `modules/promotion_engine.py`
This module will act as the "identity stabilizer."

**Core Components:**
1. **`CandidateTracker`**: A lightweight persistence layer (using `data/promotion_candidates.json`) that tracks recurring patterns extracted from session histories.
2. **`SignificanceEvaluator`**: An LLM-driven utility that analyzes a pattern to determine if it is a "transient whim" or a "stable axiom."
3. **`PromotionLogic`**:
   - **Input**: `ApolloAgentSession` results and final answer.
   - **Process**:
     1. Extract potential axioms using a specialized prompt (e.g., "Identify any new stable truths or preferences expressed in this session").
     2. Increment the `occurrence_count` for these candidates in `CandidateTracker`.
     3. If `occurrence_count >= THRESHOLD` AND `stability_score > MIN_STABILITY`:
        - Call `CoreAxiomSet.add_insight(category, claim)`.
        - Remove the candidate from `CandidateTracker`.

### C. Integration in `modules/agent_session.py`
Modify `_finalize_session` to trigger the promotion process:

```python
# Proposed addition to ApolloAgentSession._finalize_session
from modules.promotion_engine import PromotionEngine

def _finalize_session(self):
    # ... existing logging ...
    
    # Trigger Promotion Logic
    try:
        engine = PromotionEngine()
        engine.process_session(
            user_input=self.user_input,
            final_answer=self.final_answer,
            tool_results=self.results
        )
    except Exception as e:
        self.foundry.log_error(f"Promotion Engine Failure: {e}")
```

## 4. Risk Assessment
- **Identity Drift**: If the threshold is too low, the agent's personality may become unstable. 
  - *Mitigation*: Implement a `stability_score` and a "Cooling Period" for new axioms.
- **Token Overhead**: Frequent LLM calls for significance evaluation.
  - *Mitigation*: Only run the evaluator on a sampled subset of sessions or when specific "insight" keywords are detected.
