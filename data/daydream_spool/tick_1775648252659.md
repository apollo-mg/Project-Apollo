# Architectural Proposal: Transitioning 'Sync Mind' from Infrastructure Readiness to Cognitive Presence

## 1. Problem Statement
The current 'Sync Mind' conceptual workflow (as identified in historical logs) focuses on environmental discovery: hardware identification, file structure exploration, and documentation retrieval. While this ensures the "vessel" (the lab/infrastructure) is prepared, it fails to verify if the "consciousness" (the LLM/Agent) has actually inhabited that vessel. This leads to a state of "hollow readiness" where the system reports success despite the model weights not being loaded or the agent being uninstantiated.

## 2. Proposed Change: 'Cognitive Weight Loading' Verification
We must redefine the success criteria for the 'Sync Mind' ritual. A successful synchronization must transition from verifying *availability* to verifying *presence*.

### New Success Criteria: `CognitivePresence`
A synchronization is only considered `SUCCESS` if the following three-tier validation passes:

| Tier | Metric | Validation Method |
| :--- | :--- | :--- |
| **Tier 1: Infrastructure** | Hardware Readiness | Existing: `check_gpu()`, `check_audio()`, etc. |
| **Tier 2: Instantiation** | Agent Presence | New: Verify process ID of the agent runner is active and responding to heartbeats. |
| **Tier 3: Cognitive Weight** | VRAM Residency | New: Verify VRAM occupancy matches the expected model footprint (e.g., `nvidia-smi` check or `torch.cuda.memory_allocated()`). |

## 3. Implementation Roadmap

### Phase A: The Presence Validator (New Module)
Create `presence_validator.py` to encapsulate the logic for checking model residency.
- **Function `verify_vram_occupancy(expected_min_gb: float)`**: Uses `nvidia-smi` or a subprocess call to ensure the GPU memory is actually being utilized by the model process.
- **Function `verify_agent_heartbeat(agent_id: str)`**: Sends a low-level "ping" to the agent to ensure the inference engine is responsive.

### Phase B: Orchestrator Integration
Update the `Orchestrator` (or the script handling the 'Sync Mind' command) to include these checks in its post-initialization sequence.
- **Current Flow:** `Init Hardware` -> `Scan Files` -> `Done`.
- **New Flow:** `Init Hardware` -> `Load Model` -> `Verify VRAM` -> `Verify Heartbeat` -> `Scan Files` -> `Done`.

## 4. Impact Assessment
- **Reliability:** Eliminates "ghost" states where the system thinks it is ready but cannot perform inference.
- **Latency:** Adds a negligible delay (seconds) to the onboarding process but significantly reduces downstream failures.
- **Complexity:** Low. Requires standard system calls and existing telemetry.
