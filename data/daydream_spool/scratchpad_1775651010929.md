
# Epiphany Investigation: Temporal Coherence & Noise Schedules
**Timestamp:** 2024-05-22 (Simulated)
**Status:** Initializing Audit

## Hypothesis
The 'strobe effect' in video generation is caused by a mismatch between the model's internal architecture and the noise sampling schedule (specifically the 'shift' parameter). 

## Investigation Plan
1.  **Codebase Scan:** Search for implementations of video generation models, specifically looking for noise scheduling, sampling parameters, and 'shift' logic.
2.  **Identify Discrepancies:** Check if current implementations are using hardcoded schedules or if they allow for dynamic shift adjustments.
3.  **Architectural Audit:** Determine if the current pipeline relies on post-processing (interpolation) to fix temporal issues, which would validate the Epiphany's claim.
## Findings
- **Evidence of 'shift' usage:** Found `max_shift` and `base_shift` in a JSON prompt for `ModelSamplingFlux` (Flux model). This confirms that 'shift' parameters are indeed used in high-end diffusion models to control the noise schedule.
- **Absence of Centralized Registry:** A search for `noise_schedule` and `max_shift` in the core logic (excluding `site-packages` and `legacy_vault`) yielded no centralized architectural component that maps models to their required sampling parameters.
- **Current State:** The codebase appears to handle specific model configurations (like `SD15` in `comfy.text_encoders`) but lacks a unified `RequirementRegistry` for temporal/noise parameters as suggested by the Epiphany.
- **Risk:** Without a centralized registry, new video models (like Wan2.1 or HunyuanVideo) are likely to be integrated with default/incorrect noise schedules, leading to the 'strobe effect' described in the Epiphany.

## Proposed Architectural Update
1. **Implement `RequirementRegistry`**: Create a new module `src/core/model_requirements.py` (or similar) that maps model architectures to their optimal `noise_schedule` and `shift` parameters.
2. **Update Orchestrator/Sampler**: Modify the sampling logic to query this registry before initializing the noise schedule.
3. **Validation Step**: Add a pre-flight check in the video generation pipeline to ensure `max_shift` is present and matches the model's requirements.

## Conclusion
The Epiphany is correct. The current architecture lacks the mathematical alignment layer required for temporal stability in video generation. We are currently treating temporal coherence as a post-processing/interpolation issue rather than a sampling schedule issue.
