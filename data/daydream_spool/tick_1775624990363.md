# Architectural Proposal: Resource-to-Weight Validation

## 1. Problem Statement
The current deployment workflow lacks a mechanism to validate that the target storage (e.g., RunPod volumes) has sufficient capacity to accommodate the model weights, quantization artifacts, and temporary files. This leads to silent or late-stage failures during model loading or processing, which are costly and disruptive.

## 2. Proposed Solution: `Resource-to-Weight` Validation
Implement a pre-deployment validation step that ensures the physical "vessel" (storage) can accommodate the "mind" (model).

### 2.1 Core Logic
The validation must follow the formula:
`Required Capacity = (Model Raw Weight) * 2`

The `2x` multiplier accounts for:
- Quantization processes (creating new files).
- Temporary swap/cache files during model loading.
- Metadata and logs.

#### Option B: Python Deployment Guard (Orchestration)
If deployment is managed via Python (as suggested by `patch_coordinator.py`), implement a `ResourceGuard` class.

```python
import shutil
import os

class ResourceGuard:
    @staticmethod
    def check_capacity(model_weight_gb: float, mount_point: str) -> bool:
        required_gb = model_weight_gb * 2
        total, used, free = shutil.disk_usage(mount_point)
        free_gb = free / (1024**3)
        
        if free_gb < required_gb:
            raise RuntimeError(
                f"Insufficient storage: Required {required_gb:.2f}GB (2x buffer), "
                f"but only {free_gb:.2f}GB available at {mount_point}."
            )
        return True
```
