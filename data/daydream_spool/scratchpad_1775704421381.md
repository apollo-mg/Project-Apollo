## Investigation Findings

### 1. Analysis of "Negotiable" vs "Hard" Constraints
The `test_logic_trap.py` file is a perfect embodiment of the "Declarative Protocol" in testing. It defines a set of rules (the `system_prompt`) that are intended to be "Hard Constraints":
- **Constraint 1:** Output ONLY raw JSON (No Markdown).
- **Constraint 2:** Exact keys ("id", "status_code", "action") and a forbidden word ("state").
- **Constraint 3:** Specific mathematical and conditional logic.

The "Sobriety Analysis" in the script acts as the validator that converts the "request" (the prompt) into a "fact" (the pass/fail result). If the model fails, it is not "negotiating"; it is simply failing to meet the environmental constant.

### 2. Governance & Operational Framework
- **`GLASS_COCKPIT.md`**: Acts as the "Master Registry." It is currently a manual document. The Epiphany suggests this should be more than a list; it should be a "non-negotiable discipline."
- **`ROADMAP.md`**: Shows a progression from "Completed" to "Current." The "Current" phases (Phase 10 and Phase 13) are where the "Declarative Protocol" is most needed. Specifically, Phase 13's "KAIROS Daemon" is the implementation of the very thing I am investigating.

### 3. Identified Vulnerabilities (The "Negotiation" Risk)
- **Manual Documentation:** `GLASS_COCKPIT.md` relies on human agents to "register" scripts. This is a "negotiable" process. A "Hard Constraint" version would involve a system-level check where an unregistered daemon is automatically flagged or killed by the `deepseek_watchdog.py`.
- **Context Management:** `ROADMAP.md` mentions "Context Window Efficiency" (Phase 12) as a completed task. However, the "VRAM is instantly crashing" section in `GLASS_COCKPIT.md` suggests that users still have to manually "hard-cap" context. This is a "negotiable" parameter that should be an "environmental constant" enforced by the `vllm_gatekeeper.sh`.

## Architectural Proposal: The Declarative Protocol

### A. Hardening the Governance (The "Registry" Law)
Instead of a manual `GLASS_COCKPIT.md`, implement a `registry.json` that is the *only* source of truth for running daemons.
- **Constraint:** Any process found in the process tree that is not in `registry.json` (and not on a whitelist) is treated as a "rogue variable" and terminated by the `deepseek_watchdog.py`.
- **Transition:** From "Please register your script" to "Unregistered scripts are non-existent."

### B. Hardening the Operational Boundaries (The "Context" Law)
- **Constraint:** Move context length limits from "User Settings" in Open WebUI to "System Constants" in the `vllm_gatekeeper.sh`.
- **Implementation:** The gatekeeper should intercept requests and automatically truncate/reject any request that violates the `MAX_CONTEXT_TOKEN` constant, rather than relying on the user to "hard-cap" it in the UI.

### C. Hardening the Logic (The "Sobriety" Law)
- **Constraint:** All agentic outputs must pass a "Sobriety Check" (similar to `test_logic_trap.py`) before being accepted by the `MessageBus`.
- **Implementation:** Integrate the logic from `test_logic_trap.py` into the `KAIROS Daemon`. If an agent's output fails the schema or logic check, the output is discarded, and the agent is "re-initialized" with the error as a hard constraint.

## Conclusion
The lab currently operates on a "Request-Response" model for governance. To achieve "Sovereign Entity" status (Phase 13), it must transition to a "Constraint-Enforcement" model. The "Declarative Protocol" is the mechanism for this transition.
