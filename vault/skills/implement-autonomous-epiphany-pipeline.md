# Implement Autonomous Epiphany Pipeline

This skill describes a workflow to transform raw background agent daydreams into a prioritized software engineering backlog. This prevents a "hallucination loop" where the same ideas are generated repeatedly without action.

## Procedure

### Stage 1: Deduplication (Clustering)
- **Objective**: Mathematically crush the noise by grouping semantically similar ideas.
- **Workflow**:
  1. Read the raw `.jsonl` epiphany file.
  2. Use a local embedding model (e.g., `all-MiniLM-L6-v2` via ChromaDB) to convert each epiphany into a vector.
  3. Query the collection for existing similar documents using cosine distance.
  4. Use a similarity threshold (e.g., `distance < 0.55`) to identify duplicates.
  5. Save only the unique "cluster heads" to a new file (e.g., `deduplicated_epiphanies.jsonl`).

### Stage 2: The LLM Tribunal (Scoring)
- **Objective**: Use a high-reasoning model to grade the value and feasibility of each unique idea.
- **Workflow**:
  1. Read the deduplicated list.
  2. For each idea, format a strict JSON schema prompt for a low-temperature (T=0.1) LLM call.
  3. Task the model to score the idea on:
     - **Feasibility** (1-10): Can a single agent implement this?
     - **Impact** (1-10): Codebase-wide value.
     - **Risk** (Low/Medium/High): Potential blast radius.
  4. Calculate a final weighted score (e.g., `Impact * Feasibility`).
  5. Output the sorted results to a prioritized queue (e.g., `ranked_queue.json`).

### Stage 3: Executor (Sandboxed Action)
- **Objective**: Safely implement the top-ranked tasks.
- **Workflow**:
  1. Pop the top task from the ranked queue.
  2. Use `git worktree` to spin up a completely isolated, parallel folder.
  3. Unleash a specialized sub-agent (see `deploy-software-engineer-subagent`) in the worktree.
  4. The sub-agent must "Act-then-Refine": write code, run tests, and verify success before reporting.

## Verification Checklist

- [ ] Inspect the Stage 1 output to ensure unique ideas are preserved while repetitive "hallucination loops" are filtered.
- [ ] Verify the LLM Tribunal is adhering to the strict JSON schema (use a Pydantic shield or similar validation).
- [ ] Confirm that `git worktree` is used to prevent accidental corruption of the main workspace during execution.

## Pitfalls

- **Schema Drift**: Background agents often change their output format over time. Always verify the JSON keys (e.g., `epiphany` vs `content`) before running the sorter.
- **Over-Permission**: Ensure the LLM Tribunal is running at a low temperature to prevent it from "daydreaming" about the ideas instead of scoring them.
